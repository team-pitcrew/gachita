# 가치타 프로필과 동승 연결

[T19](https://github.com/team-pitcrew/gachita/issues/25) · [T42 문구정리본 반영](https://github.com/team-pitcrew/gachita/issues/60) · 폰 웹앱의 프로필, 동승 연결 QR과 기록 동의, 구글 OAuth와 현대 계정을 구분하는 화면 명세

[개편 시안(11/14)](https://www.figma.com/design/bkASxUWEfhJKjawI1sVK8n?node-id=0-1)의 폰 P1~P8(390 × 844)이 이 문서의 화면입니다. [P2 프로필 만들기](https://www.figma.com/design/bkASxUWEfhJKjawI1sVK8n?node-id=5-431)는 1절, [P3 동승 연결 QR](https://www.figma.com/design/bkASxUWEfhJKjawI1sVK8n?node-id=5-509)과 [P4 탔어요·기록 동의](https://www.figma.com/design/bkASxUWEfhJKjawI1sVK8n?node-id=5-571)는 4절의 화면입니다. 시안과 이 문서가 다르면 이 문서를 따릅니다.

## 목적

가족과 동승자가 로그인 없이도 이름과 얼굴(캐릭터나 사진)을 정해 두고, 차에 탈 때는 폰의 동승 연결 QR을 차에 보여 여행에 들어와 각자 기록 동의를 고르게 합니다. 여행 코드나 초대 코드는 입력하지 않습니다. 가족을 따로 묶는 그룹도 두지 않고, 같은 차에 탄 기록으로만 이어집니다(11/14 결정, [ADR-0009](../../docs/adr/0009-family-group-and-qr-invite.md)의 그룹·QR 초대를 대신함). 첫 고객은 어린 자녀와 이동하는 부모입니다(기준 문서 11/13).

기본 화면은 **폰 웹앱**(`gachita.mangowhois.ai`)입니다. 이름 입력·프로필 편집·계정 인증은 폰에서 하고, 차에는 참가한 일행과 기록 상태만 보입니다([차량 화면](car.md)). 폰에서는 수음하지 않으므로 목소리 등록은 차에서 합니다([차량 화면](car.md) 흐름 1). 웹앱은 홈 화면에 설치할 수 있습니다(만듦(웹, 브라우저 확인, T6, #174). 실제 휴대폰에 설치해 보지는 않음).

구현 상태는 [차량 화면](car.md)과 같은 말로 적습니다. '만듦(웹, 브라우저 확인)'은 develop에 있고 PR에서 데스크톱의 폰 크기 브라우저(헤드리스 Chromium, 내장 브라우저, ego lite)로 본 것이며, 실제 휴대폰에서 본 것은 아닙니다. '만듦(서버)'는 API가 develop에 있고 테스트가 통과하지만 부르는 화면이 아직 없는 것, '만드는 중(T번호, PR #)'은 열린 PR, '계획'은 정했지만 구현이 없는 것입니다. 기준은 develop `dab35fb`(11/14)이고, 줄 번호는 이 커밋의 `frontend/web/app.js`입니다.

## 흐름

### 1. 출발 전: 프로필 만들기와 고치기 — 폰

1. 홈에 프로필이 없으면 '프로필 만들기', 있으면 '{이름} 님'과 '프로필'을 보입니다. 동승 연결 QR(4절)을 띄우려면 이 폰에 프로필이 있어야 합니다. 로그인은 필요 없고 이름과 캐릭터만 정하면 됩니다.
2. 프로필에는 **이름 또는 별명**(앞뒤 공백을 뺀 1~20자), **캐릭터**, **사진**(고르면 캐릭터 대신 보임), **기록 동의 기본값**(처음엔 꺼짐)을 넣습니다. 얼굴은 사진, 없으면 캐릭터, 없으면 기본 캐릭터(`basic`)로 보입니다. 이름 첫 글자로는 보이지 않습니다.
3. 캐릭터는 원본 시트 '말랑' 10종입니다(11/14 결정, 그림은 원본을 잘라 쓰고 다시 그리지 않음). API 값과 보이는 이름은 `basic` 기본, `cap` 캡모자, `glasses` 안경, `travel` 여행, `game` 게임, `sport` 운동, `pet` 반려동물, `camping` 캠핑, `office` 직장인, `healing` 힐링입니다. 이전 값(`bunny` 등 동물 여섯)과 목록에 없는 값은 기본 그림으로 보입니다. 서버는 20자 문자열만 받아 바꿀 것이 없습니다. 웹은 만듦(웹, 브라우저 확인, `app.js:36-47`, `:215-218`, T20, #175), 차는 만드는 중(T20, #217).
4. '저장'을 누르면 중복 제출을 막고, 성공 응답의 프로필 토큰을 이 브라우저에 보관한 뒤 '프로필을 저장했어요.'를 보입니다. 토큰을 화면이나 공유 링크에 넣지 않습니다. 실패하면 입력을 그대로 둡니다.
5. 기록 동의 기본값은 다음 여행의 동의 묻기 화면(4절)을 미리 채우는 값일 뿐입니다. 차에 탈 때 그 여행의 기록 안내를 다시 보이고 사용자가 고릅니다. 기본값만으로 녹음을 시작했다고 표시하지 않습니다.
6. '프로필 지우기'는 확인을 거칩니다. 지우면 앨범의 장면까지 지워진다고 먼저 알립니다. 사진만 지우는 '사진 지우기'는 따로 둡니다.

- 이름·캐릭터·사진·동의 기본값·지우기: 만듦(웹, 브라우저 확인, `frontend/web/app.js:215-271`, `:321-365`, #135·#175). 아직 다른 것: 저장 중복 제출을 막는 장치는 없습니다. 동의 기본값은 저장만 되고, 동의 묻기 화면은 아직 이 값을 읽지 않습니다(기본값과 관계없이 '동의해요'가 주 단추).

### 2. 구글 OAuth로 이어 받기·연결하기 — 폰

1. 제공자는 구글 하나입니다(T21, [ADR-0006](../../docs/adr/0006-oauth-provider-google.md)). 서버가 `GET /api/config`로 공개 Client ID를 줄 때만 프로필 화면 위쪽에 구글 칸을 보이고, 비었거나 받지 못하면 숨긴 채 기기 프로필만 씁니다. 프로필이 없으면 '구글로 계속', 있으면 '구글 계정 연결'입니다.
2. 구글로 가기 전에 `state`와 PKCE verifier를 이 탭에만 두고, 구글에는 그 해시(`code_challenge`, S256)만 보냅니다. 복귀 주소는 `/oauth/google/callback` 하나입니다. 돌아오면 주소창의 코드부터 지우고, `state`가 맞을 때만 코드·복귀 주소·verifier를 서버에 넘깁니다. 클라이언트 비밀 값은 폰에 두지 않습니다.
3. 처음 보는 계정이면 서버가 프로필과 토큰을 만듭니다. 구글에서 받은 이름은 고칠 수 있고, 동의 기본값은 꺼짐으로 시작합니다.
4. 이미 연결된 계정으로 들어오면 같은 프로필을 이어 받고 이 기기의 토큰을 새로 받습니다. 기기마다 토큰을 따로 두므로 다른 기기의 토큰은 계속 씁니다(`POST /api/profiles/me/tokens`, ADR-0009).
5. 이미 기기 프로필이 있으면 '내 프로필 → 구글 계정 연결'로 지금 프로필에 연결합니다. 성공하면 '이 프로필에 구글 계정을 연결했어요.'를 알리고, 다시 읽은 프로필의 `links`에 구글이 있으면 '구글 계정을 연결했어요' 칸과 '구글 연결 끊기'를 보입니다.
6. 그 구글 계정이 다른 프로필에 이미 연결돼 `409`가 오면 지금 프로필을 그대로 두고, 두 프로필을 자동으로 합치지 않습니다.
7. 취소하거나 실패하면 프로필 화면으로 돌아와 구글로 가기 전의 입력(이름·캐릭터·동의 기본값)을 되돌립니다. 고른 사진은 다시 골라야 합니다. 구글로 가는 사이 이 폰의 프로필이 바뀌었으면 연결하지 않고 멈춥니다. 같은 코드를 다시 보내지 않습니다.
8. '구글 연결 끊기'는 계정 연결만 없앱니다. 기기 프로필과 토큰은 남습니다.

- 웹 화면: 만듦(웹, 브라우저 확인, `app.js:273-319`, `:334-350`, `:768-772`, T6, #199). 가짜 구글 제공자로 헤드리스 Chromium(375×812)에서 첫 로그인, 다른 폰에서 다시 로그인, 기존 프로필 연결, `409`, 취소, 끊기를 봤습니다. 실제 구글 화면과 실제 주소에서는 확인하지 않았습니다.
- 서버 쪽: `/api/profiles/me/links/google`(T21)은 PKCE verifier가 없거나 복귀 주소가 글자 그대로 같지 않으면 구글을 부르지 않고 `400`입니다(T27, #203·#212). 공개 Client ID는 `GET /api/config`(T27, #193).

### 3. 현대 계정 연결 — 폰, 현재는 안내만

1. 계정 영역에서 구글과 따로 '현대 계정 연결 준비 중'을 보입니다. 누를 수 있는 로그인 단추나 차량 선택 화면은 두지 않습니다.
2. 안내를 열면 '현대 계정 연결은 아직 사용할 수 없어요. 기기 프로필로 계속 이용할 수 있어요'를 보이고 프로필로 돌아갑니다.
3. T22의 제휴·프로젝트 등록 조건이 확인되면 이 절을 고칩니다([ADR-0004](../../docs/adr/0004-hyundai-profile-link.md)). 가족 구성원을 현대 계정에서 받아 오지는 않습니다(ADR-0009).

- 계획(화면 없음).

### 4. 동승 연결과 기록 동의 — 폰

1. **QR 띄우기.** 홈의 '동승 연결'을 누르면 이 폰의 프로필 토큰으로 동승 연결을 발급받아(`POST /api/ride-links`) **동승 연결 QR**을 띄웁니다. '동승 연결'은 프로필이 있을 때만 보이고, 없으면 홈의 '프로필 만들기'에서 이름(별명)과 캐릭터를 먼저 정합니다(1절). QR에는 `{"type":"gachita-ride","version":1,"code":…}`만 담고 프로필·참가자 토큰은 넣지 않습니다. 코드는 5분 뒤 만료되고 한 번만 쓸 수 있습니다. 화면에 남은 시간과 '새로 띄우기'를 보입니다. 새로 띄우거나 '닫기'를 누르면 앞 QR을 거두고, 그사이 차가 읽었으면 그 여행으로 갑니다.
2. **차가 읽음.** 탑승 중이나 주차 중인 차가 QR을 읽고 운전자가 자리를 정하면([차량 화면](car.md) 흐름 1) 그 사람을 여행에 넣습니다(`POST /api/trips/{code}/ride-links`, `{code, seat}`). 동의는 꺼진 채로 들어가고, 차의 응답에는 참가자 토큰이 없습니다. 폰은 2초마다 연결을 확인하다가(`GET /api/ride-links/{id}`) 연결되면 발급 때 받은 참가자 토큰을 그 여행의 토큰으로 두고 '{자리}에 탔어요'와 함께 기록 동의 묻기로 갑니다. 자리는 차에서 정하고 폰에서는 고르지 않습니다. 여행 코드나 초대 코드를 입력하는 길, 여행 링크를 공유하는 길은 두지 않습니다. 이 폰이 들어가지 않은 여행 주소를 열면 '이 폰은 이 여행에 없어요'와 동승 연결 안내만 보입니다.
3. **기록 동의 묻기.** 이어서 [음성 처리 명세](../../docs/api/voice.md)의 '동의 문구' 전문을 문장마다 한 줄로, 접지 않고 보이고 '동의해요'·'동의하지 않아요'를 묻습니다. 문구에는 고른 장면 구간의 소리와 받아 적은 글, 참가자 이름을 외부 음성 인식 서버로 보내 다시 받아 적는다는 것과 지울 수 있는 것이 들어갑니다(T75, [#156](https://github.com/team-pitcrew/gachita/issues/156)). 한 명이라도 동의하지 않으면 기록하지 않는다고 알립니다. '동의해요'는 이 폰에 그 여행의 참가자 토큰이 있을 때만 보입니다. 프로필의 동의 기본값이 켜져 있으면 '동의해요'를 앞에 보일 뿐, 사람이 눌러야 동의합니다.
4. **여행 중.** 여행 화면의 '대화 기록 동의'는 누구나 언제든 끌 수 있고, 끄기 전에 이 여행에서 받아 적은 글과 올라간 소리가 모두 지워진다고 묻습니다. 켜기는 이 폰에서 연결한 사람만 그 참가자 토큰으로 하고, 켜기 전에 동의 문구 전문을 다시 보입니다. 동의 문구가 약속한 지우기도 여기 둡니다. 남긴 장면마다 '소리 지우기'(그 장면의 소리만 지우고 글과 장면은 남김), 프로필로 참가한 사람에게 '내 글 지우기'(내 이름이 붙은 받아 적은 글)를 두고, 둘 다 먼저 묻습니다.
5. **여행은 차에서 만듭니다.** 폰에서 여행을 새로 만들지 않습니다. 폰이 없는 아이는 차에서 손님으로 넣습니다.

- 폰의 QR 띄우기·연결 확인·기록 동의 묻기: 만듦(웹, 브라우저 확인, `app.js:390`, `:394-462`, `:473-503`, T46, #205). 헤드리스 Chromium(375×812)에서 차 대신 API로 연결해 봤고, `/demo`의 시연 차가 폰 칸의 QR 값을 읽어 연결하는 것도 봤습니다. 실제 폰 화면을 차 카메라로 읽는 것은 확인하지 않았습니다.
- 동승 연결 API(발급·결과 확인·거두기·차의 연결): develop에 있음(T46, #195). 서버에는 코드와 참가자 토큰의 해시만 둡니다. 차가 연결하는 경로는 만듦(서버)이고, 차량 앱의 QR 읽기와 자리 고르기는 계획(T46 차량 몫, [차량 화면](car.md) 흐름 1).
- 동의 켜기의 참가자 토큰: 서버 만듦(T68, #160), 웹 만듦(웹, 브라우저 확인, `app.js:143-171`, `:495-503`, T68, #177).
- 동의 문구 전문: 만듦(웹, 브라우저 확인, `app.js:22-34`, `:481-493`, `:596-597`, T75, #179).
- 소리 지우기·내 글 지우기와 동의 끄기 확인: 만듦(웹, 브라우저 확인, `app.js:20-21`, `:512-529`, `:590-595`, `:615`, T75, #184). 클립을 실제로 지운 것과 글을 한 줄 넘게 지운 것은 PR에서 보지 않았습니다.
- 초대 코드 입력, 여행 화면의 초대 코드 공유, `/#<여행 코드>` 참가 단계, 폰의 '새 여행 만들기', `/j/<초대>` 수락 화면은 웹에서 걷었습니다(#205). 서버의 그룹·초대 API(`/api/groups`, `/api/j`)와 웹 주소 `/j`는 `410`으로 닫았습니다(#198).

## 화면 요소

| 화면 | 중요한 순서와 동작 |
|---|---|
| 홈 | 내 프로필(얼굴과 이름) 또는 '프로필 만들기' → '동승 연결'(프로필이 있을 때) → 지금 탄 여행(있으면) |
| 내 프로필 | 구글 계정 칸 → 이름 또는 별명 → 사진·캐릭터 → 기록 동의 기본값 → 저장 → 지우기(사진, 프로필) |
| 동승 연결 QR | 닫기 → 내 얼굴과 이름 → QR → 남은 시간 → 새로 띄우기 |
| 기록 동의 묻기 | '{자리}에 탔어요' → 동의 문구 전문 → '동의해요'·'동의하지 않아요' |
| 여행 화면의 내 칸 | 내 자리 → 대화 기록 동의와 켜기·끄기 → 내 글 지우기(프로필로 참가한 사람) → 동의 문구 보기. 남긴 장면마다 소리 지우기 |
| 계정 연결 | 구글 연결 상태와 연결·끊기, 현대 계정은 준비 중 항목 |
| 지우기·연결 끊기 확인 | 지우는 것과 남는 것을 짧게 알리고 취소와 확인 |

- 좌석·공조 선호(온도·열선·통풍)는 두지 않습니다(11/13 계획에서 뺌. 웹은 #174, 서버는 #160에서 걷음).
- 프로필의 `consentDefault`는 기록 안내를 대신하는 영구 동의가 아닙니다. 수음은 차에서만 하고, 받아 적은 글은 여행을 만든 뒤 48시간 두고 사람이 고른 장면만 남습니다([ADR-0007](../../docs/adr/0007-voice-processing-flow.md)·[ADR-0008](../../docs/adr/0008-in-car-capture-and-sdk-stt.md)).

| 구글 인증 취소·거절·충돌 | 프로필 화면으로 돌아와 쓰던 입력을 되돌림. 충돌(`409`)은 '이미 다른 프로필에 연결된 구글 계정이에요. 이 폰의 프로필은 그대로예요.' |
| 통신 끊김 | '연결되면 다시 저장해 주세요'. 입력을 유지하고 저장 완료로 보이지 않음 |
| 주행 중 차량 화면 | 프로필 편집·계정 인증·동승자 추가를 열지 않음. 운전자에게 폰 조작을 요구하지 않음 |

아직 코드와 다른 것(`dab35fb`):

- 저장 중복 제출을 막는 장치가 없습니다(`app.js:255-271`).
- 이름 오류: 빈 칸은 브라우저 입력 검사가 칸 옆에서 막고, 공백만 넣으면 서버의 `400` 문장을 화면 아래 알림으로 보입니다.
- 서버가 모르는 프로필 토큰(`401`)은 알리지 않고 이 폰에서 잊은 뒤 '프로필 만들기'를 보입니다(`app.js:115`).
- 통신이 끊기면 공통 알림 '연결이 끊겨서 보내지 못했어요.'를 보입니다(`app.js:139`). 입력은 남습니다.
- '사진 지우기'와 '구글 연결 끊기'는 확인 없이 바로 됩니다.
