# 도착 후 클립과 주행 기억 지도

[T18](https://github.com/team-pitcrew/gachita/issues/24) · [T17 차량 화면 명세 PR](https://github.com/team-pitcrew/gachita/pull/54) · [T12 음성 처리 설계 PR](https://github.com/team-pitcrew/gachita/pull/55) · [T42 문구정리본 반영](https://github.com/team-pitcrew/gachita/issues/60)

## 목적

여행을 마친 일행이 남길 장면을 직접 고르고, 받아쓴 문구를 확인·수정하고, 위치로 기억을 찾은 뒤 공유할 내용을 결정하게 합니다. 고른 장면은 사람별 피드에 쌓이고 짧은 세로 숏폼으로 다시 봅니다. 자동 추천은 후보이며, 사용자가 고르기 전에는 확정된 장면이나 완성된 클립으로 표시하지 않습니다.

담당 산출물은 화면 명세와 피그마 인수 자료까지입니다. T17의 도착 후 진입 화면과 T12의 백엔드 설계 결과를 기준으로 화면 동작을 정하며, 앱 구현·음성 서비스 연결·배포·실기기 검증은 후속 구현 범위입니다. 4절의 구현 상태는 [차량 화면](car.md)과 같은 말로 적고, 기준은 develop `a7879ad`(11/14)입니다.

## 흐름

### 1. 장면 후보 고르기와 자막 고치기 — 폰

1. **도착 확인.** T17에서 여행 마감이 확인되면 차량에는 결과 요약을, 일행의 폰에는 여행 기록 진입을 제공합니다. 차량의 기어 P만으로 여행을 마감하거나 결과 처리가 완료됐다고 판단하지 않습니다.
2. **준비 상태 확인.** 업로드·받아쓰기 진행이 확인되면 ‘여행 기록을 준비하고 있어요’를 표시합니다. 확인된 결과는 먼저 읽을 수 있게 하되, 나머지는 ‘아직 준비 중인 기록이 있어요’로 구분합니다. 예상 완료 시간이나 진행률은 실제 값이 있을 때만 표시합니다.
3. **후보 요청.** 참가자가 ‘장면 후보 보기’를 선택하면 준비된 받아쓰기와 기존 장면을 바탕으로 후보를 요청합니다. 요청 중에는 중복 조작을 막습니다. 후보 생성은 화면을 열거나 새로고침할 때 자동 반복하지 않습니다.
4. **사람이 선택.** 후보 카드에는 확인된 시각과 추천 이유를, 받아쓰기가 연결되면 해당 문구를 표시합니다. 원하는 후보만 고르고 선택 개수를 확인합니다. 받아쓰기를 읽을 수 없거나 위치가 없는 후보는 그 정보를 채운 것처럼 표시하지 않습니다.
5. **문구 확인·수정.** 폰에서 선택한 장면의 받아쓰기를 자막 초안으로 확인합니다. 원문과 수정본을 구분하며 ‘취소’는 마지막으로 저장된 버전으로 돌아갑니다. 저장 전에는 ‘저장하지 않은 변경이 있어요’를 표시합니다. 말한 사람은 서버의 목소리 대조가 붙인 줄에만 이름과 캐릭터로 보입니다([ADR-0019](../../docs/adr/0019-speaker-matching.md)). 좌석 구역만 아는 말은 ‘앞줄’·‘뒷줄’, 모르면 ‘누군가’로 두고 자리만으로 이름을 짐작하지 않습니다.
6. **미리 보기와 저장.** 선택 순서와 수정 문구를 미리 보고 ‘변경 저장’을 누릅니다. 저장 성공이 확인된 뒤에만 ‘변경을 저장했어요’를 표시합니다. 영상·오디오 재생은 실제 재생 가능한 결과가 준비됐을 때 제공합니다. 받아쓰기나 장면 목록만으로 클립 완성을 표시하지 않습니다.
7. **다음 화면.** 저장된 선택을 지도에서 찾거나 공유 검토로 넘깁니다. 폰을 닫았다 다시 열 때는 마지막 저장 결과를 불러오며, 기기에 남은 임시 변경은 서버 저장본과 구분합니다.

자막 수정 저장·클립 생성·화자 이름 연결의 계약은 아직 구현 연결이 필요합니다. 해당 기능은 준비 상태를 확인해 열며, 동작하는 저장 경로가 없는 상태에서 완료 문구를 제공하지 않습니다.

### 2. 지도에서 장면 다시 찾기 — 폰 중심, 차량은 주차 후 요약

1. **기록 열기.** 폰에서 ‘주행 기억 지도 보기’를 선택하면 확인된 장면 목록을 시각 순서로 보여 줍니다. 차량에서는 여행 마감·기어 P·조작 허용을 모두 확인한 뒤 준비된 기록의 요약을 볼 수 있습니다.
2. **위치 표시.** 위치가 확인된 장면만 지도에 표시하고 목록과 연결합니다. 좌표가 없는 후보는 ‘위치 정보가 없어요’로 목록에 남깁니다. 후보의 시각만으로 좌표를 추측하거나 지도에 임의의 점을 찍지 않습니다.
3. **장면 찾기.** 폰에서 지도 표식 또는 목록의 장면을 선택하면 시각·장면 이름·확인된 문구를 보여 줍니다. 화면을 다시 열어도 같은 장면을 찾을 수 있도록 확정 장면의 식별자를 기준으로 연결합니다.
4. **내용 확인.** 준비된 클립이 있으면 해당 결과로 이동합니다. 지도는 장면 사이를 실제 주행 경로처럼 이어 그리지 않습니다. 위치 기록이 장면별 점뿐인 현재 계약에서는 경로·이동 거리·방문 장소명을 추측하지 않습니다.
5. **표시 실패와 복귀.** 지도 서비스를 불러오지 못해도 장면 목록으로 계속 찾을 수 있게 합니다. 다른 화면에서 돌아오면 마지막 선택을 유지하되, 서버에서 삭제되거나 접근할 수 없어진 기록은 닫습니다.

차량에서 주행 제한이 다시 걸리면 지도·장면 상세·클립 재생을 닫고 T17 주행 요약으로 돌아갑니다. 문구 편집·공유 대상 선택은 폰에서 진행합니다. 운전자가 주행 중 폰을 조작하도록 안내하지 않습니다.

### 3. 일행에게 공유하기 — 폰

1. **공유할 내용 선택.** ‘일행에게 공유’를 누르면 저장된 장면과 문구, 위치 포함 여부를 검토합니다. 원음 전체나 선택하지 않은 장면은 자동 포함하지 않습니다.
2. **공개 범위 확인.** 어떤 일행에게 어떤 내용을 보여 줄지 최종 미리 보기에서 확인합니다. 녹음 동의와 결과 공유 확인은 별개입니다(받아쓰기는 차량 안 Pleos STT, ADR-0008). 화자 라벨을 특정인으로 임의 연결하거나 동의 상태를 추측하지 않습니다.
3. **공유 준비.** 구현에서 참가자 범위·받는 사람의 접근 권한·만료와 회수 정책을 확인할 수 있을 때만 공유를 진행합니다. 권한을 확인하지 못하면 마지막 확인 화면을 유지하고 ‘공유할 수 있는지 확인하지 못했어요’를 표시합니다.
4. **명시적 실행.** 사용자가 최종 ‘공유’를 선택한 뒤 결과 공유를 요청합니다. 요청 중에는 중복 실행을 막습니다. 취소하면 내용 검토 화면으로 돌아갑니다.
5. **결과 확인.** 서버가 공유 상태를 확인하면 그 결과를 표시합니다. OS 공유 창을 열었거나 링크를 복사한 것만으로 상대가 받았다고 표시하지 않습니다. 실패하면 저장된 선택을 유지하고 다시 시도할 수 있게 합니다.

여행 참가에는 링크나 코드를 쓰지 않습니다(폰의 동승 연결 QR을 차가 읽음, 11/14). 결과 공유에는 별도 접근 제어가 필요하므로 여행 코드를 클립·대화 결과 공유에 쓰지 않습니다. 공유·회수 API와 수신 화면은 구현 계약을 정한 뒤 연결합니다.

### 4. 여행 뒤 피드와 숏폼 재생 — 폰, 차량은 주차 중

1. **사람별 피드.** 폰의 '내 피드'는 한 프로필의 것만 최신순으로 보입니다. 내가 한 말(목소리 대조로 내 이름이 붙은 발화)은 여행을 만든 뒤 48시간까지, 내가 남긴 장면은 그 뒤에도 남습니다. 장면은 프로필로 참가한 사람이 고를 때 그 사람의 앨범에 복사되기 때문입니다([ADR-0014](../../docs/adr/0014-transcript-storage.md)).
2. **가족 앨범과의 관계.** 가족 앨범을 따로 저장하지 않습니다. 여행이 살아 있는 48시간 동안은 그 여행의 장면 목록을 일행이 함께 봅니다. 그 뒤에는 각자 프로필 앨범의 장면만 남습니다. 피드의 장면을 지우면 내 앨범에서만 빠지고 다른 사람의 앨범과 여행의 장면은 그대로입니다.
3. **장면 후보.** 후보는 받아 적은 글에서 규칙으로 고릅니다(LLM 계약 전). 1절처럼 사람이 고른 장면만 남고, 고른 구간의 소리만 차에서 서버로 올라갑니다.
4. **숏폼.** 숏폼은 **영상 파일을 만들지 않습니다.** 고른 장면들의 구성 데이터(장면마다 클립 주소, 자막 큐의 시각과 글자, 말한 사람)를 차례로 재생합니다. 폰에서는 세로 9:16 재생 페이지가 클립을 이어 틀고, 자막과 말한 사람의 캐릭터를 함께 보입니다. 길이는 60초 안팎입니다. 말한 사람을 모르면 캐릭터 없이 자막만 보입니다.
5. **차에서 재생.** 차는 따로 받지 않고 같은 구성 데이터를 그 자리에서 재생합니다. 주행 제한이 풀린 주차 중에만 열고, 제한이 다시 걸리면 바로 닫습니다([차량 화면](car.md)).
6. **재생할 수 없음.** 클립이 지워졌거나(48시간, 동의 철회, 원음 삭제) 아직 올라오지 않았으면 그 장면은 자막만 보이거나 건너뜁니다. 재생 가능한 클립이 하나도 없으면 숏폼 진입을 숨깁니다.

- 피드 API: 만듦(`GET /api/profiles/me/feed`, `openapi.yaml:406`). 폰의 피드 화면: 계획(지금 웹앱에 없음).
- 장면 후보와 숏폼 구성 데이터: 만드는 중(T43). 클립 받기·재생·지우기: 만드는 중(T76 서버, T63 차). 클립은 `media` 하위 도메인에서 API가 흘려보냅니다([ADR-0020](../../docs/adr/0020-media-delivery-subdomain.md)).
- 폰의 9:16 재생 페이지: 만드는 중(T43 웹). 차에서 재생: 계획.

## 화면 요소

| 화면 | 기기 | 표시 순서와 주요 조작 |
|---|---|---|
| 도착 후 요약 | 차량·폰 | 기록 마감 상태 → 부탁 처리 결과 → 준비된 기록 진입. 준비 중·없음에서는 해당 결과 진입 숨김 |
| 후보 목록 | 폰 | 처리 상태 → 후보의 시각·추천 이유·연결된 문구 → 선택 여부·개수 → 다음 |
| 자막 확인·수정 | 폰 | 선택 장면 → 원문·수정본 → 저장 상태 → 취소·변경 저장 |
| 주행 기억 지도 | 폰, 차량은 허용된 주차 요약 | 지도 또는 대체 목록 → 선택 장면 → 확인된 시각·이름·문구 → 준비된 결과 |
| 공유 검토 | 폰 | 선택된 내용 → 위치 포함 여부 → 공개 범위·접근 제한 → 공유·취소 |
| 내 피드 | 폰 | 최신순 항목(내 말, 내 장면) → 여행 코드와 시각 → 장면 지우기 |
| 숏폼 재생 | 폰(9:16), 차량은 주차 중 | 클립 재생 → 자막 → 말한 사람의 캐릭터 → 장면 순서·남은 개수 → 다시 보기·닫기 |

### 백엔드 산출물과 연결하는 기준

| 자료의 현재 상태 | 화면에서 사용할 정보 | 구현 인수 시 확인할 것 |
|---|---|---|
| 현재 [여행 API](../../docs/api/openapi.yaml)의 `moments` | `id, at, label`, 위치가 있으면 `lat, lng` | 목록·지도 연결에 사용. 위치는 둘 다 있거나 둘 다 없음. 위치 없는 장면은 목록에만 있고 지도에는 없음. 자막·영상 파일은 아님 |
| 기록본(`/api/trips/{code}/transcript`) | 발화의 시각·글자·좌석 구역·말한 사람, 부탁 | 녹음에 동의한 참가자만 읽음. 말한 사람은 목소리 대조가 붙인 줄에만 있음 |
| 피드(`/api/profiles/me/feed`) | `kind`(utterance·moment), 여행 코드, 시각, 글자 또는 장면 | 발화는 48시간, 장면은 앨범 복사본이라 그 뒤에도 남음 |
| 장면 후보·숏폼 구성(T43), 클립(T76) | 후보의 시각과 이유, 장면마다 클립 주소·자막 큐·말한 사람 | 만드는 중. 계약이 병합되면 이 줄을 고침 |
| 자막 편집·결과 공유 | 현재 구현된 계약 없음 | 저장 버전·동시 수정, 공유 대상·권한·회수 계약을 정한 뒤 화면 연결 |

장면 목록이 비어 있다는 사실만으로 ‘기록 없음’을 결정하지 않습니다. 받아쓰기·후보·클립은 각각 준비 상태가 다르며, 저장된 장면이 있어도 재생 파일은 없을 수 있습니다.

### 피그마와 확인 수준

[T17 도착 후 Portrait](https://www.figma.com/design/Qc58INq2ECd1ODzzmM7Nja?node-id=2-78)·[Landscape](https://www.figma.com/design/Qc58INq2ECd1ODzzmM7Nja?node-id=2-79)와 [추가 상태](https://www.figma.com/design/Qc58INq2ECd1ODzzmM7Nja?node-id=22-248)는 12개 차량 앱 창의 도착 후 진입·결과 준비 중·결과 없음 상태를 인수하는 기준입니다. 해당 파일의 120개 프레임은 T17 차량 화면 범위입니다. T18의 폰 후보 편집·지도 상세·공유 화면과 4절의 피드·숏폼은 피그마에 없고, 이 문서의 흐름을 기준으로 연결합니다.

이 문서는 저장소 코드·API 명세와 제출된 T12 설계를 대조한 화면 명세입니다. 후보 생성·자막 편집·클립 재생·공유를 실제 서비스, 폰, 차량 에뮬레이터 또는 실차에서 실행해 확인한 자료는 아닙니다.

## 상태

| 상태 | 화면과 복구 동작 |
|---|---|
| 기록 없음 확인 | ‘남은 기록이 없어요’. 후보·클립·지도 진입을 숨기며 실패를 빈 결과로 바꾸지 않음 |
| 처리 중 / 부분 준비 | ‘여행 기록을 준비하고 있어요’. 확인된 부분만 읽고 남은 기록은 준비 중 표시. 자동 후보 생성·중복 요청 없음 |
| 후보 없음 | 처리 완료 후 후보가 없다는 응답이 확인되면 ‘추천할 장면이 없어요’. 기존에 남긴 장면은 유지 |
| 위치 없음 / 지도 실패 | 위치 없는 후보는 목록에서 유지. 지도 실패는 목록으로 전환하고 ‘지도를 불러오지 못했어요’ |
| 통신 끊김 | 마지막 확인한 자료임을 표시. 읽기 가능한 기기 내 초안과 서버 저장본을 구분하고 저장·공유 완료를 표시하지 않음 |
| 재연결 / 저장 충돌 | 최신 서버 상태를 확인한 뒤 임시 변경을 다시 비교. 다른 사람의 편집을 자동 덮어쓰거나 후보·장면을 중복 생성하지 않음 |
| 저장·공유 실패 | 선택과 수정 초안을 유지하고 실패한 동작을 명시. 현재 계약의 400·404·409와 통신 실패를 모두 ‘기록 없음’으로 합치지 않음 |
| 여행 접근 불가 | 만료·권한·없는 여행을 확인한 응답에 따라 안내. 현재 API의 404는 없는 코드 또는 보관 기간 경과이며 새로고침으로 해결된다고 약속하지 않음 |
| 동의 철회 / 원음 삭제 요청 | 서버 클립, 차량의 미전송 클립 큐와 차 안 원음(T63), 이미 생성된 텍스트·장면을 따로 확인. 확인 전 ‘모두 삭제했어요’ 표시 금지 |
| 차량 주행 제한 재시작 | 상세·재생·지도 조작을 닫고 T17 요약으로 복귀. 폰 작업으로 운전자에게 즉시 응답을 요구하지 않음 |
| 피드 비어 있음 | ‘아직 쌓인 기록이 없어요’. 프로필 없이 참가한 사람에게는 피드가 없음을 알리고 프로필 만들기로 안내 |
| 숏폼 재생할 수 없음 | 클립이 지워졌거나 아직 없으면 그 장면은 자막만 보이거나 건너뜀. 재생할 클립이 하나도 없으면 진입을 숨김. 빈 화면을 완성된 숏폼처럼 보이지 않음 |

원음 보관 시계는 여행 읽기 제한과 같은 **여행 생성 후 48시간**입니다. 원음 삭제는 서버 클립과 차량의 미전송 클립 큐·차 안 원음을 비웁니다([음성 처리 명세](../../docs/api/voice.md)). 원음 삭제 뒤 받아 적은 글은 남을 수 있습니다. 서버와 차량의 삭제가 확인되기 전에는 화면에서 ‘모두 삭제했어요’를 표시하지 않습니다. 폰에서는 수음하지 않으므로 폰에는 지울 원음이 없습니다(ADR-0008, 11/13).

### 근거와 남은 계약

- 현재 제공 범위: [API 명세](../../docs/api/openapi.yaml), 웹앱의 여행 장면 목록·초대 링크, [T17 PR #54](https://github.com/team-pitcrew/gachita/pull/54).
- T12 설계 기준: [음성 처리 명세](../../docs/api/voice.md), [ADR-0007](../../docs/adr/0007-voice-processing-flow.md)·[ADR-0008](../../docs/adr/0008-in-car-capture-and-sdk-stt.md)(PR #55로 병합). 실제 음성 처리 서버 구현·계약·배포와 구분합니다.
- 구현 인수 항목: 후보와 위치의 연결, 자막 저장·충돌 처리, 결과 공유 권한·회수. 장면 후보·숏폼 구성(T43), 클립(T76·T63), 피드 화면은 4절의 상태를 따릅니다.
