# 도착 후 클립과 주행 기억 지도

[T18](https://github.com/team-pitcrew/gachita/issues/24) · [T17 차량 화면 명세 PR](https://github.com/team-pitcrew/gachita/pull/54) · [T12 음성 처리 설계 PR](https://github.com/team-pitcrew/gachita/pull/55) · [T42 문구정리본 반영](https://github.com/team-pitcrew/gachita/issues/60)

## 목적

여행을 마친 일행이 남길 장면을 직접 고르고, 받아쓴 문구를 확인·수정하고, 위치로 기억을 찾은 뒤 공유할 내용을 결정하게 합니다. 고른 장면은 사람별 피드에 쌓이고 짧은 세로 숏폼으로 다시 봅니다. 자동 추천은 후보이며, 사용자가 고르기 전에는 확정된 장면이나 완성된 클립으로 표시하지 않습니다.

담당 산출물은 화면 명세와 피그마 인수 자료까지입니다. T17의 도착 후 진입 화면과 T12의 백엔드 설계 결과를 기준으로 화면 동작을 정하며, 앱 구현·음성 서비스 연결·배포·실기기 검증은 후속 구현 범위입니다. 흐름마다 끝에 구현 상태를 [차량 화면](car.md)과 같은 말로 적습니다. 서버 쪽은 '만듦(서버)', 폰 화면은 '만듦(웹, 브라우저 확인)'으로 나눠 적습니다. '만듦(웹, 브라우저 확인)'은 PR에서 헤드리스 Chromium이나 ego lite의 휴대폰 크기 창으로 로컬 서버에 붙여 본 것이고, 실제 휴대폰에서 본 것은 아닙니다. 기준은 develop `ca3d56a`(11/14, Codex의 웹·차 개편 #239·#244·#245·#247 뒤)입니다.

## 흐름

### 1. 장면 후보 고르기와 자막 고치기 — 폰

1. **도착 확인.** T17에서 여행 마감이 확인되면 차량에는 결과 요약을, 일행의 폰에는 여행 기록 진입을 제공합니다. 차량의 기어 P만으로 여행을 마감하거나 결과 처리가 완료됐다고 판단하지 않습니다.
2. **준비 상태 확인.** 업로드·받아쓰기 진행이 확인되면 ‘여행 기록을 준비하고 있어요’를 표시합니다. 확인된 결과는 먼저 읽을 수 있게 하되, 나머지는 ‘아직 준비 중인 기록이 있어요’로 구분합니다. 예상 완료 시간이나 진행률은 실제 값이 있을 때만 표시합니다.
3. **후보 요청.** 기록에 동의한 이 폰의 참가자가 여행 화면에서 ‘장면 후보 보기’를 누르면 후보를 요청합니다. 서버는 받아 적은 글에서 말이 몰린 구간을 규칙으로 골라(LLM 없음) 최대 5개를 시각 순으로 줍니다. 이미 남긴 장면의 구간은 빼고, 요청할 때만 계산하며 저장하지 않습니다. 화면을 열거나 새로고침할 때 자동 반복하지 않고, 사람이 ‘후보 다시 보기’를 누를 때만 다시 요청합니다.
4. **사람이 선택.** 후보 카드에는 시각, 추천 이유(예: ‘30초에 말이 9번, 3명이 말함’), 구간의 발화 앞 3줄, 장면 이름 칸을 둡니다. 원하는 후보만 ‘이 장면 남기기’로 하나씩 남깁니다. 남길 때는 후보의 구간(`from`·`to`)과, 위치가 있으면 위치만 보내고 발화·점수는 보내지 않습니다. 남긴 후보는 목록에서 빠지고 서버도 다음 후보에서 뺍니다. 저장 중에는 같은 단추를 막고, 저장 결과가 불명확하면(끊김·5xx) 그대로 다시 누르게 두지 않고 후보를 다시 읽습니다. 위치가 없는 후보는 그 사실을 알리고 위치를 채운 것처럼 표시하지 않습니다.
5. **문구 확인·수정.** 자막은 장면과 따로 ‘자막 확인하기’에서 고칩니다. 여행 화면과 대화방 아래의 ‘자막 수정’, 쇼츠의 ‘대화·자막 수정’으로 엽니다. 줄을 고르면 받아쓴 원문, 자동 재전사(있을 때), 현재 저장된 자막을 나눠 보입니다. 사람이 고친 글은 원문·자동 재전사를 덮지 않고 수정본으로 따로 저장하며, 화면과 숏폼 자막은 수동 수정 → 자동 재전사 → 받아쓴 원문 순으로 보입니다. 저장 전에는 ‘저장하지 않은 변경이 있어요.’를 표시합니다. ‘취소’는 입력을 버리고 목록으로 돌아가며 마지막으로 저장된 자막은 그대로입니다. ‘수동 수정 지우기’는 수정본을 비워 자동 재전사나 원문으로 되돌립니다. 자막 화면에서는 말한 사람의 이름을 바꾸지 않습니다. 말한 사람은 서버의 목소리 대조가 붙인 줄에만 이름과 캐릭터로 보입니다([ADR-0019](../../docs/adr/0019-speaker-matching.md)). 좌석 구역만 아는 말은 ‘운전석 자리’처럼 자리로, 모르면 ‘누군가’로 두고 자리만으로 이름을 짐작하지 않습니다. 대화방(#239)은 같은 경우를 ‘운전석’, ‘앞줄’·‘뒷줄’, ‘말한 사람 미확인’으로 적어 자막 화면과 낱말이 다릅니다.
6. **저장과 충돌.** ‘변경 저장’은 읽은 편집 버전과 동의 세대를 함께 보냅니다. 서버가 저장을 확인한 뒤에만 ‘변경을 저장했어요.’를 표시합니다. 다른 사람이 먼저 고쳤거나 동의가 바뀌었으면(409) 내 입력을 유지하고 서버의 최신 자막을 보인 뒤, ‘최신 자막 다시 읽기’로 비교하고 다시 저장하게 합니다. 남의 수정을 자동으로 덮어쓰지 않습니다. 영상·오디오 재생은 실제 재생 가능한 클립이 있을 때만 제공합니다. 받아쓰기나 장면 목록만으로 클립 완성을 표시하지 않습니다.
7. **다음 화면.** 남긴 장면은 여행 화면의 ‘남긴 장면’에 쌓이고, 지도에서 찾거나(2절) 숏폼(4절)과 공유(3절)로 넘어갑니다. 자막 초안은 기기에 남기지 않습니다. 저장하지 않은 입력이 있으면 닫기 전에 묻고, 다시 열면 서버 저장본을 읽습니다.

- 도착 확인과 준비 상태 표시: 계획. 차에는 여행 마감이 없고([차량 화면](car.md) 흐름 4), 웹에는 받아쓰기 준비 상태 표시가 없습니다.
- 장면 후보 규칙과 구간 저장(`GET /api/trips/{code}/scene-suggestions`, `POST /moments`의 `from`·`to`): 만듦(서버, T43 #181, `backend/api/scenes.js`, `openapi.yaml:540`·`:928`). 서버 시험은 합성 대화로 했고, 실제 가족 대화에서 후보의 질은 보지 않았습니다.
- 후보 화면: 만듦(웹, 브라우저 확인, T43 #200·#215, `frontend/web/records.js:148-224`, 진입 `app.js:655`).
- 자막 수정본·버전 충돌·초기화(`PATCH /api/trips/{code}/captions/{device}/{seq}`): 만듦(서버, T80 #202, `openapi.yaml:687`, `backend/api/trips-6-captions.sql`). 자막 화면: 만듦(웹, 브라우저 확인, T80 #209·#215, `frontend/web/captions.js`, 진입 `app.js:655`, 대화방 `conversations.js:113`). 동시 수정은 로컬 HTTP와 브라우저로 봤고 실제 휴대폰 두 대로는 보지 않았습니다. T80 티켓은 통합 확인 전이라 열려 있습니다.
- 자동 재전사: 만듦(서버, T75 #183, `backend/api/providers/asr.js`). `ASR_URL`·`ASR_TOKEN`이 있을 때만 고른 장면 클립을 Nemotron으로 다시 받아 적고, 실패하거나 믿지 못할 답이면 원문으로 남깁니다. 값은 합성 음성으로 잰 것입니다([전사록 데이터](../../docs/transcript-data.md) 6절).

### 2. 지도에서 장면 다시 찾기 — 폰 중심, 차량은 주차 후 요약

1. **기록 열기.** 폰에서 ‘주행 기억 지도 보기’를 선택하면 확인된 장면 목록을 시각 순서로 보여 줍니다. 차량에서는 여행 마감·기어 P·조작 허용을 모두 확인한 뒤 준비된 기록의 요약을 볼 수 있습니다.
2. **위치 표시.** 위치가 확인된 장면만 지도에 표시하고 목록과 연결합니다. 좌표가 없는 후보는 ‘위치 정보가 없어요’로 목록에 남깁니다. 후보의 시각만으로 좌표를 추측하거나 지도에 임의의 점을 찍지 않습니다.
3. **장면 찾기.** 폰에서 지도 표식 또는 목록의 장면을 선택하면 시각·장면 이름·확인된 문구를 보여 줍니다. 화면을 다시 열어도 같은 장면을 찾을 수 있도록 확정 장면의 식별자를 기준으로 연결합니다.
4. **내용 확인.** 준비된 클립이 있으면 해당 결과로 이동합니다. 지도는 장면 사이를 실제 주행 경로처럼 이어 그리지 않습니다. 위치 기록이 장면별 점뿐인 현재 계약에서는 경로·이동 거리·방문 장소명을 추측하지 않습니다.
5. **표시 실패와 복귀.** 지도 서비스를 불러오지 못해도 장면 목록으로 계속 찾을 수 있게 합니다. 다른 화면에서 돌아오면 마지막 선택을 유지하되, 서버에서 삭제되거나 접근할 수 없어진 기록은 닫습니다.

차량에서 주행 제한이 다시 걸리면 지도·장면 상세·클립 재생을 닫고 T17 주행 요약으로 돌아갑니다. 문구 편집·공유 대상 선택은 폰에서 진행합니다. 운전자가 주행 중 폰을 조작하도록 안내하지 않습니다.

- 장면 위치(`lat`·`lng`, 둘 다 있거나 둘 다 없음): 만듦(서버, `openapi.yaml:540`). 후보에 위치가 있으면 장면을 남길 때 함께 저장합니다(`frontend/web/records.js:11-19`).
- 폰의 주행 기억 지도: 계획. 웹에는 지도가 없고, 여행 화면의 ‘남긴 장면’은 이름과 시각 목록입니다(`app.js:656-674`).
- 차의 주차 중 요약: 계획. 차 앱에 도착 후 화면이 없습니다([차량 화면](car.md) 흐름 4).

### 3. 일행에게 공유하기 — 폰

1. **공유할 장면 선택.** 여행 화면의 ‘내 장면 공유’(아이콘 단추)나 쇼츠의 ‘동승자에게 장면 공유’를 누르면 이 여행에서 내 앨범에 남긴 장면만 보입니다. 하나를 고릅니다. 원음·클립·대화 원문이나 선택하지 않은 장면은 포함하지 않습니다.
2. **내용과 대상 고르기.** 함께 보낼 문구는 사람이 직접 적습니다(500자 이내, 받아쓴 글을 자동으로 넣지 않음). 받는 사람은 같은 여행에서 프로필로 참가하고 기록에 동의한 다른 사람만이며, 처음에는 아무도 고르지 않은 상태입니다. 위치는 처음에 꺼 두고 위치가 있는 장면에서만 켤 수 있습니다. 녹음 동의와 결과 공유 확인은 별개입니다(받아쓰기는 차량 안 Pleos STT, ADR-0008). 화자 라벨을 특정인으로 임의 연결하거나 동의 상태를 추측하지 않습니다.
3. **미리 보기.** ‘내용 미리보기’에서 장면·시각·문구·받는 사람·위치 포함 여부·볼 수 있는 기한(여행을 만든 뒤 48시간)을 확인합니다. 공유할 내용을 확인하지 못하면 ‘공유 내용을 확인할 수 없어요’를 표시하고 진행하지 않습니다. 대상·원본이 바뀌면 미리 보기를 다시 거칩니다.
4. **명시적 실행.** 사용자가 ‘이 내용으로 공유’를 누른 뒤에만 공유를 요청합니다. 요청 중에는 수정과 중복 실행을 막습니다. ‘수정하기’는 내용 고르기로 돌아갑니다.
5. **결과 확인.** 서버가 공유를 만들었다고 응답하면 보낸 공유 목록과 ‘선택한 동승자에게 공유했어요.’를 보입니다. 이 응답은 생성 확인일 뿐이라 상대가 받았거나 봤다고 표시하지 않습니다. 결과가 불명확하면(끊김) 다시 보내기 전에 ‘보낸 공유 확인’으로 이미 보냈는지 보게 합니다. 실패하면 입력을 유지하고 다시 시도할 수 있게 합니다.
6. **받기와 회수.** 홈의 ‘나눈 장면’에서 받은 공유를 열고, 안에서 ‘보낸 공유’로 바꿉니다. 장면 이름·보낸 사람·시각·문구·위치·기한을 봅니다. 보낸 사람만 ‘공유 회수’를 확인한 뒤 거둘 수 있고, 받는 사람에게 더 이상 보이지 않습니다. 회수·동의 철회·원본 앨범 삭제·여행 만료 뒤에는 목록에서 사라집니다. 이미 본 사람이 따로 저장한 것까지 되돌리지는 않습니다.
7. **이미지로 내려받기.** 받은·보낸 공유마다 다운로드 아이콘이 있습니다. 누르면 장면 이름·문구·시각·고른 위치를 정사각 PNG 한 장으로 저장합니다. 누를 때와 이미지를 만든 뒤에 공유 권한을 다시 확인해, 회수·동의 변경·원본 삭제·만료 뒤에는 저장하지 않습니다. 원음과 받아쓴 글 전체는 이미지에 넣지 않습니다.

여행 참가에는 여행 코드나 링크를 입력하거나 공유하지 않습니다(폰의 동승 연결 QR을 차가 읽음, 11/14). 결과 공유는 프로필 토큰과 참가자 토큰으로 접근을 가르며, 응답에 여행 코드·토큰·클립 주소가 없습니다. 외부 공개 링크·메신저 발송·원음 공유는 범위 밖입니다.

- 공유 만들기·받은/보낸 목록·회수(`POST /api/trips/{code}/shares`, `GET /api/profiles/me/shares`, `DELETE /api/profiles/me/shares/{id}`): 만듦(서버, T81 #201, `backend/api/result-shares.js`, `openapi.yaml:156`·`:206`·`:248`). 공유 후보로 쓰는 한 여행의 내 앨범 장면(`GET /api/profiles/me/moments?trip=`): 만듦(서버, T81 #216, `openapi.yaml:763`).
- 공유 작성·미리보기·받은/보낸 공유·회수 화면: 만듦(웹, 브라우저 확인, T81 #206·#215·#219, `frontend/web/shares.js`, 진입 `app.js:437`·`:675`·`:892`). ego lite 390×844와 헤드리스 Chromium으로 봤고, 실제 휴대폰 두 대·운영 주소에서는 보지 않았습니다. T81 티켓은 통합 확인 전이라 열려 있습니다.

### 4. 여행 뒤 피드와 숏폼 재생 — 폰, 차량은 주차 중

1. **사람별 기록본.** 폰 홈의 ‘내 기록본’은 한 프로필의 것만 최신순으로 보입니다(최근 100개). 내가 한 말(목소리 대조로 내 이름이 붙은 발화)은 여행을 만든 뒤 48시간까지, 내가 남긴 장면은 그 뒤에도 남습니다. 장면은 프로필로 참가한 사람이 고를 때 그 사람의 앨범에 복사되기 때문입니다([ADR-0014](../../docs/adr/0014-transcript-storage.md)).
2. **가족 앨범과의 관계.** 가족을 따로 묶지 않으므로(11/14) 가족 앨범을 따로 저장하지 않습니다. 같은 차에 탄 기록으로만 이어집니다. 여행이 살아 있는 48시간 동안은 그 여행의 장면 목록을 일행이 함께 봅니다. 그 뒤에는 각자 프로필 앨범의 장면만 남습니다. 기록본의 장면을 지우면 내 앨범에서만 빠지고 다른 사람의 앨범과 여행의 장면은 그대로입니다.
3. **장면 후보.** 후보는 받아 적은 글에서 규칙으로 고릅니다(LLM 없음, [ADR-0021](../../docs/adr/0021-shortform-as-composition-data.md)). 1절처럼 사람이 고른 장면만 남고, 고른 구간의 소리만 차에서 서버로 올라갑니다.
4. **숏폼.** 숏폼은 **영상 파일을 만들지 않습니다.** (develop에는 #239로 폰·차의 영상 만들기·저장이 들어와 이 문장과 어긋납니다. 유지 여부를 정하는 중이라 이 문장은 고치지 않았습니다.) 서버는 클립이 올라온 장면마다 구성 데이터(클립 주소, 자막 큐의 시각과 글자, 말한 사람)를 클립 시각 순으로 줍니다. 폰에서는 여행 화면의 ‘쇼츠’ 탭이 세로 9:16 화면을 열어, 차 안 장면 위에 말한 사람의 전신 캐릭터와 이름, 자막을 그리며 클립을 이어 틉니다(#239). 첫 재생은 사람이 ‘재생’을 눌러 시작하고, 화면을 누르면 멈추거나 이어 듣습니다. 위아래로 밀거나 ‘이전’·‘다음’으로 장면을 넘깁니다. 클립은 같은 주소의 API에서 참가자 토큰 머리말로 받아 기기 메모리에서만 틀고, 토큰을 주소에 넣지 않습니다. 자막은 수동 수정 → 자동 재전사 → 받아쓴 원문 순입니다. 말한 사람을 모르면 이름을 짓지 않고 ‘말한 사람 미확인’으로 적습니다. 전체 길이는 남긴 장면 클립을 이은 만큼입니다(장면마다 1~60초).
5. **차에서 재생.** 차는 따로 받지 않고 같은 구성 데이터를 그 자리에서 재생합니다. 주행 제한이 풀린 주차 중에만 열고, 제한이 다시 걸리면 바로 닫습니다([차량 화면](car.md)).
6. **재생할 수 없음.** 클립이 지워졌거나(48시간, 동의 철회, 소리 지우기) 아직 올라오지 않은 장면은 구성에 들어가지 않아 건너뜁니다. 재생할 클립이 하나도 없으면 재생 화면을 열지 않고 그 사실을 알립니다. 보는 사이 동의가 바뀌거나 여행을 볼 수 없게 되면 숏폼을 닫고 받은 소리를 버립니다.

- 피드 API: 만듦(서버, `GET /api/profiles/me/feed`, `openapi.yaml:744`). 폰의 ‘내 기록본’과 앨범 장면 지우기: 만듦(웹, 브라우저 확인, T43 #200, `frontend/web/records.js:73-146`, 진입 `app.js:436`).
- 숏폼 구성 데이터(`GET /api/trips/{code}/shortform`): 만듦(서버, T43 #181, `backend/api/scenes.js`, `openapi.yaml:965`). 합성 대화의 서버 시험이며, 사람 목소리에서 어림한 자막 끝은 보지 않았습니다.
- 클립 올리기·듣기·지우기(`/api/trips/{code}/recordings`): 만듦(서버, T76 #163, `openapi.yaml:1033`·`:1065`). 가짜 S3로 시험했고 실제 버킷(T64)으로는 아직 보지 않았습니다. 클립은 `media` 하위 도메인 없이 같은 주소의 API가 내줍니다(ADR-0021, [ADR-0020](../../docs/adr/0020-media-delivery-subdomain.md)은 대체됨).
- 폰의 9:16 재생: 만듦(웹, 브라우저 확인, T43 #185, 지금 화면은 T83 #239·#244: `frontend/web/app.js:680-906`, `short-film.js:98-190`, 진입 ‘쇼츠’ 탭 `app.js:261`·`conversations.js:57`). ‘숏폼 보기’ 단추는 없어졌습니다. 헤드리스 Chromium 375×812와 가짜 S3를 붙인 로컬 서버로 봤습니다. 실제 휴대폰 소리, iOS Safari의 자동 재생 규칙은 보지 않았고, 화자 대조가 붙은 큐는 가짜 응답으로만 봤습니다.
- 장면 소리 지우기·내 글 지우기: 만듦(웹, 브라우저 확인, T75 #184, `app.js:566-583`, 단추 `:651`·`:670`). PR 때는 클립 경로가 develop에 없어 실제로 클립을 지운 경우는 보지 않았습니다.
- 차가 장면 구간을 잘라 클립을 올리기: 만듦(에뮬레이터 확인, T63 #222). 원음은 차 안에 여행·세대별로 암호화해 두고, 고른 장면 구간(없으면 장면 앞 20초~뒤 10초, 60초까지)만 16 kHz 모노로 잘라 올립니다. 가짜 S3로 `clip_e2e.py` 8/8(#239 전 화면), 실제 클립 버킷으로는 확인 전입니다. 주차 중에 '이 차에 둔 원음 지우기'가 보입니다. 차에서 숏폼 재생: 만듦(에뮬레이터 확인, T43 #233, 지금 화면은 T83 #239·#245·#247). 주행 제한이 풀린 주차 중에만 '쇼츠' 탭의 '생성된 쇼츠 보기'로 열고, 구성과 클립을 참가자 토큰으로 받아 본문 칸 전체에 말한 사람의 전신 캐릭터와 자막을 그리며 틉니다. 폰에서 고른 캐릭터를 쓰고(#245), 말한 사람을 모르면 이름을 짓지 않습니다. 좌석 구역이 있으면 자리 이름, 없으면 '화자 미확인'과 기본 캐릭터입니다(#247). `frontend/car/short_e2e.py`는 #242에서 #245 뒤 develop과 같은 앱으로 16/16이었고, 클립을 받는 중 동의 철회와 망이 끊긴 채 동의 철회를 더 봤습니다. 첫 실행은 14/16이었습니다. 재생 중 화면을 읽는 시간에 따라 결과가 갈리는 단계가 있어 다시 돌린 결과입니다. 듣는 동안은 기록을 잠시 멈추고, 기어 D가 되면 닫고 다시 기록합니다. #247에서는 에뮬레이터에 소리를 틀어 받아 적고 운영 서버에 올린 원음 클립(30.3초)을 쇼츠로 다시 그려 봤습니다. 실차와 사람 목소리는 아닙니다.

### 백엔드 산출물과 연결하는 기준

| 자료의 현재 상태 | 화면에서 사용할 정보 | 구현 인수 시 확인할 것 |
|---|---|---|
| 현재 [여행 API](../../docs/api/openapi.yaml)의 `moments` | `id, at, label`, 위치가 있으면 `lat, lng`, 구간을 남겼으면 `from, to` | 목록·지도 연결에 사용. 위치는 둘 다 있거나 둘 다 없음. 위치 없는 장면은 목록에만 있고 지도에는 없음. 자막·영상 파일은 아님 |
| 기록본(`GET /api/trips/{code}/transcript`) | 발화의 시각·원문 `text`·`asrText`·`editedText`·`editVersion`·`displayText`·좌석 구역·말한 사람, 부탁 | 녹음에 동의한 참가자만 읽음. 말한 사람은 목소리 대조가 붙인 줄에만 있음. 표시는 `displayText`(수동 수정 → 자동 재전사 → 원문) |
| 장면 후보(`GET /api/trips/{code}/scene-suggestions`) | `at, from, to, why, score, lines`, 위치가 있으면 `lat, lng` | 규칙(LLM 없음), 최대 5개 시각 순, 요청 때만 계산하고 저장 안 함. 고르면 `POST /moments`에 `at`·`from`·`to`(1~60초) |
| 숏폼 구성(`GET /api/trips/{code}/shortform`) | `title, generation, cast`, 장면마다 `clip, startAt, seconds, cues`(큐의 `start, end, text, raw, participantId, seatArea`) | 영상 파일 없음(ADR-0021). 클립이 올라온 장면만. `participantId`가 null이면 이름을 짓지 않음(‘말한 사람 미확인’). 녹음에 동의한 참가자만 |
| 클립(`/api/trips/{code}/recordings/{id}`, id는 장면 id) | WAV 소리. 듣기는 참가자 토큰 머리말, `private, no-store` | `media` 하위 도메인 없음. 지우기는 참가자 누구나, 지운 클립은 다시 올려도 409. 실제 버킷(T64)으로는 아직 보지 않음 |
| 자막 수정(`PATCH /api/trips/{code}/captions/{device}/{seq}`) | 보낼 것 `text`(null이면 수정본 초기화)·`expectedVersion`·`generation`, 받는 것 `generation`·`utterance` | 원문·자동 재전사는 그대로. 버전이나 동의 세대가 다르면 409로 다시 읽고 비교. 수정본은 동의 철회·만료·자기 글 지우기 때 함께 지움 |
| 결과 공유(`POST /api/trips/{code}/shares`, `GET /api/profiles/me/shares`, `DELETE /api/profiles/me/shares/{id}`) | 보낼 것 `momentId`, `recipientIds`(1~4명), `caption`(500자), `includeLocation`, `generation`. 받는 것 방향·보낸 사람·장면·문구·위치·기한 | 같은 여행에서 동의한 프로필 참가자만. 응답에 여행 코드·토큰·클립 없음. 201은 생성 확인일 뿐 상대의 열람이 아님. 회수·동의 철회·원본 삭제·48시간 뒤 사라짐 |
| 한 여행의 내 앨범 장면(`GET /api/profiles/me/moments?trip=`) | `id, tripCode, at, label`, 위치가 있으면 `lat, lng` | 공유 후보. 피드처럼 100개로 자르지 않음 |
| 피드(`GET /api/profiles/me/feed`) | `kind`(utterance·moment), 여행 코드, 시각, 글자 또는 장면 | 최대 100개. 발화는 48시간, 장면은 앨범 복사본이라 그 뒤에도 남음 |

장면 목록이 비어 있다는 사실만으로 ‘기록 없음’을 결정하지 않습니다. 받아쓰기·후보·클립은 각각 준비 상태가 다르며, 저장된 장면이 있어도 클립은 없을 수 있습니다.

[개편 시안(11/14)](https://www.figma.com/design/bkASxUWEfhJKjawI1sVK8n?node-id=0-1)의 [P7 기록본](https://www.figma.com/design/bkASxUWEfhJKjawI1sVK8n?node-id=6-581)과 [P8 9:16 숏폼](https://www.figma.com/design/bkASxUWEfhJKjawI1sVK8n?node-id=6-651)이 4절의 화면입니다.

[T17 도착 후 Portrait](https://www.figma.com/design/Qc58INq2ECd1ODzzmM7Nja?node-id=2-78)·[Landscape](https://www.figma.com/design/Qc58INq2ECd1ODzzmM7Nja?node-id=2-79)와 [추가 상태](https://www.figma.com/design/Qc58INq2ECd1ODzzmM7Nja?node-id=22-248)는 12개 차량 앱 창의 도착 후 진입·결과 준비 중·결과 없음 상태를 인수하는 기준입니다. 해당 파일의 120개 프레임은 T17 차량 화면 범위입니다. 폰의 기록본·숏폼은 개편 시안의 P7·P8에 있고, 후보 편집 상세·지도·공유 화면은 피그마에 없어 이 문서의 흐름을 기준으로 연결합니다.

이 문서는 저장소 코드·API 명세와 제출된 T12 설계를 대조한 화면 명세입니다. 서버는 합성 대화와 가짜 S3를 쓴 서버 시험으로, 폰 화면은 헤드리스 Chromium·ego lite의 휴대폰 크기 창과 로컬 서버로 확인했습니다(각 PR). 실제 휴대폰, 운영 주소, 차량 에뮬레이터, 실차에서 후보·자막·클립 재생·공유를 실행해 본 자료는 아닙니다.

## 상태

| 상태 | 화면과 복구 동작 |
|---|---|
| 기록 없음 확인 | ‘남은 기록이 없어요’. 후보·클립·지도 진입을 숨기며 실패를 빈 결과로 바꾸지 않음 |
| 처리 중 / 부분 준비 | ‘여행 기록을 준비하고 있어요’. 확인된 부분만 읽고 남은 기록은 준비 중 표시. 자동 후보 생성·중복 요청 없음 |
| 후보 없음 | 서버가 빈 후보 목록을 주면 ‘추천할 장면이 없어요’. 기존에 남긴 장면은 여행 화면에 그대로 |
| 위치 없음 / 지도 실패 | 위치 없는 후보는 목록에서 유지. 지도 실패는 목록으로 전환하고 ‘지도를 불러오지 못했어요’ |
| 통신 끊김 | 저장·공유 완료를 표시하지 않음. 자막 편집 중이면 마지막으로 받은 자막과 입력을 그대로 두고 다시 연결한 뒤 저장하게 함. 기록본·공유 목록은 읽기에 실패하면 이전 내용을 걷고 다시 읽을 단추를 줌 |
| 재연결 / 저장 충돌 | 자막이 409면 입력을 유지하고 서버의 최신 자막과 비교한 뒤 다시 저장. 장면 저장 결과가 불명확하면 후보를 다시 읽고(남긴 구간은 서버가 뺌), 공유 결과가 불명확하면 다시 보내기 전에 보낸 공유를 확인. 다른 사람의 편집을 자동 덮어쓰거나 장면·공유를 중복 생성하지 않음 |
| 저장·공유 실패 | 선택과 입력을 유지하고 실패한 동작을 모달 안의 상태 줄로 알림(모달 뒤의 알림은 가려짐). 400·401·403·404·409와 통신 실패를 모두 ‘기록 없음’으로 합치지 않음 |
| 여행 접근 불가 | 만료·권한·없는 여행을 확인한 응답에 따라 안내. 현재 API의 404는 없는 코드 또는 보관 기간 경과이며 새로고침으로 해결된다고 약속하지 않음 |
| 동의 철회 / 원음 삭제 요청 | 서버 클립, 차량의 미전송 클립 큐와 차 안 원음(T63), 이미 생성된 텍스트·장면을 따로 확인. 확인 전 ‘모두 삭제했어요’ 표시 금지. 동의가 바뀌면 열린 후보·자막·공유·숏폼 화면을 닫음 |
| 차량 주행 제한 재시작 | 상세·재생·지도 조작을 닫고 T17 요약으로 복귀. 폰 작업으로 운전자에게 즉시 응답을 요구하지 않음 |
| 기록본 비어 있음 | ‘아직 쌓인 기록이 없어요’. 프로필이 없는 사람(차가 손님으로 넣은 아이 등)에게는 ‘내 기록본’이 없음 |
| 공유 받을 사람 없음 | 받을 수 있는 동승자가 없다고 알리고 미리 보기로 넘어가지 않음. 공유할 내 장면이 없으면 먼저 장면을 남기라고 안내 |
| 숏폼 재생할 수 없음 | 클립이 지워졌거나 아직 없는 장면은 구성에 없어 건너뜀. 하나도 없으면 재생 화면을 열지 않음. 소리를 받지 못하면 지금 장면에 머물러 자막과 소리가 어긋나지 않게 함. 빈 화면을 완성된 숏폼처럼 보이지 않음 |

원음 보관 시계는 여행 읽기 제한과 같은 **여행 생성 후 48시간**입니다. 폰의 ‘소리 지우기’는 그 장면의 서버 클립을 바로 지우고, 차가 다시 올려도 받지 않게 표시를 남깁니다. 받아 적은 글과 장면은 남습니다. 동의를 끄면 그 여행에서 받아 적은 글과 올라간 소리가 모두 지워집니다. 차량의 미전송 클립 큐와 차 안 원음을 비우는 쪽은 T63입니다([음성 처리 명세](../../docs/api/voice.md)). 서버와 차량의 삭제가 확인되기 전에는 화면에서 ‘모두 삭제했어요’를 표시하지 않습니다. 폰에서는 수음하지 않으므로 폰에는 지울 원음이 없습니다(ADR-0008, 11/13).

화면은 '쇼츠'(탭, 재생 화면 제목)와 '숏폼'(안내 문구)을 섞어 씁니다. 한 낱말로 맞추는 것은 웹의 다음 PR 몫입니다. 쇼츠 화면의 영상 만들기·저장·공유 문구(#239·#244)는 숏폼을 영상 파일로 만들지 않기로 한 [ADR-0021](../../docs/adr/0021-shortform-as-composition-data.md)과 맞출지 정하는 중이라 이 표에 넣지 않았습니다.

### 근거와 남은 계약

- 현재 제공 범위: [API 명세](../../docs/api/openapi.yaml), [ADR-0021](../../docs/adr/0021-shortform-as-composition-data.md), 웹앱의 후보·자막·공유·기록본·숏폼 화면(`frontend/web/`), [T17 PR #54](https://github.com/team-pitcrew/gachita/pull/54).
- T12 설계 기준: [음성 처리 명세](../../docs/api/voice.md), [ADR-0007](../../docs/adr/0007-voice-processing-flow.md)·[ADR-0008](../../docs/adr/0008-in-car-capture-and-sdk-stt.md)(PR #55로 병합). 고른 장면 클립의 재전사(T75)는 ADR-0007의 예외이고, 데이터와 측정은 [전사록 데이터](../../docs/transcript-data.md)에 있습니다. 실제 음성 처리 서버의 운영·배포와 구분합니다.
- 남은 것: 받아쓰기 준비 상태 표시, 폰의 주행 기억 지도, 차의 도착 후 요약. 실제 클립 버킷(T64), 실제 휴대폰, 실차에서의 확인.
