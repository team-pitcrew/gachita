# T135: 장소 읽기·주차 단추·연결 표시(T127 후속)

2026-11-14 macOS의 Ego Lite(데스크톱 Chromium)에서 CDP로 390×844·모바일 화면을 흉내 내어 확인했습니다. **실제 폰에서 본 것이 아닙니다.** 이 브랜치의 API를 자기 포트(8841)·자기 Postgres 컨테이너로 띄우고 API로 여행·참가자 넷·발화를 넣었습니다.

**장소 읽기 경로(`GET /trips/{code}/places`, 전사 응답의 `places`)는 아직 서버에 없습니다**(서버 후속 작업). 그래서 확인하는 동안만 브라우저에 검증용 fetch 대역을 넣어, 계획서 계약 모양(`{items:[{id, kind, name, at, etaSeconds?}]}`)을 돌려주거나 403을 돌려주게 했습니다. 대역은 저장소 코드에 없습니다. 대역 없이(서버가 404) 열었을 때도 확인했습니다.

| 파일 | 확인한 것 |
|---|---|
| [near-places-contract.png](near-places-contract.png) | `/places`가 계약 모양을 주면 '곧 하나로마트에 도착해요'. '확인' 뒤 '지금은 운전에 집중하세요 / 강릉 가족 여행 / 하나로마트로 이동 중'. 대화 기록 머리 '…/ 우리 집'. 여행 문서(`GET /trips/{code}`)에는 `places`가 없음 |
| [no-places-403.png](no-places-403.png) | `/places`가 403(또는 404)이면 장소 이름 없이 '강릉 가족 여행'만, 대화 기록 머리는 시각만. 7초 동안 `/places`를 두 번 읽음(할 일과 같은 6초 주기) |
| [parked-buttons.png](parked-buttons.png) | 주차 직후(도착 전) '주차했어요'와 도착을 읽은 뒤 '하나로마트에 도착했어요' 모두 주 단추 '여행 계속', 내 자리 카드에 '여행 끝내기'. 두 단추 모두 누르면 묻고(문구는 아래), 취소하면 여행 상태가 그대로 `parked`. '여행 계속'을 받아들이면 주행으로 돌아감 |
| [offline-pill.png](offline-pill.png) | 여행 읽기를 끊으면 다음 폴링 뒤 머리가 '연결 끊김', '기록 중지'가 잠김. 다시 이으면 304인데도 '연결됨'과 단추가 돌아옴 |

물은 문구:

- 여행 끝내기: "여행을 끝낼까요? 휴대폰에서는 다시 열 수 없어요."
- 여행 계속: "다시 출발할까요? 함께 탄 모두의 화면에서 지금 도착 안내가 사라지고, 모두 기록에 동의해 있으면 차가 아직 주차 중이어도 대화 기록이 다시 켜져요."

확인하지 않은 것: 실제 서버의 장소 읽기 경로(나오면 다시 확인), 실제 폰, 브라우저 기본 확인 창의 모양(확인은 `window.confirm`을 기록하는 대역으로 했음).
