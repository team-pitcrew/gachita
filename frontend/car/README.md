# 가치타 차량 앱

Pleos Connect용 Kotlin·Compose 앱입니다(`io.github.teampitcrew.gachita`). 여행 화면은 '함께 타는 중', '대화 기록', '콘텐츠 기록'(K3·F6 전까지 쇼츠 화면)의 고정 세 탭으로 구성합니다(최종 시안 F3, 아래 '최종 시안 주행 중 좁은 창'). 차량에서 가족을 골라 여행을 만들고 기록 동의를 켭니다(T7). 모두 동의하면 차량 마이크로 수음해 Pleos STT(ON_DEVICE)로 받아 적고, 발화를 앱 안 보관함에 쌓아 서버로 올립니다(T36). 주차 중에는 현재 여행의 대화 기록을 읽고, 그 대화에서 생성한 장면을 원래 목소리와 자막으로 다시 듣습니다(T43).

주행 제한 중에는 '함께 타는 중' 화면으로 돌아가 기록 상태와 최근 대화, 일행을 보여 줍니다(T11). 쉬어 가자는 부탁을 알아채 다음 휴게소를 제안하고, 수락하면 기본 내비에 경유지로 넣습니다(T9). 장소별 할 일은 서버에서 읽고 실제 위치와 주차 상태를 확인한 뒤 도착을 알립니다(T113). Gleo를 부르면 마이크를 넘기고, Gleo가 끝나면 다시 기록합니다(T41). 주차 중에는 차량 참석 QR을 띄우고 동승자가 휴대폰 카메라로 읽어 참여할 수 있습니다(T106). 기본 내비와 가치타는 Pleos가 관리하는 별도 창으로 함께 엽니다.

## 빌드와 실행

JDK 21과 Android SDK 34가 필요합니다. `local.properties`(sdk.dir)와 서명 키는 저장소에 넣지 않습니다.

```sh
cd frontend/car
./gradlew assembleDebug testDebugUnitTest
adb install --user 10 -r -g app/build/outputs/apk/debug/app-debug.apk
adb shell am start --user 10 -n io.github.teampitcrew.gachita/.MainActivity --es server http://10.0.2.2:8787
```

- 기본 서버는 실서비스 `https://gachita.mangowhois.ai`입니다(T27). release는 https만 씁니다.
- 로컬 서버는 저장소 루트에서 `make run`(http://localhost:8787)이고, 에뮬레이터에서 Mac은 `10.0.2.2`입니다. 평문 http(10.0.2.2·localhost·127.0.0.1)는 디버그 빌드에만 열려 있어(`src/debug/res/xml/network_security_config.xml`) release로는 로컬 서버에 닿지 않습니다.
- 화면에는 서버 주소 칸이 없습니다(T83). 디버그 빌드만 `--es server <주소>`로 바꾸고, 앱은 그 주소를 기억해 다음부터 기본값보다 앞세웁니다. 예전 빌드로 `http://10.0.2.2:8787`을 기억한 기기에 release를 덮어 깔면 그 주소가 남아 연결이 막히니 앱 데이터를 지웁니다(`adb shell pm clear --user 10 io.github.teampitcrew.gachita`).
- 기어 값은 Cold boot한 에뮬레이터에서만 읽힙니다(`docs/emulator/README.md`).
- 마이크 권한(`RECORD_AUDIO`)과 알림 권한(`POST_NOTIFICATIONS`, 화면 뒤에서 '기록 멈춤'을 알림으로 보임)은 처음 기록할 때 함께 묻습니다. `-g`로 설치하면 미리 허용됩니다.

## 계정·온보딩(T142)

- 이 차에 계정 토큰이 없고 여행이 없으면 주차 중 전체 창에 시안 C01–C08(`Onboarding.kt`): 이메일 가입·로그인(`POST /api/accounts`·`/api/sessions`, 기기 이름 '차' — 토큰은 이 차에 암호화해 둠) → 계정 동의 → 이름·캐릭터 → 사진(기기 사진 선택기, 없으면 '사진 대신 캐릭터') → 15초 목소리 → 등록 완료. 서버 호출은 `Account.kt`.
- 목소리는 수음과 같은 형식(MIC, 16 kHz 2채널 → `downmix` 모노)으로 15초를 모아 `embed(pcmSamples(...))`로 값만 `POST /api/profiles/me/voice`에 올립니다(ADR-0023). 계정 동의가 켜져 있지 않으면 마이크를 열지 않습니다.
- 주행 제한이면 지금처럼 잠금 화면이고 녹음 중이면 멈춥니다. 머리 줄 '나중에'나 C08 '가족 그룹 만들기'는 지금의 여행 만들기로 가고, 처음 화면 '계정·목소리 등록'으로 다시 엽니다. 가족 그룹(F2)이 들어오기 전이라 오른쪽 '우리 가족 4명'은 고정 그림입니다(`// mock:`).
- 기존 e2e 스크립트는 첫 실행에 디버그 인자 `--ez onboarding false`를 붙여 처음 화면을 여행 만들기로 봅니다(이 차에 기억).

## 주행 중 화면(T11)

- **선언:** `MainActivity`에 `distractionOptimized`. 선언하지 않으면 기어 D에서 Pleos 차단 화면이 앱을 덮습니다.
- **판단:** 기어나 속도로 직접 정하지 않고 플랫폼의 주행 제한 값(AAOS `CarUxRestrictionsManager`, `isRequiresDistractionOptimization`)을 따릅니다(Pleos 주행 규제 개발 가이드). 값을 받기 전이거나 받지 못하면 제한된 화면입니다. 에뮬레이터에서 기어 D는 제한 80(설정 64 + 동영상 16), P는 0이었습니다.
- **주행 중 보이는 것:** 기록 상태, 받아 적은 말 두 줄, 일행, 보관한 부탁 수, 기록 동의 스위치(주행 제한 중에는 끄기만 눌림. 켜기는 지금처럼 기어 P에서만), 연결 상태입니다. 높이가 짧은 창에서는 좌석 지도 대신 일행 수를 표시하고 기록 상태와 현재 필요한 카드에 집중합니다. 주행 중 본문 글자는 24sp 이상입니다.
- **주행 중 가리는 것:** 여행 만들기, 여행 관리, 동승 QR 카메라, 콘텐츠 기록(쇼츠)입니다. 콘텐츠 기록 탭은 비활성화하고 쇼츠를 닫습니다. 쇼츠를 받는 중이어도 요청을 취소하며, 다시 주차해도 자동으로 재생하지 않습니다. **대화 기록은 최종 시안(2026:2308·2358)대로 주행 중에도 읽기만으로 보입니다(T130, T11 완화 — 오너가 되돌릴 수 있음).** 고치기·새로고침·장면 고르기는 주차 중에만 있습니다.
- 에뮬레이터에서 제한이 걸리지 않거나 차단 화면이 뜨지 않았다고 심사 기준을 통과한다는 뜻은 아닙니다.

## 화면 꾸밈(T20)

- **기준:** 디자인 1급 문서(11/14, 로컬 작업공간 `gachita/docs/디자인`)와 이후의 전신 캐릭터 요청을 따릅니다. 지민님 '말랑' 원본 시트에서 캐릭터를 각각 분리하고, 다른 캐릭터에 가려졌던 부분을 복원한 투명 PNG를 사용합니다. 원본의 형태·색·소품을 유지하며 얼굴만 자르지 않습니다. 상징색은 시트의 민트 #60C090입니다.
- **시안:** [피그마 '가치타 · T20 화면 개편'](https://www.figma.com/design/bkASxUWEfhJKjawI1sVK8n) 페이지 '개편 · 차와 폰'(차 C1~C7, 841 폭 C1n·C2n, 근거 보드, 원본 시트). 한국형 기준은 `vmc-inner-circle/k-style-ui-ux`입니다.
- **토큰:** `Theme.kt`. 색 이름과 값은 웹(`frontend/web/style.css`)과 같고, 시스템 다크(밤)에서는 어두운 값입니다. 어두운 화면은 밝은 민트 바탕에 먹색 글자, 밝은 화면은 짙은 민트(#2B7A53) 바탕에 흰 글자입니다. Material 단추가 primary를 테두리 단추의 글자색으로도 써서, 밝은 민트를 그대로 두면 흰 바탕 위 글자가 2.2:1이 되기 때문입니다. 주행 화면 글자는 24sp 이상입니다.
- **그림:** 가족 캐릭터는 `res/drawable-nodpi/char_<값>.png` 전신 자산입니다. 작은 캐릭터는 `char_<값>_small.png`로 분리합니다. `Character`는 `ContentScale.Fit`을 사용해 전신을 보존하며 원형으로 자르지 않습니다. 손님 참가자에는 캐릭터 값이 없어 자리 순서로 기본·캡모자·안경·여행·게임을 씁니다. 가치타 본체는 차 모양 마스코트입니다. 공통 캐릭터·마스코트는 움직이지 않고, 주차 중 쇼츠 장면에서만 현재 화자에 짧은 반응을 붙입니다.
- **말하는 사람:** 좌석 지도는 방금 받아 적은 말의 좌석 구역(`Utterance.seatZone`, 0 앞줄·1 뒷줄, T37이 채움)을 그 줄의 바탕과 테두리로, 목소리 대조가 맞춘 사람(`highlight`, 참가자 id)을 캐릭터 테두리로 보입니다. 값이 없으면 강조하지 않습니다.
- **공통 배치:** 위에는 마스코트·앱 이름·여행 제목·주차 또는 주행 상태를 둡니다. 연결이 끊기면 '연결 대기'를 표시합니다. 배포 중처럼 서버 앞단이 잠깐 못 받으면(502·503·504) '서버가 거절했어요' 대신 '서버가 잠깐 응답하지 않아요. 다시 시도할게요'를 보이고, 다음 조회가 성공하면 그 문구를 지웁니다. 녹음 시작의 여행 조회와 본인 동의 켜기 뒤의 여행 조회는 그런 응답이면 두 번 더 묻습니다. 동의 켜기 요청 자체는 다시 보내지 않습니다. 그사이 다른 기기의 철회를 되살리지 않도록, 잠깐 못 받아 실패하면 '동의 저장을 확인하지 못했어요'를 보이고, 다음 조회가 실제 동의를 보이며 그 문구를 지웁니다(T122). 그 아래 세 탭과 선택한 탭의 본문을 배치하고, 기록 동의는 화면 아래에 유지합니다. 주차 중에는 동의를 켤 수 있고, 주행 제한 중에는 끄기만 할 수 있습니다.
- **함께 타는 중:** 기록 상태, 일행 좌석 지도, 지금 필요한 카드, 보관한 부탁·도착 할 일 수를 보여 줍니다. 카드 우선순위는 경유지 제안 → 도착 브리핑 → 출발 전 목소리 등록 → 최근 대화입니다. 주차 중에는 '여행 관리', '동승자 연결', '기본 내비 열기'를 사용할 수 있습니다. 목소리 등록, 말한 사람 고치기, 원음 삭제, 새 여행 만들기는 여행 관리에서 이어집니다.
- **대화 기록:** 현재 여행의 목록 카드에서 대화방을 엽니다. 참가자 인증을 거쳐 받은 서버 기록을 시간순으로 표시합니다. 말한 사람이 확인되면 캐릭터·이름을 붙이고, 확인되지 않으면 '말한 사람 미확인'으로 표시합니다. 상세한 권한·세대 처리는 아래 '현재 여행의 대화 기록'을 따릅니다.
- **쇼츠:** 현재 여행에서 생성한 장면만 엽니다. 재생 중에는 탭 본문을 9:16 장면 패널과 재생 조작으로 바꿉니다. 외부 추천 영상이나 좋아요 수는 표시하지 않습니다. 동승자 연결도 탭 본문에서 카메라와 자리 선택 화면으로 이어집니다.
- **좁거나 높이가 짧은 창:** 함께 타는 중의 본문 너비가 1000dp 이상이면 좌석 지도와 카드를 나란히 둡니다. 약 841dp의 반쪽 창에서는 위아래로 쌓고 좌석 캐릭터와 여백을 줄입니다. 주차 중 본문 높이가 720dp보다 작으면 본문을 세로로 넘겨 봅니다. 주행 제한 중 680dp보다 작으면 기록 상태·일행 수·현재 필요한 카드로 줄입니다. 쇼츠 패널은 고정 900dp 높이 대신 남은 가로·세로 공간에 맞춰 9:16 비율을 유지합니다. `--ei widthDp 841`은 앱 내부 너비를 줄이는 디버그 옵션이며, OS 분할 창 검증을 대신하지 않습니다(실제 분할은 아래 창 바 동작). 420×780처럼 높이가 작은 창의 전체 탭 배치는 별도 검증이 필요합니다.
- **여행 만들기(C6):** '누구랑 같이 타나요?', 가족마다 캐릭터 카드(누르면 같이 탐·안 탐), 'N명으로 여행 만들기'.
- **좌석 지도의 칸:** 차가 알려 주는 좌석 영역(Vehicle SDK `Seat.checkSeatOccupancyCapabilities`, 권한 `pleos.car.permission.CAR_SEATS`)에서 줄과 칸을 만듭니다. Pleos 에뮬레이터는 앞 둘·뒤 셋(SEAT_OCCUPANCY 영역 0x1·0x4·0x10·0x20·0x40)을 줬습니다. 서버의 자리 값(Seat)에 없는 칸(3열)은 그리지 않고, 못 읽으면 앞 둘·뒤 셋으로 둡니다. 빈 칸에 사람이 앉았다고 차가 알리면 '앉아 있어요'라고 적습니다. SDK의 Boolean은 원값이 1인지를 알리는데 AAOS에서 1은 '빔'입니다(Virtual Console에서 조수석을 앉음으로 바꾸면 false가 옴, 11/14 에뮬레이터).

'● 기록 중'·'기록 멈춤'(같은 단추로 멈춤·재개, 동의는 그대로), 재개 뒤 새 말을 받기 전 '중지한 지점부터 이어서 기록해요', 방금 받아 적은 말 두 줄(새것이 위, '이름 / 좌석'), 말한 사람 고리와 '· 말하는 중'. 시안에 없는 것은 카드 안 단추로 둡니다: 'Gleo에게 말하기'·주차 중 '여행 관리'(기록 상태 칸), 주행 중 '동의 철회 · 기록 삭제'·주차 중 '동승자 설정'(일행 칸 머리). 가운데 칸은 휴게소 제안 > 목소리 등록(주차 중) > 받아 적은 말. 본문 높이가 860dp보다 작으면 일행을 한 줄로 줄입니다.

- **대화 기록(`TranscriptScreen.kt`):** 서버 기록을 'HH:MM / 장소' 머리로 묶습니다(10분 넘게 끊기거나 장소가 바뀌거나 부탁 카드 뒤. 장소는 기록본 응답의 `places`가 있을 때만, 없으면 시각만). 서버 할 일의 원발화(`todos[].sources`)는 '{이름}의 부탁' 카드. 주차 중에는 날짜 칩, '말한 사람 고치기'(여행 관리), '새로고침', '추천 장면 고르기'(F5 전까지 콘텐츠 기록의 만들기 화면). 주행 중에는 '현재 주행 / 대화 기록 중·멈춤' 칩과 '함께 타는 중으로'만, 가장 새 줄이 보이게 내용이 늘 때 끝으로 옮깁니다(움직임 효과 없음).
- 도착 전·도착 브리핑(C19·C20 등)은 흐름 F4의 범위이고 지금은 T123 카드 그대로입니다.

## 기본 내비와 가치타를 함께 표시하기

기본 배치는 왼쪽 내비, 오른쪽 가치타의 반쪽 창(약 841 × 1210dp)이고 화면도 이 크기를 기준으로 짭니다. 두 앱은 각각의 Activity로 실행하며, 가치타 안에 내비 지도를 임베드하지 않습니다. 창의 자리와 크기는 Pleos가 정하고 운전자가 창 바(⋮)로 바꿉니다. 앱이 정하지 못합니다(T112).

- **문서로 확인한 것:** [창 정책](https://document.pleos.ai/en/docs/connect/guide/docs-design/getting-started/window)은 새로 연 앱을 주 창(primary)에 띄우고, 좌우 바꾸기와 크기 전환은 운전자가 창 바나 제스처로 한다고만 적습니다. 처음 위치나 크기를 고르는 매니페스트·앱 카테고리 선언은 없습니다. 화면 모델 문서는 `screenOrientation`을 정하지 않으면 portrait 창 하나라고 하지만 에뮬레이터는 그렇게 동작하지 않습니다(아래). Pleos Platform SDK의 `WindowStateManager`는 앱에 조회·구독만 열고, 상태를 바꾸는 쪽은 SystemUI 전용입니다.
- **에뮬레이터에서 본 것(11/14, Pleos AVD `-read-only`, 밀도 160):** 내비가 앞에 있을 때 가치타를 열면 앱 영역 전체 `[853,90]–[2535,1300]`을 차지하고 내비는 가려집니다. 이미 1:1로 나뉘어 있어도 가치타를 다시 열면(런처, Gleo 호출 같은 `startActivity`) 가치타가 왼쪽 주 창으로 옮겨 갑니다.
- **운전자가 하는 것:** ① 가치타가 넓게 뜬 상태에서 오른쪽 끝 ⋮를 왼쪽으로 끌면 1:1로 나뉩니다(가치타 왼쪽 `[853..1694]`, 내비 오른쪽 `[1718..2559]`). ② 가운데 ⋮를 누르면 좌우가 바뀌어 내비 왼쪽 `[853,90]–[1694,1300]`, 가치타 오른쪽 `[1718,90]–[2559,1300]`이 됩니다. ③ 넓게 보려면 가운데 ⋮를 왼쪽 끝까지 끕니다(가치타 `[853..2535]`). 다시 열어 가치타가 왼쪽에 있으면 먼저 ②로 오른쪽에 옮깁니다. 가운데 ⋮를 오른쪽 끝으로 끄는 동작은 재지 않았습니다. 다시 반쪽으로 가려면 ①·②를 합니다. 길게 누르기로 뜨는 메뉴는 없었습니다.
- **앱이 못 하는 것(에뮬레이터에서 시도):** 매니페스트 `screenOrientation="portrait"`는 넓은 영역 가운데에 레터박스(양옆 검정)만 만들고 내비는 그대로 가려집니다. 1:1에서 `setRequestedOrientation(LANDSCAPE)`는 반쪽 창 안 레터박스(아래 검정)일 뿐 넓어지지 않습니다. `ActivityOptions.setLaunchBounds`와 `FLAG_ACTIVITY_LAUNCH_ADJACENT`는 내비를 열 때도, 자기 자신을 다시 열 때도 무시됩니다. 그래서 매니페스트는 바꾸지 않았습니다. 숨겨진 창 관리 API, 시스템 권한, 접근성 서비스로 창을 옮기지 않습니다.
- **앱 안 창 크기 단추:** 주차 중 머리 줄에 반쪽 창(너비 1000dp 미만)이면 '전체화면', 넓은 창이면 '반쪽 창'이 있습니다. 앱이 창을 바꾸지 못하므로 누르면 위 ①~③ 가운데 맞는 창 바 동작을 대화 상자로 알립니다. Pleos가 앱의 토스트를 띄우지 않아(CarToastUI) 대화 상자로 했습니다. 주행 중에는 단추가 사라집니다.
- **'기본 내비 열기':** 주차 중 누르면 `Navigation.kt`가 내비의 launcher Activity를 `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_LAUNCH_ADJACENT`로 엽니다. 옆 창 요청은 무시되므로 가치타가 넓게 떠 있었다면 내비가 그 자리를 덮습니다. 앱을 찾지 못하거나 실행 권한이 없으면 결과를 화면에 알립니다.
- 확인은 에뮬레이터에서 한 것이고 실차에서는 하지 않았습니다. 이 AVD의 내비는 지도 타일 없이 검색 상자만 보였습니다.

## 부탁을 경유지로(T9)

- **알아채기:** 받아 적은 말에 쉬어 가자는 낱말(화장실, 쉬었다 가, 배고파)이 있으면 서버에 부탁을 남깁니다(`held`). 누가 말했는지는 아직 몰라 운전석 참가자로 남깁니다(T37·T38이 붙이면 그 사람으로).
- **제안:** 서버의 경로 위 휴게소 추천(`POST /api/rest-stops`, T97)에 내비가 아는 지금 위치·진행 방향(`getCurrentLocationInfo`)과 목적지·남은 길(`getDestinationInfo`)을 보내 후보 셋을 받습니다(2초 제한: 추천 전용 실행기에서 묻고, 2초가 지나면 통신이 끝나지 않았어도(늦은 DNS 등) 고정 목록으로 넘어가며 늦게 온 답은 버립니다). 후보마다 내비에 길 위 거리·시간을 묻고(`requestTrip` → `onTripInfo`), 직선의 1.5배 + 2 km보다 멀거나 목적지보다 먼 곳은 나란한 고속도로나 건너편으로 보고 건너뜁니다(`Asks.kt`의 `onRoad`). 모두 걸리면 첫 후보입니다. 조회와 거리 묻기는 화면이 넘어가지 않습니다. 목적지 조회는 도착 알림(T40)과 함께 쓰므로, 둘이 겹치면 한 번만 묻고 같은 답을 나눕니다. 서버가 빈 목록으로 답하면 앞에 들를 곳이 없는 것으로 보고 부탁을 보관합니다. 서버가 그 경로를 모르거나(404) 닿지 않거나 위치를 모르면 강릉 가는 길(영동고속도로 강릉방향) 고정 목록 7곳(`Asks.kt`)에서 아직 지나치지 않은 가장 가까운 곳으로 돌아갑니다(직선, '강릉역까지 지금보다 가까운가'). 어느 쪽을 썼는지는 로그 '휴게소 후보 N곳 · 추천 서버/고정 목록'에 남습니다. 부탁을 `proposed`로 바꾸고 카드와 TTS "하남드림휴게소에 들를까요?". 제안은 한 번에 하나이고(휴게소 찾는 중 → 답 기다림 → 넣는 중 → 반영·실패), 그동안의 새 부탁은 같은 제안에 묶여 그 단계를 따라갑니다(넣는 중에 들어온 부탁은 함께 `reflected`).
  - 에뮬레이터(11/14, Pleos 2.1, 내비 위치 판교 · 목적지 강릉역): 추천 서버는 서하남행복드림쉼터·하남드림휴게소·이천휴게소 남이방향을 줬고, 서하남은 길 위 31.2 km(직선 15.3 km)라 건너뛰고 하남드림휴게소(21 km · 23분)를 제안 → "응" → 경유지 반영. 서버에 그 경로가 없을 때(develop 서버, 404)는 고정 목록의 용인휴게소 강릉방향 → 반영. 실제 주행은 확인하지 않았습니다.
- **답:** 제안이 열린 동안의 말을 띄어쓰기로 나눈 낱말 단위로 봅니다("그래서", "좋아하는"은 답이 아님). 거절 낱말(아니, 나중에, 괜찮아 …)이 먼저, 그다음 수락(응, 그래, 가자 …). "그래, 쉬었다 가자"처럼 쉬어 가자는 말이 섞여도 수락입니다. 둘 다 아니면 답 낱말이 없는 말로 한 번 다시 묻습니다(스피커 소리가 마이크로 되돌아와도 답이 되지 않게). 수락은 앞줄(좌석 구역 0)이나 구역을 모르는 말만 받습니다. 카드의 '경유지로 추가'·'나중에'도 같습니다. 거절·나중에와 30초 동안 답이 없으면 `held`로 되돌리고 저절로 다시 제안하지 않습니다.
- **반영:** `accepted`가 된 부탁만(그사이 폰에서 취소된 것은 409로 빠짐) `addWaypoint` → `onWaypointChanged`(ADD)를 받으면 `reflected`와 "용인휴게소를 경유지로 추가했어요". 경로 오류(`onError`, 거리 묻기의 `CAUSE_SEARCH_TRIP`은 빼고)나 30초 안에 오지 않으면 `held`와 "경유지를 추가하지 못했어요. 부탁은 보관했어요". 안내 취소(`onRouteCancelled`)는 경유지를 더할 때 한 번 오므로 실패로 보지 않습니다. `cancelRoute`는 쓰지 않습니다.
- **내비가 앞에 있는 동안:** 경유지를 넣는 과정에서 내비가 가치타 화면을 가리더라도 판정과 서버 갱신은 이어집니다(수음 서비스와 리스너). 결과는 말로 알리고, 가치타 화면으로 돌아오면 결과 카드를 1분 동안 보여 줍니다. 앱이 스스로 앞으로 나오지는 않습니다.
- 낮·밤 전환이나 창 크기 변화로 화면이 다시 만들어지면 기다리던 경유지 추가와 수음이 끊기므로 `configChanges`로 다시 만들지 않고 Compose가 다시 그립니다.
- 연결이 끊겨 부탁을 `accepted`로 바꾸지 못하면 경유지를 넣지 않고 실패로 알립니다(확인되지 않은 동작을 하지 않음). 그 부탁은 서버에 `proposed`로 남습니다.
- 경로 요청과 경유지 추가에는 `pleos.car.permission.NAVI_ROUTE_SEARCH`가 필요합니다(없으면 `SecurityException`).

## 서버 할 일과 도착 브리핑(T113)

- **차 안 도출(T144):** `TodoActions.kt`의 `deriveActionTodos`는 서버 `backend/api/todos.js`(`place-rules-v2`, T141)의 `todoOf`·`actionOf`·`deriveTodos`와 같은 규칙입니다. 받아 적은 발화에서 장소별 할 일과 행동 항목(분류 `first`·`buy`·`remember`·`bring`, 제목, 물건 이름·수량, 요청한 사람)을 차 안에서 냅니다. id는 서버와 같은 `sha256(JSON [장소, 글])` 앞 32자라 서버에 남은 완료·취소 상태가 그대로 붙습니다. 두 구현은 `backend/api/todo-vectors.json` 한 파일로 맞춥니다(`TodoActionsTest.kt`, 18건). 아직 화면은 아래 서버 목록을 쓰고, 차 결과를 서버에 올려 저장하는 경로와 도착 브리핑 선정의 차 이전은 남았습니다.
- **차 안 도착 판정(T144):** `Todos.kt`의 `pickArrival`은 서버 `todos.js`의 `arrivalBriefing`과 같은 규칙입니다(주차가 아니면 `not_parked`, 위치가 60초보다 오래면 `stale_position`, 장소에서 250 m 밖이면 `outside_place`, 아니면 그 장소 낱말의 대기 할 일). 서버 응답과 같은 `SharedArrival`을 돌려주고, 두 구현은 `backend/api/arrival-vectors.json`으로 맞춥니다(`TodosTest.kt`). 폰이 읽는 도착 기록은 서버 `POST /arrival-briefing`이 남기므로 그 경로는 그대로입니다. 화면 연결은 개편 흐름 담당(F4)이 합니다.
- **같은 목록:** 참가자 토큰으로 `GET /api/trips/{code}/todos`를 읽습니다. 웹과 차량이 같은 전사와 보정문에서 추출된 할 일·원발화·상태·버전을 봅니다. 추출은 서버의 `place-rules-v1` 낱말 규칙이며 모델 추론이 아닙니다. 이전 `todos-<여행 코드>.json` 파일은 그대로 두고 새 목록에 합치지 않습니다.
- **변경:** 실제 P이고 주행 제한이 풀렸을 때 완료·취소·다시 열기를 보냅니다. PATCH에는 현재 동의 세대와 `expectedVersion`이 들어갑니다. 서버 성공 뒤 목록을 다시 읽어 화면에 반영합니다. 404·409는 최신 목록을 보여 주고 다시 선택하도록 안내하며 자동으로 덮어쓰지 않습니다. 연결 실패 시 마지막 서버 목록·동기화 시각·재시도를 표시합니다. 여행·서버·참가 토큰·동의 세대가 바뀌면 이전 응답과 목록을 버립니다.
- **도착 근거:** 최초 P는 도착으로 보지 않습니다. 주차로 전환하고 주행 제한이 풀렸거나 사용자가 '도착 확인'을 누르면 내비 SDK의 다음 경유지(없으면 목적지) 이름·좌표와 별도의 현재 위치를 읽습니다. 좌표가 없거나 `(0, 0)`이면 도착 안내를 보류합니다. 현재 위치 콜백을 받은 시각을 `observedAt`, 출처를 `vehicle`로 보냅니다. SDK가 원래 측정 시각을 주지 않아 센서의 실제 측정 시각까지 검증하지는 못합니다.
- **서버 판정과 음성:** 실제 P·제한 해제·여행 범위를 다시 확인한 뒤 여행을 `parked`로 PATCH하고 `POST /arrival-briefing`을 요청합니다. 서버가 60초 이내 위치와 장소에서 250m 이내 거리를 확인하여 `eligible=true`로 돌려준 미완료 항목만 읽습니다. 응답이 오기 전에 출발·내비 변경·동의 변경·화면 이탈이 발생하면 안내를 취소합니다. 장소는 이름 포함 규칙으로 연결하며 좌표·주차의 센서 진위를 서버가 증명하는 것은 아닙니다.
- **화면과 Gleo:** 카드에서 원발화와 보정문, 확인된 화자, 시각을 펼쳐 볼 수 있습니다. 도착을 서버가 확인한 카드는 시안 C3의 순서(‘도착 브리핑’ 알약 → ‘{장소}에 도착했어요’ → ‘여기서 할 일 N건’ → 화자 캐릭터가 붙은 할 일 줄 → 전체 폭 ‘닫기’)를 따르고, 낮은 초점 칸(반쪽 창)에서는 글자와 여백을 기존 크기로 줄입니다(T123, 에뮬레이터 미확인). Gleo 함수 `GACHITA_ARRIVAL_TASKS`도 서버를 새로 읽고 미완료 목록을 반환합니다. 이 함수는 현재 장소에 도착했다고 말하지 않습니다. 조회 실패는 실패 응답을 반환합니다. 실제 도착 음성과 Gleo 호출은 기기에서 별도로 검증해야 합니다.

## 수음과 받아쓰기(T36)

- **언제:** 기록 상태가 '기록 중'(모두 동의, 주차 중 시작)이고 우리 화면이 앞일 때 마이크 포그라운드 서비스(`CaptureService`)를 시작합니다. 화면 뒤에서는 서비스를 시작할 수 없어(T10) 앱을 열 때 시작합니다. 동의가 빠지면 그 자리에서 `AudioRecord`를 멈추고 마이크를 놓습니다. 수음 중에는 화면이 뒤에 있어도 10초마다 서버의 동의를 확인합니다.
- **어떻게:** `AudioRecord`(MIC, 16 kHz 2채널)를 0.1초씩 읽어 좌+우 모노로 `SpeechToText.sendAudio()`에 넣습니다. STT가 마이크를 여는 `request()`는 쓰지 않습니다. 같은 모노 소리를 원음 파일로 암호화해 둡니다(아래 T63).
- **동의를 확인하지 못할 때:** 여행 조회(10초, 녹음 중에는 화면 뒤에서도)가 끊김이나 서버 오류로 5분 넘게 성공하지 못하면 녹음을 멈춥니다(ADR-0007: 최신 동의를 확인할 수 없으면 기록을 멈춘다). 그사이 누군가 폰에서 철회했어도 차는 알 수 없기 때문입니다. 저절로 다시 켜지 않고, 연결된 뒤 사람이 '녹음 시작'을 누릅니다. 5분은 앱을 켠 때부터 셉니다.
- **발화:** 첫 중간 결과 − 1초에서 최종 결과까지를 한 건으로 묶어 `files/utterances-<여행 코드>.jsonl`에 순번(여행·기기마다 1부터)과 함께 한 줄씩 씁니다. 필드는 서버에 올리는 칸(순번 `seq`, 시작 시각 `at`, 글자 `text`, 동의 세대 `generation`, 위치 `lat`·`lng`)과 차에만 두는 칸(여행, 끝 시각, 원음 구간, 좌석 구역 `seatZone`: T37이 채우고 서버 `seatArea`와는 T37에서 맞춤). 위치는 기록 중에 10초마다 내비에 물어 둔 값(`getCurrentLocationInfo`)이고 30초보다 오래됐거나 모르면 비웁니다. 기어는 서버에 칸이 없어 적지 않습니다. 화면에는 방금 받아 적은 말 두 줄만 보입니다(자동 스크롤 없음).
- **막힘:** `isClientSilenced`, 값이 모두 0인 조각 1초, `read()`가 2초 넘게 돌아오지 않음 중 하나면 '기록 멈춤'.
- **올리기:** 10초 조회 때 `POST /api/trips/{code}/utterances {device, items}` → `{lastSeq}`(`docs/api/openapi.yaml`). 서버가 빠짐없이 받았다고 한 순번 뒤의 것만 100건씩 보내고, 못 보내면(끊김, 동의하지 않은 사람이 있어 403) 보관함에 두었다 다음 조회에 다시 보냅니다. 서버가 준 값이 차의 확인 순번보다 작으면(DB를 백업에서 되살림) 그 값으로 내립니다(ADR-0014 2절). 인증은 이 차가 참가시킨 사람 가운데 id가 가장 앞인 사람의 참가자 토큰입니다(서버는 기기를 처음 올린 참가자에 묶음). `device`는 설치 때 만든 무작위 값입니다.
- **동의 철회:** 여행의 `generation`이 오른 것(철회)을 알게 되면 그때까지 쌓인 순번의 글과 위치를 모두 지우고 그 경계 순번을 보관함 상태 파일(`.acked`, 암호화)에 남깁니다. 다시 켜도 그 경계로만 지웁니다(세대를 견주지 않음: 서버 DB가 되살아나 세대가 오르내려도 철회 전 글은 남지 않고 철회 뒤 글은 지워지지 않게). 서버에는 지운 순번을 `{seq, generation}`(앞 세대)만 보내 확인받습니다(ADR-0014 2절).

## 좌석 구역과 말한 사람(T37)

- **수음이 2채널인지:** 녹음을 열 때 로그에 `녹음 시작 16000 Hz 2채널`을 남깁니다(에뮬레이터는 2채널). 1채널이면 구역은 늘 '모름'입니다.
- **좌석 구역:** `downmix`가 두 채널을 합치기 전에 채널별 에너지를 셉니다. 발화의 원음 구간(첫 중간 결과 − 1초 ~ 최종 결과)의 에너지를 더해 두 채널 차가 6 dB 이상이면 큰 쪽의 줄, 아니면 '모름'(`zoneOf`, `Levels`). 왼쪽 = 앞줄은 에뮬레이터 기준이고(11/13 실측: 두 채널이 완전히 갈림), 실차의 마이크 수·배치를 보고 `LEFT_IS_FRONT`·`ZONE_DB`를 고칩니다. 구역은 차 안 보관함과 대조에만 쓰고, 서버 `seatArea`(좌석 하나)로는 보내지 않습니다.
- **출발 전 목소리 등록:** 주차 중 기록이 시작되면 여행 관리의 '출발 전 목소리 등록'에 이 차가 참가시킨 사람이 보입니다. 이름을 누르면 그 사람이 두 문장을 읽는 10초 동안 수음 중인 모노 소리를 모아 **차 안에서 대조 값(벡터)으로 바꾸고 값만** `POST /api/trips/{code}/participants/{id}/voice`(JSON, 그 사람의 참가자 토큰)로 올립니다(ADR-0023). 소리는 차를 떠나지 않습니다. 그 사이 받아 적힌 말은 보관함에, 소리는 원음에 남기지 않습니다(원음 자리는 무음). 그 사람의 동의가 꺼지면 서버가 등록값을 지우므로 차도 '등록함' 표시를 뺍니다.
- **대조(차 안에서, ADR-0023):** 누가 말했는지는 차 안에서 가립니다. `Voice.kt`의 임베더는 서버 `backend/api/providers/voice.js`와 같은 수식·같은 상수이고, 두 구현은 `backend/api/voice-vectors.json` 한 파일로 맞춥니다(`VoiceTest.kt`, 성분마다 1e-6). 기록을 시작한 뒤 첫 대조 전에 탑승자의 대조 값과 기준(`GET /voice-prints`: 녹음에 동의한 참가자의 값만)을 받아 `voiceprints-<여행>.json`에 암호화해 두고(`Vault.kt` 방식) **3시간 30분** 씁니다. 그 뒤에는 지우고 다시 받습니다. 탑승자·동의가 바뀌거나 이 차에서 등록하면 다음 대조 전에 다시 받고, 동의 세대가 오르면(누군가 철회) 사본을 지우며, 여행이 지워지면 다른 파일과 함께 지웁니다. 이 차에서 동의를 철회하면 끊겨서 서버에 전하지 못해도 사본부터 바로 버리고, 여행을 떠날 때도 버립니다. 버린 뒤에 도착한 조회 응답은 저장하지 않습니다. 서버가 받은 발화마다 이 차의 원음(T63)에서 그 구간(첫 결과 쪽 0.5초를 빼고 10초까지)을 잘라 벡터로 바꾸고, 그 줄(좌석 구역)의 동의한 사람 가운데 가장 비슷한 사람이 서버가 준 기준을 넘으면 그 사람, 아니면 줄 없이 한 번 더 봅니다(앞뒤 사람이 이어 말하면 구역이 틀릴 수 있음). 찾은 사람은 `speakers-<여행>.jsonl`(암호화)에 남겨 화면에 보이고, 그 발화를 화자와 함께 `POST /utterances`로 다시 올려 서버 기록에 남깁니다(`participantId`, `speakerMethod: device-voice`; 서버는 화자가 빈 줄에만 채움). 밀린 것은 100건씩 나눠 올리고 성공한 묶음만 남긴 것으로 적습니다. 보관 시간이 지난 대조 값 사본은 대조할 말이 없어도 여행을 받을 때마다(10초) 보고 지웁니다. **발화 소리와 발화의 벡터는 차 밖으로 나가지 않고 `/voice-match`는 부르지 않습니다.** 이 차에서 등록했거나 프로필 참가자가 있을 때만, 원음을 풀어 읽으므로 클립과 같은 따로 둔 실행기에서 돌고 발화마다 동의를 다시 봅니다. 한 차례에 20건까지, 대조를 마친 순번을 적어 두어 실패하거나 앱이 꺼져도 그 뒤부터 다시 합니다. 끊겼으면(여행 조회가 서버에 닿지 않음) 마지막으로 동의를 확인한 지 5분 안에서만, 보관 시간 안의 사본으로 서버가 이미 받은 발화를 대조하고, 찾은 사람은 연결된 뒤에 올립니다. 끊긴 동안 새로 받아 적은 말은 서버가 받은 뒤에 대조합니다. 고친 화자나 찾은 화자를 보내지 못해도 대조는 막히지 않습니다(재전송 대기로 남음). 대조 값 조회가 없는 옛 서버(404)에서는 대조를 미루며 소리를 보내는 옛 경로로 돌아가지 않습니다. 실차 헤드유닛의 계산 시간과 사람 목소리 정확도는 재지 않았습니다.
- **고치기:** 대조를 마친 줄('누구?'든 이름이 틀렸든)은 주차 중에 이름 단추로 고릅니다(그 구역 사람이 앞, 구역이 틀렸을 수 있어 모두 보임). 서버에 남기기 전에는 '(보내는 중)'이 붙고, 끊겨 못 보냈으면 다음 조회마다 다시 보냅니다. 고친 것은 차 안에 남기고(대조가 덮지 않음) 서버 기록에도 보냅니다(`PATCH /api/trips/{code}/utterances/{device}/{seq}`, 올린 참가자의 토큰, #65).

## 원음과 장면 클립(T63)

- **쌓기:** 수음 한 번(서비스 시작~끝, 같은 동의 세대)이 파일 하나 `files/audio-<여행>-<세대>-<첫 표본 시각>.raw`입니다. STT에 넣은 16 kHz 모노를 0.1초 묶음마다 AES-256-GCM으로 암호화해 이어 씁니다(1시간 약 115 MB). 데이터 키는 파일마다 새로 만들어 Keystore 키(T69)로 감싸 파일 머리에 둡니다. 시각은 첫 표본 시각 + 표본 수 ÷ 16 ms입니다(`Raw.kt`).
- **클립:** 10초 조회 때 여행의 `moments`(사람이 확정한 장면)를 보고, 아직 올리지 않은 장면의 구간(장면의 `from`~`to`, 없으면 `at` 앞 20초 ~ 뒤 10초, 60초까지)을 잘라 16 kHz 모노 WAV로 `POST /api/trips/{code}/recordings?moment=&generation=&from=`(T76, `Authorization` 머리말)에 올립니다. 구간이 끝나고 3초 뒤부터, 모두 동의한 동안만. 400·404·409·413은 다시 하지 않고 401·403·503·끊김은 5분 뒤 다시. 올린 장면은 `clips-<여행>.done`.
- **지우기:** 보관 기간에 따른 자동 삭제는 없습니다. 동의 세대가 오르면 옛 세대 파일을 지웁니다. '이 차에 둔 원음 지우기'는 주차 중에 보이며, 지난 원음만 지우고 기록은 이어 갑니다(동의 철회와 다른 요청, ADR-0007). 남은 공간이 500 MB 아래면 다른 원음 파일을 오래된 것부터 지우고, 그래도 모자라면 원음만 남기지 않습니다.
- 차 앱이 켜져 있을 때만 올립니다. 원음 전체는 차 밖으로 보내지 않습니다.
- **장면 후보(차 안 규칙, T144):** `Scenes.kt`의 `suggestScenes`는 서버 `scenes.js`의 `suggest`와 같은 규칙·같은 상수입니다(30초 창의 발화 수 + 2 × (말한 사람 수 − 1), 4줄 미만 제외, 이미 남긴 장면과 겹치지 않게 5개까지, 구간 15~35초). 두 구현은 `backend/api/scene-vectors.json` 한 파일로 맞춥니다(`ScenesTest.kt`). 받아 적은 말만 보며 소리와 서버 호출은 쓰지 않습니다. 폰은 지금처럼 `GET /scene-suggestions`를 씁니다. 차 화면 연결은 아직 없습니다.

## 차 안 보관과 지우기(T69)

- **암호화:** 보관함(`utterances-<여행>.jsonl`, 상태 파일 `.acked`), 이전 판의 할 일 파일(`todos-<여행>.json`), 저장한 여행과 참가자 토큰(`car` 환경설정의 `trip`·`tokens`)은 Android Keystore 키(`gachita-vault`, AES-256-GCM)로 암호화합니다. 보관함은 줄마다 IV 12바이트 + 암호문 + 태그 16바이트를 Base64 한 줄로 써서 쓰다 끊긴 줄만 건너뜁니다(`Vault.kt`). Pleos 앱 보안 가이드의 '기기에 저장하는 민감정보는 암호화'를 따른 것입니다.
- **키를 잃으면:** 앱 데이터를 지우거나 다시 깔면 키가 바뀌어 옛 파일은 열리지 않습니다. 열리지 않는 줄·파일은 없는 것으로 다루고 새로 시작하므로, 아직 서버에 보내지 못한 발화는 잃습니다.
- **보관 기간:** 여행·녹취·원음·할 일은 기본적으로 시간에 따라 만료하지 않습니다. 무기한은 `null`로 표현하며 큰 만료 시각을 더하지 않습니다. 명시적 삭제, 동의 철회와 기기 저장 공간 보호는 유지합니다. 디버그 빌드에서 `--el keepMs <ms>`를 명시한 경우에만 그 기간으로 만료를 시험합니다.
- **서버가 여행을 모르면(404):** 기록을 멈추고 그 여행의 차 안 사본을 지운 뒤 처음 화면에 '서버에 없는 여행이라 이 차에 남은 기록도 지웠어요'를 보입니다.
- **동의 철회:** 동의 세대가 오르면 옛 세대 발화의 글·위치를 지웁니다(T36, 아래 '동의 세대').
- **참가자가 자기 글을 지우면:** 서버(`DELETE /utterances`)는 줄을 남기고 글만 비웁니다. 차는 5분(조회 30번)마다 빈 묶음으로 `lastSeq`를 받은 뒤 `GET /utterances?device=<이 차>`로 글이 남은 순번을 받아, 서버가 받았는데 지금은 없는 지금 세대의 발화는 차 사본에서도 글을 지웁니다. 같은 차례에 받은 `lastSeq` 안에서만 지워, DB를 백업에서 되살려 잃은 순번을 지운 것으로 보지 않습니다.

## 기록 동의(T7·T68)

- 참가 응답의 참가자 토큰(이때 한 번만 옴)을 앱 저장소(`car` 환경설정의 `tokens`, 암호화)에 두어 앱을 다시 켜도 남습니다. 새 여행을 만들면 지웁니다.
- '기록 시작'은 이 차가 참가시킨 사람의 동의만 그 사람의 토큰(`Authorization: Bearer`)으로 켭니다. 폰으로 들어온 사람은 일행 목록에 '동의 대기'로 보이고, 자기 폰에서 켜야 모두 동의가 되어 기록이 시작됩니다. 스위치는 이 차가 참가시킨 사람이 모두 동의했으면 켜짐으로 보여, 폰 참가자를 기다리는 동안에도 끌 수 있습니다.
- 끄기는 지금처럼 모든 사람의 동의를 토큰 없이 끕니다(서버가 막지 않음).

## Gleo와 마이크 주고받기(T41)

우리 앱이 수음하는 동안 Gleo는 운전대 버튼을 무시하고, 앱이 Gleo를 대신 깨우는 길은 없습니다(T10, ADR-0008). 그래서 마이크를 넘기고 돌려받습니다.

- **넘기기:** 받아 적은 말에 호출어가 있거나(STT가 "글레오"를 "클레오"·"클리오"로도 적어 `Gleo.kt`의 변형 목록으로 낱말 앞에서 찾음) `AudioRecord`만 멈춥니다(화면 단추는 없습니다, T83)(서비스·STT·순번은 그대로). 화면은 '기록 잠시 멈춤 · 운전대 버튼을 누르세요', 알림은 '기록 잠시 멈춤 · Gleo 쓰는 중'. 호출어는 최종 결과에서 찾으므로 호출어 뒤에 이어 한 말은 우리도 Gleo도 받지 못합니다.
- **돌려받기:** 넘기는 동안만 오디오 포커스를 시스템 소리 용도(`USAGE_ASSISTANCE_SONIFICATION`, `GAIN_TRANSIENT_MAY_DUCK`)로 쥡니다. 운전대 버튼으로 Gleo가 들으면 포커스를 잃고(`LOSS_TRANSIENT`), Gleo가 잠들면 돌려받아(`GAIN`) 다시 수음합니다. Gleo가 음악 앱 등에 포커스를 넘겨 `LOSS`가 오면 그때도 다시 수음합니다. 이 포커스는 사용자의 음악을 멈추지 않습니다(에뮬레이터, ADR-0008).
- **시간:** 버튼을 15초 안에 누르지 않으면 저절로 다시 수음하고, Gleo가 60초 넘게 포커스를 돌려주지 않아도 다시 수음합니다. 호출어로 넘긴 수, 그중 Gleo가 들은 수, 버튼 없이 시간이 지난 수(잘못 알아챘거나 누르지 않음)를 로그 `GachitaGleo`에 남깁니다.
- **Gleo 함수:** `GACHITA_PAUSE_RECORDING`(기록 멈추기), `GACHITA_RESUME_RECORDING`(기록 다시 시작). 멈추기는 동의를 끄지 않고 수음만 멈춥니다(동의를 끄면 서버가 그 여행의 글을 지움). 멈춘 동안 화면은 '기록 멈춤'과 '다시 기록' 단추이고, 앱을 다시 켜도 멋대로 다시 기록하지 않게 저장합니다. 기록이 끝나면(동의 끔, 새 여행) 풀립니다. 다시 시작은 우리 화면이 앞으로 나오면 수음을 엽니다. 실제 음성 호출과 Pleos 승인은 확인하지 않았습니다.

## 현재 여행의 대화 기록

'대화 기록' 탭은 지금 참가한 여행의 서버 기록을 보여 줍니다. 지난 여행 목록이나 공개 대화 피드는 제공하지 않습니다. 주차 중에 목록 카드를 눌러 대화방을 열고, 시각·말한 사람·대화 내용을 시간순으로 읽습니다.

- **인증:** `GET /api/trips/{code}/transcript`에 이 차가 가진 참가자 토큰을 보냅니다. 해당 참가자가 현재 기록에 동의했고 끄기 요청이 대기 중이지 않을 때 조회합니다. 여행 생성 후 경과 시간으로 조회를 차단하지 않습니다. 이 차의 최근 발화 두 줄과 서버 대화 기록은 별도로 표시합니다.
- **내용과 화자:** 서버의 `displayText`를 우선 표시합니다. 이 값이 없으면 `editedText`, `asrText`, `text` 순서로 읽고, 빈 글은 제외합니다. `participantId`가 현재 여행 참가자와 일치할 때만 그 사람의 이름과 캐릭터를 붙입니다. 좌석만으로 화자를 추정하지 않습니다. 사람이 수정한 자막에는 수정 표시를 붙입니다.
- **갱신과 지우기:** 탭 진입과 새로고침, 탭을 연 동안의 주기 조회로 갱신합니다. 여행·동의 세대·시청자 토큰이 바뀌거나 동의를 끄면 표시 중인 기록을 비웁니다. 응답의 세대가 다르면 내용을 표시하지 않고 여행 상태를 다시 조회합니다. 주행 제한이 걸리면 대화방을 닫고 기록을 비웁니다. 취소된 요청의 늦은 응답은 화면에 반영하지 않습니다.

## 생성된 쇼츠 재생(T43)

- **차 안 자막 큐(T144):** `Scenes.kt`의 `cuesOf`는 서버 `scenes.js`의 `cues`와 같은 규칙으로 클립 구간의 발화를 자막 시각(클립 처음부터의 초)과 글로 바꿉니다. 두 구현은 `backend/api/cue-vectors.json`으로 맞춥니다(`ScenesTest.kt`). 재생 화면은 아직 `GET /shortform`의 큐를 씁니다.
쇼츠는 현재 여행의 음성 클립·자막 큐·화자로 구성한 장면입니다(`GET /api/trips/{code}/shortform`, #63 계약). 미리보기는 앱이 이 데이터를 조합해 재생합니다. 영상 저장은 별도 내보내기 단계에서 실제 AVC 영상과 AAC 원음을 MP4로 만듭니다. 외부 영상 피드는 제공하지 않습니다.

기획은 대화에서 추천한 장면을 먼저 보여 주고, 사용자가 원음을 확인한 뒤 생성·저장하는 흐름을 우선합니다. 수정은 필요한 부분에만 적용하고 녹음된 목소리를 유지합니다. 현재 차량 앱은 서버에 준비된 장면의 재생과 영상 내보내기를 구현합니다. 추천 후보의 선택·확정과 자막 본문 편집 UI는 차량 앱에 아직 없습니다. 서버에서 수정한 자막은 조회 결과에 반영하며, 말한 사람 고치기는 주차 중 여행 관리에서 제공합니다.

- **언제:** 주행 제한이 풀린 주차 상태에서 '쇼츠' 탭의 '생성된 쇼츠 보기'를 누릅니다. 주행 제한, 다른 탭으로 이동, 동의 철회, 여행·동의 세대 변경 시 재생과 진행 중인 요청을 취소합니다. 재생할 클립이 없거나 요청이 실패하면 라이브러리에서 이유를 알립니다.
- **인증:** 이 차가 참가시킨 사람 가운데 현재 기록에 동의한 사람의 토큰을 머리말로 보냅니다. 끄기 요청이 대기 중이면 열 수 없습니다. 여행 생성 후 경과 시간으로 재생을 차단하지 않습니다. 절대 주소의 클립은 서버와 같은 호스트나 그 아래 이름의 HTTPS 주소만 받습니다(`clipUrl`).
- **화면:** 검은 9:16 무대 위에 상황 제목을 두고, 직접 그린 차 실내에 최근 대화의 두 캐릭터를 함께 배치합니다. 전신은 자르지 않고 표시합니다. 실제 자막 구간의 화자에게만 짧은 움직임과 민트 표시를 붙이고, 그 아래에 큰 대사를 표시합니다. 화자를 구분할 수 없으면 마스코트를 씁니다. 자막 사이에는 직전 대사를 유지하며 일시정지된 첫 화면에는 첫 대사를 보여 줍니다. 현재 장면 번호, 클립 진행률, 재생 시간은 실제 데이터에 연결합니다.
- **조작:** 위아래로 쓸어 다음·이전 장면으로 이동합니다. '이전', '일시정지·재생', '음소거·소리 켜기', '다음', '닫기' 단추도 제공합니다. 단추 높이는 최소 56dp입니다. 첫·마지막 장면의 범위를 벗어나는 이동은 비활성화합니다. 클립을 받는 중에도 일시정지와 음소거 상태를 반영합니다.
- **재생과 종료:** 장면별 클립을 `cacheDir`에 받아 `MediaPlayer`로 재생합니다. 장면이 끝나면 다음으로 넘어가고, 마지막 장면이 끝나면 처음 위치에서 일시정지합니다. 닫을 때 받은 클립을 지웁니다. 재생 화면을 열어 둔 동안 미디어 포커스(`GAIN_TRANSIENT`)를 쥐고 수음을 멈춥니다. 닫으면 포커스를 반환하고 현재 동의·기록 상태에 맞춰 수음을 다시 시작합니다.

## 차량에서 영상 만들기와 저장하기

`ShortVideoExport.kt`는 주차 중 사용자가 저장을 요청했을 때 실행하는 네이티브 내보내기입니다. 장면 순서의 앞 45초까지 540×960·24fps AVC 영상과 AAC 음성을 MP4로 만듭니다. 차 실내·두 캐릭터·제목·실제 자막을 Canvas로 그리고, EGL을 통해 MediaCodec에 전달합니다. 녹음 클립을 그대로 AAC로 변환하며 합성 목소리로 바꾸지 않습니다. 입력 원음은 현재 서버 계약인 16kHz·모노·PCM16 WAV만 허용합니다.

- **지원 확인:** AVC와 AAC 인코더가 해당 형식을 지원하는지 먼저 확인합니다. 지원하지 않거나 원음이 없으면 성공한 것으로 표시하지 않습니다. 입 모양을 음소 단위로 맞추는 립싱크나 생성형 영상 모델 호출은 포함하지 않습니다.
- **명시적 저장:** 쇼츠 재생 화면의 '영상 만들기'를 누르면 영상·음성·합친 MP4를 앱 캐시에서 완성한 뒤 `MediaStore.Video`의 `Movies/Gachita`에 저장합니다. 저장 중에는 `IS_PENDING`으로 다른 앱에 노출하지 않습니다. 저장 완료 후 '공유'는 권한을 다시 확인하고 Android의 앱 선택창을 엽니다. 저장된 URI와 공유창을 연 결과는 외부 앱의 실제 전송 완료와 구분합니다.
- **진행과 취소:** 변환 중에는 진행률과 '취소'를 표시하고 장면 이동·재생·음소거를 비활성화합니다. 닫기는 계속 사용할 수 있습니다. `MainActivity`가 서버의 참가 권한·세대를 주기적으로 다시 확인하고, 주행 제한·동의 철회·여행 또는 세대 변경·화면 이탈 시 취소합니다. 변환기는 취소·실패 시 임시 MP4와 미완료 저장 항목을 지웁니다. 성공 응답이 늦게 도착해도 `MainActivity`가 현재 권한을 다시 확인하고 무효한 결과 URI를 삭제합니다. 원음 다운로드와 그 캐시의 정리도 `MainActivity`가 맡습니다.
- **검증 범위:** 통합 Kotlin 컴파일과 단위 검사가 통과했습니다. 신규 단위 검사 5개는 WAV 메타데이터·청크 순서, PCM 표본 보존, 지원하지 않는 형식과 잘린 파일의 거부, 45초 제한과 취소 경계를 확인합니다. 실제 Pleos에서 인코더 실행, 완성 MP4의 소리·영상·길이, 저장·공유까지는 통합 검증 결과로 구분합니다.

## 동승 연결(T106)

차량에서 참석 QR을 열고 동승자가 휴대폰 기본 카메라로 읽어 참여합니다. 차량 카메라 권한과 스캔 화면은 사용하지 않습니다. 폰이 없는 사람은 차량에서 이름으로 추가할 수 있습니다.

- **차량:** 주차(P) 상태에서 동승자 설정 → 참석 QR 띄우기를 누릅니다. 운전석 참가자 토큰으로 5분 초대를 발급하며, QR이 앱 창 전체에 표시됩니다. 다른 폰도 같은 유효 초대로 참여할 수 있습니다.
- **휴대폰:** 일반 URL을 열어 프로필과 빈자리를 고르고 참여합니다. 개인 녹음 동의는 휴대폰에서 별도로 선택하며, 참여만으로 마이크를 켜지 않습니다.
- **결과:** QR 화면에서는 여행을 2초 간격으로 조회해 참가자 이름·좌석을 갱신합니다. 참가자 토큰과 프로필 토큰은 QR에 넣지 않습니다.
- **닫기·만료:** 닫기, 뒤로, 앱 이탈, 여행 변경, 주행 제한은 QR을 거두고 서버 초대를 폐기합니다. 발급 도중 닫혔다면 늦게 받은 초대도 폐기합니다. 연결이 끊겨 폐기를 확인하지 못하면 서버의 5분 만료가 적용됩니다. 만료된 QR은 화면에서 없애며 새 QR 만들기를 제공합니다.
- **API:** `POST /api/trips/:code/boarding-invites`와 `DELETE /api/trips/:code/boarding-invites/:id`입니다. 새 발급은 이전 초대를 무효화합니다. 서버와 웹 참여 화면은 별도 변경으로 함께 배포해야 합니다.

빌드·단위 테스트와 실제 휴대폰 스캔·에뮬레이터 참여 결과는 각각 기록합니다. 이전 `ride_e2e.py`는 폐기된 폰 QR → 차량 카메라 흐름의 과거 검증이며 새 방향의 완료 근거로 사용하지 않습니다.

## 로컬 E2E

차량 앱에서 여행을 만들어 서버에 생기는 것까지 한 번에 확인합니다. 에뮬레이터를 다른 사람이 쓰는 중이면 먼저 물어봅니다.

1. 저장소 루트에서 `make run`(서버와 Postgres).
2. Pleos 에뮬레이터를 Cold boot하고 `adb forward tcp:8088 tcp:8088`(Virtual Console로 기어를 바꿈).
3. `frontend/car`에서 `./gradlew assembleDebug`.
4. `python3 frontend/car/e2e.py frontend/car/app/build/outputs/apk/debug/app-debug.apk <저장소 밖 폴더>`

부탁을 경유지로(T9)는 `python3 frontend/car/waypoint_e2e.py <APK> <저장소 밖 폴더> [시도 수]`입니다. 앱이 내비에 강릉역 경로를 넣고(디버그 빌드의 `--es route "위도,경도,이름"`), 기어 D에서 "화장실 가고 싶어" 류 → 제안 → "아니, 나중에 갈게"를 [시도 수]번 돌려 부탁하는 말 끝에서 제안까지의 시간을 재고, 부탁 둘 중 하나를 폰처럼 취소한 뒤 "응, 다음 휴게소 가자"로 남은 하나만 경유지에 들어가는지 봅니다. 준비는 아래 `capture_e2e.py`와 같습니다.

이전 `arrival_e2e.py`는 이름과 P만으로 도착을 판단하던 T40 시나리오입니다. T113의 완료 근거로 사용하지 않습니다. T113은 실제 내비의 장소·현재 좌표와 P·주행 제한을 제공하는 기기에서 서버 목록 조회 → 완료/취소 → 다른 클라이언트의 상태 확인 → 실제 도착 → 서버 선정 항목 음성을 확인해야 합니다. 좌표가 0인 에뮬레이터에서는 안내 보류가 정상입니다.

Gleo와 마이크 주고받기(T41)는 `python3 frontend/car/gleo_e2e.py <APK> <저장소 밖 폴더>`입니다. 호출어 → 멈춤 → 운전대 버튼 대신 `cmd voiceinteraction show` → Gleo가 듣고 잠듦 → 다시 수음 → 이어 넣은 말이 받아 적힘, 버튼 없이 시간 초과, 화면에 'Gleo 쓰기' 단추가 없음, Gleo 함수 두 개를 봅니다. Gleo가 듣는 동안에는 소리를 넣지 않습니다(에뮬레이터가 멈춘 적이 있음). 준비는 `capture_e2e.py`와 같습니다.

쇼츠 재생(T43)은 `python3 frontend/car/short_e2e.py <APK> <저장소 밖 폴더>`입니다. 계약 모양의 가짜 구성·클립을 내고 나머지 요청은 서버로 넘기는 프록시(`SHORT_PORT`, 기본 8798)를 씁니다(`FAKE=0`이면 서버에 바로 연결합니다). 쇼츠 탭 → 생성된 쇼츠 보기 → 장면별 자막·화자와 실제 수음 중단 → 주행 시 재생 종료 → 마지막 장면의 일시정지 → 닫기·함께 타는 중 탭에서 기록 재개를 검사합니다. Gleo로 기록을 멈춘 뒤 쇼츠 재생 중 `GACHITA_RESUME_RECORDING`을 호출해 수음이 열리지 않는지 확인하고, 닫은 뒤 실제 수음 재개를 확인합니다. 재생 중 동의를 끄면 쇼츠 무대가 사라지고 캐시가 비는지 검사한 뒤, 함께 타는 중 탭에서 기록 꺼짐과 실제 수음 중단을 확인합니다.

이 스크립트에서 `ANDROID_SERIAL`을 지정하면 공유 캡처·마이크 검사 도구의 adb 대상도 함께 바뀝니다. 지정하지 않으면 `emulator-5554`를 사용합니다. Virtual Console 주소는 기존 `localhost:8088`이므로 선택한 기기에 `adb -s <serial> forward tcp:8088 tcp:8088`을 설정해야 합니다. 2026-11-14의 `emulator-5558` 개별 검증은 별도 포트 8093에서 주행 시 쇼츠 종료를 확인했습니다. 현재 UI에 맞춘 이 스크립트의 전체 실행은 아직 확인하지 않았습니다. 요청 중 탭 이동과 클립 다운로드 중 일시정지의 경합 검사는 별도 시나리오로 남습니다.

동승 연결(T46)은 `python3 frontend/car/ride_e2e.py <APK> <저장소 밖 폴더>`입니다. 에뮬레이터의 뒤 카메라를 가상 장면으로 켜 둡니다(`-camera-back virtualscene`). 스크립트가 폰 역할로 프로필과 동승 QR을 받아 PNG로 만들고 가상 장면의 벽 포스터로 넣으면(`adb emu virtualscene-image wall <png>`), 차가 그 QR을 읽어 조수석에 넣는지, 폰의 결과 조회가 linked인지, 같은 QR을 다시 읽히면 거절되는지, 기어 D에서 카메라를 놓는지 봅니다.

좌석 구역과 말한 사람(T37)은 `GACHITA_PORT=<서버 포트> python3 frontend/car/voice_e2e.py <APK> <저장소 밖 폴더> [문장 수]`입니다. 서버는 대조 값 조회와 발화의 화자 칸(ADR-0023 계약)이 있는 것을 띄웁니다. 차는 차 안에서 대조하고, 스크립트는 같은 음성을 서버의 `/voice-match`에 바로 넣은 결과를 기준으로 견줍니다. 가족 넷(합성 음성의 음높이만 다름)이 차례로 두 문장을 읽어 등록하고, 대화를 넣어 발화마다 구역(앱 로그)과 말한 사람(서버 기록)의 맞힘·틀림·모름을 셉니다.

원음과 장면 클립(T63)은 `GACHITA_PORT=<서버 포트> python3 frontend/car/clip_e2e.py <APK> <저장소 밖 폴더> [분]`입니다. 서버는 클립 API(T76)를 가짜 S3(`AWS_ENDPOINT_URL_S3=http://127.0.0.1:9787`, `CLIPS_BUCKET=clips`)에 붙여 띄웁니다(스크립트 머리 주석). [분]을 주면 그만큼 더 넣으며 CPU·메모리·원음 크기를 잽니다.

수음과 받아쓰기는 `python3 frontend/car/capture_e2e.py <APK> <저장소 밖 폴더> [분]`입니다. 에뮬레이터를 `-grpc 8556 -grpc-use-token -audio none`으로 켜 두면 macOS 합성 음성으로 만든 가족 대화를 gRPC `injectAudio`로 가상 마이크에 넣고(호스트 마이크는 쓰지 않음), 내비를 앞에 둔 기어 D에서 보관함에 쌓인 발화를 넣은 문장과 맞춰 봅니다. 30초마다 CPU·메모리를 재고, 내비가 앞일 때 시스템 마이크 차단(`cmd sensor_privacy`) → '기록 멈춤', 동의 끄기 → 마이크 놓음, 앱 다시 켜기 → 순번 이어짐까지 확인합니다. 공용 DB를 다른 시험이 비울 수 있으면 따로 띄운 서버를 `GACHITA_PORT`로 줍니다. 넣은 문장과 받아 적은 문장은 `transcript.tsv`에 나란히 남습니다.

`e2e.py`의 스크립트는 설치 → 기어 D에서 여행 만들기가 가려지고 앞 화면이 우리 앱(차단 화면 아님) → 여행 만들기(가족 4명) → 폰 참가자 한 명이 API로 참가 → 기어 D에서 동의 켜기(안 켜짐) → 기어 P에서 켜기(차 참가자만 켜지고 폰 참가자는 '동의 대기') → 폰이 자기 토큰으로 켬(기록 중) → 기어 D에서 유지 → 끄기(바로 멈춤) → 반쪽 폭(841) 순서로 화면을 캡처하고, 단계마다 서버의 여행(`GET /api/trips/{코드}`)을 함께 적어 `results.json`에 판정을 남깁니다. 실패가 있으면 종료 코드 1입니다.

## 쇼츠 피드와 보관함(T87)

주차 중 **쇼츠** 탭을 누르면 완성된 세로 영상이 먼저 재생됩니다. 위아래로 넘기거나 이전·다음으로 이동하고, 오른쪽에서 저장·공유·음소거를 선택합니다. 다른 서비스의 영상이나 미완성 제작 계획은 피드에 넣지 않습니다. 완성된 영상이 없으면 빈 상태와 만들기 진입점이 보입니다.

**보관함**은 실제 영상 표지·제목·길이를 3열로 표시합니다. `이번 여행`은 현재 참가자 인증으로 조회하는 완성 작업이고, `기기에 저장`은 이 앱이 MediaStore의 `Movies/Gachita`에 직접 저장한 MP4입니다. 저장본은 기록 동의 철회나 현재 여행이 없는 상태에서도 재생할 수 있습니다. 여행이 없는 초기 화면에서도 **저장한 쇼츠**로 들어갑니다. 제목 검색과 기기 사본 삭제를 지원하며, 삭제는 확인 뒤 갤러리에서도 지웁니다. 다른 기기로 자동 동기화하지 않습니다.

쇼츠 화면은 실제 활성 상태를 `MainActivity`에 전달합니다. Gleo로 기록을 중지했다가 재개해도 쇼츠 화면이 열린 동안에는 수음 서비스를 새로 시작하지 않으며, 화면을 닫은 뒤 동의·주행·기록 상태를 다시 확인합니다. 기본 영상 제작의 로딩·빈 결과·실패 안내도 쇼츠 탭에 표시합니다.

**+ 만들기**에서 템플릿(차 안 대화극·여행 엽서)과 추천 장면의 자막을 확인합니다. `short-plans`는 원음과 자막이 있는 15~45초 장면을 추천합니다. 원음을 외부 제작에도 보내는 선택은 추가 설정 안에 있고 기본 꺼짐입니다. 최종 확인 화면에서 실제 전달 자료를 표시하며 **동의하고 만들기**를 누른 뒤에만 `short-generations`를 요청합니다. 최종 영상에는 원래 목소리와 자막을 사용합니다.

원격 영상은 참가자 토큰 헤더로 받은 뒤 재생합니다. 원문·캐릭터·동의 세대가 바뀌면 임시 영상을 비우고, 저장·공유 직전에도 작업의 유효성을 확인합니다. 접수 응답을 못 받으면 보관한 같은 요청 키로만 다시 확인합니다. 공급자 접수 상태가 불명확하면 자동으로 다시 생성하지 않습니다. 제작·미완료 상태는 보관함에서 확인하고 취소합니다. 주행 제한이나 앱이 화면 뒤로 가면 영상 재생을 멈춥니다.

서버가 제작을 비활성화하면 추천 계획만 확인할 수 있습니다. **기본 영상으로 만들기**도 만들기 화면에 남아 있습니다. 앱은 생성 활성화나 충전을 수행하지 않습니다. 실제 유료 생성 품질은 공급자 잔액과 생성 활성화 후 별도로 확인해야 합니다.
