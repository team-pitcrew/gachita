# 이메일 계정과 계정 동의

2026-11-14(T128). 최종 디자인의 공유 계정(C02/P02)과 한 번 받는 녹음 동의(C03/P03)를 서버 계약으로 옮긴 문서입니다. 경로와 모양은 [`openapi.yaml`](openapi.yaml)이 기준이고, 여기에는 흐름과 규칙을 적습니다.

## 계정은 프로필에 붙는다

계정은 따로 있는 사용자 표가 아니라 기존 프로필 한 줄에 이메일과 비밀번호를 붙인 것입니다. 기기 프로필(`POST /api/profiles`)과 구글 연결(ADR-0006)은 그대로이고, 토큰도 지금처럼 기기마다 하나씩입니다(ADR-0009).

| 하려는 것 | 부르는 것 | 결과 |
|---|---|---|
| 처음 가입 | `POST /api/accounts` `{email, password, name, character?, device?}` | 201, 새 프로필과 이 기기 토큰 |
| 이미 쓰던 기기 프로필을 계정으로 | 같은 경로 + 그 프로필 토큰 | 200, 같은 프로필 id. `token`은 보낸 토큰 그대로 |
| 다른 기기(차·새 폰)에서 들어가기 | `POST /api/sessions` `{email, password, device?}` | 200, 그 프로필과 이 기기의 새 토큰 |

- 선택 칸(`device`, `character`, 붙일 때의 `name`)의 빈 글은 보내지 않은 것과 같습니다.
- 이메일은 앞뒤 공백을 빼고 소문자로 저장합니다. 이메일·비밀번호에 NUL이나 짝 없는 서로게이트가 있으면 DB에 묻기 전에 400입니다(가입과 로그인 모두, T136). 이미 가입한 이메일이거나 이미 계정이 있는 프로필에 다시 붙이면 409입니다.
- 비밀번호는 8~72자(글자 수)입니다. node:crypto의 scrypt(N=2^14, r=8, p=1, 소금 16바이트, 값 64바이트)로만 저장하고 비교는 `timingSafeEqual`로 합니다. 저장 모양은 `scrypt:N:r:p:<소금>:<값>`이라 비용을 올려도 옛 값을 읽습니다.
- 로그인이 틀리면 이메일이 없든 비밀번호가 틀리든 같은 401입니다. 없는 이메일에도 같은 scrypt 계산을 해 응답 시간으로 가입 여부를 알 수 없게 합니다.
- 차는 로그인으로 받은 프로필 토큰으로 프로필 경로(동의, 목소리, 그룹)를 부릅니다. 차를 다른 사람에게 넘길 때 토큰을 지우는 경로(로그아웃)는 아직 없습니다.

## 계정 동의

`PATCH /api/profiles/me` `{consent: true|false, consentVersion?}`로 계정의 녹음 동의를 켜고 끕니다. 켜면 시각(`consentAt`)과 동의한 문구의 판(`consentVersion`, 보내지 않으면 서버의 지금 판 `2026-11-14`)을 남기고, 끄면 둘 다 비웁니다.

계정 동의는 **본인이 자기 프로필 토큰으로 여행에 처음 들어갈 때의 값**입니다. 여행으로 이어지는 것은 켜져 있고 서버의 지금 문구 판(`2026-11-14`)에 동의했을 때뿐입니다 — 문구가 바뀌어 판을 올리면 다시 동의를 받습니다.

| 들어가는 길 | 계정 동의(지금 판)가 켜져 있으면 | 아니면 |
|---|---|---|
| (가) 프로필 토큰으로 참가 `POST /trips/{code}/participants`, `consent`를 보내지 않음 | 동의를 켠 채 들어감 | 지금처럼 프로필의 기본값(`consentDefault`) |
| (가) 같은 경로, `consent`를 보냄 | 보낸 값(본인의 요청) | 보낸 값 |
| (나) 차량 QR 초대 `POST /boarding-invites/{invite}/participants` | 동의를 켠 채 들어감 | 지금처럼 꺼진 채(본인 참가자 토큰으로 켬). `consentDefault`는 쓰지 않음 |
| 폰이 발급하고 차가 읽는 동승 연결(`/ride-links`) | 꺼진 채(차가 대신 상환하므로) | 꺼진 채 |

(다) 여행에 들어간 뒤의 동의 끄기와 지우기는 지금처럼 여행마다입니다(동의 세대, ADR-0007). 여행에서 끄면 그 여행만 꺼지고 세대가 올라 그 여행의 기록이 지워지며, 계정 동의는 그대로입니다. 반대로 계정 동의를 꺼도 이미 참가한 여행의 동의는 바뀌지 않으니, 그 여행에서도 끄려면 여행 화면에서 끕니다. 같은 프로필로 다시 참가하면 있던 참가자를 돌려줄 뿐 여행에서 끈 동의를 되살리지 않습니다.

그룹으로 여행을 만드는 길(가족·동승 그룹)은 다음 티켓(T133)에서 열고, 같은 규칙(각자 계정 동의, 아이는 보호자 동의)을 씁니다.

## 목소리 먼저(T173)

오너 원칙: **프로필을 만들 때 목소리를 반드시 등록합니다.** 서버도 목소리가 없는 프로필이 그룹·여행에 들어가지 못하게 막습니다. '목소리가 있다'는 `hasVoice`(지금 임베더 길이의 값)이고, 보호자 동의가 꺼진 아이는 녹음하지 않으므로 예외입니다.

| 막는 자리 | 응답 |
|---|---|
| 그룹 만들기 `POST /groups` | 409 `{type: "conflict", reason: "voice_required"}` |
| 초대 참여 `POST /group-invites/{code}`(새 구성원만, 이미 구성원이면 200) | 같음 |
| 프로필 참가 `POST /trips/{code}/participants`(새 참가자만, 다시 참가는 그대로) | 같음 |
| 차량 QR `POST /boarding-invites/{invite}/participants`(새 참가자만) | 같음 |
| 동승 연결 `POST /trips/{code}/ride-links` | 같음 |
| 그룹 여행 `POST /trips {groupId}` | 자리 있는 구성원 가운데 목소리가 없는 사람이 있으면 409 `reason: "voice_required"`, `missing: [{profileId, name, child}]`(문장에도 이름) |

- 폰·차는 문장이 아니라 `reason`으로 가르고, 목소리 등록으로 보냅니다(성인 P06·C06, 아이는 보호자가 P12·C12).
- 임베더가 바뀌면 옛 등록값은 `hasVoice: false`가 되므로, 옛 사용자도 이 409를 받고 다시 등록합니다(ADR-0023).
- 이름만 있는 손님 참가(토큰 없음)와 아이 만들기(`POST /groups/{id}/children`)는 막지 않습니다. 아이는 그룹 여행을 만들 때 위 표의 마지막 줄로 막힙니다.
- 목소리 지우기(`DELETE /profiles/me/voice`)는 그대로 됩니다(지울 권리). 지운 뒤에는 새로 들어가는 자리에서 막힙니다.

## 프로필에 더한 칸

| 칸 | 뜻 |
|---|---|
| `email` | 계정 이메일, 없으면 null. 프로필 모양은 본인 응답에만 쓰입니다 |
| `hasVoice` | 목소리 대조 값이 지금 임베더 길이(112)로 등록돼 있는지. 옛 임베더의 값은 차가 쓰지 못하므로 false(ADR-0023) |
| `consent`, `consentAt`, `consentVersion` | 위의 계정 동의 |

## 사진

`GET /api/profiles/{id}/photo`는 지금 본인 것만 줍니다. 볼 수 없는 프로필은 사진이 없는 것과 같은 404입니다. 같은 그룹 구성원의 사진으로 넓히는 것은 그룹 티켓(T133)에서 합니다.

## 하지 않은 것

비밀번호 바꾸기·찾기, 이메일 확인 메일, 로그아웃, 로그인 시도 횟수 제한은 없습니다.
