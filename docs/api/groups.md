# 가족·동승 그룹

2026-11-14(T133). 최종 디자인의 가족·좌석·동승 그룹(C09–C16, C39–C43 / P09–P16, P39–P43)과 '이 가족과 출발'을 서버 계약으로 옮긴 문서입니다. 경로와 모양은 [`openapi.yaml`](openapi.yaml)이 기준입니다. 계정과 계정 동의는 [accounts.md](accounts.md)에 있습니다.

## 그룹과 역할

그룹은 가족(`family`)과 동승(`guest`) 둘입니다. 역할은 저장하지 않고 정합니다.

| 역할 | 누구 | 할 수 있는 것 |
|---|---|---|
| `owner` | 그룹을 만든 사람 | 초대 코드, 아이 만들기, 자리, 남(성인·아이) 빼기, 나가기(그룹이 없어짐) |
| `adult` | 초대 코드로 들어온 계정 | 초대 코드, 아이 만들기, 자리, 자기 나가기, 자기가 보호자인 아이 다루기 |
| `child` | 그룹 안에서 만든 계정 없는 프로필 | 토큰이 없음. 만든 사람이 보호자(`guardianId`) |

- 그룹 경로는 구성원만 부릅니다. 구성원이 아니면 없는 그룹과 같은 404입니다(있는 id인지 알려 주지 않음).
- 구성원의 `consent`는 그 사람의 계정 동의(아이는 보호자 동의)가 지금 문구 판으로 켜져 있는지입니다. 판이 다르면 false라 화면이 다시 동의를 받습니다.
- 그룹을 만들면 대표 자리가 운전석(`ROW_1_LEFT`)입니다(가족·동승 모두, T162 — 동승 그룹도 차의 참석 QR을 띄우려면 운전석이 차 계정이어야 함). 그룹은 10명까지(아이 포함), 한 사람은 그룹 20개까지입니다.
- **들어온 사람은 빈자리에 앉습니다(T162).** 초대·QR·링크로 들어온 성인은 조수석 → 뒤 왼쪽 → 뒤 오른쪽, 새로 만든 아이는 뒤 왼쪽 → 뒤 오른쪽 → 조수석 차례로 비어 있는 첫 자리에 앉습니다. 운전석(대표 자리)과 뒤 가운데(차 좌석 화면 C16B가 네 칸)는 고르지 않고, 다 차 있으면 자리 없이 들어가 좌석 배정에서 앉힙니다. 다시 들어온 구성원의 자리는 바꾸지 않습니다. 자리 없이 들어가면 '이 가족과 출발'이 그 사람을 빼고 여행을 만들었습니다.
- 같은 그룹 구성원은 서로의 사진(`GET /profiles/{id}/photo`)을 봅니다(아이 포함).

## 초대

`POST /groups/{id}/invites`가 `{code, expiresAt, url}`을 줍니다. 코드는 `FAMILY-1234`(가족)·`TRIP-1234`(동승), 24시간, 그룹당 하나입니다 — 새로 만들면 이전 코드는 바로 410입니다. `url`은 같은 출처의 앱 주소 `/?group=<코드>`이고 QR은 이 주소를 담습니다. **코드 입력, QR, 링크는 모두 같은 `POST /group-invites/{code}`로 들어갑니다.**

- `GET /group-invites/{code}`(토큰 없음)는 그룹 이름·종류·대표 이름·만료 시각만 보여 줍니다.
- `POST /group-invites/{code}`(프로필 토큰)는 성인 구성원으로 넣고 그룹을 돌려줍니다. 이미 구성원이면 그대로 200입니다. 코드는 24시간 동안 여러 사람이 씁니다.
- 없는 코드는 404, 만료됐거나 새 코드로 바뀐 코드는 410입니다. 끝난 지 하루 지난 코드는 비워 다시 씁니다(코드가 1만 개뿐이라).
- **코드는 숫자 4자리라 짐작할 수 있습니다.** 그래서 틀린 코드 시도를 프로세스마다 10분 창으로 묶습니다: 프로필 하나에 10번, 모두 합쳐 60번(넘으면 429). 24시간 수명, 그룹당 하나, 대표가 구성원을 보고 뺄 수 있는 것과 함께 막습니다. 파드마다 따로 세므로 공개 규모가 커지면 공용 카운터나 더 긴 코드가 필요합니다.
- 옛 QR 초대(`/api/j`, 웹 `/j`)는 계속 410입니다. 옛 초대 코드(UUID)는 새 경로에서 404입니다.

## 아이 프로필과 목소리

`POST /groups/{id}/children {name, character?, guardianConsent}`로 계정 없는 아이 프로필을 만듭니다. 만든 사람이 보호자이고 아이의 동의는 보호자 동의입니다. 보호자는 `PATCH /groups/{id}/members/{profileId}`로 아이의 이름·캐릭터·보호자 동의를 고칩니다.

아이 목소리는 보호자가 `POST /groups/{id}/members/{profileId}/voice`로 등록합니다. 본문과 검사는 `/profiles/me/voice`와 같습니다 — 기기가 계산한 값(`{embedder:"logmel-pitch-1", vector:[112], seconds}`, ADR-0023) 또는 WAV. 보호자가 아니면 403, 보호자 동의가 꺼져 있으면 409입니다. 값은 아이 프로필(`voice_prints`)에 남고 `DELETE`로 바로 지웁니다. 그룹 쪽 값 조회 경로는 없습니다 — 차는 여행의 `GET /trips/{code}/voice-prints`로 받습니다(아래).

## 자리

`PUT /groups/{id}/seats {seats: {<profileId>: 좌석|null}}`은 적은 구성원의 자리만 한 트랜잭션에서 바꿉니다(맞바꾸기). 바꾼 뒤 같은 자리에 두 사람이면 409이고 아무것도 바뀌지 않습니다. DB에도 같은 그룹·같은 자리를 막는 유일 제약이 있고, 맞바꾸기를 위해 커밋 때 검사합니다.

## 빼기와 나가기

`DELETE /groups/{id}/members/{profileId}`:

- 대표는 남을 빼고, 성인은 자기만 나가고, 아이는 대표나 그 보호자가 뺍니다.
- **아이를 빼면 아이 프로필을 지웁니다**(계정 없는 구성원, ADR-0009). 프로필 지우기와 같은 정리라 아이가 탔던 여행은 동의 세대가 올라 그 여행의 기록이 지워집니다.
- 성인이 나가면 그가 보호자인 아이도 함께 지웁니다. 대표가 나가면 그룹이 없어지고 그룹의 아이를 모두 지웁니다.
- 대표가 프로필을 지우면(`DELETE /profiles/me`) 그룹과 그룹의 아이(다른 보호자의 아이 포함)를 함께 지웁니다.

## 그룹으로 여행 만들기

`POST /trips {groupId, title?}`(프로필 토큰, 그 그룹의 구성원):

1. 자리가 정해진 구성원을 그 자리로 넣습니다. 자리 없는 구성원은 빠지고, 아무도 없으면 409입니다.
2. 동의는 각자 계정 동의가 지금 문구 판으로 켜져 있는지(아이는 보호자 동의)입니다. 여행에 들어간 뒤의 끄기·지우기는 지금처럼 여행마다입니다(동의 세대).
3. **모든 참가자에 `profileId`가 붙습니다**(토큰 없는 아이 포함). 차 안 화자 식별은 `GET /trips/{code}/voice-prints`에서 여행 등록값이 없으면 프로필 목소리 값을 `profileId`로 찾아 받아 갑니다(ADR-0023).
4. 응답의 `tokens`(`{참가자 id: 토큰}`)는 부른 사람과 그가 보호자인 아이 몫입니다. 다른 성인은 자기 폰에서 프로필 토큰으로 `POST /trips/{code}/participants`를 불러 있던 참가자와 새 토큰을 받습니다(자리·동의는 그대로).
5. 그룹 id·이름은 응답과 여행 문서 안에만 두고, 토큰 없이 읽는 여행 문서(`GET /trips/{code}`)에는 싣지 않습니다. 내 여행 목록(`GET /profiles/me/trips`)의 `groupName`이 이 값을 읽습니다.

## 저장

옛 표(`groups`, `group_members`, `invites`, `profiles.managed_by`, profiles-4-groups.sql)를 그대로 다시 쓰고, `group_members.seat`와 자리 유일 제약을 더했습니다(profiles-8-groups.sql). 이전 이미지로 되돌려도 옛 코드의 프로필 지우기가 같은 표를 치웁니다. 옛 그룹의 `crew`는 `guest`로 읽습니다.

## 하지 않은 것

아이 사진 올리기, 그룹 이름 바꾸기, 대표 넘기기, 초대 코드 지우기(새 코드로 바꾸면 이전 것은 못 씀)는 없습니다.
