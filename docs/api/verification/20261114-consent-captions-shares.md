# 동의·자막 수정·동승자 공유의 통합 확인

2026년 11월 14일 `develop`의 API와 웹을 함께 실행해 T68·T80·T81의 완료 기준을 확인했습니다. 제품 기준은 가족의 차량 대화를 본인의 동의로 기록하고, 원문을 보존하면서 자막을 고치고, 직접 선택한 장면만 같은 여행의 동승자와 나누는 것입니다.

## 실행 환경과 범위

- 기준: `ca3d56a25a627e0bc0ed6700fccb7ca681f15a38`의 API·웹. 이후 T14 문서 PR #249의 병합은 실행 파일을 바꾸지 않습니다.
- macOS, Node.js, 별도 PostgreSQL 17, Ego Lite의 390×844 화면을 사용했습니다. 합성 프로필·여행·문구만 만들었습니다.
- `make -o db check DATABASE_URL=<전용 DB>`: 웹 29개, API 43개 통과했습니다. `-o db`는 공용 개발 DB 시작만 생략하며 동일한 검사를 실행합니다.
- `.github/scripts` 검사 59개, `make e2e`의 실제 이미지·일회용 DB 여정 12단계가 통과했습니다.
- 실제 휴대폰, 실차, 실제 Google 로그인·S3·ASR 검증은 이 기록에 포함하지 않습니다. 만료 검사는 DB의 합성 시각을 옮긴 검사이며 실제 48시간을 기다린 시험이 아닙니다.

## 본인만 녹음 동의를 켭니다 — T68 #140

현재 `server.test.js`의 실제 HTTP 검사에서 토큰 없음/잘못된 토큰 401, 다른 참가자 토큰 403, 본인 토큰 200, 토큰 없는 동의 OFF 200을 확인했습니다. 거절된 요청은 좌석도 바꾸지 않으며, OFF 때 기록 세대가 증가합니다.

차량의 `MainActivity`의 동의 처리는 보관한 참가자 토큰이 있는 사람만 ON 요청을 보냅니다. `e2e.py`도 폰 참가자 토큰을 별도로 보관합니다. [차량 PR #172](https://github.com/team-pitcrew/gachita/pull/172)의 Pleos 에뮬레이터 20/20 결과와 원본 `results.json`을 대조했습니다. 차에서 켜도 폰 참가자는 동의 대기이며, 폰의 본인 토큰으로 켠 뒤에만 기록 중으로 바뀌었습니다. 이 차량 결과는 기존 시험의 재확인이며 이번에 에뮬레이터를 다시 실행했다고 뜻하지 않습니다.

서버 [#160](https://github.com/team-pitcrew/gachita/pull/160), 웹 [#177](https://github.com/team-pitcrew/gachita/pull/177), 차량 [#172](https://github.com/team-pitcrew/gachita/pull/172)이 develop에 있습니다. 제출 APK 갱신과 실제 기기 시험은 T13·T6·T46에서 관리합니다.

## 원문을 남기고 자막을 수정합니다 — T80 #194

서버 [#202](https://github.com/team-pitcrew/gachita/pull/202)와 웹 [#209](https://github.com/team-pitcrew/gachita/pull/209)를 통합한 현재 코드에서 확인했습니다.

- 실제 HTTP 검사: 원문/ASR 보존, 수동본 우선 표시와 숏폼 반영, 동시 수정 200/409, 초기화, 늦은 ASR, 동의 세대 충돌, 자기 글 삭제, 철회와 만료 시 접근 차단이 통과했습니다.
- 폰 크기 UI: 원문 ‘우리 바다 봐’는 유지되고 ‘우리 함께 바다를 보자’가 수정본으로 저장됐습니다. 다른 참가자가 HTTP로 먼저 수정하자 웹은 작성 중인 입력을 유지하고 새 저장을 막았습니다. ‘최신 자막 다시 읽기’로 비교한 뒤 명시적으로 저장하니 수정본이 갱신됐습니다.
- 기존 #209의 실제 409 응답·취소·늦은 응답·철회·만료 UI 근거를 현재 API 회귀 검사와 함께 대조했습니다.

## 선택한 장면을 동승자에게 공유하고 회수합니다 — T81 #197

서버 [#201](https://github.com/team-pitcrew/gachita/pull/201), 웹 [#206](https://github.com/team-pitcrew/gachita/pull/206), 후보 목록 [#216](https://github.com/team-pitcrew/gachita/pull/216)·[#219](https://github.com/team-pitcrew/gachita/pull/219), 이미지 저장 [#223](https://github.com/team-pitcrew/gachita/pull/223)이 develop에 있습니다.

- 실제 HTTP 검사: 본인 앨범과 동의한 같은 여행의 참가자만 선택, 송수신자 접근, 외부 프로필 격리, 보낸 사람만 회수, 세대/철회/만료/원본 삭제 시 접근 차단이 통과했습니다.
- 폰 크기 UI: 수신자는 처음에 선택되지 않았고 위치 포함도 꺼져 있었습니다. 문구와 수신자를 직접 고른 뒤 장면·문구·대상·위치 제외·만료를 미리 확인하고 별도 버튼으로 공유했습니다.
- 현재 브라우저와 HTTP 조회에서 송신자 1건·수신자 1건·외부 프로필 0건을 확인했습니다. 보낸 사람이 회수한 뒤 열린 수신 화면에서 문구가 사라지고 받은 공유가 없다는 안내로 바뀌었습니다.
- #223의 실제 PNG 다운로드, 회수·만료 뒤 다운로드 차단과 경합 시험도 근거로 유지합니다. 저장한 로컬 파일은 서버의 회수로 지워지지 않으며 화면에서 이를 안내합니다.

## 재현과 증거

API의 동의·자막 검사는 `backend/api/server.test.js`, 공유 검사는 `backend/api/result-shares.test.js`, 웹의 충돌·수신·다운로드·철회 회귀 검사는 `frontend/web/*.test.mjs`에서 실행합니다. 각 구현 PR은 같은 완료 기준의 개별 근거를 담고 있습니다.

이번 작업의 로컬 로그·합성 화면은 저장소 밖 `research/evidence/20261114-issue-completion/`에 보관합니다. 토큰·DB·원문 상태 파일은 공개 증거에 넣지 않습니다. 브라우저에서 검증한 범위와 에뮬레이터의 기존 근거를 구분해 이슈에 연결합니다.
