# 차량 QR로 동승자 참여

차량이 초대 QR을 전체 화면에 표시하면 동승자는 휴대폰 카메라로 읽고 참여합니다. QR에 담는 주소는 서버가 반환한 `/?join=<초대 코드>`에 서비스의 origin을 붙인 일반 URL입니다. 프로필 토큰이나 참가자 토큰은 QR에 넣지 않습니다.

운전석 참가자가 `POST /api/trips/:code/boarding-invites`를 호출합니다. 참가자 Bearer 토큰이 필요하고 차량 상태는 `boarding` 또는 `parked`여야 합니다. 응답의 `id`, `url`, `expiresAt`으로 QR과 5분 남은 시간을 표시합니다. 새 초대를 열면 이전 QR은 폐기합니다. 여러 동승자가 유효 시간 안에 같은 QR로 서로 다른 빈 좌석에 참여할 수 있습니다.

휴대폰은 `GET /api/boarding-invites/:opaque`로 제목과 빈 좌석을 읽습니다. 인증 전 미리보기에는 제목·빈 좌석·만료 시각만 있습니다. 동승자가 본인 프로필로 로그인하고 좌석을 선택하면 `POST /api/boarding-invites/:opaque/participants`에 프로필 Bearer 토큰과 `{seat}`만 보냅니다. 성공 응답은 `{tripCode, participant, token}`입니다. 폰은 본인 참가자 토큰을 보관하고, 차는 기존 여행 조회의 버전 변경으로 새 참가자를 확인합니다.

처음 참여할 때 녹음 동의는 항상 꺼집니다. 프로필의 기본 동의가 켜져 있어도 초대 가입이 이를 대신 적용하지 않습니다. 이후 본인 참가자 토큰으로 기존 동의 변경 API를 호출합니다. 같은 프로필의 가입 재시도는 기존 참가자를 반환하고 토큰을 복구하며, 이미 선택한 자리와 이후 본인이 변경한 동의는 유지합니다.

| 상황 | 결과 |
|---|---|
| 다른 사람이 같은 자리를 먼저 선택함 | 409. 빈 좌석을 새로 읽고 다시 선택합니다. |
| QR 만료·닫기·재발급·운전석 발급자 변경 | 410. 차에서 새 QR을 엽니다. |
| 주행 또는 여행 종료 | 409. 가입 요청이 참가자를 만들지 않습니다. |
| 프로필 인증 없음·잘못된 인증 | 401. 폰에서 본인 프로필로 로그인합니다. |
| QR 화면 닫기 | 발급자가 `DELETE /api/trips/:code/boarding-invites/:id`를 호출합니다. 반복 호출도 204이며, 이미 참여한 동승자는 남습니다. |

서버는 초대 코드의 SHA-256 해시만 여행 DB에 저장합니다. 모든 응답은 `no-store`입니다. 여행 행 잠금으로 좌석 선택과 초대 폐기를 직렬화하며, 프로필 삭제와 가입은 기존 프로필 잠금 순서를 따릅니다. 외부 서비스나 인증 토큰 전달 없이 이 서버에서 완료합니다. 기존 폰 발급 `/ride-links`는 이전 클라이언트 호환을 위해 유지하지만 새 화면은 차량 발급 흐름을 사용합니다.
