# 웹·차량 공용 쇼츠 보관함

웹 데모와 차량 APK는 같은 클러스터의 아래 API를 사용합니다. 브라우저에서 만든 기본 영상도 실제 파일을 서버에 올린 뒤 보관함에 표시합니다. 로컬 blob 주소를 서버 저장 완료로 취급하지 않습니다. 서버 생성 작업(생성 일꾼, [ADR-0025](../adr/0025-shorts-generation-worker-codex-skill.md))은 통합 목록에서 `origin: provider`로 구분합니다. 기본 영상은 `origin: local-render`입니다. 새 유료 생성이나 유료 기능 활성화는 이 API의 범위에 없습니다.

## 서버 원본으로 렌더링하고 저장합니다

모든 요청은 같은 여행에서 받은 참가자 `Authorization: Bearer` 토큰을 사용합니다. 프로필 토큰은 사용할 수 없습니다. 조회·저장·다운로드에는 참가자 전원의 녹음 동의가 필요합니다.

1. `GET /api/trips/{code}/short-assets/source?moment={momentId}`로 `{momentId,generation,sourceHash,seconds,source}`를 받습니다. `source`에는 `title`, `generation`, `cast`, 선택한 장면 하나인 `scenes`가 있습니다. 장면의 `clip`도 참가자 토큰으로 읽습니다.
2. 이 스냅샷의 원음·자막 큐·화자·캐릭터로 9:16 파일을 렌더링합니다. 서버의 기존 `/shortform`과 같은 구성입니다. 스냅샷을 가져온 뒤 별도로 텍스트를 바꾸어 렌더링하지 않습니다.
3. `POST /api/trips/{code}/short-assets?moment={momentId}&generation={generation}&sourceHash={sourceHash}&key={idempotencyKey}`에 `Content-Type: video/mp4` 또는 `video/webm`과 **실제 파일 바이트**를 보냅니다. multipart나 JSON 본문이 아닙니다. 키는 영문·숫자·`_`·`-` 8~100자입니다.
4. 201 응답은 서버 파일·메타데이터 저장 완료입니다. 동일 키·동일 파일·동일 원본의 재전송은 200과 같은 ID를 줍니다. 통신 결과를 잃었을 때는 같은 파일과 키로 재시도합니다. 같은 키로 파일을 바꾸면 409입니다.
5. `GET /api/trips/{code}/short-assets`로 최신 서버 목록을 다시 읽습니다. APK와 웹은 같은 결과를 받습니다.

저장은 여행 상태가 `parked` 또는 `ended`일 때만 가능합니다. 서버는 본문 수신 전, 파일 검사 후, 저장소 PUT 후에 동의 세대와 원본 해시를 다시 검사합니다. 해시는 서버에 실제 존재하는 장면 클립의 키·크기와 구성 스냅샷을 묶습니다. 자막 보정, 화자·캐릭터 변경, 클립 삭제·변경 뒤에는 409이며 원본을 다시 받아 렌더링해야 합니다.

## 실제 파일을 검사합니다

파일은 최대 64,000,000바이트이며 선택한 원음 장면은 0.5~60초입니다. ffprobe로 컨테이너, 스트림, 실제 디코딩 프레임과 패킷 시각을 확인합니다. 영상·소리 트랙이 각각 하나 있고 시작 시각이 -1~0.5초 범위여야 하며, 두 트랙 길이가 모두 장면 길이와 1초 이내여야 합니다. 영상은 9:16(허용 오차 0.02), 240×426~2160×3840, 초당 1~61프레임, 소리는 8~96kHz·1~2채널을 받습니다. 검사는 파일 프로토콜만 허용하고 외부 데이터 참조를 끕니다. 먼저 해상도를 확인하고 제한된 시간·메모리로 프레임을 읽습니다. [ffprobe 공식 문서](https://ffmpeg.org/ffprobe.html), [프로토콜 제한 문서](https://ffmpeg.org/ffmpeg-protocols.html)를 따릅니다.

검사 결과에는 실제 `seconds`, `width`, `height`, `fps`, 코덱, 음성 샘플레이트·채널, 프레임 수, 바이트 수와 SHA-256을 저장합니다. 이는 파일이 재생 가능한지와 서버 원본의 버전이 일치하는지 검사하는 계약입니다. 업로드된 픽셀·음성이 원문 내용을 정확히 표현하는지, 원음과 음향적으로 동일한지는 증명하지 않습니다. `local-render`를 공급자 생성 완료로 바꾸거나 AI가 만든 결과라고 표시하지 않습니다.

## 목록과 파일을 공유합니다

`GET /short-assets`는 `{generation,items}`를 반환합니다. 현재 동의 세대의 모든 기본 영상과 기존 공급자 작업을 최신 순으로 줍니다. 기본 영상은 여행당 활성 항목 최대 100개이며 프로세스당 파일 검사·업로드는 2개로 제한합니다.

기본 항목에는 `id`, `origin`, `state`, `momentId`, `generation`, `sourceHash`, `createdAt`, `createdBy`가 있습니다. `state`는 `uploading`, `completed`, `failed`, `source_changed`입니다. 완료 상태만 `result`를 갖습니다. 원본이 바뀐 항목은 목록에서 `source_changed`와 함께 파일 주소를 생략하고 정리 작업이 삭제합니다. 기본 영상에는 48시간 만료를 적용하지 않습니다.

`result.url`은 기본 영상이면 `/api/trips/{code}/short-assets/{id}/file`, 공급자 결과면 기존 `/api/trips/{code}/short-generations/{id}/file`입니다. 파일 주소를 임의로 조립하지 않고 이 값을 같은 참가자 토큰으로 호출합니다. 응답의 MIME으로 파일 확장자를 정합니다. `GET /short-assets/{id}`로 기본 항목 상태만 읽을 수도 있습니다. 파일 다운로드는 원음·동의·삭제 상태를 S3 응답 뒤 다시 검사하고 업로드 때 SHA-256과 대조한 실제 바이트를 반환합니다. 공개 S3 주소나 서명 URL을 앱에 노출하지 않습니다.

## 삭제와 실패를 처리합니다

`DELETE /short-assets/{id}`는 저장한 참가자만 호출할 수 있으며 204입니다. 동의 철회 뒤에도 보관자는 삭제할 수 있습니다. 접근은 즉시 차단합니다. 실제 객체는 별도 정리 큐에서 지웁니다. 철회 시 기존 세대의 항목은 같은 DB 트랜잭션에서 차단됩니다. 클립·자막 변경과 여행 삭제는 주기적 재검사에서도 발견합니다. 삭제 대기 키는 여행 삭제에 따라 사라지지 않습니다.

진행 중 PUT이 늦게 끝나도 객체 키를 다시 정리 큐에 남깁니다. 실패한 요청 재시도는 시도마다 다른 객체 키를 써서 옛 파일 정리가 새 파일을 지우지 않습니다. 저장소 장애가 지속되면 실제 객체 삭제는 지연될 수 있지만 API 접근은 계속 차단됩니다. 삭제 큐는 30초마다 재시도하며 진행 중 업로드의 3분 임대가 끝날 때까지 기다립니다.

| 상태 | 프론트 처리 |
|---|---|
| 400 | 실제 파일 형식·길이·트랙 또는 요청 값을 확인합니다. |
| 401 / 403 | 참가자 토큰과 전원 동의 상태를 다시 확인합니다. |
| 404 | 여행·장면·영상이 존재하지 않습니다. |
| 409 | 주차 상태, 원본 변경, 진행 중인 동일 업로드, 요청 키 충돌을 확인합니다. 자동으로 다른 파일을 같은 키에 재전송하지 않습니다. |
| 410 | 삭제되거나 철회된 항목입니다. 보관 완료로 복구하지 않습니다. |
| 413 / 429 | 64MB 한도 또는 동시 업로드 한도입니다. |
| 503 / 504 | 저장소·검사 도구 장애 또는 시간 초과입니다. 동일 파일·키로 재시도할 수 있습니다. |

배포에는 기존 `SHORTS_BUCKET`(없으면 `CLIPS_BUCKET`)과 비공개 S3 읽기·쓰기·삭제 권한을 사용합니다. ffprobe와 쓰기 가능한 `/tmp`가 필요합니다. 현재 API 이미지에 도구가 있고 클러스터의 `/tmp`는 임시 볼륨입니다. 추가 유료 공급자 키는 필요하지 않습니다. migration `trips-12-short-assets.sql`은 항목·삭제 큐를 추가합니다. 이전 이미지로 되돌리면 새 API가 사라지므로 프론트도 함께 되돌리고 남은 삭제 큐는 지원 이미지로 정리해야 합니다.
