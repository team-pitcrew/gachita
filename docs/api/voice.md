# 음성 처리 API 초안

2026-11-13, [ADR-0007](../adr/0007-voice-processing-flow.md)의 설계를 API 모양으로 옮긴 **초안**입니다. 구현 전이라 `openapi.yaml`에는 아직 없습니다. 만들 때 이 문서를 openapi.yaml로 옮기고 서버·테스트와 같은 PR에서 고칩니다(개발 규칙). 오류 형식과 크기 제한(10 KB)은 기존 API와 같지만, 조각 오디오 본문은 그보다 크므로 **올리기 경로만 따로 한도를 둡니다**(아래).

## 인증 — 참가자 토큰

음성 경로의 인증은 프로필 토큰이 아니라 **참가자 토큰**이다. 참가(`POST /api/trips/:code/participants`, 프로필·손님 모두) 응답에 일회성이 아닌 참가자 토큰을 더해 발급하고(구현 시 기존 참가 API에 추가), 서버에는 해시만 둔다. `Authorization: Bearer <참가자 토큰>`으로 보낸다. 여행 코드나 공개 참가자 id는 비밀로 쓰지 않는다. 수명은 여행과 같아 만든 뒤 48시간, 참가 해제·여행 종료와 함께 폐기한다. 프로필 인증, 참가 자격, 녹음 동의, 대표 녹음 기기 역할은 각각 확인한다.

| 경로 | 허용 조건 |
|---|---|
| `POST /recordings` | 이 여행의 유효한 참가 + 대표 녹음 기기로 지정됨 + 녹음 동의가 켜져 있음 |
| `GET /recordings` | 이 여행의 허용된 참가자(동기화 목적 포함) |
| `DELETE /recordings` | 이 여행의 참가자(원음 삭제 요청) |
| `GET /transcript` | 이 여행의 허용된 참가자 |
| `POST /scene-suggestions` | 이 여행의 허용된 참가자 |

자격이 없거나 만료·폐기되었으면 `401`, 유효한 자격이지만 이 여행·기능의 권한이 없으면 `403`으로 나눈다. 대표 녹음 기기는 기본 운전자 참가자이고 여행에서 바꿀 수 있다(지정 계약은 구현 때 확정).

## 동의 세대와 오프라인

- 여행에 **동의 세대**(정수)가 있다. 참가자가 동의를 끄거나 원음 삭제가 일어나면 세대가 오른다.
- 폰은 조각에 만들 때의 세대를 적어 올린다. 서버는 지금 세대와 다른 조각을 `409`로 거절하고, 이미 받은 조각은 폐기한다. 삭제·철회 이력을 남겨 늦은 업로드·처리 결과가 폐기된 원음을 되살리지 않는다.
- 폰은 오프라인이면 **마지막 동의 확인 뒤 5분**(초안 값, 구현 때 조정)까지만 녹음을 이어가고 그 뒤엔 멈춘다. 자동 재개는 없다(사람이 다시 켠다) — T17의 "최신 동의를 확인할 수 없으면 기록을 멈춘다"와 같은 기준이다.
- 재연결한 폰은 올리기보다 먼저 아래 상태 조회로 동기화하고, 폐기 대상 큐를 지운 뒤 확인을 보내고, 남은 조각을 시각 순서로 올린다.

## 폰 → 서버: 원음 조각

| 요청 | 본문 | 하는 일 |
|---|---|---|
| `POST /api/trips/:code/recordings` | multipart: `chunk`(오디오, 최대 5 MB), `startedAt`(epoch ms), `durationMs`, `generation`(동의 세대) | 조각을 받아 저장. 같은 `startedAt`이면 덮어쓰지 않고 200. 세대가 다르면 409(거절·폐기 대상) |
| `GET /api/trips/:code/recordings` | | 서버가 받은 조각 목록(`startedAt`·길이·상태)과 함께 `generation`(지금 동의 세대), `recording`(지금 녹음 가능 여부), `pendingDeletion`(삭제 진행 상태)을 돌려준다. 폰이 무엇이 밀렸고 무엇을 버릴지 안다 |
| `DELETE /api/trips/:code/recordings` | | 원음 전체 삭제를 요청·실행. 응답은 서버 삭제 완료와 각 기기의 로컬 삭제 확인을 나눠 담는다. 받아쓰기가 끝났으면 텍스트는 남긴다 |

조각 상태: `stored`(받음) → `transcribed`(받아쓰기 끝) → `dropped`(48시간 지나 지움, 세대가 바뀌어 폐기, 또는 참가자가 지움).

## 서버 → 받아쓰기 결과

| 요청 | 하는 일 |
|---|---|
| `GET /api/trips/:code/transcript?v=버전` | 받아쓰기 결과. 한 줄: `{ speaker, text, at, durationMs }[]`. 아직 준비 중이면 `{ status: "pending", doneUntil }` |

- 화자 라벨은 STT 제공자가 매기는 `1, 2, 3…`을 그대로 둔다(누구인지 매핑은 화면 문서 과제).
- 여행 버전(`v`) 규칙은 기존 여행 읽기와 같아서, 받아쓰기가 끝날 때 여행 `version`이 오른다.

## 장면 후보(추천)

LLM이 후보만 추천하고 사람이 고릅니다(ADR-0007). 확정된 장면은 이미 있는 `POST /api/trips/:code/moments`로 남긴다 — 새 경로를 만들지 않는다.

| 요청 | 본문 | 하는 일 |
|---|---|---|
| `POST /api/trips/:code/scene-suggestions` | `{ windowMs? }` | 받아쓰기와 moments를 보고 후보를 만든다: `{ at, why, lat?, lng? }[]`. `lat`·`lng`는 그 시각 근처 moments에서 얻을 수 있을 때만 들어 있고, 없는 후보는 지도에 표시하지 않는다(T18 화면 문서). 만들어 둔 뒤 결과로 돌려줌(비용 때문에 요청할 때만) |

**위치 없는 장면의 저장.** 후보에 좌표가 없어도 확정할 수 있게 moments 계약을 확장한다(ADR-0007): `lat`·`lng`는 둘 다 있거나 둘 다 없음만 허용. 위치 없는 장면은 목록에 저장·재조회되고 지도에는 나오지 않는다. 좌표가 없다고 0,0을 채우거나 다른 장면의 좌표를 옮겨 적지 않는다. 이 확장은 구현 PR에서 openapi·서버·테스트·T18에 함께 반영한다.

## 동의 문구(기록 동의에 더하는 글)

> 대화가 녹음되어 받아쓰기 위해 클라우드(제3자)로 전송되고, 원음은 여행 기록과 함께 여행을 만든 뒤 48시간이 지나면 지워집니다. 남는 것은 받아쓴 텍스트와 장면입니다. 원음은 참가자가 요청하면 바로 지울 수 있습니다.

보관 시계는 여행 읽기 제한과 같은 '여행을 만든 시각부터 48시간' 한 개뿐이다(기준이 갈라지지 않게 — T18 검토에서 정리). 원음 삭제(지난 것을 지움)와 녹음 동의 철회(앞으로를 멈춤)는 다른 요청이고, 화면에서도 구분해 말한다.
