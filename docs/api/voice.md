# 음성 처리 API 초안

2026-11-13, [ADR-0007](../adr/0007-voice-processing-flow.md)·[ADR-0008](../adr/0008-in-car-capture-and-sdk-stt.md)의 설계를 API 모양으로 옮긴 **초안**입니다. 구현 전이라 `openapi.yaml`에는 아직 없습니다. 만들 때 이 문서를 openapi.yaml로 옮기고 서버·테스트와 같은 PR에서 고칩니다(개발 규칙). 오류 형식과 크기 제한(10 KB)은 기존 API와 같지만, 발화 묶음과 원음 클립 본문은 그보다 크므로 **그 두 경로만 따로 한도를 둡니다**(아래).

## 흐름 개요

차량 앱이 직접 수음해 Pleos STT로 받아 적고(ADR-0008), **발화 단위**로 서버에 보냅니다. 서버는 발화를 기록본으로 저장하고(T39, 저장 모양은 ADR-0014), 화자를 프로필에 붙이고(T38), 장면 후보를 추천해 사람이 고릅니다. 원음이 차 밖으로 나가는 것은 **사람이 장면으로 확정한 구간의 클립뿐**입니다(ADR-0007).

## 인증 — 참가자 토큰

음성 경로의 인증은 프로필 토큰이 아니라 **참가자 토큰**이다. 참가(`POST /api/trips/:code/participants`, 프로필·손님 모두) 응답에 일회성이 아닌 참가자 토큰을 더해 발급하고(구현 시 기존 참가 API에 추가), 서버에는 해시만 둔다. `Authorization: Bearer <참가자 토큰>`으로 보낸다. 여행 코드나 공개 참가자 id는 비밀로 쓰지 않는다. 수명은 여행과 같아 만든 뒤 48시간, 참가 해제·여행 종료와 함께 폐기한다. 프로필 인증, 참가 자격, 녹음 동의, 발화를 올리는 기기 역할은 각각 확인한다.

| 경로 | 허용 조건 |
|---|---|
| `POST /utterances` | 이 여행의 유효한 참가 + 발화를 올리는 기기로 지정됨(기본 차량 앱) + 녹음 동의가 켜져 있음 |
| `GET /utterances` | 이 여행의 허용된 참가자(동기화 목적 포함) |
| `GET /transcript` | 이 여행의 허용된 참가자 |
| `POST /scene-suggestions` | 이 여행의 허용된 참가자 |
| `POST /recordings` | 이 여행의 유효한 참가 + 확정 장면의 클립만 |
| `DELETE /recordings` | 이 여행의 참가자(원음 삭제 요청) |

자격이 없거나 만료·폐기되었으면 `401`, 유효한 자격이지만 이 여행·기능의 권한이 없으면 `403`으로 나눈다. 프로필 피드(`GET /profiles/me/feed`)만 프로필 토큰을 쓴다 — 기록이 프로필에 묶이기 때문이다(T39).

## 동의 세대와 오프라인

- 여행에 **동의 세대**(정수)가 있다. 참가자가 동의를 끄거나 원음·발화 삭제가 일어나면 세대가 오른다.
- 차량은 발화를 만들 때의 세대를 발화마다(`items[].generation`) 적어 올린다. 서버는 지금 세대보다 옛 세대의 발화를 저장하지 않되 받은 것으로 쳐서 `lastSeq`에 넣고(`409`로 돌려보내지 않음), 이미 받은 옛 세대 발화는 지운다. 삭제·철회 이력을 남겨 늦은 올리기·처리 결과가 폐기된 것을 되살리지 않는다.
- 동의가 꺼지면 차량은 그때까지 못 보낸 옛 세대 발화 큐를 버린다(ADR-0014). 동의가 꺼진 동안의 올리기는 `403`이라 확인 순번이 오르지 않는다.
- 차량은 오프라인이면 **마지막 동의 확인 뒤 5분**(초안 값, 구현 때 조정)까지만 수음을 이어가고 그 뒤엔 멈춘다. 자동 재개는 없다(사람이 다시 켠다) — T17의 "최신 동의를 확인할 수 없으면 기록을 멈춘다"와 같은 기준이다.
- 재연결한 차량은 올리기보다 먼저 아래 상태 조회로 동기화하고, 폐기 대상 큐를 지운 뒤 확인을 보내고, 남은 발화를 순번 순서로 올린다.

## 차량 → 서버: 발화 묶음

| 요청 | 본문 | 하는 일 |
|---|---|---|
| `POST /api/trips/:code/utterances` | `{ device, items: [{ seq, at, text, seatArea, generation, confidence?, lat?, lng? }] }`. `seatArea`는 모르면 `null`. 화자(`profileId`)는 받지 않는다 — 서버의 화자 대조(T38)가 채운다 | 발화 묶음을 받아 저장. 같은 `(device, seq)`는 다시 보내도 한 번만 남는다(멱등). 순서가 어긋나도 좋다. 옛 세대 발화는 받은 것으로 치고 저장하지 않는다. 응답은 빠짐없이 받은 `lastSeq` — 차량은 그 뒤만 다시 보낸다. `lastSeq`가 전보다 작아지면(DB를 백업에서 되살림, ADR-0016의 RPO 5분) 차량은 그 뒤부터 다시 보낸다. 한 묶음은 500건·본문 1 MB까지(넘으면 400·413, T39) |
| `GET /api/trips/:code/utterances?after=순번` | | 순번 뒤의 발화를 시각 순서로. 차량의 재동기화·빠진 것 확인 |

발화 한 줄이 담는 것: 시각(epoch ms), 글자, 좌석 구역(모르면 비어 있음), 세대, 프로필(서버가 화자 대조로 채움, 아직 없으면 비어 있음), 확신도(Pleos STT는 주지 않아 비어 있을 수 있음), 위치(있을 때만). 열과 제약은 ADR-0014와 T39(PR #85)를 따른다. 부탁·도착 할 일·장면은 발화와 따로 두고(기존 `requests`, `moments`), 기록본 읽기에서 함께 보여준다.

## 기록본과 프로필 피드 (T39)

| 요청 | 하는 일 |
|---|---|
| `GET /api/trips/:code/transcript?v=버전` | 기록본. 발화를 시간순으로, 부탁과 도착 할 일과 함께. 여행 버전(`v`) 규칙은 기존 여행 읽기와 같다 |
| `GET /api/profiles/me/feed` | 프로필 토큰으로 자기 피드. 48시간 안의 자기 발화와 사람이 장면으로 남긴 것을 여행을 가로질러 최신순으로(48시간이 지나도 남는 것 — ADR-0014의 '복사') |

- 발화는 여행 만든 뒤 48시간이 지나면 지우고, 사람이 고른 장면만 프로필로 복사해 남긴다(기준 문서: '선택한 장면만 개인 앨범에').
- 프로필 주인이 자기 발화를 지우는 경로, 다른 가족의 말이 섞인 장면의 처리는 T39에서 정한다.

## 장면 후보(추천)

LLM이 후보만 추천하고 사람이 고릅니다(ADR-0007). 확정된 장면은 이미 있는 `POST /api/trips/:code/moments`로 남긴다 — 새 경로를 만들지 않는다.

| 요청 | 본문 | 하는 일 |
|---|---|---|
| `POST /api/trips/:code/scene-suggestions` | `{ windowMs? }` | 기록본과 moments를 보고 후보를 만든다: `{ at, why, lat?, lng? }[]`. `lat`·`lng`는 그 시각 근처 moments에서 얻을 수 있을 때만 들어 있고, 없는 후보는 지도에 표시하지 않는다(T18 화면 문서). 만들어 둔 뒤 결과로 돌려줌(비용 때문에 요청할 때만) |

**위치 없는 장면의 저장.** 후보에 좌표가 없어도 확정할 수 있게 moments 계약을 확장한다(ADR-0007): `lat`·`lng`는 둘 다 있거나 둘 다 없음만 허용. 위치 없는 장면은 목록에 저장·재조회되고 지도에는 나오지 않는다. 좌표가 없다고 0,0을 채우거나 다른 장면의 좌표를 옮겨 적지 않는다. 이 확장은 구현 PR에서 openapi·서버·테스트·T18에 함께 반영한다.

## 원음 클립 — 확정 장면만

원음 전체를 올리는 경로는 없다(ADR-0007). 사람이 장면으로 확정한 구간의 클립만 올라간다.

| 요청 | 본문 | 하는 일 |
|---|---|---|
| `POST /api/trips/:code/recordings` | multipart: `clip`(오디오, 최대 5 MB), `momentId`(확정한 장면), `generation` | 확정 장면의 원음 클립을 받아 저장. 같은 장면의 클립은 다시 보내면 덮어쓰지 않고 200. 세대가 다르면 409 |
| `DELETE /api/trips/:code/recordings` | | 원음 삭제를 요청·실행. 응답은 서버 삭제 완료와 각 기기의 로컬 삭제 확인을 나눠 담는다. 차량의 미전송 큐도 함께 비운다. 받아 적은 글과 장면은 남는다(지우려면 각자의 삭제 경로) |

원음 클립의 보관 시계는 여행과 같은 '만든 뒤 48시간'이고, 장면 앨범에는 장면의 시각·위치·이름표가 남는다(T39). 서버 삭제는 클립의 모든 버전을 지운 뒤 완료로 친다(데이터 버킷은 버전 관리가 켜져 있음, T64). 각 기기의 로컬 삭제에는 차 안에 암호화해 둔 원음(T63)이 들어간다.

## 동의 문구(기록 동의에 더하는 글)

> 대화는 차에서 받아 적힙니다. 녹음은 기본 꺼져 있고, 참가자 모두가 동의할 때만 켭니다. 받아 적은 글은 여행 기록과 함께 여행을 만든 뒤 48시간이 지나면 지워지고, 그 뒤엔 사람이 장면으로 남긴 것만 남습니다. 장면을 고를 수 있게 소리는 48시간 동안 차 안에 암호화해 두었다가 지웁니다. 장면으로 남기면 그 구간의 소리가 서버로 올라갑니다. 누가 말했는지 가리려고 말소리가 잠시 서버로 갔다가 저장되지 않고 지워집니다. 받아 적은 글과 장면은 참가자가 요청하면 바로 지울 수 있습니다.

보관 시계는 여행 읽기 제한과 같은 '여행을 만든 시각부터 48시간' 한 개뿐이다(기준이 갈라지지 않게 — T18 검토에서 정리). 원음 삭제(지난 것을 지움)와 녹음 동의 철회(앞으로를 멈춤)는 다른 요청이고, 화면에서도 구분해 말한다. 목소리 대조 값(T38)을 등록할 때의 고지는 T38에서 이 문구와 맞춘다.

## 남은 것

- 발화 표·기록본·피드의 구현과 openapi 이동(T39, PR #85) — ADR-0014(병합됨)와 이 문서의 발화 계약을 따른다.
- 화자 대조 API와 목소리 등록(T38) — 발화의 `profileId`를 채우는 쪽.
- 차량 앱의 수음·발화 송신·좌석 판정·Gleo 넘겨주기(T36, T37, T41, 지환).
- Pleos STT의 사람 목소리·소음 정확도 재측(T36 실측 뒤) — 모자라면 받아쓰기 위치 다시 검토.
- 폰 수음은 후순위 차선안(기준 문서) — 만들 때 이 문서의 기기 지정 규칙을 함께 고친다.
