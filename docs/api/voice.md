# 음성 처리 API

2026-11-13, [ADR-0007](../adr/0007-voice-processing-flow.md)·[ADR-0008](../adr/0008-in-car-capture-and-sdk-stt.md)의 설계를 API 모양으로 옮긴 문서입니다. 구현된 경로(참가자 토큰, 발화 묶음, 기록본, 피드, 화자 대조)는 [`openapi.yaml`](openapi.yaml)이 기준이고, 이 문서는 흐름과 동의·보관 규칙을 적습니다. 장면 후보와 원음 클립은 아직 계획이라 `openapi.yaml`에 없습니다. 만들 때 openapi.yaml에 옮기고 서버·테스트와 같은 PR에서 고칩니다(개발 규칙). 오류 형식과 크기 제한(10 KB)은 기존 API와 같지만, 발화 묶음과 원음 클립 본문은 그보다 크므로 **그 두 경로만 따로 한도를 둡니다**(아래).

## 흐름 개요

차량 앱이 직접 수음해 Pleos STT로 받아 적고(ADR-0008), **발화 단위**로 서버에 보냅니다. 서버는 발화를 기록본으로 저장하고(T39, 저장 모양은 ADR-0014), 화자를 프로필에 붙이고(T38), 장면 후보를 추천해 사람이 고릅니다. 차량의 클립 저장은 **사람이 장면으로 확정한 구간**으로 제한합니다(ADR-0007). (11/14, [ADR-0024](../adr/0024-full-trip-audio-upload.md)) 주차한 뒤에는 차가 여행 전체 음성을 올리고, 장면 클립은 서버가 그 안에서 잘라 씁니다 — 콘텐츠는 여전히 고른 장면으로만 만듭니다(아래 '여행 전체 음성'). 웹은 Pleos STT를 사용할 수 없어, 전원 동의 아래 짧은 발화 음성을 서버 ASR에 보내 첫 전사를 받습니다(T96). 이 일시 처리와 클립 저장을 구분합니다.

## 웹 입력의 첫 전사 (T96)

웹에서도 실제 서버를 호출해 음성을 받아 적습니다. `POST /api/trips/:code/transcriptions?generation=<녹음 시작 때 읽은 세대>`에 참가자 Bearer 토큰과 `Content-Type: audio/wav`를 붙입니다. 입력은 **16 kHz·모노·PCM16 WAV, 0.5~10초, 최대 400,000바이트**입니다. WAV의 표본이 잘렸거나 채널·표본율이 다르면 거절합니다.

성공 응답은 `200 {text, seconds, generation, providerText, segments, diarization}`입니다. `text`는 ASR 공급자의 글에서 화자 태그와 확인된 양끝 시각을 제거한 발화이며, 문장 안의 숫자·시각 표현은 보존합니다. `providerText`는 공급자 원문을 그대로 담습니다. 초안, 임의 대화, 화자를 만들지 않습니다. 이 요청은 음성·결과를 DB나 파일에 저장하지 않습니다. 장면 후보 선택·클립 저장·숏폼 구성은 차량과 같은 API를 사용합니다.

`segments`는 공급자가 실제로 반환한 `<spk:N> MM:SS.xx 발화 MM:SS.xx`를 `{start, end, text, speakerLabel}`로 읽은 배열입니다(T110). `start`와 `end`는 입력 WAV 시작에서 잰 초입니다. 모든 구간의 글이 비어 있지 않고 `0 ≤ start < end ≤ seconds`일 때만 배열을 반환합니다. 실제로 겹치는 발화는 보존합니다. 하나라도 형식·화자 라벨·시각이 잘못되면 `segments: null`, `diarization.status: invalid`와 `reason`을 반환하며, 태그나 시각이 전혀 없으면 `unavailable`입니다. 시각을 추정하거나 범위 안으로 잘라 성공으로 만들지 않습니다. 메타데이터가 무효여도 발화와 `providerText`는 응답에 남습니다.

`diarization`은 `{method: "provider-window", scope: "request", requestId, status, reason?}`입니다. `requestId`는 매 응답의 UUID이고, `spk:0` 같은 번호는 **해당 요청 안의 익명 화자**만 뜻합니다. 다른 요청의 같은 번호를 동일인으로 묶거나 실제 참가자 이름으로 표시하면 안 됩니다.

웹은 유효한 구간마다 `POST /utterances`에 `at = 입력 시작 시각 + start × 1000`, `endAt = 입력 시작 시각 + end × 1000`을 밀리초 정수로 보내고 `speakerLabel`, `speakerScope = diarization.requestId`를 함께 저장합니다. `endAt`는 선택 칸이며 `at < endAt ≤ at + 10000`이어야 합니다. 익명 라벨과 범위는 둘 다 있거나 둘 다 없어야 합니다. 기존 Android 입력은 새 칸 없이 그대로 받습니다. 기록본·발화 조회·수동 자막 및 화자 수정·자기 피드·장면 후보·숏폼 자막에도 이 값이 유지됩니다. 숏폼은 실제 끝 시각을 사용하고 겹침을 보존하며, 기존 발화에 끝 시각이 없으면 종전 추정 규칙을 씁니다.

실제 참가자 신원은 기존 `POST /voice-match?device=...&seq=...`로 해당 구간의 원음을 대조한 결과만 붙입니다. 0.5초 미만 구간은 이 API의 입력 하한보다 짧으므로 익명으로 남기거나, 실제 주변 원음을 포함한 입력으로 별도 대조해야 합니다. 익명 라벨만으로 프로필을 정하지 않습니다. 구간 메타데이터가 없거나 무효면 한 발화로 글을 저장할 수 있지만, 화자나 시각을 만들지 않습니다. 원문·늦은 응답은 동의 세대가 바뀌면 버립니다.

전원 녹음 동의와 호출자의 참가자 토큰을 본문을 읽기 전, 공급자로 보내기 직전, 응답 직후에 확인합니다. 누구든 철회하면 403이며, 철회 후 재동의했더라도 세대가 바뀌었으면 409입니다. 이때 웹은 이전 원음과 늦은 결과를 지워야 합니다. 공급자를 기다리는 동안 여행의 DB 연결이나 행 잠금을 유지하지 않아 동의 철회를 막지 않습니다.

| 결과 | 웹에서 할 일 |
|---|---|
| 422 `invalid` | 무음 또는 빈 전사입니다. 자막을 만들지 않습니다. |
| 400·413 | 지원하지 않는 파일·길이·크기입니다. 입력 형식을 고칩니다. |
| 401·403·409 | 인증·동의·세대를 다시 확인합니다. 철회 전 소리를 재사용하지 않습니다. |
| 429 `rate_limited` | 요청이 많거나 공급자가 제한했습니다. 원음을 보존하고 대기 상태를 표시합니다. |
| 503·504 `unavailable` | 미설정·공급자 실패·제한 시간 초과입니다. 자막 성공으로 처리하지 않고, 현재 동의 세대의 원음을 유지해 사용자가 다시 시도할 수 있게 합니다. |

공급자는 `ASR_URL`·`ASR_TOKEN`으로 설정한 OpenAI 호환 `/chat/completions`의 `nemo_transcribe30`입니다. 키가 없으면 503이며 대체 문장을 반환하지 않습니다. 기존 재전사와 요청 간격(`ASR_GAP_MS`, 기본 1.1초)을 공유하고, 프로세스당 대기·처리를 합해 8건으로 제한합니다. 대기와 외부 응답에 `ASR_TIMEOUT_MS`(기본 10초, 최대 20초)를 적용합니다. 클라이언트 연결이 끊기면 외부 요청도 취소합니다. **첫 전사는 자동 재시도하지 않습니다.** 이미 전송한 요청이 제한 시간에 걸렸는지 알 수 없으므로 웹도 같은 원음을 자동 반복 전송하지 않습니다. 기존 장면 재전사의 초안 교정과 재시도 규칙은 유지합니다.

## 인증 — 참가자 토큰

음성 경로의 인증은 프로필 토큰이 아니라 **참가자 토큰**이다. 참가(`POST /api/trips/:code/participants`, 프로필·손님 모두) 응답이 참가자 토큰을 주고, 서버에는 해시만 둔다. `Authorization: Bearer <참가자 토큰>`으로 보낸다. 여행 코드나 공개 참가자 id는 비밀로 쓰지 않는다. 시간으로 만료하지 않는다(T90): 여행이 지워지거나 그 참가자가 빠질 때까지 쓴다. 같은 프로필이 다시 참가하면(다른 기기, 토큰을 잃음) 새 토큰을 주고 앞서 준 토큰도 최근 4개까지 산다(T68). 아이(계정 없는 구성원)의 토큰은 참가시킨 보호자의 기기가 받고, 보호자가 다시 참가시키면 새로 받는다. 손님은 다시 참가할 길이 없으니 참가시킨 기기(차량 앱)가 토큰을 보관한다. 프로필 인증, 참가 자격, 녹음 동의, 발화를 올리는 기기 역할은 각각 확인한다.

| 경로 | 허용 조건 |
|---|---|
| `GET /api/trips/:code/me` | 해당 여행의 참가자 토큰으로 본인 `{id,name,seat,consent}`만 확인합니다(T115). 동의 false와 남아 있는 ended 여행도 허용하며 상태를 바꾸지 않습니다. 누락·무효·프로필·다른 여행 토큰은401, 없는 여행은404입니다. 토큰은 반환하지 않고 응답을 저장하지 않습니다(no-store) |
| `PATCH /participants/:id`의 `consent: true` | 그 참가자 본인의 토큰(T68). 없거나 틀리면 `401`, 다른 참가자의 토큰이면 `403`. 동의 끄기(`consent: false`)와 자리(`seat`)는 토큰 없이 누구나 — 끄기는 기록을 멈추는 쪽이고, 자리는 차 화면이 고른다(T46) |
| `POST /utterances` | 이 여행의 참가자 + 그 기기 이름을 처음 올린 참가자(차량 앱만 올린다) + 모두 녹음에 동의함 |
| `GET /utterances` | 녹음에 동의한 참가자(동기화 목적 포함) |
| `PATCH /utterances/:device/:seq` | 그 기기 이름으로 발화를 올린 참가자(T37, 사람이 화자를 고침). 녹음에 동의한 참가자의 이름만 붙인다 |
| `DELETE /utterances` | 프로필로 참가한 참가자(자기 이름이 붙은 발화만) |
| `GET /transcript` | 녹음에 동의한 참가자 |
| `POST /participants/:id/voice` | 그 참가자 본인의 토큰 + 그 참가자가 녹음에 동의함(T38). 본문은 음성(WAV)이나 기기가 계산한 값(JSON, ADR-0023). 값은 동의가 꺼지거나 다시 켜지면 바로 지우고, 참가자가 빠지거나 여행이 지워질 때 함께 지운다. 시간이 지났다는 이유로는 지우지 않는다(T90) |
| `POST /voice-match` | 녹음에 동의한 참가자. 발화 줄에 화자를 채우는 것은 그 발화를 올린 참가자만 |
| `GET /voice-prints` | 녹음에 동의한 참가자. 녹음에 동의한 참가자의 대조 값만 준다(ADR-0023). `private, no-store` |
| `POST /moments` | 토큰은 없어도 된다. 있으면 고른 사람의 프로필 앨범에 복사한다 |
| `GET /scene-suggestions`, `GET /shortform` | 녹음에 동의한 참가자(기록본과 같음, T43) |
| `POST /recordings` | 이 여행의 유효한 참가 + 녹음 동의 + 탑승자 모두 동의 + 이 여행의 장면 클립만(T76) |
| `GET /recordings/:id` | 이 여행의 참가자 + 녹음 동의(기록본과 같음, T76) |
| `DELETE /recordings/:id` | 이 여행의 참가자(원음 삭제 요청, 동의 여부 무관, T76) |
| `PUT /audio/parts/:n`, `POST /audio/start`, `POST /audio/complete` | 그 여행의 발화를 올린 기기의 참가자(기기 주인) + 탑승자 모두 녹음에 동의 + 지금 동의 세대(ADR-0024). 받아 적은 말이 하나도 없는 여행은 내비 장소를 올린 참가자(차)나 운전석 참가자가 기기 주인을 대신한다(T162 — 아니면 차가 403을 '나중에 다시'로 보고 C22가 0%에서 멈췄음) |
| `GET /audio` | 이 여행의 참가자(진행률만, 동의 여부 무관) |
| `DELETE /audio` | 이 여행의 참가자(전체 음성 지우기, 동의 여부 무관) |

자격이 없거나 만료·폐기되었으면 `401`, 유효한 자격이지만 이 여행·기능의 권한이 없으면 `403`으로 나눈다. 프로필 피드(`GET /profiles/me/feed`)만 프로필 토큰을 쓴다 — 기록이 프로필에 묶이기 때문이다(T39).

## 동의 세대와 오프라인

- 여행에 **동의 세대**(정수)가 있다. 참가자가 켜져 있던 동의를 끄면 세대가 오른다. 원음 삭제와 프로필 주인의 자기 발화 지우기는 세대를 올리지 않는다 — 세대를 올리면 옛 세대 전부, 곧 그 여행의 받아 적은 글이 모두 지워지는데, 원음 삭제 뒤에도 글은 남고(아래 원음 표) 자기 글 지우기는 자기 것만 지운다(T39).
- 차량은 발화를 만들 때의 세대를 발화마다(`items[].generation`) 적어 올린다. 서버는 지금 세대보다 옛 세대의 발화를 저장하지 않되 받은 것으로 쳐서 `lastSeq`에 넣고(`409`로 돌려보내지 않음), 이미 받은 옛 세대 발화는 지운다. 삭제·철회 이력을 남겨 늦은 올리기·처리 결과가 폐기된 것을 되살리지 않는다.
- 동의가 꺼지면 차량은 그때까지 못 보낸 옛 세대 발화의 내용을 버린다(ADR-0014). 버린 발화의 순번은 내용 없이 `{seq, generation}`만 올려 확인받는다 — 순번을 아예 빼면 그 앞에서 `lastSeq`가 멈춘다. 동의하지 않은 탑승자가 있는 동안의 올리기는 `403`이라 확인 순번이 오르지 않는다.
- 차량은 오프라인이면 **마지막 동의 확인 뒤 5분**(초안 값, 구현 때 조정)까지만 수음을 이어가고 그 뒤엔 멈춘다. 자동 재개는 없다(사람이 다시 켠다) — T17의 "최신 동의를 확인할 수 없으면 기록을 멈춘다"와 같은 기준이다.
- 재연결한 차량은 올리기보다 먼저 아래 상태 조회로 동기화하고, 폐기 대상 큐의 내용을 지운 뒤 그 순번을 `{seq, generation}`으로 보내 확인받고, 남은 발화를 순번 순서로 올린다.

## 차량 → 서버: 발화 묶음

| 요청 | 본문 | 하는 일 |
|---|---|---|
| `POST /api/trips/:code/utterances` | `{ device, items: [{ seq, at, text, seatArea, generation, confidence?, lat?, lng? }] }`. `seatArea`는 모르면 `null`. 화자는 선택 칸 `participantId`·`speakerMethod`·`speakerConfidence`(아래 '기기에서 화자 대조'). 없으면 서버의 화자 대조(T38)가 채운다 | 발화 묶음을 받아 저장. 같은 `(device, seq)`는 다시 보내도 한 번만 남는다(멱등). 순서가 어긋나도 좋다. 옛 세대 발화는 받은 것으로 치고 저장하지 않는다. 응답은 빠짐없이 받은 `lastSeq` — 차량은 그 뒤만 다시 보낸다. `lastSeq`가 전보다 작아지면(DB를 백업에서 되살림, ADR-0016의 RPO 5분) 차량은 그 뒤부터 다시 보낸다. 한 묶음은 500건·본문 1 MB까지(넘으면 400·413, T39) |
| `GET /api/trips/:code/utterances?after=순번` | | 순번 뒤의 발화를 시각 순서로. 차량의 재동기화·빠진 것 확인 |

발화 한 줄이 담는 것: 시각(epoch ms), 글자, 좌석 구역(모르면 비어 있음), 세대, 화자(참가자와 프로필 — 차가 함께 올리거나 서버 대조가 채움, 아직 없으면 비어 있음)와 붙인 방법, 확신도(Pleos STT는 주지 않아 비어 있을 수 있음), 위치(있을 때만). 열과 제약은 ADR-0014와 T39(PR #85)를 따른다. 부탁·도착 할 일·장면은 발화와 따로 두고(기존 `requests`, `moments`), 기록본 읽기에서 함께 보여준다.

## 기기에서 화자 대조 (ADR-0023, 구현됨)

누가 말했는지 가르는 계산을 차 안에서 할 수 있게 서버가 세 가지를 연다. 계약 원본은 `openapi.yaml`이다. **새 차량 앱(T126)은 이 경로로 차 안에서 대조하고 `/voice-match`를 부르지 않는다.** `/voice-match`는 구버전 차량 앱과 웹 입력(T96)의 구간 대조가 쓴다.

| 요청 | 하는 일 |
|---|---|
| `GET /api/trips/:code/voice-prints` | 녹음에 동의한 참가자의 대조 값(이 여행 등록값 먼저, 없으면 프로필 등록값)과 임베더 이름·확신 기준을 준다. 차는 암호화해 두고 차 안에서 대조한다 |
| `POST /api/trips/:code/utterances`의 화자 칸 | 차가 대조한 참가자를 발화와 함께(`participantId`, `speakerMethod: "device-voice"`, `speakerConfidence`). 이미 올린 순번을 화자와 함께 다시 보내면 화자가 빈 줄에만 채운다 |
| `POST …/participants/:id/voice`, `POST /api/profiles/me/voice`에 JSON | `{embedder, vector, seconds}` — 기기가 계산한 값만 등록한다. 음성 본문(WAV)도 그대로 받는다 |

- **믿는 범위.** 화자 칸은 그 기기 이름으로 올리는 참가자의 발화에만(올리기의 기기 주인 규칙), 녹음에 동의한 이 여행 참가자만 붙는다. 모르는 참가자 id는 화자 없이 저장한다(묶음을 거절하면 `lastSeq`가 멈춘다). 사람이 고친 화자와 이미 붙은 화자는 덮지 않는다. 같은 참가자가 `PATCH /utterances/:device/:seq`로 할 수 있는 범위를 넘지 않는다. 서버는 차의 계산을 다시 하지 않는다(소리가 없다).
- **붙인 방법.** 발화 줄에 `speakerMethod`가 남는다: `device-voice`(차), `server-voice`(`/voice-match`). 사람이 고치면 이 표시와 확신도를 비운다.
- **둘째 값(강한 화자 값, 11/15).** 1차 임베더는 실제 목소리에서 같은 성별의 어른을 잘 가르지 못한다(시연 원천의 교정본 36줄에서 늘 누군가로 정하면 22줄, 학습된 화자 모델로는 27줄 — 맥에서 잰 값). 그래서 차와 폰이 같은 공개 모델(wespeaker resnet34)로 256차원 값을 하나 더 만들어 올린다: 1차 값을 올린 같은 경로에 `{embedder: "wespeaker-resnet34-v1", vector, seconds}`를 한 번 더. 서버는 계산하지 않고(모델도 소리도 없다) 1차 값과 같은 줄에 둔다 — 1차 값이 없으면 409, 1차 값을 다시 등록하면 둘째 값은 비우고, 지우는 규칙은 같다. `GET /voice-prints`는 있는 사람의 항목에 `strong`을, 응답에 `strongEmbedder`를 준다. 기기는 후보 모두에게 둘째 값이 있을 때 그것으로 판정하고, 없으면 아래 규칙을 쓴다. 기기끼리 같은 값을 내는지는 같은 소리에 대한 sherpa-onnx 2.0.1의 값과 견줘 맞춘다(폰 웹은 onnxruntime-web + JS fbank로 코사인 0.99999999999, 11/15).
- **판정(여백 규칙).** 절대 기준 하나로는 실제 목소리에서 '말한 사람 미확인'이 많다(11/15 실제 차 안 목소리 조각 118개: 절대 기준 0.85 → 맞힘 55 · 틀림 14 · 모름 49). 조회 응답이 `floor`(기본 0.6)·`margin`(기본 0.06)을 함께 주고, 차는 후보가 둘 이상이면 가장 비슷한 사람이 `floor` 이상이고 두 번째 사람보다 `margin` 이상 앞설 때만 붙인다(같은 조각에서 69 · 12 · 37). 발화의 좌석 줄과 다른 줄에 앉은 사람이면 붙이지 않고, 후보가 한 명이면 `threshold`를 쓴다. 값은 녹음 하나로 고른 것이라 환경 변수(`VOICE_MATCH_FLOOR`·`VOICE_MATCH_MARGIN`)로 둔다. 학습된 모델 없이 더 나아지기는 어렵다(같은 조각을 공개 화자 모델로 대조하면 거의 다 가린다 — 제출 뒤 과제). 서버의 `/voice-match`(구버전 APK·웹 입력)는 절대 기준 그대로다.
- **같은 값.** 임베더는 `providers/voice.js`(이름 `logmel-pitch-1`, 112차원)이고, 차량 구현은 `backend/api/voice-vectors.json`(정수 연산으로 만든 입력 신호 여섯과 출력 벡터, 허용 오차 1e-6)으로 서버와 맞춘다. 서버 시험(`voice-vectors.test.js`)이 같은 파일을 본다. 값 등록은 이름과 모양(길이, 묶음별 평균 0·길이 1)을 본다 — 다른 수식의 값이 섞이면 조용히 '모름'이 늘기 때문이다.
- **대조 값은 민감정보다.** 조회 응답은 저장되지 않게 하고(`private, no-store`), 동의가 꺼진 참가자의 값은 서버에서 지워져 조회에도 나오지 않는다. 받은 쪽의 사본을 지우는 때는 ADR-0023 3절.

## 기록본과 프로필 피드 (T39)

| 요청 | 하는 일 |
|---|---|
| `GET /api/trips/:code/transcript?v=버전` | 기록본. 발화를 시간순으로, 부탁과 도착 할 일과 함께. 여행 버전(`v`) 규칙은 기존 여행 읽기와 같다 |
| `GET /api/profiles/me/feed` | 프로필 토큰으로 자기 피드. 지워지지 않은 여행의 자기 발화와 사람이 장면으로 남긴 것을 여행을 가로질러 최신순으로(각 100줄까지. 장면은 여행이 지워져도 남는 것 — ADR-0014의 '복사') |

- 발화는 시간이 지났다는 이유로 지우지 않는다(T90, `backend/api/retention.md`). 동의 철회·자기 글 지우기·여행 삭제 때 지운다. 사람이 고른 장면은 프로필로 복사해 여행이 지워져도 남는다(기준 문서: '선택한 장면만 개인 앨범에').
- 프로필 주인의 자기 발화 지우기: `DELETE /api/trips/:code/utterances`(참가자 토큰, 프로필로 참가한 사람만). 자기 이름이 붙은 발화만 지우고 동의 세대는 올리지 않는다(T39).
- 다른 가족의 말이 섞인 장면: 앨범에는 장면의 시각·위치·이름표만 복사하고 발화 글자는 복사하지 않아 남지 않는다(T39, ADR-0014).

## 장면 후보와 숏폼 (T43, 구현됨)

후보는 규칙으로 고르고(LLM 없음, Claude API 계약 전) 사람이 고른다(ADR-0007). 확정한 장면은 이미 있는 `POST /api/trips/:code/moments`로 남긴다 — 새 경로를 만들지 않는다. 계약 원본은 `openapi.yaml`이다.

| 요청 | 하는 일 |
|---|---|
| `GET /api/trips/:code/scene-suggestions` | 각 발화에서 시작하는 30초 창의 발화 수 + 2 × (말한 사람 수 − 1)로 점수를 매기고(말한 사람은 좌석 구역으로 셈, 발화 4개 미만 제외), 이미 남긴 장면과 겹치지 않는 창을 서로 겹치지 않게 최대 5개, 시각 순으로: `{ items: [{ at, from, to, why, score, lines(30줄까지), lat?, lng? }] }`. 구간 15~35초. 요청할 때만 계산. 차량 앱의 `Scenes.kt`가 같은 규칙이고 두 구현은 `backend/api/scene-vectors.json`으로 맞춘다(T144) |
| `POST /api/trips/:code/moments` | 고른 후보의 `at`·`from`·`to`를 남긴다. `from`·`to`는 선택 칸(`from ≤ at ≤ to`, 1~60초)이고 차(T63)가 이 구간을 잘라 클립으로 올린다. **구간이 없는 장면(차에서 바로 표시한 것)은 `at` 앞 20초~뒤 10초로 본다 — 차도 이 기본 구간으로 자른다** |
| `GET /api/trips/:code/shortform` | 클립이 올라온 장면마다 소리 주소(`/api/trips/:code/recordings/:id`, 같은 출처, ADR-0021)·자막 큐(클립 안의 초, 글, 말한 참가자, 좌석 구역)·출연(이름, 캐릭터, 자리). 이 응답은 영상 파일이 아니다. 영상 파일은 기기가 이 데이터로 만들거나, 꺼 둔 서버 생성(`short-generation.md`)이 만든다(ADR-0022). 자막 큐 계산(`scenes.js` `cues`)은 차량 앱이 재생에 쓰려고 같은 규칙으로 차 안에서도 하며, 두 구현은 `backend/api/cue-vectors.json`으로 맞춘다(T144) |

- 셋 다 녹음에 동의한 참가자만 읽는다(기록본과 같은 규칙, 받아 적은 글이 들어감).
- 자막 큐는 발화의 `at`을 말 시작으로 보고, `endAt`가 있으면 실제 끝 시각과 겹침을 보존합니다. 클립 이전에 시작한 구간도 겹치면 포함하고 클립 양끝에서 자릅니다. `endAt`가 없는 기존 발화만 글자 수로 끝을 어림합니다(글자당 0.15초, 1~6초). 다음 자막에서 자르되 1초는 남기고, 클립 끝은 넘지 않습니다.
- 말한 사람은 화자 대조(T38)로 붙은 프로필의 참가자만 채운다. 못 붙였으면 좌석 구역만 준다 — 자리만으로 이름을 붙이지 않는다(`frontend/spec/after-trip.md`).
- 웹은 9:16 재생 페이지(`clip`을 참가자 토큰 머리말로 `fetch` → blob → `<audio>`, 자막·캐릭터를 그 위에), 차는 같은 데이터로 그 자리에서 재생한다(머리말 인증, web·car-ui). 기기는 같은 데이터로 영상 파일도 만든다(ADR-0022). media 하위 도메인은 없다(ADR-0021).

**위치 없는 장면의 저장.** 후보에 좌표가 없어도 확정할 수 있게 moments 계약을 확장한다(ADR-0007): `lat`·`lng`는 둘 다 있거나 둘 다 없음만 허용. 위치 없는 장면은 목록에 저장·재조회되고 지도에는 나오지 않는다. 좌표가 없다고 0,0을 채우거나 다른 장면의 좌표를 옮겨 적지 않는다. 이 확장은 구현 PR에서 openapi·서버·테스트·T18에 함께 반영한다.

## 원음 클립 — 확정 장면만 (T76, 구현됨)

차가 사람이 장면으로 확정한 구간을 잘라 올리는 경로다. (11/14) 주차 뒤 여행 전체 음성을 올린 여행은 서버가 장면 클립을 자르므로(아래 '여행 전체 음성', ADR-0024) 이 경로는 전체 음성이 없을 때의 대체 경로로 남는다. 계약 원본은 `openapi.yaml`의 `/recordings`이고, 여기에는 흐름만 적는다.

| 요청 | 본문 | 하는 일 |
|---|---|---|
| `POST /api/trips/:code/recordings?moment=<장면 id>&generation=<세대>&from=<클립 시작 epoch ms>` | `audio/wav`(16 kHz·16비트 PCM·모노, 5,000,000 B까지) | 차가 자른 WAV를 다시 자르지 않고 클립 버킷에 둔다. 클립 구간은 그 장면의 구간 안이어야 한다(앞뒤 1초 여유, 밖이면 400). 장면 하나에 클립 하나라 클립 id는 장면 id다. 같은 장면을 다시 보내면 저장하지 않고 200. 옛 세대(철회 전 소리)와 사람이 지운 클립은 409 |
| `GET /api/trips/:code/recordings/:id` | | 받은 WAV를 그대로, `Cache-Control: private, no-store`. 토큰은 머리말로만 — 웹은 `fetch` → blob → `<audio>`(클립 하나 약 0.5~1.1 MB, 15~35초). 서명한 S3 주소를 주지 않고, 별도 media 주소도 두지 않는다(ADR-0021, ADR-0020은 대체됨) |
| `DELETE /api/trips/:code/recordings/:id` | | 버킷에서 바로 지우고 지운 표시를 남긴다(차가 다시 올려도 409). 받아 적은 글과 장면은 남는다(지우려면 각자의 삭제 경로) |

- **저장.** 클립 전용 S3 버킷(`CLIPS_BUCKET`, 서울, 버전 관리 끔, SSE-S3, 공개 차단 — 버킷과 역할은 T64가 만듦)에 `<여행 코드>/<장면 id>-<임의>.wav`로 둔다. 정보(장면·세대·크기·길이·지운 표시)는 trips DB의 `recordings` 표. 서버는 AWS SDK의 기본 자격 체인(서비스 계정 역할)으로 쓰고 손으로 서명하지 않는다(`providers/clips.js`). 버킷이 없는 환경은 클립 API가 503이다.
- **지우는 길.** 사람의 지우기는 바로(버킷에 닿지 못하면 503, 다시 하면 됨). 녹음 동의 철회(켜져 있던 동의를 끔)는 그 여행의 클립을 모두 지운다. 시간이 지났다는 이유로는 API가 지우지 않는다(T90). 철회는 여행 줄을 잠근 채 S3를 기다리지 않도록 같은 트랜잭션에서 지울 키(`clip_trash`)만 적고 커밋 뒤에 버킷에서 지운다. 실패하면 키가 남아 10분마다 다시 한다. **주의:** 클립 버킷의 수명 규칙(테라폼 `expire-clips`, 올린 뒤 2일을 다음 UTC 자정으로 올려 만료 — 최대 약 3일)은 T90 뒤에도 `backend/infra/terraform/persist/main.tf`에 남아 있다. 버킷에 적용돼 있으면 소리는 그때 지워져 보관 정책과 어긋난다(#398에서 확인·수정, 실제 버킷 상태는 확인하지 않음). 사람이 지운 표시는 동의 철회 뒤에도 여행이 지워질 때까지 남아, 다시 동의해도 그 장면의 클립을 다시 받지 않는다. 버전 관리를 끈 버킷이라 지운 뒤 남는 버전이 없다.
- **차가 할 일(T63).** `400`·`404`·`409`·`413`이면 그 클립을 버리고, `401`(다시 참가해 토큰을 받음)·`403`·`503`이면 나중에 다시 보낸다. 차 안에 암호화해 둔 원음과 보내지 못한 클립 큐를 지우는 것은 차의 몫이다(T63·T69).

원음 클립에는 시간 만료가 없다(T90, 위 버킷 수명 규칙의 불일치는 #398). 장면 앨범에는 장면의 시각·위치·이름표가 남는다(T39).

## 여행 전체 음성 (ADR-0024, T132, 구현됨)

11/14 오너 결정("전체 음성 올리기"): 여행을 마치고 주차하면 차가 그 여행의 원음 전체를 조각으로 올린다. 서버는 클립 버킷에 하나로 두고, 고른 장면의 클립을 그 안에서 잘라 쓴다. 계약 원본은 `openapi.yaml`의 `/audio`이고 여기에는 흐름만 적는다.

| 요청 | 본문 | 하는 일 |
|---|---|---|
| `POST /api/trips/:code/audio/start` | `{generation, expectedBytes, seconds, startedAt}` | 전체 크기(짝수 바이트, 8시간 = 921,600,000 B까지)·길이·첫 표본의 시각(epoch ms)을 알린다. 같은 값으로 다시 부르면 받은 조각을 그대로 둔다. 다른 값이면 새로 올리기를 열고 받던 조각을 버린다. 응답은 `GET /audio`와 같은 상태 |
| `PUT /api/trips/:code/audio/parts/:n?generation=G` | `application/octet-stream`: 16 kHz 모노 s16le PCM(머리 없음, 짝수 바이트, 4 MiB = 4,194,304 B까지) | 조각 하나. `n`은 0부터(0~9999). 같은 `n`은 덮고 순서는 상관없다. `201 {n, bytes}` |
| `POST /api/trips/:code/audio/complete` | `{generation, parts, seconds, sha256}`(start를 안 불렀으면 `startedAt`도) | 조각 `0`~`parts-1`을 순서대로 이어 sha256을 세며 객체 하나로 두고(8 MiB가 넘으면 S3 멀티파트) 조각을 지운다. `200 {state: "ready", seconds, bytes, startedAt}`. 같은 sha256으로 다시 부르면 `200` |
| `GET /api/trips/:code/audio` | | `{state: none·uploading·ready, receivedParts, receivedBytes, expectedBytes?, seconds?, progress(0~1), generation?, startedAt?, partNumbers?, previous?, deleted?}`. 폰(P22)과 차(C22)가 진행률을 읽는다 |
| `DELETE /api/trips/:code/audio` | | 전체 음성·받던 조각·전체 음성에서 자른 장면 클립을 지우고 표시를 남긴다. 그 세대의 전체 음성은 다시 받지 않는다. `204` |

- **장면 자르기.** 차가 장면 클립을 올리지 않은 장면은 `GET /recordings/:momentId`가 장면 구간(`from`~`to`, 없으면 `at` 앞 20초~뒤 10초)과 전체 음성이 겹치는 곳의 바이트 범위만 읽어(S3 Range, 시각 1 ms = 32 B) WAV 머리를 붙이고 일반 클립 줄로 남긴 뒤 준다(`recordings.cut_from_audio`). `GET /shortform`도 읽기 전에 클립이 없는 장면(최대 20개)을 같은 방법으로 자른다. 숏폼·재전사(T75)·내보내기(T107)·클립 지우기는 차가 올린 클립과 같은 길이다. 겹치는 곳이 장면 구간의 절반에 못 미치면 자르지 않는다(`404`). 동의하지 않은 탑승자가 있으면 자르지 않는다. 사람이 지운 장면은 다시 자르지 않는다.
- **장면 후보.** 전체 음성이 다 올라와 있으면 `GET /scene-suggestions`는 그 소리가 후보 구간의 절반 넘게 덮는 후보만 준다(자르기와 같은 기준). 화면은 점수 상위 셋을 추천으로 보인다.
- **차가 할 일(K2).** 주차하면 `start` → 조각 → `complete`. 끊기면 `GET /audio`의 `partNumbers`를 보고 빠진 조각만 다시 보낸다. `409`면 옛 세대·지운 음성이라 차 안 사본을 버리고(sha256 틀림은 같은 올리기에 조각을 처음부터 다시), `401`(다시 참가)·`403`(동의하지 않은 탑승자)·`429`(합치는 중·바쁨)·`503`이면 나중에 다시 한다. `400`·`413`이면 이 여행은 장면 클립 올리기로 돌아간다. **`ready`를 받을 때까지** 차 안의 암호화한 원음을 지우지 않고, 받으면 지운다.
- **보관과 삭제(11/15 01:20 오너 결정 "Expire after 2 days").** **여행 전체 음성은 다 올린 뒤 2일, 서버의 치우기(10분마다)가 지운다. 장면 클립은 사람이 지울 때까지 남는다.** 버킷에는 시간 규칙이 없다(T145). 전체 음성은 `<여행 코드>/trip-audio/` 아래에 따로 둔다. 2일이 지났거나 버킷에 없으면(404) `GET /audio`에 `state: "expired"`(`expiresAt`)를 주고 장면을 새로 자르지 않는다 — 그 뒤 장면 소리는 장면 클립 경로만(있으면 그 클립, 없으면 404, 500 없음). 그 전에는 사람의 행동으로 바로 지운다: 녹음 동의 철회(세대 오름 — DB 트리거가 같은 트랜잭션에서 지울 키를 `clip_trash`에 적음), 여행 줄 삭제(트리거), `DELETE /audio`. 버킷에서는 커밋 뒤에 지운다.
- **개인정보.** 여행 전체의 가족 목소리(아이 포함)가 우리 클립 버킷에 남는다. 전체를 내려받는 경로는 없고 장면 구간만 녹음에 동의한 참가자에게 API로 준다(서명 주소 없음). 외부 ASR로 가는 소리는 지금처럼 고른 장면의 클립뿐이다(T75).
- **크기.** 32,000 B/s ≈ 115 MB/시간. 여행 100개 × 1.5시간 ≈ 17 GB, S3 서울 저장 약 $0.43/월(ADR-0024 5절).

## 재전사 — 고른 장면 클립의 자막 (T75, 구현됨)

숏폼 자막에 Pleos STT 원문을 그대로 쓰면 이름·호칭이 자주 틀린다(합성 가족 대화 2구간 56쌍에서 36.4%). 그래서 **사람이 고른 장면 클립만** 상현님 Nemotron ASR(`nemo_transcribe30`, 연동 가이드 v1.0)로 다시 받아 적는다. 원음이 차 밖으로 나가는 범위가 가장 좁은 자리다(클립은 어차피 서버에 올라옴, T76).

- **언제.** 클립이 새로 올라오면(`POST /recordings` 201) 서버가 기다리지 않고 돈다. `ASR_URL`·`ASR_TOKEN`이 둘 다 있을 때만 — 없으면 건너뛰고 원문 자막을 쓴다. 파드마다 한 클립씩 차례로 돈다. 대기열은 클립 id만 쥐고(10개, 넘치면 `clip_retranscribe_dropped`) 소리는 돌 때 클립 버킷에서 읽는다. 발화 묶음이 클립보다 늦게 오면(차가 끊겼다 이어짐 등) 그 묶음을 받은 뒤 클립 구간에 새로 들어온 줄로 다시 예약한다. 클립마다 '여기까지 봤다'(`asr_done_at`)를 남겨, 다음 실행은 그 뒤에 들어온 줄만 보낸다 — 고치지 못한 줄을 되풀이해 보내지 않는다.
- **보내는 것.** 실제 `endAt`가 있는 발화는 `[at, endAt]`와 클립이 겹치는 원음만 16 kHz 모노 WAV로 보냅니다(T110). 클립 이전에 시작한 발화와 클립 뒤에서 끝나는 발화는 클립 양끝에서 자르며, 겹친 다른 화자의 시작 시각 때문에 줄이지 않습니다. 실제 구간을 늘려 만들지 않고, 잘라 남은 길이가 0.8초보다 짧으면 보내지 않습니다. `endAt`가 없는 기존 APK 발화만 발화 시각 0.5초 앞부터 같은 자리의 다음 말까지 어림합니다. 이때 글자당 0.15초·1.5초 이상의 길이를 남기되 앞 0.5초를 포함해 15초·클립 끝을 넘지 않습니다. 소리와 함께 그 발화의 원문 초안, 여행이 아는 낱말(참가자 이름, 흔한 호칭, 목적지인 여행 제목, 호출어 글레오)을 보냅니다. 지시는 '한국어로, 번역하지 말 것', '다른 인식기의 초안, 틀릴 수 있음'이며 `temperature 0`, `enable_thinking false`, `skip_special_tokens false`, `max_tokens`는 초안 글자 × 3 + 64, 512 이하입니다. 원문 보존·수동 편집 우선순위는 유지합니다.
- **저장.** 고친 글은 발화 줄의 `asr_text`에, 원문(`text`)은 그대로 둔다. 숏폼 자막 큐는 `text`(고친 글, 없으면 원문)와 `raw`(원문)를 함께 준다. 기록본(`/transcript`)의 발화에도 `asrText`가 있을 때만 붙는다. 자기 글 지우기·동의 철회는 원문과 함께 지운다.
- **되돌아감.** 제한 시간(10초, `ASR_TIMEOUT_MS`)·연결 실패·오류, 429가 네 번(처음 + 1·2·4초 뒤 다시), 빈 답, 믿지 못할 답(초안과 공백·문장부호를 뺀 글자가 절반 넘게 다름 — 짧은 말도 같은 기준, 또는 초안에 없던 12자 넘는 되풀이)이면 그 줄은 원문 자막으로 남는다. **보내기 직전마다**(간격을 기다린 뒤와 429 뒤에도) 클립이 살아 있고 동의 철회 전 세대이며 그 줄의 글이 그대로인지 본다 — 아니면 보내지 않는다. 답을 붙일 때도 같은 조건을 본다. 요청 간격은 파드마다 1.1초(`ASR_GAP_MS`, 파드 둘이 한 IP로 나가므로 합쳐 초당 2건 아래), 429면 그 파드의 다음 요청 모두가 물러선다.
- **관측.** 클립마다 로그 `clip_retranscribed`(줄 수, 고친 줄, 되돌아간 줄과 그 이유별 수 `reasons` — `timeout`·`unreachable`·`http_NNN`·`bad_response`·`empty`·`suspicious`·`short`·`stopped`, 원문과 글자가 달라진 줄, 걸린 시간). 글과 토큰은 남기지 않는다. 토큰이 틀리면 `http_401`로 보인다.
- **측정(11/14, 이 모듈로).** 2구간 56쌍을 `providers/asr.js`로 다시 보냄(정답 대본 시각 ±0.3초로 자름, 모노, 위 판정 모두 켬): 이름·호칭 36.4% → 72.7%(목표 60% 이상), 원래 맞던 29문장 중 틀리게 바꾼 것 0(목표 2% 이하), 글자 오류율 11.17% → 7.77%(나빠지지 않음), 되돌아감 0/56, 문장 하나 중앙값 0.54초(간격 0.55초로 잼). 기록은 저장소 밖 `research/evidence/20261114-asr-nemotron/server-path-T75/`. 합성 음성이고, 서비스는 Pleos 발화 시각으로 자르므로 실제 값은 다를 수 있다(재지 않음).
- **개인정보.** 고른 장면 클립의 원음(가족 목소리, 아이 포함)과 그 구간의 받아 적은 글(초안), 참가자 이름·여행 제목이 우리 서버 밖(상현님 회사 GPU 서버)으로 나간다. T12의 '외부로 보내지 않는다'는 이 하나의 예외를 두고, 아래 동의 문구에 밝힌다. 연동 가이드 7절: 전 구간 TLS, 게이트웨이는 요청 메타데이터만 남기고 오디오 본문은 기록하지 않음. **모델 서버의 보관 여부는 확인되지 않아 동의 문구에 '남기지 않는다'를 쓰지 않았다** — 상현님이 글로 확인해 주면 더한다. 계속 운영·장애 연락도 상현님 확인(사람 몫). 토큰은 비밀 값으로만 둔다.

## 동의 문구(기록 동의에 더하는 글)

> 대화는 차에서 받아 적힙니다. 녹음은 기본 꺼져 있고, 참가자 모두가 동의할 때만 켭니다. 받아 적은 글과 여행 기록은 기간 제한 없이 보관합니다. 기록 동의를 끄면 이 여행의 받아 적은 글과 서버에 올린 소리를 지웁니다. 장면을 고를 수 있게 소리는 차 안에 암호화해 보관합니다. 차에서 원음을 직접 지우거나 기록 동의를 끄면 지웁니다. 여행을 마치고 주차하면 장면을 고를 수 있게 이 여행의 소리 전체가 서버로 올라가고, 다 올린 뒤 2일이 지나면 지워집니다. 콘텐츠는 고른 장면으로만 만들고, 소리 전체는 외부로 보내지 않습니다. 고른 장면의 소리는 지울 때까지 남습니다. 고른 장면으로 AI 쇼츠를 만들 때는 만드는 사람이 한 번 더 확인한 뒤 그 장면의 받아 적은 글(이름은 빼고)과 캐릭터 그림을 OpenAI(미국)로 보내 장면 그림을 그립니다. 소리는 보내지 않고, 아이의 글은 보호자 동의 범위에서만 보냅니다. 자막을 바로잡으려고 그 구간의 소리와 받아 적은 글, 참가자 이름을 외부 음성 인식 서버로 보내 다시 받아 적습니다. 누가 말했는지는 차 안에서 가립니다. 이전 버전의 차량 앱과 웹 입력에서는 이를 위해 말소리가 잠시 서버로 갔다가 저장되지 않고 지워집니다. 등록한 목소리는 화자를 가리는 값으로만 바뀌어 서버에 저장되고, 동의를 끄면 지워집니다. 프로필로 참가한 사람은 자기 이름이 붙은 글을, 참가자 누구나 장면으로 남긴 소리를 바로 지울 수 있습니다. 동의는 여행 중 언제든 끌 수 있고, 끄면 이 여행에서 그때까지 받아 적은 글과 올라간 소리가 모두 지워집니다.

(11/15, T157) AI 쇼츠 문장은 [ADR-0025](../adr/0025-shorts-generation-worker-codex-skill.md) 3절이다. OpenAI로 가는 것은 고른 장면의 받아 적은 글(참가자 이름은 캐릭터 번호로 바꿈)과 앱에 든 캐릭터 그림이고, 원음은 운영자 맥의 생성 일꾼에서 합치기만 한다. 만드는 요청마다 `externalGenerationConsent: true`와 동승자 전원 녹음 동의가 필요하다. 아이는 보호자가 동의해 참가시킨 범위 안에서만 들어간다. 웹 `CONSENT`는 같은 문장을 프론트 PR에서 더하고, 차 C03은 차 열차에서 맞춘다.

(11/14, T126 뒤) 화자 문장은 ADR-0023 8절의 전환기 글이다. 웹은 같은 문장을 쓴다.

(11/14) 지우는 길의 문장은 실제 경로에 맞췄다: 손님의 발화에는 프로필이 붙지 않아 '자기 글'을 가려낼 수 없으므로, 글 지우기는 프로필로 참가한 사람의 `DELETE /utterances`, 소리 지우기는 참가자 누구나의 `DELETE /recordings/:id`, 그리고 누구든 동의를 끄면 그 여행의 글과 소리가 모두 지워진다(세대 올림). 웹은 같은 문장을 쓴다(web 세션, #179).

보관에는 시간 제한이 없다(T90, `backend/api/retention.md`). 지우는 것은 사람의 요청뿐이다: 원음 지우기, 자기 글 지우기, 동의 철회, 프로필·여행 삭제. 위 문구는 웹 화면(`frontend/web/app.js`의 `CONSENT`)과 글자까지 같다. 원음 삭제(지난 것을 지움)와 녹음 동의 철회(앞으로를 멈춤)는 다른 요청이고, 화면에서도 구분해 말한다. 목소리 대조 값(T38)을 등록할 때의 고지는 T38에서 이 문구와 맞춘다.

**전체 음성으로 바뀜(ADR-0024 7절, 11/15).** 차가 전체 음성을 올리기 시작해(#439) 위 문구의 '장면으로 남기면 그 구간의 소리가 서버로 올라갑니다.'를 전체 소리·2일 보관 두 문장으로 바꿨다(웹 `CONSENT`와 차 C03, #461). 아래는 바꾸기 전에 적어 둔 계획이다. 차가 전체 음성을 올리기 시작하는 판과 같은 판에서 차·웹의 문구를 바꾸고(프론트 PR), 차는 바뀐 문구로 동의를 받은 여행에서만 전체 음성을 올린다. 바꿀 문장(안): '여행을 마치고 주차하면 장면을 고를 수 있게 이 여행의 소리 전체가 서버로 올라가 저장됩니다. 콘텐츠는 고른 장면으로만 만들고, 소리 전체는 밖으로 내보내지 않습니다. 소리 전체는 참가자 누구나 지울 수 있고, 동의를 끄면 함께 지워집니다.' 재전사(T75) 문장과 화자 식별의 전환기 문장(ADR-0023 8절)은 그대로 둔다.

폰에서는 수음하지 않는다(11/13, ADR-0008). 발화를 올리는 기기는 차량 앱뿐이고, 폰 웹앱은 프로필·초대·참가와 동의·부탁·기록본 보기를 맡는다.

## 남은 것

- **전체 음성(ADR-0024).** 차량의 주차 뒤 올리기·진행률·`ready` 뒤 차 안 사본 지우기(K2), 폰의 진행률(P22, W2), 동의 문구 교체(위 '전체 음성으로 바뀔 때'). 인프라: API 역할의 `s3:AbortMultipartUpload`, 긴 여행 `complete`를 위한 로드 밸런서 유휴 제한.
- **화자 식별을 차 안으로 옮김([ADR-0023](../adr/0023-speaker-identification-on-device.md)) — 끝남.** 서버 계약(T125·T129)과 차량 구현(T126)이 들어갔다. 새 차량 앱은 대조 값을 받아 차 안에서 가리고 화자를 발화와 함께 올리며, 목소리 등록도 값만 올린다. 위 동의 문구의 화자 문장은 ADR-0023 8절의 전환기 글이다 — 구버전 차량 앱과 웹 입력이 소리를 보내는 동안에는 그 문장을 빼지 않고, `/voice-match`를 닫을 때(ADR-0023 7절) 가운데 문장을 뺀다. 대조 값과 그 조회에는 시간 만료가 없다(T90, `backend/api/retention.md`).
- 차량 앱의 수음·발화 송신·좌석 판정·Gleo 넘겨주기(T36, T37, T41, 지환).
- Pleos STT의 사람 목소리·소음 정확도 재측(T36 실측 뒤) — 모자라면 받아쓰기 위치 다시 검토.


### 수동 자막 수정 (T80)

기록본의 `text`는 Pleos 원문, `asrText`는 자동 재전사 결과입니다. 폰에서 표시할 글은 `displayText`이며 수동 `editedText` → `asrText` → 원문 순입니다. 숏폼 cue의 `text`도 같은 순서이고 `raw`는 원문입니다.

동의한 여행 참가자는 `PATCH /api/trips/:code/captions/:device/:seq`에 `{text, expectedVersion, generation}`을 보냅니다. `device`는 `encodeURIComponent`로 인코딩합니다. `text`는 trim 후 1~500자, `null`은 수동 수정본 초기화입니다. 초기 `editVersion`은 0이며 저장과 초기화가 모두 버전을 올립니다. 200 응답은 `{generation, utterance}`입니다.

같은 버전으로 저장한 둘 중 하나만 성공합니다. 버전·동의 세대 불일치는 409이며 기록본을 다시 읽고 사용자가 글을 재확인해야 합니다. 없는/삭제한 발화와 만료 여행은 404, 미동의는 403, 다른 여행·누락 토큰은 401입니다. 마지막 편집 참가자 id(`editedBy`)와 시각(`editedAt`, epoch ms)만 보관하고 수정 이력은 쌓지 않습니다. 늦은 ASR 결과는 수동본이나 버전을 바꾸지 않습니다. 자기 글 삭제·동의 철회는 수정본과 편집 메타데이터에도 그대로 적용됩니다.

마이그레이션은 nullable 칸과 기본 버전 0을 추가합니다. 구 이미지와 함께 돌거나 되돌린 뒤에도 원문을 비우는 기존 삭제 SQL이 수정본을 남기지 않도록 DB 트리거가 편집 칸을 함께 비웁니다. 이전 이미지는 원문을 계속 읽지만 수동 수정 UI/API는 제공하지 않습니다.
