# 장소 기록과 내 여행·콘텐츠 목록

2026-11-14(T131, 읽기 권한은 T136, 장면 자막·여행 하나 읽기는 F6). 최종 디자인의 '콘텐츠 기록'(C33–C38/P33–P38: 갤러리, 타임라인, 지도, 지도에서 고른 장면, 플레이어)과 폰의 '곧 도착'(P19)을 서버 계약으로 옮긴 문서입니다. 경로와 모양은 [`openapi.yaml`](openapi.yaml)이 기준입니다.

## 장소: 차가 내비에서 읽은 이름

차는 내비의 상태가 바뀔 때 `POST /api/trips/{code}/places`에 그 여행의 참가자 토큰으로 `{kind, name, lat?, lng?, at?, etaSeconds?}`를 보냅니다. 서버는 여행 문서 안에 쌓고, **녹음에 동의한 참가자만** `GET /api/trips/{code}/places`(참가자 토큰)와 기록본 `GET /transcript`의 `places`로 읽습니다. 동의하지 않은 참가자는 403입니다. 토큰 없이 읽는 여행 문서(`GET /trips/{code}`)에는 싣지 않습니다 — 가족이 어디로 가고 어디에 닿았는지를 여행 코드만 아는 사람과 서비스 워커 캐시에 내주지 않게(도착 장소 T119와 같은 규칙, T136). 장소가 없는 여행은 빈 목록입니다.

`places`는 늘 **`at` 순서**입니다(같은 `at`이면 받은 순서, `at`을 보내지 않으면 서버가 받은 시각). 통신이 끊겼다가 늦게 올라온 장소도 제 시각 자리에 들어가므로, 10:00의 '곧 도착'이 10:05의 '도착'보다 늦게 와도 '도착'을 덮지 않습니다. **지금 상태는 `at`이 가장 큰 장소(목록의 마지막)**입니다. 여행 하나에 200개까지 두고, 넘으면 `at`이 가장 이른 것부터 버립니다(새로 받은 것이 모두보다 이르면 그것이 바로 밀려나도 201).

| `kind` | 언제 |
|---|---|
| `start` | 출발(주행 시작 때의 위치) |
| `destination` | 내비에 목적지를 정하거나 바꿈 |
| `stop` | 경유지에 들름 |
| `approaching` | 곧 도착(내비 남은 시간 5분 이하, `etaSeconds`와 함께) |
| `arrived` | 도착 |

- 쓰기는 녹음 동의와 관계없습니다(차가 내비의 장소를 남김). 읽기는 동의한 참가자만입니다.
- 폰은 `GET /places`를 다시 읽어 `at`이 가장 큰 장소(마지막)가 `approaching`이면 '곧 도착'을 보여 줍니다.
- 여행 문서에 `startedAt`(처음 주행을 시작한 시각)과 `endedAt`(끝낸 시각, 다시 출발하면 지움)도 남깁니다.

## 내 여행과 콘텐츠

`GET /api/profiles/me/trips`(프로필 토큰)는 내 프로필이 참가자로 있는 여행을 최신 순으로 50개까지 줍니다. 여행마다 다음이 들어 있습니다.

| 칸 | 내용 |
|---|---|
| `members` | 참가자 id, 이름, 캐릭터(프로필의 지금 값, 없으면 참가할 때의 값), 자리. 프로필 참가자는 `profileId` |
| `places` | 위의 장소 기록(그 여행에서 내가 동의했을 때만) |
| `route` | 좌표 있는 발화를 시간순으로 골고루 줄인 `[lat, lng, at]`, 200점까지(첫 점·끝 점은 남김) |
| `contents` | 서버 보관을 마친 기본 영상(`device`)과 생성을 마친 영상(`generated`) 가운데 **지금 원본(원음·자막·화자)과 같은 것만**(T162 — 원본이 바뀐 영상은 파일이 409라 목록에 두면 눌러도 열리지 않았음). 제목·시각·좌표는 그 장면, 장면 제목이 없으면 여행 제목. `place`는 그 시각 전에 남은 마지막 장소 이름 |
| `groupName` | 그룹으로 만든 여행일 때 그 그룹 이름(그룹 API), 아니면 null |
| `groupId` | 그룹으로 만든 여행일 때 그 그룹 id, 아니면 null(T162) |
| `recording` | 지금 기록 중인지(T162) |
| `me` | 이 여행에서의 나: `{participantId, seat, consent}`(T162). 참가자 토큰은 싣지 않는다 |

**진행 중 여행만 가볍게(T165).** `GET /api/profiles/me/trips?status=active`는 끝나지 않은(`ended`가 아닌) 여행만 같은 모양으로 주고, `places`·`route`·`contents`는 셈하지 않아 빈 목록입니다. 폰 처음 화면처럼 자주(몇 초마다) 읽을 때 씁니다. 다른 `status` 값은 400입니다.

**폰이 그룹 여행을 이어 타는 길(T162).** 차가 그룹으로 여행을 만들면(groups.md) 다른 성인의 폰에는 토큰이 없습니다. 폰은 이 목록에서 `status`가 `ended`가 아니고 `groupId`가 내 그룹인 여행을 찾아, 그 폰에 참가자 토큰이 없으면 프로필 토큰으로 `POST /api/trips/{code}/participants`(본문 없음, `seat`를 보내도 무시)를 불러 있던 참가자(`me.participantId`, 자리·동의 그대로)와 새 토큰을 받습니다.

콘텐츠 하나에는 `from`·`to`(장면 구간, 없으면 장면 시각 앞 20초~뒤 10초), `cast`(그 구간에서 말한 사람, 화자를 확인한 줄만, 처음 말한 순서 — 갤러리 타일과 플레이어의 캐릭터), `lines`(그 구간의 발화 30줄까지 `{at, participantId, name, text}` — 플레이어의 자막 줄, 화자를 모르면 이름 없이)도 있습니다(F6). 글은 고친 글 → 다시 받아 적은 글 → 원래 글 순으로 고릅니다.

## 프로필 없는 기기: 이 여행 하나

`GET /api/trips/{code}/contents`(참가자 토큰)는 위 목록의 항목 하나와 **같은 모양**으로 이 여행의 구성원·장소·경로·콘텐츠를 줍니다(F6). 프로필 토큰이 없는 차가 콘텐츠 기록을 그릴 때 씁니다. 기록본과 같이 녹음에 동의한 참가자만 읽고(동의 전 403, 토큰이 없거나 다른 여행이면 401), 영상 파일은 전원 동의 규칙을 따릅니다. 차에 계정 로그인이 들어오면(흐름 F1) 여러 여행은 `GET /profiles/me/trips`로 읽습니다.

`places`·`route`·`contents`는 기록본과 같은 규칙으로, **그 여행에서 내 참가자가 녹음에 동의했을 때만** 채웁니다(아니면 빈 목록). 경로와 콘텐츠는 지금 동의 세대의 것만 담습니다. 누가 동의를 끊어 세대가 오르면 그 전의 발화 좌표와 영상은 빠집니다(ADR-0007). 지도는 지도 제공자 없이 이 좌표를 화면에 투영해 그립니다(개편 계획 결정 5).

영상 파일(`url`)은 지금처럼 그 여행의 **참가자 토큰**으로 받고 전원 동의 규칙을 따릅니다([short-assets.md](short-assets.md)). 서버에 미디어 CDN 값이 있고 그 여행의 참가자 전원이 동의했으면 생성 영상(`generated`) 항목에 `mediaUrl`·`mediaAuth`(표지가 있으면 `thumbnailMediaUrl`·`thumbnailMediaAuth`)가 더해져 참가자 토큰 없이 CDN에서 받을 수 있습니다(T178, [short-generation.md](short-generation.md)의 'CDN 서명 주소'). 이 기기에 그 여행의 참가자 토큰이 없으면 프로필 토큰으로 다시 참가(`POST /api/trips/{code}/participants`)해 이 기기의 토큰을 받습니다. 목록은 원본이 바뀐 영상(`source_changed`)을 따로 거르지 않습니다 — 정리 작업이 1분 안팎에 지우고, 그 사이 파일을 받으면 409입니다.

## 하지 않은 것

지도 타일·장소 검색 같은 외부 지도 제공자, 장소 고치기·지우기, 50개 너머의 여행 넘겨 보기는 없습니다.
