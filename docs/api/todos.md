# 장소별 할 일과 도착 브리핑

현재 전사록에서 장소가 붙은 할 일을 읽고 완료·취소 상태를 함께 저장합니다. 웹과 차량이 같은 API를 사용할 수 있습니다. 차량의 기존 `Todos.kt` 연동은 별도 프론트 변경이며, 이 서버 변경만으로 차량 로컬 목록이 자동 동기화되지는 않습니다.

## 전사와 할 일의 연결

`GET /api/trips/{code}/todos`는 참가자 토큰과 기록 동의를 확인한 뒤 `{generation, method, items, arrival}`를 반환합니다. `method`는 `place-rules-v2`입니다(T141). 모델 추론이 아니라 규칙입니다. v1(차량 `Todos.kt`와 같음)은 ‘마트에서 우유 사자’, ‘숙소에서는 가방을 꺼내야지’처럼 장소 뒤 ‘에서’가 있고 권유·의무형(자·야지·야 돼)으로 끝나는 문장을 추출했습니다. v2는 여기에 ‘하나로마트 가면 …’, ‘숙소(에) 가서 …’, ‘… 도착하면 …’도 장소로 읽고, 끝에 ‘요’(가야 돼요)와 ‘급해’를 받습니다. ‘에서’가 있으면 v1처럼 그것만 보므로 v1이 뽑던 문장의 장소·글·id는 바뀌지 않고, 저장된 완료·취소 상태도 그대로입니다. 장소 없이 말하거나 복잡한 문장은 놓칠 수 있습니다.

할 일은 `{id,place,text,status,version,sources,category,title,items,requestedBy,method}`입니다(뒤의 다섯 칸은 v2 도착 브리핑을 위해 T141에서 더함, 아래 '행동 항목'). `sources`에는 원발화의 `device`, `seq`, `at`, `text`, `displayText`와 확인된 경우 `participantId`가 있습니다. 수동 교정본, 자동 교정본, 원문 순으로 읽고 원전사는 함께 남깁니다. 같은 장소와 문장은 하나로 묶고 출처 발화들을 모두 연결합니다. `GET /transcript.todos`에도 같은 목록이 들어갑니다.

내용이 바뀌면 ID가 바뀌고 새 확인 대상으로 나타납니다. 같은 내용의 발화가 다시 들어오면 이미 완료·취소한 항목을 되살리지 않습니다. 상태 표에는 원문을 복사하지 않습니다. 원발화를 삭제하거나 동의를 철회하면 그 발화에서 나온 항목도 목록과 브리핑에서 사라집니다. 동의 철회는 상태 행도 지웁니다. 48시간 제한은 없습니다.

## 행동 항목(v2 도착 브리핑, T141)

도착 브리핑(차 C20·폰 P20·최종 목적지 finalBrief)은 사람별이 아니라 분류별로 보입니다. 서버는 할 일마다 아래를 규칙으로 계산해 붙입니다. 읽을 때 전사에서 계산하고 저장하지 않습니다.

| 칸 | 규칙 | 예 |
|---|---|---|
| `category` | 화장실·먼저·급해 → `first`(먼저 할 일), 사다·사 가자·사 오자 → `buy`(잊지 말고 살 것), 챙기다·가져가다·내리다·꺼내다(앞에 물건이 있을 때) → `bring`(챙길 것), 나머지 → `remember`(잊지 말기). 앞의 것이 먼저 | ‘마트에서 물 먼저 사자’ → `first` |
| `title` | 끝(자·야지·야 돼·요)을 떼고 마지막 동사를 ‘…하기’꼴로(가 → 가기, 화장실이면 다녀오기, 챙겨 → 챙기기, 내려 → 내리기, ‘보관해’ → ‘보관’) | ‘숙소에서 체크인하고 가방 내려야 돼’ → ‘체크인하고 가방 내리기’ |
| `items` | 살 것·챙길 것: 동사 앞 말을 쉼표·‘그리고’와 낱말 끝 이음 조사(랑·이랑·하고·와·과)로 나눔. 받침으로 조사를 가림(‘사과’의 과, ‘노랑’의 랑은 그대로). 낱말 끝 은·는·을·를·부터·까지와 세 글자 이상의 도를 뗌. 먼저 할 일·잊지 말기: 동사를 뺀 말 하나. 물건을 말하지 않았으면 빈 배열 | ‘마트에서 삼겹살 600g이랑 귤 한 봉지 사 가자’ → `[{삼겹살, 600g}, {귤, 1봉지}]` |
| `items[].qty` | 숫자+단위(g·kg·개·병·봉지·팩·캔·마리, 그램·킬로는 g·kg로) 또는 한·두·세·네…열+단위를 ‘600g’·‘1봉지’·‘2병’으로. 그 밖의 단위(리터 등)는 지어내지 않고 이름에 남기며 `null` | ‘우유 1리터’ → `{우유 1리터, null}` |
| `requestedBy` | 출처 발화(`sources`)의 확인된 화자(`participantId`)를 중복 없이 처음 말한 순서로. 화자가 없으면 빈 배열 — 화면은 이름을 지어내지 않음 | |
| `method` | `place-rules-v2` | |

디자인의 문장으로 시험합니다(`backend/api/todos.test.js`): ‘하나로마트 가면 화장실 먼저 가야 돼’ → `first`·‘화장실 먼저 다녀오기’, ‘숙소에서 고기는 바로 냉장 보관해야 돼’ → `remember`·‘고기는 바로 냉장 보관’, ‘숙소 가서 가방 챙겨야지’ → `bring`·`[{가방}]`. 이모지는 클라이언트가 이름 낱말로 고릅니다(고기·삼겹살 🥩, 귤·과일 🍊, 젤리·간식·과자 🍬, 음료·탄산수·물·커피 🥤, 화장실 🚻, 장보기 🛒, 냉장·얼음 🧊, 가방·짐 🧳). `POST /arrival-briefing`의 `items`와 `GET /transcript`의 `todos`에도 같은 칸이 들어갑니다.

## 완료와 취소

`PATCH /api/trips/{code}/todos/{id}`에 `{generation,expectedVersion,status}`를 보냅니다. `status`는 `pending`, `done`, `cancelled` 중 하나입니다. 참가자 토큰이 필요하며 동의한 참가자가 변경할 수 있습니다. 응답은 `{generation,item}`입니다.

처음 `version`은 0이고 저장할 때마다 하나 올라갑니다. 두 기기가 같은 버전으로 저장하면 하나만 성공하며 다른 요청은 409입니다. 현재 세대와 다르면 409, 원문이 수정·삭제되어 해당 항목이 사라졌으면 404입니다. 클라이언트는 목록을 다시 읽고 사용자가 재확인하도록 해야 합니다.

## 도착 브리핑

`POST /api/trips/{code}/arrival-briefing`은 다음 입력을 받습니다.

```json
{
  "generation": 1,
  "place": {"name": "이마트 강릉점", "lat": 37.75, "lng": 128.9},
  "position": {"lat": 37.75, "lng": 128.9},
  "parked": true,
  "observedAt": 1794646800000,
  "source": "vehicle"
}
```

위 좌표와 시각은 형식 예시이며 실제 관측값으로 바꿔 보냅니다. 서버가 저장한 여행 상태도 `parked` 또는 `ended`여야 합니다. `parked=true`, 60초 이내 위치, 선택한 장소에서 250m 이내라는 조건이 모두 맞아야 `eligible=true`입니다. 미래 관측은 5초까지만 허용합니다. 장소 매칭은 차량과 같은 이름 포함 규칙이므로 ‘마트’는 ‘이마트 강릉점’에 대응합니다. 실제 장소의 정확한 ID 일치는 후속 작업입니다.

응답은 `{generation,eligible,reason,source,observedAt,place,distanceMeters,method,items}`입니다. `reason`은 성공 시 `null`, 조건 미충족 시 `not_parked`, `stale_position`, `outside_place`입니다. 조건이 맞아도 해당 장소의 미완료 항목이 없으면 `items`는 빈 배열입니다. 완료·취소한 항목과 다른 장소 항목은 제외합니다.

`source`는 `vehicle` 또는 `browser`이며 클라이언트가 전달한 근거 출처입니다. 서버가 실차 센서를 직접 확인하거나 GPS의 진위를 보증한다는 의미가 아닙니다. 브라우저에서 기어 신호나 차량 도착을 만들어 보내면 안 됩니다. 위치·장소·주차 상태를 실제 연결 경로에서 확보하지 못하면 전체 할 일 목록을 표시하고 자동 도착 브리핑으로 표현하지 않습니다. 이 API는 여행 상태를 바꾸거나 내비 명령을 보내지 않습니다.

### 도착한 장소를 폰이 읽는 길(T119)

폰은 내비의 장소 좌표를 모르므로 스스로 도착을 판정하지 않습니다. `eligible=true`가 나오면 서버가 그 장소의 `{place, at, source}`(이름·관측 시각·출처)만 여행에 남기고, `GET /todos`의 `arrival`로 알립니다. 좌표와 거리는 남기지 않습니다. 같은 장소를 다시 확인해도 처음 시각을 유지합니다.

`arrival`은 여행이 다시 `driving`이나 `boarding`으로 바뀌거나 동의 세대가 오르면 `null`이 됩니다. 토큰 없이 읽는 `GET /api/trips/{code}`에는 들어가지 않습니다. 폰은 `arrival.place`에 할 일의 `place`가 들어 있는 미완료 항목을 '지금 도착한 곳에서 할 일'로 보일 수 있습니다(브리핑과 같은 이름 포함 규칙). 이 값도 클라이언트가 보낸 관측에 대한 판정이며 실차 센서를 서버가 확인했다는 뜻이 아닙니다.

## 배포와 확인 범위

`trips-10-todos.sql`이 상태 표를 추가합니다. 이전 이미지가 읽는 전사·여행 문서의 모양은 바꾸지 않습니다. API·DB·동의·편집 경쟁·삭제·거리·관측 유효성을 로컬과 CI에서 검사하며 실차·에뮬레이터의 위치/기어 입력은 별도 검증해야 합니다.
