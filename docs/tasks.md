# 작업 목록

2026-11-12 기준입니다. 작업 하나가 GitHub 이슈(티켓) 하나입니다. **진행 상황의 기준은 이슈와 [프로젝트 보드](project-board.md)이고**, 이 문서는 계획입니다.

## 읽는 법

- **제목 줄:** `### T번호 제목 (우선순위) · 파트 · 선행 T번호`
- **파트와 담당:** 작업은 네 파트로 나누고, 담당은 파트를 따릅니다. 지금 작업을 나눠 맡는 사람은 상현님과 지환님 둘입니다. 원본은 `.github/parts.json`입니다.

| 파트 | 다루는 것 | 경로 | 담당 |
|---|---|---|---|
| `frontend-spec` | 프론트 · 피그마 전 단계. 화면이 무엇을 해야 하는지 글로 정함 | `frontend/spec/` | 상현 |
| `frontend-app` | 프론트 · 피그마 이후 단계. 시안과 구현(웹앱, 차량 앱) | `frontend/web/`, `frontend/car/` | 지환 |
| `backend-api` | 백엔드 · 비즈니스 로직. API 서버와 명세 | `backend/api/`, `docs/api/` | 상현 |
| `backend-infra` | 백엔드 · 인프라. 클라우드, 클러스터, 저장·네트워크, CI | `backend/infra/`, `.github/` | 지환 |

- **우선순위:** `P0` 11/14 제출에 꼭 필요 · `P1` 제출 점수에 도움 · `P2` 2차 발표(12/3~4) 전까지
- **선행:** 먼저 끝나야 시작할 수 있는 작업
- **에뮬레이터:** Pleos 에뮬레이터에서 확인해야 하는 작업은 파트와 관계없이 지환이 맡습니다. 작업에 `환경: 에뮬레이터` 줄을 적으면 담당과 `env:emulator` 라벨이 그렇게 붙습니다.
- **적어도 되는 줄:** `왜:`, `환경:`, `하지 않는 것:`, `위험:`. 이슈 양식의 같은 이름 칸으로 들어갑니다.

## 작업 규칙

1. 보드나 이슈에서 **자기 작업**을 찾고 선행이 끝났는지 봅니다.
2. `make ticket-start T=T번호 NAME=설명`으로 시작하고, `make ticket-pr`로 PR을 엽니다. 상태와 라벨, 보드는 자동으로 옮겨집니다([개발 규칙](development.md)).
3. 끝낸 할 일은 PR이 병합되고 확인한 뒤 이슈에서 체크합니다. 이 문서의 체크 상자는 고치지 않습니다.
4. 계획을 바꿀 때(작업 추가, 할 일 문장, 우선순위, 파트)는 이 문서를 고쳐 PR로 올립니다. 병합 뒤 `python3 .github/scripts/tasks.py --apply`가 없는 이슈를 만들고 파트 라벨과 담당을 맞춥니다.
5. 바로 필요한 작업이나 결함은 GitHub의 이슈 양식으로 만들어도 됩니다. 번호는 자동으로 붙습니다.
6. 작업 번호는 바꾸거나 다시 쓰지 않습니다.

위험: 프로필 표가 바뀌면 이미 만든 기기 프로필이 깨질 수 있다. 표를 고칠 때 기존 줄이 그대로 읽히는지 테스트한다. 비밀 값은 `gh secret set`으로 둔다.

### T22 현대차 개인 프로필 연동 (P2) · backend-api · 선행 T2

왜: 기획안은 현대 계정(마이현대) 연동을 향후 제휴로 둔다. 받을 수 있는 정보와 조건을 모르면 구조를 정할 수 없다.

- [ ] 현대 계정에서 받을 수 있는 정보와 조건 조사(개발자 포털, 제휴 여부)
- [ ] 조사한 출처(문서 주소, 확인한 날짜)를 결정 기록에 남김
- [ ] OAuth 프로필(T21)과 다른 모듈로 두는 구조 결정

하지 않는 것: 구현하지 않는다. 현대 계정으로 실제 로그인해 보는 시험은 조건이 확인된 뒤에 한다.

완료 기준: 결정 기록 한 건(받을 수 있는 정보, 조건, 받을 수 없는 것)과 명세 초안이 병합됨. 문서에서 확인한 것과 추정을 구분해 적음.

위험: 제휴 없이는 받을 수 있는 정보가 없을 수 있다. 그 경우 '연동하지 않음'도 결론이다.

### T23 프로필 저장소와 여행 저장소를 코드에서 나누기 (P1) · backend-api · 선행 T2

왜: 프로필과 여행 데이터를 격리하기로 했다(T26). 코드가 DB 하나를 전제로 하면 파드를 나눌 수 없다.

- [ ] 접속 주소를 프로필용과 여행용 둘로, 표 정의도 둘로
- [ ] 여행을 처리하다 프로필을 읽는 곳을 프로필 저장소로 바꿈
- [ ] 로컬과 CI에서 DB 둘로 테스트

완료 기준: 프로필 표와 여행 표가 서로 다른 DB에 있어도 테스트가 통과.

### T12 음성 처리 흐름 설계 (P2) · backend-api · 선행 T10

왜: 받아쓰기, 화자 구분, 장면 고르기를 어디서 돌리느냐에 따라 비용과 동의 범위가 달라진다. 차량 안의 자원은 화면에 쓰고 연산은 클라우드에 두는 방향이다.

- [ ] 올리기, 받아쓰기, 화자 구분, 장면 고르기를 어디서(차량, 폰, 서버) 할지
- [ ] 원음을 차 밖으로 보내는지와 동의 문구, 보관 기간, 지우는 방법
- [ ] 여행당 비용 어림(외부 API는 `docs/api/external.md`)
- [ ] 통신이 끊겼을 때 무엇이 밀리고 무엇이 계속 되는지

하지 않는 것: 구현하지 않는다. 외부 API를 계약하거나 결제하지 않는다.

완료 기준: 결정 기록 한 건과 API 명세 초안이 병합됨. T10의 결론(차량에서 녹음이 되는지)을 전제로 적음.

위험: 원음을 서버로 보내면 동의, 보관 기간, 제3자 고지가 필요하다(Pleos 심사 기준). 기획 쪽과 먼저 맞춰야 하는 결정이다.

### T7 차량 앱 틀 (P0) · frontend-app · 선행 T1

왜: 제출물은 차량에서 도는 앱이다. 지금은 폰 웹앱과 서버만 있고 차량 앱이 없다.

환경: 에뮬레이터

- [ ] `frontend/car`에 빌드되는 Android 앱(차박지도 앱의 내비·TTS·공조 연동 코드를 옮김)
- [ ] 여행 코드로 서버에 붙어 '기록 중' 화면(일행, 보관한 부탁 수)을 보여 줌. 서버 주소는 설정으로 받음
- [ ] 앱 창 1682 × 1210과 반쪽(약 841 × 1210)에서 깨지지 않는 배치(`docs/emulator/README.md`)
- [ ] CI `frontend-app`에서 빌드와 단위 테스트
- [ ] Pleos 에뮬레이터에 설치해 실행

하지 않는 것: 공조 적용(T8), 경유지(T9), 주행 중 제한(T11), 녹음은 넣지 않는다. 화면 꾸밈은 시안(T20) 뒤에 한다.

완료 기준: 에뮬레이터에서 앱이 뜨고, 폰 웹앱에서 남긴 부탁의 수가 차량 화면에 나타나는 캡처. CI `frontend-app`이 APK를 빌드함. 에뮬레이터 확인.

위험: 화면 문서(T17)가 아직 없다. 틀을 먼저 만들고 화면은 문서가 나오면 맞춘다. 서버에 2초마다 묻는 방식은 주행 중 자원 기준에 걸릴 수 있어 차량 앱의 간격을 따로 정한다.

### T8 차량 앱: 탑승자 프로필 적용 (P0) · frontend-app · 선행 T7, T2

왜: 탑승자 프로필(자리별 공조 선호)은 기획안 v4에서 더한 기능이고, 차량 제어 연동을 보여 주는 자리다.

환경: 에뮬레이터

- [ ] 자리별 선호를 지원 여부 조회 → 적용 → 다시 읽어 확인 → 끝날 때 복원
- [ ] 기어 P에서만 적용. 시트 이동은 넣지 않음
- [ ] 지원하지 않는 영역이나 값은 건너뛰고 화면에 '적용하지 못함'으로 남김
- [ ] 적용하기 전의 값을 저장해 두었다가 여행이 끝나면 되돌림

하지 않는 것: 시트 위치나 등받이처럼 움직이는 부품은 다루지 않는다. 주행 중(기어 D)에는 적용하지 않는다.

완료 기준: 에뮬레이터에서 참가자의 온도·열선·통풍이 그 자리에 적용되고, 다시 읽은 값이 요청한 값과 같다는 기록이 남음. Virtual Console을 켠 상태에서 확인.

위험: 설정 호출이 성공으로 답해도 값이 바뀌지 않은 적이 있다(콘솔 세션이 꺼져 있을 때). 반드시 다시 읽어 확인한다. 차량 제어 권한은 Pleos와 사전 협의가 필요한 항목이다.

### T9 차량 앱: 부탁을 경유지로 반영 (P0) · frontend-app · 선행 T7

왜: 부탁이 실제 경로에 들어가는 것이 시연의 핵심 장면이다. 경유지 요청은 화면이 내비로 넘어가고 결과가 몇 초 뒤에 와서 따로 처리해야 한다.

환경: 에뮬레이터

- [ ] 수락한 부탁을 NaviHelper 경유지로 요청하고, `onWaypointChanged`를 받은 뒤 '경유 반영'으로 바꿈
- [ ] 실패하면 부탁을 보관 상태로 되돌림
- [ ] 반영하는 동안과 끝난 뒤를 말(TTS)로 알림
- [ ] 내비가 앞으로 나와 우리 화면이 가려진 동안(약 6초)의 처리

하지 않는 것: 안내 취소(`cancelRoute`)에 기대지 않는다. 들르면 몇 분 늘어나는지는 계산하지 않는다(장소까지의 거리와 시간만 보여 줌).

완료 기준: 에뮬레이터에서 부탁 두 건 중 하나를 취소하고 남은 하나가 경유지로 들어가는 녹화나 캡처. `onWaypointChanged`를 받은 기록.

위험: 경유지를 더하면 기존 안내가 끊겼다 다시 시작한다. 에뮬레이터는 경유지 좌표를 0.0으로 돌려주는 등 실차와 다르다.

### T11 주행 중 화면 규칙 (P0) · frontend-app · 선행 T7

왜: 주행 중에 보여도 되는 화면에는 제한이 있다. 기어 D에서 '기록 중' 화면이 유지되는지 아직 확인하지 않았다.

환경: 에뮬레이터

- [ ] 주행 중 쓰는 화면으로 선언(`distractionOptimized`)하고 기어 D에서 화면이 유지되는지 확인
- [ ] 주행 중 막을 화면(영상, 긴 기록, 시트 설정)을 기어 D에서 가림
- [ ] 주행 중 화면의 글자 크기와 조작 수를 공식 기준에 맞춤(`docs/emulator/README.md`)

하지 않는 것: 심사 통과를 보장하는 일이 아니다. 실차 확인은 하지 않는다.

완료 기준: 에뮬레이터 기어 D에서 '기록 중' 화면이 떠 있고, 막을 화면이 가려진 캡처.

위험: 에뮬레이터에서 차단 화면이 뜨지 않았다고 심사 기준을 통과한다는 뜻은 아니다.

### T6 웹앱: 홈 화면 설치와 프로필 화면 (P1) · frontend-app · 선행 T2

왜: 일행은 폰 웹앱으로 참가한다. 설치와 프로필 화면이 없으면 여행마다 선호를 다시 입력한다.

- [ ] 매니페스트와 서비스 워커(설치, 통신이 끊겨도 마지막 화면)
- [ ] 프로필 만들기·고치기 화면, 참가할 때 프로필의 선호를 미리 채움
- [ ] 실제 휴대폰에서 확인

하지 않는 것: OAuth 로그인 화면은 넣지 않는다(T19, T21 뒤). 푸시 알림은 넣지 않는다.

완료 기준: 실제 휴대폰의 홈 화면에 설치해 열고, 두 번째 여행에서 선호가 미리 채워져 있음. 통신을 끊어도 마지막 화면이 보임. 확인한 기기와 브라우저를 PR에 적음.

위험: 서비스 워커가 옛 파일을 붙잡아 새 판이 보이지 않을 수 있다. 판 번호로 캐시를 바꾼다. iOS와 Android의 설치 동작이 다르다.

### T20 피그마 시안: 차량 화면과 한국형 기준 적용 (P1) · frontend-app · 선행 T17

왜: 차량 화면의 시안이 없고, 팀이 고른 한국형 UI 기준을 아직 읽고 적용하지 않았다.

- [ ] 화면 문서(T17)대로 차량 화면 시안을 피그마에 그림
- [ ] 앱 창 두 크기(1682 × 1210, 약 841 × 1210)의 시안
- [ ] 한국형 UI 기준(`vmc-inner-circle/k-style-ui-ux`)을 읽고 폰 화면과 차량 화면에 적용
- [ ] 시안과 구현의 색·글자 토큰을 맞춤

하지 않는 것: 화면이 무엇을 해야 하는지는 정하지 않는다(화면 문서가 기준). 시안에서 새 기능을 더하지 않는다.

완료 기준: 피그마 파일에 차량 화면 시안이 있고, 구현(`frontend/web`, `frontend/car`)이 같은 색·글자 토큰을 씀. 시안 주소를 `docs/`에 적음.

위험: 피그마 파일이 지환의 개인 초안에 있다. 팀이 볼 수 있게 옮기거나 보기 권한을 준다.

- [ ] CI에서 형식 검사와 `terraform validate`
- [ ] 비용 어림과 만드는 절차 문서

### T5 GitOps: Argo CD · Postgres · API 배포 선언 (P1) · backend-infra · 선행 T2, T4

- [ ] Postgres 클러스터와 S3 백업 선언
- [ ] API 서버 배포·서비스·인그레스, 이미지 게시
- [ ] CI에서 선언을 조립해 스키마 검사

### T24 실제 자원을 만들고 클러스터에 올려 확인 (P1) · backend-infra · 선행 T5

왜: Terraform과 클러스터 선언은 검사만 통과했고 실제로 만들어 본 적이 없다. 밖에서 붙을 서버가 있어야 폰과 차량이 같은 여행을 본다.

- [ ] 지환님 승인 뒤 `terraform apply`
- [ ] 클러스터가 이미지를 받을 `read:packages` 토큰과 Argo CD 배포 키를 넣음
- [ ] 첫 부팅 스크립트, Argo CD가 올리는 순서, Postgres 백업을 실제로 확인
- [ ] 로컬에서 올린 이미지를 태그 변경 PR로 내보내 보기
- [ ] 다 쓴 뒤 자원을 내리는 절차를 문서에 적음

하지 않는 것: OIDC(T25), 저장소를 파드로 나누기(T26), 프록시 교체(T27)는 하지 않는다. 지금 선언 그대로 올린다.

완료 기준: 밖에서 `/healthz`가 200으로 답하고, 태그를 바꾼 PR이 병합되면 새 이미지로 바뀌는 것을 확인. 든 비용을 PR에 적음.

위험: 비용이 든다(서버, 고정 IP, 저장소). 승인 없이 만들지 않는다. 되돌리기는 `terraform destroy`이고 백업 버킷은 따로 지운다.

### T25 자격 증명을 OIDC로 (P1) · backend-infra · 선행 T4

왜: 인프라 자격 증명은 OIDC로 관리하기로 했다. 오래 쓰는 열쇠를 저장소와 서버에 두지 않는다.

- [ ] GitHub Actions가 열쇠 없이 AWS 역할을 받도록 OIDC 제공자와 역할을 Terraform으로
- [ ] PR에서 `terraform plan`을 그 역할로 실행
- [ ] 파드가 AWS에 접근할 때도 서비스 계정 OIDC를 쓰는 방법을 정함(지금은 인스턴스 역할)

하지 않는 것: 이미지 받기 토큰과 배포 키는 없애지 않는다. 예외로 적는다.

완료 기준: 저장소와 서버에 오래 쓰는 AWS 열쇠가 없음(`gh secret list`와 서버에서 확인). PR에서 `terraform plan`이 OIDC 역할로 돎. 남는 고정 비밀 값은 문서에 예외로 적음.

위험: 역할의 신뢰 조건을 넓게 잡으면 다른 저장소나 브랜치가 역할을 받는다. 저장소와 브랜치로 좁힌다.

### T26 프로필과 여행 Postgres를 파드로 나누고 네트워크로 격리 (P1) · backend-infra · 선행 T23

왜: 유저 프로필과 여행 데이터를 격리하기로 했다. 노드가 하나라 파드와 네트워크 정책으로 나눈다.

- [ ] 프로필용과 여행용 Postgres를 서로 다른 파드로
- [ ] API에 `TRIPS_DATABASE_URL`과 `PROFILES_DATABASE_URL`을 따로 줌(T23의 코드)
- [ ] 기본은 모두 막고, API 파드만 두 DB에 닿게 하는 네트워크 정책
- [ ] 한 대짜리 클러스터에서 정책이 실제로 막는지 확인
- [ ] 프로필 저장소가 느리거나 죽었을 때 여행 쓰기가 얼마나 막히는지 보고 질의 시간 제한을 정함

하지 않는 것: 노드를 늘리지 않는다. 저장 장치와 CNI를 바꾸는 일은 T28.

완료 기준: API가 아닌 파드에서 두 DB로의 접속이 거절되고, API는 두 DB에 모두 닿음(`/healthz` 200). 클러스터에서 확인.

위험: K3s의 기본 네트워크가 정책을 실제로 막는지부터 확인해야 한다(T28). 이미 든 데이터를 두 DB로 옮기는 절차가 필요하다.

### T27 리버스 프록시를 AWS 스택으로 (P1) · backend-infra · 선행 T4

왜: 리버스 프록시는 AWS가 제공하는 스택을 쓰기로 했다. 지금 선언은 Traefik과 cert-manager다.

- [ ] CloudFront와 ALB를 Terraform으로. 서버의 80·443 공개를 닫음
- [ ] 클러스터 안의 Traefik 인그레스와 cert-manager를 걷어냄
- [ ] 요청 수 제한을 AWS 쪽으로 옮길지 정함

하지 않는 것: 도메인을 따로 사지 않는다. CloudFront가 주는 주소를 쓴다.

완료 기준: 밖에서는 CloudFront 주소로만 닿고 HTTPS가 됨. 서버의 80·443에 직접 닿으면 거절됨.

위험: ALB와 CloudFront는 켜 둔 시간만큼 비용이 든다. 비용 어림을 먼저 적고 승인받는다. 되돌리기는 이전 선언(Traefik)으로의 revert.

### T28 저장 장치와 네트워크(CSI · CNI) 정하기 (P2) · backend-infra · 선행 T24

왜: 저장 장치와 파드 네트워크를 K3s 기본값으로 둘지 정하지 않았다. 네트워크 정책(T26)이 되는지는 CNI에 달려 있다.

- [ ] Postgres 볼륨을 EBS(CSI)로 옮길지와 방법
- [ ] 지금의 네트워크 구성(K3s 기본)으로 충분한지, 바꾼다면 무엇으로

하지 않는 것: 노드를 여러 대로 늘리는 구성은 다루지 않는다.

완료 기준: 결정 기록 한 건과, 정한 대로 바꾼 선언이 병합됨. 바꿨다면 클러스터에서 확인.

위험: CNI를 바꾸면 클러스터를 다시 만들어야 할 수 있다. 볼륨을 옮기기 전에 데이터를 백업한다.
