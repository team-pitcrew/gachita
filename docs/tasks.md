# 작업 목록

2026-11-12 기준입니다. 작업 하나가 GitHub 이슈(티켓) 하나입니다. **진행 상황의 기준은 이슈와 [프로젝트 보드](project-board.md)이고**, 이 문서는 계획입니다.

## 읽는 법

- **제목 줄:** `### T번호 제목 (우선순위) · 파트 · 선행 T번호`
- **파트와 담당:** 작업은 네 파트로 나누고, 담당은 파트를 따릅니다. 지금 작업을 나눠 맡는 사람은 상현님과 지환님 둘입니다. 원본은 `.github/parts.json`입니다.

| 파트 | 다루는 것 | 경로 | 담당 |
|---|---|---|---|
| `frontend-spec` | 프론트 · 피그마 전 단계. 화면이 무엇을 해야 하는지 글로 정함 | `frontend/spec/` | 상현 |
| `frontend-app` | 프론트 · 피그마 이후 단계. 시안과 구현(웹앱, 차량 앱) | `frontend/web/`, `frontend/car/` | 지환 |
| `backend-api` | 백엔드 · 비즈니스 로직. API 서버와 명세 | `backend/api/`, `docs/api/` | 상현 |
| `backend-infra` | 백엔드 · 인프라. 클라우드, 클러스터, 저장·네트워크, CI | `backend/infra/`, `.github/` | 지환 |

- **우선순위:** `P0` 11/14 제출에 꼭 필요 · `P1` 제출 점수에 도움 · `P2` 2차 발표(12/3~4) 전까지
- **선행:** 먼저 끝나야 시작할 수 있는 작업

## 작업 규칙

1. 보드나 이슈에서 **자기 작업**을 찾고 선행이 끝났는지 봅니다.
2. `make ticket-start T=T번호 NAME=설명`으로 시작하고, `make ticket-pr`로 PR을 엽니다. 상태와 라벨, 보드는 자동으로 옮겨집니다([개발 규칙](development.md)).
3. 끝낸 할 일은 PR이 병합되고 확인한 뒤 이슈에서 체크합니다. 이 문서의 체크 상자는 고치지 않습니다.
4. 계획을 바꿀 때(작업 추가, 할 일 문장, 우선순위, 파트)는 이 문서를 고쳐 PR로 올립니다. 병합 뒤 `python3 .github/scripts/tasks.py --apply`가 없는 이슈를 만들고 파트 라벨과 담당을 맞춥니다.
5. 바로 필요한 작업이나 결함은 GitHub의 이슈 양식으로 만들어도 됩니다. 번호는 자동으로 붙습니다.
6. 작업 번호는 바꾸거나 다시 쓰지 않습니다.
