## 작업 규칙

1. 보드나 이슈에서 **자기 작업**을 찾고 선행이 끝났는지 봅니다.
2. `make ticket-start T=T번호 NAME=설명`으로 시작하고, `make ticket-pr`로 PR을 엽니다. 상태와 라벨, 보드는 자동으로 옮겨집니다([개발 규칙](development.md)).
3. 끝낸 할 일은 PR이 병합되고 확인한 뒤 이슈에서 체크합니다. 이 문서의 체크 상자는 고치지 않습니다.
4. 계획을 바꿀 때(작업 추가, 할 일 문장, 우선순위, 파트)는 이 문서를 고쳐 PR로 올립니다. 병합 뒤 `python3 .github/scripts/tasks.py --apply`가 없는 이슈를 만들고 파트 라벨과 담당을 맞춥니다.
5. 바로 필요한 작업이나 결함은 GitHub의 이슈 양식으로 만들어도 됩니다. 번호는 자동으로 붙습니다.
6. 작업 번호는 바꾸거나 다시 쓰지 않습니다.

- [ ] 부탁 제안과 운전자의 말로 하는 수락. 모호할 때 다시 묻는 문구
- [ ] 도착 브리핑: 주차하면 그 장소의 미완료 할 일만 보여 주는 화면과 완료 처리
- [ ] Gleo를 쓰는 동안: '기록 잠시 멈춤'과 '운전대 버튼을 누르세요' 안내, 다시 기록으로 돌아오는 표시
- [ ] 여행 후: 기록본이 사람별 프로필에 쌓이는 화면(피드)과 가족 앨범의 관계

하지 않는 것: 색, 크기, 글꼴은 적지 않는다(T20). 좌석·공조 적용 화면은 넣지 않는다(T8, 기준 문서에서 빠짐). 구현하지 않는다. 에뮬레이터에서 확인할 것이 나오면 지환에게 넘긴다.

완료 기준: `frontend/spec/`의 화면 문서가 병합되고 `frontend-spec` 검사 통과. 위 여섯 항목이 각각 어느 문서 어느 절에 있는지 PR에 적음.

위험: 기준 문서는 다음 판이 예정돼 있다(11/13 오후). 바뀌면 이 문서를 다시 고친다. 4자리를 따로 가리는 표시는 에뮬레이터에서 확인하지 못했다.

### T12 음성 처리 흐름 설계 (P1) · backend-api · 선행 T10

왜: 받아쓰기, 화자 구분, 장면 고르기를 어디서 돌리느냐에 따라 비용과 동의 범위가 달라진다. 기준 문서는 차량에서 직접 수음한다. 11/13 실측에서 받아쓰기는 차량의 Pleos STT로 됐다(앱이 받은 원음을 `sendAudio()`로 넣어 11분, 말이 끝나고 0.6초). 받아쓰기를 차량에 두면 원음을 차 밖으로 보내는 범위가 줄고 Pleos SDK 활용이 는다.

- [ ] 받아쓰기를 차량의 Pleos STT로 둘 때와 서버 ASR로 둘 때의 비교(정확도, 비용, 동의 범위)와 결정. 될 수 있으면 SDK로 둔다
- [ ] 화자 대조, 장면 고르기, 도착 할 일 뽑기를 어디서(차량, 서버) 할지
- [ ] 원음을 차 밖으로 보내는 범위(전부, 고른 장면만, 안 보냄)와 동의 문구(기본값 꺼짐), 보관 기간, 지우는 방법
- [ ] 여행당 비용 어림(외부 API는 `docs/api/external.md`)
- [ ] 통신이 끊겼을 때 무엇이 밀리고 무엇이 계속 되는지
- [ ] 받아 적은 기록본의 보정 단계(언제·어디서 돌고, 원문과 보정본을 어떻게 남기는지)를 흐름에 넣는다. 실측은 T59 보고서 `docs/research/stt-correction.md`

하지 않는 것: 구현하지 않는다. 외부 API를 계약하거나 결제하지 않는다. 에뮬레이터에서 재야 하는 것은 하지 않고 지환에게 넘긴다(T36, T41).

설계: 차량은 수음과 Pleos STT(ON_DEVICE, `sendAudio()`)로 발화 단위 기록본(시각, 글자, 좌석 구역)을 만들어 서버로 보낸다(T36, T39). 서버는 여행이 끝나면(기어 P·여행 종료) 한꺼번에 화자 대조(T38), 전사 보정, 도착 할 일 뽑기를 한다. 전사 보정은 자리만 두고 T59 기준(이름·호칭 정확도 상승, 원래 맞던 문장 변경 2% 이하)을 넘기 전에는 끈다(11/13 실측: 2구간에서 기준 미달). 켜면 보정본은 원문을 지우지 않고 함께 두며 바꾼 자리를 표시한다. 원음을 서버로 보낼지와 그 범위는 이 티켓에서 정한다.

대안: 서버 ASR로 다시 받아 적기(상현 11/13 실측 qwen3_asr 한국어 오류 5.7~8.1%, 원음 전체를 보내야 함) · 보정 없이 Pleos STT 원문 그대로 · Bedrock Qwen3 32B로 보정(서울은 `bedrock-mantle`만, 토큰 과금, 대화가 밖으로 나감) · 작은 모델이 문장을 직접 고쳐 쓰기(T59에서 비교).

서비스 수준: 받아 적기 지연(말 끝 → 최종 결과) 중앙값 0.6초 이하(에뮬레이터 30분 실측 0.60초). 이름·호칭 정확도(30분 실측 39%)와 보정이 원래 맞던 문장을 바꾸는 비율(2% 이하)은 T59 보고서 기준. 여행이 끝난 뒤 기록본이 피드에 오르기까지의 목표 시간은 이 티켓에서 정한다.

용량: 30분 대화에 발화 약 280개. 보정 후보 모델 Qwen3.5-2B(Q4) 1,281 MB. Mac에서 문장 하나 보정 중앙값 0.52초(30분 대화 2~3분 어림). 서버 한 대(t4g.large, 2 vCPU·8 GiB)에서의 시간과 메모리는 아직 재지 않음.

의존성: 차량의 Pleos STT SDK, 서버 API(T39), 보정 모델 파일(해시 고정). 보정이 실패하거나 늦으면 원문을 그대로 피드에 올리고 나중에 다시 돌린다. 통신이 끊기면 차량이 모았다가 보낸다(T36).

관측: 여행마다 보정한 문장 수, 바꾼 비율, 처리 시간, 실패 수를 로그로 남긴다. 바꾼 비율이 평소보다 크게 오르면(과교정 의심) 알린다.

보안: 기록본(대화 글자)은 기록에 동의한 여행에서만 만든다. 보정은 우리 서버 안에서만 돌리고 외부 API로 보내지 않는다. 원문과 보정본의 보관 기한은 기록본과 같다(T39). 원음의 범위와 동의 문구는 이 티켓에서 정한다.

완료 기준: 결정 기록 한 건과 API 명세 초안이 병합됨. T10의 결론(차량에서 녹음이 되고, 그 원음을 Pleos STT에 넣어 받아 적을 수 있음)과 기준 문서(차량 직접 수음, 폰은 차선안)를 전제로 적음.

위험: 원음을 서버로 보내면 동의, 보관 기간, 제3자 고지가 필요하다(Pleos 심사 기준). 기획 쪽과 먼저 맞춰야 하는 결정이다. 11/13에 올라온 결정 기록 초안은 '대표 폰에서 녹음'을 전제로 쓰였으므로 병합 전에 이 전제를 맞춘다. Pleos STT의 사람 목소리·소음 정확도는 재지 않았다.

### T38 화자 대조: 모델 고르기와 API (P1) · backend-api · 선행 T12

왜: 기준 문서는 짧은 목소리 등록으로 화자를 맞추고 화자별 자막을 만든다. Pleos SDK에는 화자를 알려 주는 공개 API가 없다. 11/13 실측에서 좌석 두 구역은 차량 앱이 채널로 갈랐지만(8/8), 같은 구역 안의 사람은 간이 대조기로 7/8이었다. 사람 구분에는 학습된 화자 모델이 필요하다.

- [ ] 화자 임베딩 모델 후보와 고른 이유(한국어, 아이 목소리, 2~4초 발화에서의 정확도, 실행 비용)를 결정 기록에
- [ ] 목소리 등록 API: 프로필마다 등록 음성을 받아 대조용 값만 저장. 등록 음성 원본을 남길지 정함
- [ ] 발화 대조 API: 발화 음성과 좌석 구역 후보를 받아 프로필과 확신도를 돌려줌. 확신이 낮으면 '모름'
- [ ] 등록 길이(문장 수)에 따른 정확도를 같은 음성으로 비교

하지 않는 것: 모델을 직접 학습하지 않는다. 겹쳐 말하는 구간을 나누지 않는다. 외부 서비스를 계약하거나 결제하지 않는다. 에뮬레이터의 마이크로 받은 소리로 재는 것은 하지 않는다(지환, T37). 시험 음성 파일은 지환이 넘긴다.

완료 기준: 결정 기록 한 건과 명세가 병합되고, 테스트에서 등록한 두 목소리의 발화가 맞는 프로필로 돌아옴. 고른 모델로 잰 정확도 표(발화 길이별)가 PR에 있음.

위험: 목소리 대조용 값은 생체 정보로 다뤄질 수 있다. 동의 범위와 지우는 방법을 T12와 맞춘다. 11/13 실측의 목소리는 한 합성 음성의 음높이만 바꾼 것이라 실제 가족의 구분 난이도를 대신하지 못한다.

### T39 기록본 저장과 프로필 피드 API (P1) · backend-api · 선행 T2

왜: 실시간 전사를 기록본으로 남기고 프로필에 묶어 저장한다. 사람마다 자기 말과 장면이 프로필에 쌓이는 모양이다(지환, 11/13). 지금 서버에는 발화를 저장하는 경로가 없고, 여행 읽기는 48시간으로 닫힌다.

- [ ] 발화 저장: 여행 코드로 발화(시각, 글자, 좌석 구역, 프로필, 확신도, 원음 구간, 위치)를 받음. 위치가 없는 발화도 받음. 순서가 어긋나거나 다시 보내도 중복되지 않음
- [ ] 기록본 읽기: 여행의 발화를 시간순으로, 부탁과 도착 할 일과 함께
- [ ] 프로필 피드: 한 프로필의 발화와 장면을 여행을 가로질러 최신순으로
- [ ] 48시간 뒤에 무엇이 프로필에 남는지 정함(전체 전사, 사람이 고른 장면만, 요약만). 기준 문서는 '선택한 장면만 개인 앨범에'라고 적는다
- [ ] 프로필 주인이 자기 글을 지우는 경로, 다른 가족의 말이 섞인 장면의 처리
- [ ] 명세(`docs/api/openapi.yaml`)와 테스트

하지 않는 것: 화면은 만들지 않는다(T42, T20). 영상은 만들지 않는다(T43). 공개 공유는 넣지 않는다. 차량 앱에서 보내는 쪽과 에뮬레이터 확인은 하지 않는다(지환, T36).

완료 기준: 테스트에서 두 프로필의 발화를 저장한 뒤 각 프로필의 피드에 자기 발화만 나오고, 여행 읽기가 닫힌 뒤에도 남기기로 한 것만 남음. 명세 검사 통과.

위험: 남기는 범위가 넓을수록 동의와 보관 고지가 무거워진다. 범위는 기획 쪽과 먼저 정한다. 프로필 저장소와 여행 저장소가 나뉘어 있어(T23) 피드가 두 저장소를 함께 읽는다.

### T45 가족·동승자 그룹과 초대 API (P1) · backend-api · 선행 T21

왜: 기준 문서의 첫 고객은 가족이고 아이(6세, 4세)는 계정이 없다. 지금 서버는 계정 하나에 프로필 하나, 여행 코드로 그 여행에만 참가하는 구조라 '우리 가족'이나 '늘 같이 타는 일행'을 묶어 둘 자리가 없다. 현대·Pleos 쪽에서 가족이나 차량 프로필을 받아 올 길은 찾지 못했다([ADR-0009](adr/0009-family-group-and-qr-invite.md)). 그래서 그룹을 직접 두고 QR로 초대한다(지환, 11/13).

- [ ] 그룹: 종류(가족, 동승자), 대표, 구성원. 계정이 없는 구성원(아이)은 대표가 만든 프로필로 둠
- [ ] 초대: 그룹이나 여행에 들어오는 초대를 만들면 QR에 담을 주소(`https://gachita.mangowhois.ai/j/<초대>`)를 돌려줌. 만료 시각, 쓸 수 있는 횟수, 대표의 취소
- [ ] 수락: 초대 주소로 들어온 사람이 계정으로 로그인하면 있던 프로필로, 가입한 적이 없거나 계정이 없으면 새 프로필(이름 또는 닉네임, 캐릭터나 사진)을 만들어 구성원이 됨. 진행 중인 여행이 있으면 그 여행에도 참가. 기록 동의는 각자 따로 받고 기본값은 꺼짐
- [ ] 프로필 사진: 올리기, 크기와 형식 제한, 보관하는 곳, 지우기. 캐릭터는 정해 둔 목록에서 고른 값만 저장
- [ ] 그룹으로 여행 시작: 대표가 여행을 만들면 구성원이 자리만 고르면 되게 함
- [ ] 한 프로필을 차량과 폰에서 함께 쓸 수 있게 기기마다 토큰을 따로 둠(지금은 다른 기기에서 계정으로 들어오면 앞 기기의 토큰을 못 쓰게 됨)
- [ ] 구성원 내보내기와 스스로 나가기, 그룹을 지울 때 기록본(T39)의 처리
- [ ] 명세(`docs/api/openapi.yaml`)와 테스트

하지 않는 것: 현대 계정 연동은 구현하지 않는다(ADR-0004). 화면과 QR 그림은 만들지 않는다(T46). 차량의 Pleos 프로필을 읽으려 하지 않는다(공개 API 없음).

완료 기준: 테스트에서 대표가 가족 그룹과 초대를 만들고, 두 사람이 그 초대로 들어와 구성원이 되고, 만료되거나 취소된 초대는 거절됨. 계정 없는 구성원 프로필로 여행에 참가됨. 같은 프로필의 두 기기 토큰이 서로를 끊지 않음.

위험: 초대 주소가 새면 모르는 사람이 가족 그룹에 들어온다. 짧은 만료와 횟수 제한, 대표의 수락 확인 중 무엇을 둘지 정한다. 아이의 프로필과 사진, 목소리 대조 값은 보호자 동의가 필요한 정보다. 사진은 프로필에만 쓰고 영상에는 캐릭터를 쓴다(기준 문서). 올린 파일을 그대로 내보내면 위험하므로 형식을 확인하고 다시 저장한다. 프로필 표를 고칠 때 이미 만든 프로필이 그대로 읽히는지 테스트한다.

### T43 장면 추천과 숏폼 생성 (P2) · backend-api · 선행 T39

왜: 기준 문서의 첫 기능은 원래 목소리, 화자별 자막, 가족 캐릭터로 만든 15~45초 숏폼이다. 제출 영상에서는 시안으로 보여 주고 구현은 2차 발표 전까지로 둔다.

- [ ] 기록본에서 장면 후보를 고르는 기준과 결과 모양
- [ ] 고른 구간의 원음, 자막, 캐릭터 강조로 세로 영상을 만드는 방법과 비용
- [ ] 차량에 완성본을 돌려주는 경로

하지 않는 것: 음성을 새로 합성하지 않는다. 얼굴이나 차 안 영상을 쓰지 않는다.

완료 기준: 결정 기록 한 건과, 시험 기록본 하나에서 만든 영상 한 편.

위험: 영상 생성 비용과 시간이 주차 중 기다릴 수 있는 범위인지 모른다.

### T8 차량 앱: 탑승자 프로필 적용 (P2) · frontend-app · 선행 T7, T2

왜: 탑승자 프로필(자리별 공조 선호)은 기획안 v4에서 더한 기능이고, 차량 제어 연동을 보여 주는 자리다. 기준 문서(문구정리본)에는 좌석·공조 적용이 없고, Pleos ID가 시트 위치 같은 설정을 이미 되살린다는 지적이 있어(11/13) 제출 범위에서 뺐다. 기획에 다시 들어오면 우선순위를 올린다.

환경: 에뮬레이터

- [ ] 자리별 선호를 지원 여부 조회 → 적용 → 다시 읽어 확인 → 끝날 때 복원
- [ ] 기어 P에서만 적용. 시트 이동은 넣지 않음
- [ ] 지원하지 않는 영역이나 값은 건너뛰고 화면에 '적용하지 못함'으로 남김
- [ ] 적용하기 전의 값을 저장해 두었다가 여행이 끝나면 되돌림

하지 않는 것: 시트 위치나 등받이처럼 움직이는 부품은 다루지 않는다. 주행 중(기어 D)에는 적용하지 않는다.

완료 기준: 에뮬레이터에서 참가자의 온도·열선·통풍이 그 자리에 적용되고, 다시 읽은 값이 요청한 값과 같다는 기록이 남음. Virtual Console을 켠 상태에서 확인.

위험: 설정 호출이 성공으로 답해도 값이 바뀌지 않은 적이 있다(콘솔 세션이 꺼져 있을 때). 반드시 다시 읽어 확인한다. 차량 제어 권한은 Pleos와 사전 협의가 필요한 항목이다.

### T9 차량 앱: 부탁을 경유지로 반영 (P0) · frontend-app · 선행 T7, T36

왜: 부탁이 실제 경로에 들어가는 것이 시연의 핵심 장면이다. 경유지 요청은 화면이 내비로 넘어가고 결과가 몇 초 뒤에 와서 따로 처리해야 한다.

환경: 에뮬레이터

- [ ] 전사(T36)에서 부탁을 알아채 보관하고, 갈 수 있는 휴게소를 화면과 말로 제안. 이미 지나친 곳이면 다음 후보
- [ ] 운전자의 말("응, 다음 휴게소 가자")을 수락으로 받음. 모호하면 다시 물음. 화면 수락도 남김
- [ ] 수락한 부탁을 NaviHelper 경유지로 요청하고, `onWaypointChanged`를 받은 뒤 '경유 반영'으로 바꿈
- [ ] 실패하면 부탁을 보관 상태로 되돌림
- [ ] 반영하는 동안과 끝난 뒤를 말(TTS)로 알림
- [ ] 내비가 앞으로 나와 우리 화면이 가려진 동안(약 6초)의 처리

하지 않는 것: 안내 취소(`cancelRoute`)에 기대지 않는다. 들르면 몇 분 늘어나는지는 계산하지 않는다(장소까지의 거리와 시간만 보여 줌).

완료 기준: 에뮬레이터에서 가상 마이크에 넣은 "화장실 가고 싶어"와 "응, 다음 휴게소 가자"로 경유지가 들어가는 녹화. 부탁 두 건 중 하나를 취소하고 남은 하나만 들어가는 경우도 확인. `onWaypointChanged`를 받은 기록. 부탁하는 말이 끝난 뒤 제안이 뜨기까지의 시간을 재서 기준 문서의 목표(p95 5초)와 비교한 값.

위험: 경유지를 더하면 기존 안내가 끊겼다 다시 시작한다. 에뮬레이터는 경유지 좌표를 0.0으로 돌려주는 등 실차와 다르다. 11/13 실측에서는 수락 뒤 `onWaypointChanged`까지 7.6초였고 낱말 규칙으로 알아챘다. 누가 말했는지는 틀릴 수 있어(T38) 수락은 운전자 자리의 말만 받는 식으로 좁힌다.

### T36 차량 앱: 수음과 실시간 전사 (P0) · frontend-app · 선행 T7

왜: 기준 문서의 모든 기능이 차량이 대화를 받아 적는 데서 시작한다. 11/13 실측에서 일반 앱이 마이크 포그라운드 서비스로 수음하고 같은 원음을 Pleos STT(ON_DEVICE)에 `sendAudio()`로 넣어 받아 적었다. 앞 화면에서 11분 150문장을 받아 적었고 결과는 말이 끝나고 0.6초 뒤에 왔다. 내비가 앞에 있고 기어 D인 상태에서는 약 95초짜리 실행 한 번을 봤다.

환경: 에뮬레이터

- [ ] 마이크 포그라운드 서비스에서 `AudioRecord`(16 kHz, 2채널)로 수음. 동의가 켜져 있을 때만 시작하고 앱이 앞에 있을 때 시작함
- [ ] 같은 원음을 모노로 합쳐 Pleos STT에 0.1초 조각으로 넣고, 인식이 끝나도 계속 넣어 다음 발화를 이어 받음
- [ ] 발화 단위(시각, 글자, 좌석 구역)에 그때의 위치(FusedLocation)와 기어 상태를 붙여 화면에 올리고 서버로 보냄(T39). 전송은 TLS로 하고, 통신이 끊기면 모아 두었다 보냄
- [ ] 수음이 막힌 것(`isClientSilenced`, 값이 0인 구간)을 알아채 '기록 멈춤'으로 보임
- [ ] 주행 중 CPU와 메모리를 재서 Pleos 기준(5% 미만, 400 MB 이하)과 비교

하지 않는 것: 원음 전체를 서버로 보내지 않는다(범위는 T12에서 정함). 서버 ASR을 붙이지 않는다. 사람 구분은 하지 않는다(T37, T38).

완료 기준: 에뮬레이터에서 가상 마이크에 넣은 가족 대화 다섯 문장이 내비를 앞에 둔 기어 D 상태에서 차량 앱의 기록과 서버 기록에 남음. 10분 동안 끊기지 않음. 자원 측정값이 PR에 있음.

위험: 쉬지 않고 말하면 약 20초에서 끊어 이어 가고 그 자리에서 몇 글자가 틀렸다. 짧은 물음("바다는 왜 짜?")은 합성 음성에서 틀리게 적혔다. 사람 목소리, 차 안 소음, 스피커 소리가 마이크로 되돌아오는 경우는 재지 않았다. 마이크 서비스는 앱이 앞에 있을 때만 시작돼, 다음 탑승 때 저절로 수음을 시작하는 것은 확인하지 않았다. 우리가 수음하는 동안 Gleo는 듣지 못한다(T41). `AudioRecord`로 원음을 받는 것이 Pleos 심사에서 받아들여지는지는 모른다.

### T37 차량 앱: 좌석 구역 판정과 목소리 등록 (P1) · frontend-app · 선행 T36

왜: 화자별 자막과 말하는 사람 강조에는 누가 말했는지가 필요하다. 11/13 실측에서 에뮬레이터의 두 채널은 완전히 분리돼(한쪽이 말할 때 반대쪽은 무음) 발화를 앞줄·뒷줄로 가르는 것은 8번 모두 맞았다.

환경: 에뮬레이터

- [ ] 발화마다 두 채널의 소리 크기를 비교해 좌석 구역을 붙임. 차이가 작으면 '모름'
- [ ] 출발 전 목소리 등록: 프로필마다 문장 두 개를 받아 서버에 등록(T38)하고, 그 사람의 좌석 구역을 여행에 적어 둠
- [ ] 좌석 구역과 서버의 대조 결과를 합쳐 발화에 프로필을 붙이고, 확신이 낮으면 화면에서 고칠 수 있게 표시

하지 않는 것: 4자리를 따로 가리지 않는다. 채널이 어느 자리인지는 에뮬레이터 기준으로만 정한다. 화자 모델은 차량에 넣지 않는다.

완료 기준: 에뮬레이터에서 왼쪽·오른쪽 채널에 나눠 넣은 발화가 맞는 좌석 구역으로 기록되고, 등록한 네 프로필의 발화에 프로필이 붙은 기록. 틀린 것의 수를 PR에 적음.

위험: 실차의 마이크 수와 배치, 자리 사이에 소리가 새는 정도는 모른다. Pleos SDK의 화자 인식 API(`AmbientAiApi`)는 특권 앱 전용이라 쓰지 못한다. 겹쳐 말하면 한 사람 말만 받아 적혔다.

### T40 차량 앱: 도착 브리핑 (P0) · frontend-app · 선행 T36

왜: 기준 문서에서 새로 들어온 기능이다. 이동 중 나온 할 일을 장소별로 모아 두고, 그 장소에 주차하면 미완료 항목만 보여 준다.

환경: 에뮬레이터

- [ ] 전사에서 장소가 붙은 할 일("마트에서 우유랑 간식 사자")을 모아 장소별 목록으로 둠
- [ ] 도착 판정: 기어 P와, 그 장소가 지금 목적지나 경유지인지(NaviHelper 조회)
- [ ] 주차하면 그 장소의 미완료 항목을 화면과 말(Pleos TTS)로 알리고 완료 처리
- [ ] Gleo에서 "도착해서 할 일 알려 줘"로 부를 수 있게 App Schema 액션 하나

하지 않는 것: 장소 검색을 새로 만들지 않는다. 주행 중에는 목록을 띄우지 않는다. 할 일을 뽑는 규칙을 LLM으로 바꾸는 것은 T12 뒤에 한다.

완료 기준: 에뮬레이터에서 주행 중 넣은 할 일 두 건이 기어 P로 바꾼 뒤 화면에 나오고, 하나를 완료하면 다음 알림에서 빠지는 녹화.

위험: 11/13 실측은 기어 P 콜백까지만 봤다. 목적지나 경유지에 도착했다는 알림은 에뮬레이터에서 차 위치를 옮기지 않아 재지 못했다. 에뮬레이터는 경유지 좌표를 0.0으로 돌려준다.

### T41 차량 앱: Gleo와 마이크 주고받기 (P1) · frontend-app · 선행 T36

왜: 우리 앱이 수음하는 동안 Gleo는 운전대 버튼을 무시한다. 기준 문서는 호출어 감지 → 마이크 반환 → Gleo 호출 → 재개를 개발 항목으로 둔다. 11/13 실측에서 감지, 반환, 재개는 됐고 앱이 Gleo를 깨우는 것만 길이 없었다.

환경: 에뮬레이터

- [ ] 전사에서 호출어를 찾음. STT가 "글레오"를 "클레오"·"클리오"로 적는 경우가 많아 변형 목록으로 찾고, 잘못 알아챈 횟수를 잼
- [ ] 알아채면 `AudioRecord`만 멈추고(서비스는 유지) '기록 잠시 멈춤 · 운전대 버튼을 누르세요'를 보임. 화면의 'Gleo 쓰기' 단추로도 같은 동작
- [ ] Gleo가 쓰는 중과 끝난 것을 알아채 다시 수음. 실측에서는 미디어 오디오 포커스의 상실과 복귀로 알았다. 사용자의 음악을 멈추지 않는 방법을 정함
- [ ] 버튼을 누르지 않으면 정한 시간 뒤 다시 수음
- [ ] Gleo가 우리 기능을 부르는 App Schema 액션: 기록 멈추기, 기록 다시 시작

하지 않는 것: Gleo를 대신 깨우는 우회로를 만들지 않는다(문서에 없는 호출, 다른 앱의 패키지 이름 쓰기). 차량 제어를 우리 앱이 직접 하지 않는다.

완료 기준: 에뮬레이터에서 호출어 → 멈춤 → 버튼 → Gleo 듣기 → Gleo 종료 → 다시 수음 → 이어지는 전사가 한 번에 이어지는 녹화. 멈춰 있던 시간과 재개까지 걸린 시간을 PR에 적음.

위험: 호출어 뒤에 바로 이어 한 말은 우리도 Gleo도 받지 못한다. Gleo를 한 번 쓰면 말이 없어도 약 6초, 답을 들으면 약 24초 동안 기록이 빈다. 넘겨받은 Gleo가 말을 알아듣는지는 에뮬레이터가 멈춰 재지 못했다. 실차에서도 마이크를 나눠 쓰지 못하는지는 확인하지 못했다.

### T46 차량 앱·웹앱: QR로 그룹에 초대하고 들어오기 (P1) · frontend-app · 선행 T7, T45

왜: 가족이나 동승자를 그룹에 넣는 가장 짧은 길이 차량 화면의 QR을 폰으로 찍는 것이다. 지금 웹앱은 여행 코드를 손으로 넣거나 주소를 공유해야 한다.

환경: 에뮬레이터

- [ ] 차량 앱: 주차 중에 '가족 초대'와 '동승자 초대' QR을 띄움. 남은 시간과 들어온 사람을 보여 주고, 대표가 취소할 수 있음
- [ ] 주행 중(기어 D)에는 QR을 띄우지 않음
- [ ] 웹앱: QR의 주소(`gachita.mangowhois.ai`)로 폰 브라우저가 열리면 설치 없이 수락 화면(누구의 어떤 그룹인지, 기록 동의)으로 들어감

- [ ] 대표의 폰 웹앱에서도 같은 QR을 띄움

하지 않는 것: 그룹과 초대의 규칙은 만들지 않는다(T45). 차량에서 카메라로 QR을 읽지 않는다. 현대 계정 로그인은 넣지 않는다.

완료 기준: 에뮬레이터 화면에 뜬 QR을 실제 휴대폰 카메라로 찍어 웹앱에서 수락하고, 차량 화면의 구성원 목록에 나타나는 녹화. 기어 D에서 QR이 가려진 캡처. 확인한 휴대폰과 브라우저를 PR에 적음.

위험: 에뮬레이터 화면을 폰으로 찍는 확인이라 실차 화면의 밝기와 거리에서는 다를 수 있다. 폰이 주소를 열려면 `gachita.mangowhois.ai`가 서버에 닿아야 한다(T27). 그 전에는 같은 통신망 안에서만 확인된다.

왜: 주행 중에 보여도 되는 화면에는 제한이 있다. 기어 D에서 '기록 중' 화면이 유지되는지 아직 확인하지 않았다.

### T24 실제 자원을 만들고 클러스터에 올려 확인 (P1) · backend-infra · 선행 T5, T25

왜: 밖에서 붙을 서버가 있어야 폰과 차량이 같은 여행을 본다. 구성은 [ADR-0016](adr/0016-slo-capacity-single-postgres.md)(t4g.large 한 대, Postgres 하나, Cloudflare → ALB → API, SLO 99.5%)을 따른다. 구축 단계는 [ADR-0012](adr/0012-cluster-build-and-node-size.md), 펴기·접기 순서는 ADR-0017(PR #104). 계정은 다른 프로젝트와 같이 쓰는 지금 계정이다(지환, 11/13).

- [ ] Terraform을 세 묶음으로: `account/`(T25), 남는 묶음 `persist/`(T51), 접는 묶음(VPC, 공개 서브넷 둘과 ALB 태그, 노드 보안 그룹, EC2 t4g.large, 파드 역할 `pg`·`alb-controller`). 사설 서브넷·NAT·워커는 만들지 않음(`worker_count` 기본 0)
- [ ] 첫 부팅과 구축 7단계(Ansible), Argo CD 물결 0~5, Postgres 백업(WAL 보관)을 실제 계정에서 확인
- [ ] 비밀 값을 `gh secret set` → `infra-secrets` 워크플로 → SSM → External Secrets 길로 넣음(이미지 받기 토큰, 저장소 읽기 자격, 구글 클라이언트, Cloudflare 토큰)
- [ ] 병합 때 올라간 이미지를 태그 변경 PR로 내보내 보기(T56)
- [ ] 다 쓴 뒤 접고 `Project=gachita` 태그로 남은 것이 남는 묶음뿐인지 확인

하지 않는 것: Traefik·cloudflared·NAT·사설 서브넷·노드 셋(ADR-0015의 구성)은 두지 않는다. ALB와 대상 그룹은 Terraform이 아니라 클러스터의 AWS Load Balancer Controller가 만든다(T27). 같이 쓰는 계정의 다른 프로젝트 자원은 건드리지 않는다.

완료 기준: 밖에서 `https://gachita.mangowhois.ai/healthz`가 200으로 답하고, 태그를 바꾼 PR이 병합되면 새 이미지로 바뀌는 것을 확인. 든 비용을 PR에 적음.

위험: 켜 두면 월 약 $99(ADR-0016). 같이 쓰는 계정이라 적용 역할은 `Project=gachita` 태그와 `gachita-*` 이름이 맞는 자원만 고친다([ADR-0011](adr/0011-aws-credentials-via-oidc.md)). 되돌리기는 `backend/infra/infra.sh down`이고, 백업이 든 데이터 버킷(남는 묶음)은 사람만 지운다.

### T25 자격 증명을 OIDC로 (P1) · backend-infra · 선행 T4

왜: 인프라 자격 증명은 OIDC로 관리하기로 했다. 오래 쓰는 열쇠를 저장소와 서버에 두지 않는다. 설계는 [ADR-0011](adr/0011-aws-credentials-via-oidc.md).

- [ ] GitHub Actions가 열쇠 없이 AWS 역할을 받도록 역할 둘(PR 계획, develop 적용)을 Terraform으로. 이 계정에 이미 있는 GitHub OIDC 제공자(다른 프로젝트가 관리)는 만들지 않고 읽어 씀
- [ ] 신뢰 조건을 GitHub의 불변 sub 형식(`repo:team-pitcrew@351326633/gachita@1455271774:…`)으로 저장소와 브랜치에 정확히 맞춤
- [ ] PR에서 `terraform plan`을 그 역할로 실행
- [ ] 파드는 서비스 계정 OIDC로 역할을 받고(Postgres 백업, ALB 컨트롤러), 서버의 역할(IMDS)에는 닿지 않게 함
- [ ] 같이 쓰는 계정이라 역할과 권한 경계가 우리 자원(`Project=gachita` 태그, `gachita-*` 이름)만 고치게 좁힘. ALB 컨트롤러 몫(ELB, EC2 보안 그룹, ACM 읽기)도 이 조건으로

하지 않는 것: AWS가 아닌 곳의 자격은 OIDC로 바꿀 수 없어 예외로 적는다: 이미지 받기 토큰, 저장소 읽기 자격, 구글 클라이언트 비밀 값, Cloudflare API 토큰.

완료 기준: 저장소와 서버에 오래 쓰는 AWS 열쇠가 없음(`gh secret list`와 서버에서 확인). PR에서 `terraform plan`이 OIDC 역할로 돎. 남는 고정 비밀 값은 문서에 예외로 적음.

위험: 신뢰 조건을 넓게 잡으면 다른 저장소나 브랜치가 역할을 받는다. 같이 쓰는 계정이라 권한을 넓게 잡으면 다른 프로젝트 자원에 닿는다. GitHub OIDC 제공자를 다른 프로젝트가 지우면 우리 워크플로가 역할을 받지 못한다.

### T26 프로필과 여행 데이터를 Postgres 하나 안에서 격리 (P1) · backend-infra · 선행 T23, T24

왜: 유저 프로필과 여행 데이터를 격리하기로 했다. ADR-0016으로 Postgres는 하나(클러스터 `db`, 네임스페이스 `gachita-db`)로 잡고, 격리는 데이터베이스·역할 단위로 한다. 파드 둘로 나누던 앞의 설계(ADR-0013 5절)는 대신한다.

- [ ] 데이터베이스 둘(`trips`, `profiles`)과 소유 역할 둘, `pg_hba`의 교차 거절 두 줄
- [ ] API에 `TRIPS_DATABASE_URL`과 `PROFILES_DATABASE_URL`을 따로 줌(같은 Postgres, 다른 데이터베이스와 역할. 주소는 `db-rw.gachita-db.svc.cluster.local`)
- [ ] 기본 차단 네트워크 정책으로 DB에는 API와 운영자만 닿게 함
- [ ] 실제 클러스터에서 교차 접속 거절, API가 아닌 파드의 DB 접속 거절을 확인
- [ ] 한쪽의 무거운 질의가 다른 쪽을 느리게 할 때의 질의 시간 제한을 정함(코드는 backend-api 담당과 맞춤)

하지 않는 것: Postgres 인스턴스를 나누지 않는다. 대기 복제본은 ADR-0016의 3단계. 저장 장치는 T28.

완료 기준: 실제 클러스터에서 두 역할이 서로의 데이터베이스에 접속하지 못하고, API가 아닌 파드에서 DB 접속이 막히며, API는 두 데이터베이스에 모두 닿음(`/healthz` 200). 정한 질의 시간 제한을 문서에 적음.

위험: Postgres 자체가 뚫리거나 관리자 권한이 새면 둘 다 보인다. 하나가 멈추면 여행과 프로필이 같이 멈추고 같이 복구된다(ADR-0016 2절). 되돌리기는 선언 PR의 revert.

### T27 도메인과 가장자리를 Cloudflare로 (P1) · backend-infra · 선행 T24

왜: 서비스 주소는 `gachita.mangowhois.ai`, 가장자리는 Cloudflare다([ADR-0010](adr/0010-domain-and-cloudflare-edge.md)). 들어오는 길은 ADR-0016대로 Cloudflare → ALB(AWS Load Balancer Controller가 Gateway·HTTPRoute를 보고 만듦, Argo CD가 올림) → API NodePort다. Traefik과 Cloudflare Tunnel은 쓰지 않는다. QR 초대(T46)는 폰이 밖에서 이 주소를 열 수 있어야 한다.

- [ ] AWS Load Balancer Controller(공식 차트 3.6.2)를 물결 3으로 올리고, Gateway(HTTPS 443, ACM 인증서)·HTTPRoute·인스턴스 대상(`/healthz`)으로 ALB를 만듦
- [ ] ALB는 Cloudflare IPv4 대역만 받음. 노드는 ALB 보안 그룹에서 오는 NodePort만 받음
- [ ] `gachita` 레코드(프록시)와 ACM 검증 레코드를 Terraform(Cloudflare 제공자)으로. 영역의 다른 레코드(메일 전달 등)는 읽지도 고치지도 않음
- [ ] 요청 수 제한은 Cloudflare 엣지, 본문 크기 제한은 API
- [ ] 구글 OAuth의 리다이렉트 주소와 서버의 허용 출처를 이 이름으로 맞춤
- [ ] 폰의 이동통신망과 차량(에뮬레이터)에서 이 주소로 닿는지 확인

하지 않는 것: `mangowhois.ai` 영역 전체를 Terraform으로 가져오지 않는다. 네임서버와 메일 설정을 바꾸지 않는다. CloudFront, external-dns, AWS WAF는 두지 않는다. Cloudflare의 유료 기능을 켜지 않는다.

완료 기준: 폰의 이동통신망에서 `https://gachita.mangowhois.ai/healthz`가 200으로 답함. ALB에 Cloudflare 밖에서 직접 닿으면 거절됨. `mangowhois.ai`의 메일 전달이 그대로 동작함(변경 전후의 레코드 목록을 PR에 적음).

위험: 같은 영역에 메일 전달 설정이 있어 레코드를 잘못 건드리면 메일이 끊긴다. ALB가 Terraform 상태 밖이라 접기 전에 edge 앱을 지워야 한다(ADR-0017). API 토큰은 저장소에 넣지 않고, OIDC로 바꿀 수 없어 T25의 예외로 둔다. 원음이나 사진이 Cloudflare를 지나가므로 동의 문구의 제3자 고지에 넣을지 T12와 맞춘다.

### T28 Postgres 저장 장치(EBS CSI) 정하기 (P2) · backend-infra · 선행 T24

왜: Postgres 볼륨(8Gi, ADR-0016)이 서버의 루트 디스크(K3s local-path)에 있다. 서버를 갈면 볼륨도 함께 사라져 백업에서 되살린다(RPO 5분, RTO 30분). 파드 네트워크(CNI)는 Cilium으로 정했다([ADR-0012](adr/0012-cluster-build-and-node-size.md)).

- [ ] Postgres 볼륨을 EBS(CSI)로 옮길지와 방법(같이 쓰는 계정이라 볼륨에도 `Project=gachita` 태그)
- [ ] 옮긴다면 서버를 갈거나 접었다 펼 때 볼륨을 다시 붙이는 절차와, 지금의 백업 복구(T52)와 어떻게 나눌지

하지 않는 것: 노드를 여러 대로 늘리는 구성은 다루지 않는다. CNI는 다시 정하지 않는다.

완료 기준: 결정 기록 한 건과, 정한 대로 바꾼 선언이 병합됨. 바꿨다면 클러스터에서 확인.

위험: 볼륨을 옮기기 전에 데이터를 백업한다. EBS CSI 컨트롤러가 메모리를 더 쓴다(ADR-0016 3절의 표에 더함).

### T49 서울 리전의 VPC 한도를 올린다 (P1) · backend-infra

왜: 같이 쓰는 계정의 서울 리전에 VPC가 5개이고 한도도 5개라 우리 VPC를 만들면 `VpcLimitExceeded`가 났다(Service Quotas `L-F678F1CE`, 11/13 아침 확인).

- [ ] 서울 VPC 한도를 10으로 올림
- [ ] 한도를 `aws service-quotas get-service-quota --service-code vpc --quota-code L-F678F1CE`로 확인

하지 않는 것: 다른 프로젝트의 VPC를 지우거나 고치지 않는다. 기본 VPC를 같이 쓰지 않는다. 고정 IP(EIP)는 쓰지 않는다(ADR-0016은 인스턴스의 공인 IPv4를 나가는 길에만 씀).

완료 기준: 서울 VPC 한도가 6 이상이고 그 값을 이슈에 적음.

위험: 한도 요청은 비용이 없다.

### T50 계정 번호·버킷·역할 ARN을 Git 밖에서 받아 펴기에 사람 손이 없게 한다 (P1) · backend-infra · 선행 T24, T25

왜: 클러스터 선언에 계정 번호 자리 표시(000000000000)가 있어 펴기 전에 사람이 채워야 했다. ADR-0017(PR #104)로 펼 때마다 바뀌는 값(VPC, 서브넷, 인증서)은 태그와 호스트 이름으로 찾고, 계정 번호·버킷·역할 ARN은 비밀이 아닌 고정 값이라 Git에 채워 두기로 했다(PR #109). 그래서 이 티켓의 ApplicationSet 방식은 하지 않는다.

- [ ] 선언의 자리 표시를 실제 계정 값으로 채움(PR #109)
- [ ] `grep -r 000000000000 backend/infra`가 비는지 확인

하지 않는 것: ApplicationSet이나 클러스터 정보 주석으로 값을 넘기지 않는다. 계정을 바꿀 때만 값을 다시 채운다.

완료 기준: `grep -r 000000000000 backend/infra`가 비고, 실제 계정에서 사람 손 없이 펴짐(T53).

위험: 계정을 바꾸면 선언의 계정 값도 PR로 바꿔야 한다.

### T51 접어도 남는 묶음과 접는 묶음을 Terraform에서 나눈다 (P1) · backend-infra · 선행 T24

왜: 접었다 펴도 같은 결과가 나오려면 오래 남는 것과 접는 것을 나눠야 한다. 지금 Terraform 한 묶음에 데이터 버킷(백업)과 발급자 버킷, 서버·네트워크가 같이 있다.

- [ ] 남는 묶음 `persist/`: 데이터 버킷, 서비스 계정 발급자 버킷과 발급자 문서, ACM 인증서와 검증 레코드, Cloudflare 요청 수 제한
- [ ] 접는 묶음: VPC, 공개 서브넷 둘, 노드 보안 그룹, EC2, IAM 역할, `gachita` 레코드(ALB를 태그로 찾았을 때만). 남는 묶음의 값은 이름 규칙으로 읽음
- [ ] 접는 묶음의 `destroy`가 남는 묶음을 건드리지 않음을 실제 계정에서 확인

하지 않는 것: 남는 묶음을 자동으로 지우지 않는다. 계정 묶음(`account/`)은 그대로. ALB는 어느 묶음에도 넣지 않는다(컨트롤러가 만듦).

완료 기준: 접기 뒤 `Project=gachita` 태그로 남은 것이 남는 묶음과 `account/`뿐이고, 다시 펴면 같은 버킷을 씀.

위험: 남는 묶음의 데이터 버킷에는 백업이 있으므로 사람 말고는 지우지 않는다.

### T52 접었다 펴도 Postgres 데이터가 이어지게 한다 (P1) · backend-infra · 선행 T24

왜: Postgres를 언제나 initdb로 만들면 접고 다시 펼 때 데이터가 사라지고, 같은 S3 경로에 WAL이 남아 있으면 보관 검사에 걸려 DB가 뜨지 않는다. Postgres는 하나(`db`, 백업 경로 `postgres/db`)다(ADR-0016).

- [ ] 데이터 버킷에 백업이 있으면 복구(`bootstrap.recovery`, `apps/db/recover/`)로, 없으면 initdb로 시작. 고르는 것은 구축 6단계이고 서버마다 한 번 정해 기록
- [ ] 복구한 뒤 새 타임라인으로 같은 경로에 WAL 보관을 이어 씀
- [ ] 접기 전에 마지막 전체 백업을 받고, 실패하면 접지 않음
- [ ] 실제 계정에서 데이터를 넣고 접었다 편 뒤 같은 데이터가 읽히는지 확인

하지 않는 것: 시점 복구 화면이나 다른 리전 복제는 하지 않는다.

완료 기준: 접었다 편 뒤 접기 전 데이터가 그대로 읽히고 WAL 보관이 이어짐. 결과를 PR에 적음.

위험: 복구를 잘못 고르면 빈 DB로 뜨거나 뜨지 않는다. RPO는 5분(ADR-0016).

### T53 펴기와 접기를 워크플로 한 번으로 묶는다 (P1) · backend-infra · 선행 T24, T25

왜: 지환님 목표는 코드만으로 접었다 펴는 것이다(11/13). 순서는 ADR-0017: ALB가 Terraform 상태 밖이라 접기 전에 edge 앱을 지워 컨트롤러가 ALB를 지우게 한다. 워크플로를 시작하는 것을 비용 승인으로 삼는다.

- [ ] `backend/infra/infra.sh up`: 남는 묶음 → 접는 묶음 → 구축 7단계를 SSM으로 기다림 → ALB active → 레코드 → 대상 건강과 실제 주소 `/healthz`
- [ ] `backend/infra/infra.sh down`: 마지막 백업 → edge 앱 지우기(컨트롤러가 ALB를 지움) → 접는 묶음 destroy → `Project=gachita` 태그로 남은 것 확인
- [ ] `infra` 워크플로(develop, 수동, OIDC 적용 역할)가 같은 스크립트를 부름
- [ ] 적용 역할에 SSM 명령 보내기를 우리 서버 태그로 좁혀 더함
- [ ] 실제 계정에서 접었다 펴기를 두 번 되풀이해 남는 것과 충돌이 없는지

하지 않는 것: 계정 묶음(`account/`)과 남는 묶음은 자동으로 지우지 않는다. 노드를 늘리지 않는다.

완료 기준: `infra` 워크플로 `up` 한 번으로 `https://gachita.mangowhois.ai/healthz` 200과 E2E 통과, `down` 한 번으로 태그 붙은 자원이 남는 묶음만 남음.

위험: 켜 두면 월 약 $99, 접으면 약 $1. 실패하면 중간 상태가 남을 수 있어 다시 돌려도 같은 결과가 되게 짠다.

### T54 실제 주소에 대고 E2E를 돌린다 (P1) · backend-infra

왜: 이미지에 대고 도는 E2E(`.github/scripts/e2e.mjs`, #76)는 주소를 인자로 받는다. 편 뒤와 새 이미지를 내보낸 뒤 `https://gachita.mangowhois.ai`에 대고 같은 스크립트를 돌리면 실제 길(Cloudflare → ALB → API → Postgres 하나)을 본다. ADR-0016의 바깥 점검(가용성 SLI)도 이 스크립트를 쓴다.

- [ ] 실제 주소에 E2E를 돌리는 워크플로(수동 실행, 그리고 다른 워크플로가 부를 수 있게)
- [ ] 실제 DB에 쓰는 시험 데이터를 구분하고 지우는 방법
- [ ] 결과를 워크플로 요약에 남김

하지 않는 것: 부하 시험과 주기 실행은 T62에서 한다.

완료 기준: 워크플로가 주소가 없거나 닿지 않을 때 분명히 실패하고, 닿으면 E2E 결과를 요약에 남김. 실제 주소 확인은 클러스터가 선 뒤.

위험: 실제 DB에 시험 데이터가 쌓인다. 지우는 단계를 같이 둔다.

### T55 물결 E2E를 로컬 K3s 스크립트로 만들어 인프라 PR마다 돌린다 (P2) · backend-infra

왜: 11/13에 Docker 위 K3s로 뿌리 앱부터 `/healthz`까지 물결 E2E를 손으로 돌렸다. CI는 세 폴더의 스키마만 보고, `apps/db`·`apps/edge`·`cluster/argocd`, `account/`·`persist/` 정합성, Ansible 구문은 보지 않는다.

- [ ] 로컬 E2E를 스크립트로(K3s 한 대, 로컬 git 서버, Argo CD, 가짜 비밀 값, 물결 기록, 쿠버네티스 DNS 이름으로 `/healthz`)
- [ ] 인프라가 바뀐 PR에서 그 스크립트를 도는 워크플로(필수 검사 일곱 개는 바꾸지 않음)
- [ ] CI가 안 보던 폴더의 조립·스키마, `account/`·`persist/` validate, Ansible 구문 검사

하지 않는 것: Cilium, ALB 컨트롤러가 만드는 AWS 자원, Cloudflare는 로컬에서 흉내 내지 않는다(edge 앱은 스키마만).

완료 기준: 인프라 PR에서 워크플로가 물결 순서와 `/healthz` 200을 보고 통과. 결과를 요약에 남김.

위험: CI 시간이 10분 안팎 늘어난다. 이미지 받기가 실패하면 거짓 실패가 난다.

### T56 새 이미지 내보내기와 되돌리기를 워크플로로 한다 (P2) · backend-infra

왜: 병합 때 이미지가 GHCR에 올라가지만(#76), 클러스터에 내보내려면 사람이 `make deploy-tag`로 태그를 바꿔 PR을 연다. 되돌리기도 손 명령이다.

- [ ] 병합 때 올라간 태그로 dev 오버레이의 태그를 바꾸는 PR을 자동으로 염
- [ ] 지정한 태그로 되돌리는 워크플로
- [ ] 바뀐 뒤 실제 주소 E2E를 부름

하지 않는 것: PR 병합은 자동으로 하지 않는다(병합은 사람이 정함). Argo CD Image Updater는 두지 않는다.

완료 기준: 이미지가 올라가면 태그 변경 PR이 열리고, 되돌리기 워크플로가 이전 태그 PR을 엶. 실제 내보내기 확인은 클러스터가 선 뒤.

위험: 잘못된 태그가 병합되면 API가 뜨지 않는다. 순차 교체라 옛 파드가 남아 서비스는 이어진다. 되돌리기는 이전 태그 PR.

### T57 상태 확인·구축 다시 돌리기·백업 복구를 운영 워크플로로 한다 (P2) · backend-infra · 선행 T24

왜: 운영 절차(앱 상태 보기, 구축 단계 다시 돌리기, 손 백업과 복구)가 README의 손 명령이다. 지환님 목표는 운영 절차도 코드로 두는 것이다(11/13). ADR-0016의 복구 목표(RPO 5분, RTO 30분)를 지키는 복구 연습도 이 길로 한다.

- [ ] 상태 확인 워크플로(앱 물결 상태, 노드, 백업 시각, ALB 대상 건강, 실제 주소 응답)
- [ ] 구축 단계를 다시 돌리는 워크플로(SSM으로 `gachita-converge`, 단계 고르기)
- [ ] 손 백업과 지정 시점 복구 워크플로

하지 않는 것: 알림(메신저·메일)은 하지 않는다. 소진 속도 알림은 T62.

완료 기준: 세 워크플로가 클러스터가 없을 때 분명히 실패하고, 있을 때 결과를 요약에 남김. 실제 확인은 클러스터가 선 뒤.

위험: 구축 다시 돌리기는 서버를 바꾼다. 같은 결과가 되게 짠 단계만 부른다.
