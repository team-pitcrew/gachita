# 전사록 데이터: 품질을 올리는 데이터, 출처, 다듬기, 넣는 자리

2026-11-14 기준이다. 전사록(차에서 받아 적은 기록본)의 품질을 올리는 데 쓰는 데이터를 적는다: 어디서 오는지, 어떻게 모으고 다듬는지, 파이프라인 어디에 들어가는지, 지금 어디까지 쟀는지. 처리 단계 자체는 `docs/architecture.md`의 '음성 처리 흐름'에 있어 여기서 되풀이하지 않는다.

표시: **실측**은 우리가 돌려 본 것(어디서 봤는지 함께 적음), **구현**은 코드가 있고 서버 시험을 통과한 것, **계획**은 아직 없는 것. 에뮬레이터에서 본 것은 실차가 아니고, 합성 음성은 사람 목소리가 아니다.

## 1. 무엇을 위해, 무엇으로 재나

전사록은 기록본·프로필 피드(T39), 부탁 제안과 도착 브리핑(T40), 장면 후보와 숏폼 자막(T43)에 쓰인다. 가족 대화라 틀리면 가장 아픈 곳은 **이름·호칭·호출어·목적지**다. 피드가 사람에 묶이고, 자막에 이름이 나오고, 호출어를 놓치면 Gleo로 넘겨주지 못한다.

| 지표 | 뜻 | 기준 |
|---|---|---|
| 글자 오류율 | 공백과 문장부호를 뺀 글자 단위 편집 거리 ÷ 정답 글자 수 | 고친 뒤 나빠지지 않을 것 |
| 이름·호칭 정확도 | 정답에 나온 이름·호칭·호출어·목적지 가운데 맞게 적힌 비율 | 60% 이상(T75) |
| 맞던 문장을 깨뜨린 비율 | 원래 정답과 같던 문장을 고쳐서 틀리게 만든 비율(과교정) | 2% 이하(T59) |
| 화자 표시 | 결과마다 좌석 줄·사람이 맞았나 | 측정만(기준 미정) |
| 지연 | 말이 끝나고 최종 결과까지 | 측정만 |

## 3. 모으기

- **기록본(서비스):** 차량 앱이 수음해 Pleos STT로 받아 적고, 발화를 몇 초마다 묶어 올린다. 한 줄은 `{seq, at, text, seatArea, generation, lat?, lng?}`이다(`docs/api/voice.md`). 녹음은 탑승자 모두 동의할 때만 하고, 동의를 끄면 세대가 올라 그때까지의 글과 소리를 지운다. 원음 전체는 차 밖으로 나가지 않는다. 사람이 장면으로 고른 구간만 올라간다(T63 → T76).
- **여행이 아는 낱말:** 따로 모으지 않는다. 여행을 만들고 참가할 때 이미 있는 값(참가자 이름, 프로필, 여행 제목, 차의 목적지)을 그때 읽는다. 사람이 입력한 값이라 소리를 다시 들을 필요가 없다.
- **재전사:** 고른 클립이 올라오면 그 구간의 발화마다 소리를 잘라 보낸다(`ASR_URL`·`ASR_TOKEN`이 있을 때만). 동의 문구에 '그 구간의 소리와 받아 적은 글, 참가자 이름을 외부 음성 인식 서버로 보낸다'고 밝힌다.
- **평가용 합성 대화:** 대본을 먼저 쓰고 정답을 고정한 뒤에 시스템을 돌린다. 대본에는 이름·호칭·호출어·목적지가 나오는 자리와 끝말잇기·아이의 빠른 말·끼어든 말을 일부러 넣었다. 대본은 합성 → 스테레오 섞기 → 에뮬레이터에 오디오로 넣기 → 결과 받기 순서로 처리한다(스크립트는 저장소 밖 실측 폴더).
- **실제 녹음:** 동의한 팀원만 녹음하고, 개인 정보라 저장소에 넣지 않는다. 정답이 없어 사람이 받아 적어야 지표를 낼 수 있다.

## 5. 파이프라인에 넣는 방식: 학습 대신 맥락

**모델을 학습시키지 않는다.**
- 차 안 받아쓰기(Pleos STT)는 바꿀 수 없다. 낱말 힌트나 다른 후보를 주는 공개 API도 없다(문서).
- 가족마다 이름이 달라 미리 모을 학습 데이터가 없다.

대신 **여행이 아는 낱말을 그대로 맥락으로 넣는다.**
- 여행 하나의 낱말은 수십 개라 찾아올 필요가 없다. 임베딩도 검색 색인도 두지 않는다.
- 맥락 문장 하나(`등장인물: …. 호칭: …. 목적지: …. 차 비서 이름: 글레오.`)를 만들어 재전사 요청에 Pleos 초안과 함께 붙인다(`backend/api/providers/asr.js`의 `contextOf`, #183).

| 넣는 자리 | 데이터 | 방식 | 상태 |
|---|---|---|---|
| 재전사(T75) | 클립 소리 + Pleos 초안 + 여행이 아는 낱말 | Nemotron에 한 요청. 초안과 절반 넘게 다르거나 새 되풀이가 생기면 원문을 그대로 둔다 | 구현(#183) |
| 글자만 보정(T59) | Pleos 초안 + 낱말 후보 | 작은 언어모델로 후보 고르기 / Nemotron 글자 보정 | **쓰지 않음**: 소리 근거가 없어 흔한 호칭으로 바꿈('연말에' → '엄마랑'), 2구간 기준 미달 |
| 화자(T37·T38) | 좌석 구역 + 목소리 대조값 | 같은 구역 안에서만 대조, 확신 낮으면 '모름' | 구현 |
| 호출어 찾기(T41) | 호출어 + 잘못 적히는 꼴 목록 | 중간 결과에서 문자열 찾기 | 실측(에뮬레이터, 변형 목록 필요) |
| 장면 후보(T43) | 발화 시각·좌석·사람이 남긴 장면 | 규칙(밀도·말한 사람 수) | 구현(#181) |

## 7. 아직 없는 데이터와 다음 순서(계획)

1. **사람 목소리·실차 소음·아이 목소리.** 지금 값은 모두 합성 음성이다. 동의한 가족의 실제 주행 녹음 30분과 사람이 받아 적은 정답으로 6절을 다시 잰다. 아이는 법정대리인 동의가 필요하다(T12). AI Hub의 공개 아동·차 안 음성은 이용 조건(출처 표시, 상업 이용 범위)을 확인한 뒤 평가용으로만 쓴다.
2. **서비스 경로 그대로 재기.** 56쌍은 정답 시각으로 잘랐다. 서비스는 Pleos 발화 시각으로 자르므로(차가 `at`을 말 시작으로 보낼 때) 그 자르기로 다시 잰다.
3. **사람이 고친 자막을 정답 쌍으로.** 도착 후 화면의 자막 고치기에 저장 계약을 붙이면 원문 ↔ 고친 글 쌍이 쌓인다. 동의 문구와 보관 기간(48시간 시계)을 먼저 정한다.
4. **낱말 사전 넓히기.** 지금 목적지는 여행 제목뿐이다. 차의 내비 목적지·경유지 이름을 여행 문서에 함께 올리면 맥락에 넣는다.
5. **측정 규칙.** 설정을 바꿀 때마다 1구간에서만 맞추고, 2구간 56쌍은 봉인한 설정으로 한 번만 돌린다(T59의 절차). 결과와 스크립트는 저장소 밖 실측 폴더에, 숫자는 이 문서 6절에 남긴다.
6. **다른 방법과 넓은 시험 자료(T79 #190, 재는 중).** 이름·호칭을 더 올리는 경로를 T79가 잰다:
   - 2절 12번 자료로 여러 목소리·차 소음에서 재고, 신뢰 구간을 낸다.
   - 비교하는 방법: 받아쓰기 낱말 힌트(hotwords), 문맥 편향, 여러 결과의 합의(ROVER 식), 확신이 낮을 때만 사람 확인, 모델이 주는 낱말 확률(logprobs)을 신뢰도로 쓰기.
   - T75 재전사 경로도 새 자료로 다시 잰다. 새 자료에는 Pleos 원문이 없어 '소리 + 맥락(`contextOf`와 같은 문장), 초안 없음'을 기준으로 삼는다.
   - 기존 2구간 56쌍도 이 문서의 6절과 같은 방식(정답 시각 ±0.3초, 모노, 같은 판정·채점)으로 다시 만들어, 1구간에서 고른 설정을 봉인한 뒤 한 번만 돈다.

   같은 측정을 두 번 하지 않도록 이 문서는 숫자를 다시 재지 않는다. 결과는 T79의 `docs/research/closed-words.md`(작성 중)와 실측 기록 `research/evidence/20261114-closed-words/`를 따르고, 확정되면 6절에 나란히 옮긴다.
