# 목소리 등록 길이별 화자 대조 정확도 (2026-11-14)

T38(#61) 할 일 4. 목소리를 몇 문장 등록해야 하는지와, 발화 길이에 따라 얼마나 맞히는지를 쟀습니다. 대조기는 서버의 참조 임베더(`backend/api/providers/voice.js`, ADR-0019)이고 기준은 0.9입니다.

**이 표의 값은 macOS 합성 음성을 Mac(Apple M5 Pro, macOS 27.0)에서 잰 것입니다. 사람 목소리, 차 안 마이크, 에뮬레이터에서 잰 값이 아닙니다.**

## 결론

- **등록은 두 문장(약 7초)이면 됩니다.** 3초 발화 기준으로 1문장 85%, 2문장 95%, 3문장 91%입니다. 셋째 문장은 더 올리지 못했습니다(2문장과 3문장의 차이는 이 표본 크기에서 잡음 수준).
- **발화 길이가 정확도를 가릅니다.** 3.2초 발화는 후보가 둘일 때 85~95%를 맞히고 틀림은 0%입니다. 1.4초 발화("Okay, sounds good" 같은 말)는 절반이 '모름'입니다.
- **틀리기보다 모른다고 합니다.** 후보가 둘일 때 틀린 비율은 0~1%이고 나머지는 '모름'입니다. 그래서 줄(앞줄·뒷줄)로 후보를 좁히는 것이 효과가 있고, 화면은 '모름'을 고칠 수 있어야 합니다(T37 할 일 3).
- 후보를 좁히지 않으면(17명 전체) 3초 발화의 1등이 맞는 비율이 94%, 1.4초는 68~71%입니다.
- 학습된 화자 모델(ECAPA)은 ADR-0019대로 이번 범위 밖입니다. 사람 목소리로 같은 표를 다시 재 모자라면 다시 엽니다.

## 표

목소리 17개, 발화 종류마다 목소리당 4개입니다. '두 명 후보'는 그 목소리와 다른 16개 각각을 짝지은 1,088쌍입니다. 앞줄 두 자리처럼 후보가 둘일 때 서버가 내는 판정(높은 쪽이 기준을 넘으면 그 사람, 아니면 모름)을 셌습니다.

## 조건과 한계

- **음성:** macOS `say`의 영어 음성 17개입니다. 여자 8(Samantha, Karen, Moira, Tessa, Flo, Sandy, Shelley, Grandma), 남자 8(Daniel, Rishi, Fred, Ralph, Eddy, Reed, Rocko, Grandpa), 아이 1(Junior)이고 장난 음성은 뺐습니다. 이 Mac에 받아진 한국어 음성은 Yuna 하나뿐이라 영어 문장을 썼습니다. 참조 임베더는 음높이와 스펙트럼만 봐서 언어를 타지 않습니다. 그래도 한국어 가족 대화로 다시 재야 합니다.
- **문장:** 등록 3문장(가족 여행, 목소리 등록, 휴게소 음료), 짧은 발화 4개(1초 안팎), 보통 발화 4개(2~3초)입니다. 등록과 대조에 같은 문장을 쓰지 않았습니다.
- **소리:** 16 kHz 16비트 모노로 바로 만들었습니다. 차 안 소음, 마이크 거리, 두 채널 섞임, Pleos가 자른 발화 경계는 들어 있지 않습니다. 실제 값은 이보다 나쁠 것입니다.
- **합성 음성은 사람보다 쉽습니다.** 같은 목소리는 늘 똑같이 말하고, 다른 목소리끼리는 음색 차이가 큽니다. 11/13 실측도 한 합성 음성의 음높이만 바꾼 것이라 실제 가족의 구분 난이도를 대신하지 못합니다(T38 위험).
- 한 번 잰 값입니다. `say`의 출력은 실행마다 같아서 다시 돌려도 같은 표가 나왔습니다(11/14에 두 번).

## 다시 재는 법

```sh
node docs/research/voice-enroll-length.mjs   # macOS, 2분쯤. 음성 파일은 임시 폴더에 만들고 지운다
```

목소리, 문장, 기준은 스크립트 맨 위의 `VOICES`, `ENROLL`, `SHORT`, `LONG`, `THRESHOLD`입니다. 사람 목소리로 잴 때는 `speak()`를 녹음 파일(16 kHz WAV)을 읽는 것으로 바꿉니다.
