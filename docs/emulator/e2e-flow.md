# 핵심 흐름 E2E 실측 (2026-11-13)

2026-11-13에 Pleos Connect Emulator 2.1.0에서 잰 결과입니다. **모든 값은 에뮬레이터에서 본 것이고 실차가 아닙니다.** 스크립트, 로그, 기록본은 저장소 밖 증거 폴더 `research/evidence/20261113-gachita-e2e/`에 있고, 녹음 파일은 저장소에 넣지 않습니다. 긴 전사 시험은 `research/evidence/20261113-stt-longform/`, 마이크 녹음은 T10 문서(PR #52)에 있습니다.

**결론: 에뮬레이터에서 '차량 수음 → 온디바이스 전사 → 좌석 열 판정 → 목소리 대조 → 프로필에 묶인 기록본 → 부탁 수락 → 경유지 → TTS 안내 → 호출어에서 마이크 반환 → Gleo → 자동 재개 → 주차 감지'가 한 번의 실행으로 이어졌습니다.** 2회 돌렸고 2회차가 끝까지 갔습니다. 되지 않은 것은 둘입니다. 앱이 Gleo를 대신 깨울 수 없어 사용자가 운전대 버튼을 눌러야 하고, 마이크를 넘겨받은 Gleo가 말을 실제로 알아듣는지는 에뮬레이터가 멈춰서 재지 못했습니다.

합성 음성으로 봤습니다. 요청·수락 판정과 목소리 대조, 기록본 저장은 차량 앱이나 서버에 아직 없어 시험 스크립트(Mac)가 대신했습니다. 기준 문서는 민준님의 `같이타_공모전_참가신청서_문구정리본_2026-11-13`입니다.

## 누가 무엇을 했나

| 자리 | 한 일 | 구현 |
|---|---|---|
| 차량 앱(프로브 앱) | 마이크 포그라운드 서비스에서 `AudioRecord` 스테레오 수음, 같은 소리를 Pleos STT(ON_DEVICE)에 `sendAudio()`로 넣어 전사, 발화마다 어느 채널이 컸는지 판정, 전사에 호출어가 보이면 수음을 멈춤, 포커스가 돌아오면 다시 수음, NaviHelper 경유지, Pleos TTS | 실제 SDK 호출 |
| 시험 스크립트(Mac) | 0.1초 조각 수신, 발화별 목소리 대조, 기록본·프로필 피드 저장, "화장실"·"휴게소 가자" 같은 낱말 규칙, 운전대 PTT 대신 `cmd voiceinteraction show`, 기어·속도(Virtual Console) | 서버·앱 로직의 대역 |
| 넣은 소리 | 가족 4명 역할의 합성 음성. 왼쪽 채널 = 앞줄(아빠·엄마), 오른쪽 채널 = 뒷줄(아들·딸) | gRPC `injectAudio`, 호스트 마이크 안 씀 |

## 단계별 결과 (2회차 `e2e-r2`, 94.8초)

| # | 단계 | 본 것 | 판정 |
|---|---|---|---|
| 1 | 수음 시작 | 앞 화면에서 마이크 서비스 시작. 입력 장치 `Built-In Mic`, 2채널 16 kHz. 조각 948개가 빠짐없이 Mac에 도착 | 됨 |
| 2 | 목소리 등록(주차, 문장 2개씩) | 8문장 모두 전사되고 채널로 앞줄·뒷줄이 갈림 | 됨 |
| 3 | 주행 맥락 | `requestRoute` 강릉역 → `onRouteStarted`(195 km, 8,160초, 통행료 6,860원). 기어 D, 80 km/h. 내비가 앞으로 나오고 우리 서비스는 계속 수음(중요도 125) | 됨 |
| 4 | 대화 전사 | 5문장 모두 최종 결과. 말이 끝나고 0.58~0.70초 뒤(가운데 0.64초). "바다는 왜 짜?"는 두 번 다 틀림("바다는 왜 자", "사다리 모이자") | 됨(짧은 물음은 틀림) |
| 5 | 좌석 열 | 발화 8개 모두 맞음(등록 뒤 기준). 한 채널이 말할 때 다른 채널은 완전한 무음 | 됨 |
| 6 | 목소리 대조 | 좌석 열 + 목소리 7/8, 목소리만 6/8. 뒷줄의 "화장실 가고 싶어"(아들)를 딸로 잘못 붙임 | 간이 대조기라 부족 |
| 7 | 부탁 → 수락 → 경유지 | "화장실 가고 싶어" 보관 → "응 다음 휴게소 가자" 수락 → `addWaypoint` 용인휴게소 강릉방향 → 7.6초 뒤 `onWaypointChanged(ADD)`(29 km, 1,680초). 그 사이 `onRouteCancelled`로 안내가 한 번 끊김 | 됨 |
| 8 | 말로 안내 | 콜백 직후 Pleos TTS "용인휴게소를 경유지로 추가했어요." 수락 뒤 7.64초에 시작, 10.22초에 끝 | 됨 |
| 9 | 호출어 감지 | "글레오"를 STT가 "클레오"로 적음. 중간 결과에서 감지(소리 넣기 시작 1.8초 뒤) → 0.11초 안에 `AudioRecord` 정지. 서비스는 유지 | 됨(표기가 흔들림) |
| 10 | Gleo 진입 | 정지 1초 뒤 PTT → Gleo `ListeningPassiveState`. 같은 순간 우리 앱에 `AUDIOFOCUS_LOSS_TRANSIENT` | 됨(버튼은 사람이 눌러야 함) |
| 11 | 자동 재개 | Gleo가 5.0초 뒤 잠듦 → 우리 앱에 `AUDIOFOCUS_GAIN` → PTT 뒤 6.13초에 수음 재개. 내비가 앞에 있는 상태(화면 뒤)에서 서비스 안에서 다시 시작 | 됨 |
| 12 | 재개 뒤 전사 | 2문장 모두 전사, 좌석 열과 프로필 모두 맞음 | 됨 |
| 13 | 주차 | 속도 0, 기어 P → `GEAR_SELECTION` 콜백(값 4) | 됨 |
| 14 | 기록본 | `record.json`(발화 16개: 시각, 좌석 열, 프로필, 글자, 원음 구간), 부탁 1건(보관 → 수락 → 경로 반영), 도착 할 일 2건(마트, 숙소), 프로필별 피드 4개 | 됨(Mac 대역) |

1회차(`e2e-r1`)는 9번까지 같았고, 11번에서 Gleo가 아직 듣는 중에 재개했습니다. 재개 판단을 '다른 녹음이 보였다 사라짐'으로 했는데, **Gleo의 녹음은 일반 앱의 `getActiveRecordingConfigurations()`에 보이지 않았습니다.** 2회차에서 오디오 포커스로 바꿨습니다. 1회차의 12번은 시험 스크립트가 소리 넣기를 겹쳐 보내 실패했습니다(gRPC `FAILED_PRECONDITION`).

## 좌석별 음향

- 에뮬레이터가 알리는 입력 장치: `Built-In Mic`(1~2채널), `Built-In Back Mic`(1~2채널), `Echo-Reference Mic`, 좌석 구역용 `input_bus_tone_zone_0`·`1`(48 kHz 2채널), 튜너. 마이크 정보는 `builtin_mic1`~`4` 넷이 모두 `Built-In Mic` 아래입니다.
- 왼쪽에만 넣은 말은 왼쪽 채널에만(−14~−18 dBFS), 오른쪽에만 넣은 말은 오른쪽 채널에만 녹음됐고 반대쪽은 −90 dBFS였습니다. 앞·뒤 마이크 장치 모두 같았습니다(두 장치가 같은 가상 입력을 받음).
- 그래서 에뮬레이터에서는 **2채널을 좌석 두 구역으로 쓰는 것까지** 볼 수 있습니다. 4자리를 따로 받는 것, 실차에서 채널이 어느 자리인지, 자리 사이에 소리가 새는 정도는 볼 수 없습니다.
- Pleos SDK에는 화자·좌석을 주는 공개 API가 없습니다. STT SDK 안의 `AmbientAiApi`(화자 인식·목소리 등록·음원 분리)는 특권 앱 전용입니다(11/13 STT 시험).

## 화자 식별

- 시험에 쓴 대조기는 음높이와 MFCC 평균을 비교하는 간이 방식(numpy)입니다. 서비스에 쓸 모델이 아닙니다. 네 목소리는 한 합성 음성의 음높이만 바꾼 것입니다.
- 이 조건에서도 2~4초 발화에서는 틀렸습니다(목소리만 6/8). 좌석 열로 후보를 둘로 줄이면 7/8이었습니다. **좌석 열은 차량 앱에서 바로, 같은 열 안의 구분은 학습된 화자 모델과 더 긴 등록이 필요합니다.**
- STT는 좌우를 더한 모노를 받았고 전사는 영향이 없었습니다.

## Gleo와 마이크

| 확인한 것 | 결과 |
|---|---|
| 전사에서 호출어 찾기 | STT가 "글레오"를 6번 중 4번 "클레오"·"클리오"로 적음(`w1-wake-spelling`). 변형 목록으로 찾아야 하고 오탐 가능성이 있음 |
| 마이크 반환 | `AudioRecord.stop()`만으로 충분. 서비스와 객체를 둔 채 PTT가 받아들여짐 |
| 앱이 Gleo를 깨우기 | 못 함(11/13 T10: `ACTION_ASSIST`는 듣기로 가지 않음). 사용자가 운전대 버튼을 눌러야 함. 호출어 뒤에 이어 한 말은 우리도 Gleo도 받지 못함 |
| Gleo가 쓰는 중임을 알기 | 미디어 오디오 포커스를 쥐고 있으면 PTT 순간 `LOSS_TRANSIENT`, Gleo가 잠든 약 1초 뒤 `GAIN`. 비서 용도 재생(효과음·답변 음성)도 보임. Gleo의 녹음은 안 보임 |
| Gleo가 실제로 답할 때(`gleo-first-r1`, 새 부팅 직후) | "오늘 날씨 어때" → PTT 뒤 1.8초에 듣기(`ListeningActiveState`) → 3.3초에 생각 → 7.2초에 답(`AskingState`) → 18.1초에 다시 듣기 → 23.1초에 잠듦 → 24.1초에 우리 앱 포커스 복귀. 그 0.13초 뒤 수음을 시작해 2문장 전사 |
| 넘겨받은 Gleo가 말을 알아듣는지 | **재지 못함.** 우리 앱이 수음한 적이 있는 부팅에서 Gleo만 듣는 중에 소리를 넣자 에뮬레이터가 2번 멈춤(05:57, 06:04, `audio_forwarder_enable` SIGSEGV) |

- 포커스를 쥐는 것은 시험용입니다. 실제 앱이 미디어 포커스를 쥐면 사용자의 음악이 멈춥니다. 어떤 포커스로 같은 신호를 받을지는 정하지 않았습니다.
- Gleo를 한 번 쓰면 말이 없어도 약 6초, 답을 들으면 약 24초 동안 우리 전사가 비었습니다.

## 재지 못한 것

- 실차, 사람 목소리, 실제 소음, 스피커 소리가 마이크로 되돌아오는 경우(에뮬레이터는 되돌아오지 않음)
- 목적지·경유지에 실제로 도착했다는 알림(차 위치를 옮기지 않음). 주차는 기어 P 콜백으로만 봄
- 겹쳐 말하기에서의 좌석·화자 판정, 4자리 구분
- 서버 저장. 기록본은 Mac의 JSON 파일이고 백엔드에는 발화·피드 API가 아직 없음
- 영상 생성, 동의 화면, 48시간 보관·삭제
- 반복 횟수. 끝까지 간 실행은 1회, Gleo 응답 실측도 1회

## 다시 돌리기

증거 폴더의 `scripts/`에 있습니다. 에뮬레이터를 `-grpc 8556 -grpc-use-token -audio none`으로 Cold boot하고 `adb forward tcp:8088 tcp:8088`, 프로브 앱을 설치한 뒤 `make-family.py`로 소리를 만들고 `e2e.py <실행 이름>`을 돌립니다. Gleo가 실제로 답하는 장면은 새로 켠 직후 `gleo-first.py`로 따로 돌립니다. 값은 `results.json`에 모았습니다. 프로브 앱은 이 저장소 밖(`tools/feature-probe`)에 있습니다.
