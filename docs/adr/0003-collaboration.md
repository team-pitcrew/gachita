# ADR-0003: 네 파트, 자동으로 도는 티켓, 한 이미지

* **상태:** 채택됨, 2026-11-12 (지환님 요청)
* **관련:** T16, T14, T21~T28

## 배경

작업을 나눠 맡는 사람은 상현님과 지환님 둘입니다. 지환님이 협업 설정을 먼저 끝내고 인프라는 뒤로 미루라고 했습니다. 요청은 다음과 같았습니다.

- PR 양식과 커밋 양식을 Google SRE 기준으로, SOVA 설정을 참고해.
- 작업 범위는 넷: 프론트의 피그마 전 단계(상현), 피그마 이후 단계(지환), 백엔드의 비즈니스 로직(상현), 인프라(지환).
- CI는 그 네 파트 중 바뀐 것만 검사하고 빌드. 서버는 모놀리식 하나, 이미지도 하나.
- 이슈를 티켓으로 쓰고, 이슈·PR·프로젝트의 연동에 사람이 끼지 않게.
- 로컬에서 이미지를 만들어 GHCR에 올리고, 정상으로 묶이면 GitOps로 내보냄.

## 결정

- **파트:** `frontend-spec`, `frontend-app`, `backend-api`, `backend-infra`. 경로와 담당은 `.github/parts.json` 한곳에 두고 CODEOWNERS, 이슈 양식, CI 범위, 티켓 담당이 따릅니다.
- **양식:** 제목과 본문은 Google의 변경 설명 쓰는 법을, PR의 위험·내보내기·되돌리기 칸은 SRE의 변경 관리와 출시 점검표를 따릅니다. 장애는 비난하지 않는 사후 검토 양식으로 남깁니다.
- **티켓:** 번호, 라벨, 담당, 상태를 GitHub 워크플로가 옮깁니다. 사람은 체크 상자만 체크합니다. SOVA는 계획 문서와 이슈를 스크립트로 맞추고 상태 일부를 손으로 옮겼는데, 여기서는 브랜치와 PR 이벤트로 상태를 옮깁니다.
- **CI:** 검사 일곱 개가 항상 결과를 내고, 범위 밖 파트는 할 일 없이 통과합니다(SOVA의 방식). 워크플로를 경로로 건너뛰면 필수 검사가 '대기'로 남기 때문입니다.
- **이미지:** API와 웹앱을 한 이미지에 담습니다. 평소에는 로컬에서 `make push`로 올리고, 태그를 바꾸는 PR이 병합되면 Argo CD가 내보냅니다. CI는 이미지가 만들어지고 뜨는지만 봅니다.

## 같은 날 정했지만 아직 하지 않은 것

지환님이 방향만 정했고, 인프라 우선순위를 미뤄 티켓으로 남겼습니다.

| 방향 | 티켓 |
|---|---|
| OAuth로 사용자 프로필을 만드는 것과 현대차 개인 프로필 연동을 서로 다른 기능으로 둠. 앞서 정한 'OAuth 없음'은 기기 프로필에만 해당 | T21, T22 |
| 사용자 프로필과 여행 데이터를 격리. 노드가 하나라 파드로 나누고 네트워크로 막음 | T23, T26 |
| 인프라의 자격 증명은 OIDC로 | T25 |
| 리버스 프록시는 AWS가 제공하는 것으로 | T27 |
| 저장 장치와 네트워크(CSI, CNI) | T28 |

## 결과

- 파트 이름을 바꾸면 `parts.json`, 이슈 양식의 선택지, CODEOWNERS를 같이 고쳐야 하고, 어긋나면 `scope` 검사가 실패합니다.
- 프로젝트 보드 연동은 토큰이 있어야 돕니다. 토큰이 없으면 라벨까지만 맞춥니다.
- 티켓 자동화는 `develop`에 병합된 뒤부터 돕니다. 실제 이벤트로는 이 결정이 병합된 뒤에 처음 확인됩니다.
