# ADR-0004: 현대 계정 연동은 구조만 먼저 나누고 구현은 제휴 확인 뒤에

* **상태:** 채택됨, 2026-11-13
* **관련:** T22, #27, T21, ADR-0003

## 배경

기기 프로필은 기기를 바꾸면 이어지지 않는다. T21이 일반 OAuth로 계정 프로필을 만들고, T22는 현대차 통합계정 연동을 다룬다. ADR-0003에서 둘은 서로 다른 기능으로 두기로 했다.

조사한 것(2026-11-13, 공개 문서 기준 — [계정 API 소개](https://developers.hyundai.com/web/v1/hyundai/account_api), [API 활용 가이드](https://developers.hyundai.com/web/v1/hyundai/guide_api)):

- Hyundai Developers(developers.hyundai.com)가 계정 API와 데이터 API를 공식 제공한다.
- 계정 API는 OAuth2 인증코드 방식이다. 로그인 인증 요청으로 현대 통합계정 창을 열고, 사용자가 차량별 접근 권한에 동의하면 인증코드가 redirect URL로 오고, 이를 사용자 토큰(발급·갱신·삭제)으로 바꾸며, 사용자 정보 조회로 프로필을 얻는다.
- 데이터 API는 개인정보 제3자 제공 동의를 거쳐 내 차량 리스트(carId)와 차량 상태를 준다.
- 조건: 서비스 콘솔에서 개발 프로젝트를 등록해 Client ID/Secret을 받아야 한다. 차량 데이터는 블루링크 커넥티드카 소유 고객으로 한정되고 공유받은 차량은 제외된다. 대고객 상용화는 별도 프로세스(서비스 약관 등록·심사)를 밟는다.
- Pleos 콘솔의 SDK 상태에도 '제휴 필요(Affiliation Required)' 범주가 있다(2026-10-29 공모전 설명회).
- 확인하지 못한 것: 팀 자격으로 콘솔 프로젝트를 등록할 수 있는지와 심사 소요 기간, 사용자 정보 조회의 정확한 응답 필드(로그인 필요), 계정 API만 쓸 수 있는지(데이터 API 동의가 앞에 오는 구조).

## 검토한 선택

1. **지금 구현한다.** 프로젝트 등록과 심사 조건, 일정(P0 제출 11/14)을 채울 수 없다. 기각.
2. **연동을 아예 배제한다.** 기획서 v4가 현대 계정 연동을 후속 제휴로 두므로, 경계만은 미리 정해 둘 가치가 있다. 기각.
3. **T21 OAuth 코드에 현대 제공자를 함께 넣는다.** ADR-0003의 '서로 다른 모듈' 방침과 어긋난다. 기각.
4. **모듈 경계와 명세 초안만 정하고 구현은 조건 확인 뒤.** 채택.

## 결정

- 현대 계정 연동은 T21의 OAuth 프로필과 같은 '제공자' 자리를 따르되 **별도 모듈**로 둔다. 예: `backend/api/providers/standard.js`(T21)와 `backend/api/providers/hyundai.js`(T22). 프로필 표와 여행 흐름은 제공자가 누군지 모른다.
- 현대 제공자가 맡는 것: 인증코드 교환, 토큰 갱신·삭제, 사용자 정보 조회, carId 확보. 차량 상태·경고등 같은 데이터 API는 이 연동의 범위 밖이다.
- 계정과 차량을 잇는 값은 현대 API의 carId를 기본으로 하되, 차 안에서 읽는 차대번호(VIN, Pleos Vehicle SDK)와의 대응은 제휴 조건을 확인한 뒤 정한다. 지금 정하지 않는다.
- 구현을 다시 여는 조건: ① 콘솔 프로젝트 등록과 Client ID/Secret 확보 ② 공유받은 차량 제외가 같이타 쓰임(가족·친구 차량)에 어떤 영향을 주는지 검토 ③ 상용화 조건 확인. 하나라도 확인되면 이 기록을 고치는 PR과 함께 티켓을 다시 나눈다.

## 결과

- `docs/api/external.md`에 현대 계정 API 향을 넣고 결정 칸에 '구현 유보(ADR-0004)'를 적는다.
- 이 결정으로 코드는 바뀌지 않는다. T21은 이 경계 안에서 일반 OAuth를 구현한다.
- P0 제출(11/14)과 2차 PT(12/3~4) 범위에는 현대 계정 연동이 들어가지 않는다.
