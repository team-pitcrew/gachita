# ADR-0022: 숏폼은 구성 재생, 기기에서 만드는 영상, 꺼 둔 서버 생성 세 가지로 둔다

* **상태:** 채택됨, 2026-11-14 — 쇼츠 영상 파일 기능을 유지하고 문서를 코드(develop `dff62ce`)에 맞춤(지환님, 11/14)
* **대체:** [ADR-0021](0021-shortform-as-composition-data.md)의 '영상 파일을 만들지 않는다'와 '외부 영상 업체를 쓰지 않는다'. ADR-0021의 나머지(장면 후보 규칙, 숏폼 구성 데이터, 클립을 기존 API 주소에서 머리말 인증으로 내줌, `media` 하위 도메인을 두지 않음, 클립 저장)는 그대로 유효하다.
* **관련:** T43(#63), T83(#239·#244·#245), T85(#252·#257), T86(#255), T63(#117), [ADR-0020](0020-media-delivery-subdomain.md), [ADR-0013](0013-network-edge-and-isolation.md) 7절, [힉스필드 쇼츠 생성 API](../api/short-generation.md)

> **11/14 T90으로 대체됨(보관 기간).** 이 문서의 '48시간' 보관·만료 문장은 옛 결정입니다. 지금은 여행·발화·원음 클립·영상·공유를 시간이 지났다는 이유로 지우지 않고, 사람의 요청(삭제, 동의 철회)으로만 지웁니다 — `backend/api/retention.md`. 나머지 결정은 그대로입니다.

## 배경

ADR-0021은 숏폼을 영상 파일 없이 구성 데이터(클립 소리, 자막 큐, 말한 사람)로 내주고, 웹과 차가 그 자리에서 재생하기로 했다. 외부 영상 업체는 #117 조사(기본 약관상 학습에 씀, 국외로 옮김, 18세 이상만 씀)를 이유로 쓰지 않기로 했다.

그 뒤 develop에 영상 파일을 만드는 코드가 두 갈래로 들어왔다.

- **기기에서 만드는 영상**(#239·#244·#245): 웹과 차가 구성 데이터와 클립으로 영상 파일을 만든다.
- **서버의 힉스필드 생성**(T85 #252·#257, T86 #255): API가 힉스필드(Seedance 2.5)에 두 캐릭터의 반응 장면을 맡기고, 원음과 자막을 합쳐 MP4로 둔다.

11/14에 지환님이 이 기능을 유지하고 문서를 코드에 맞추기로 했다.

## 검토한 선택

| 선택 | 좋은 점 | 걸리는 점 |
|---|---|---|
| 영상 코드를 걷고 ADR-0021로 돌아감 | 문서를 고치지 않음 | 병합된 코드를 걷어야 함. 파일로 저장·공유할 수 없음 |
| 기기 영상만 남기고 서버 생성을 걷음 | 서버 밖으로 나가는 것이 없음 | T85·T86 코드와 배포를 걷어야 함 |
| **셋 다 두고 서버 생성은 꺼서 배포** | 코드와 문서가 맞음. 서버 생성을 켜는 결정을 따로 남김 | 꺼 둔 기능의 남은 위험을 문서로 들고 있어야 함 |

## 결정

### 1. 숏폼의 세 가지 형태

| 형태 | 어디서, 어떻게 | 서버 밖으로 나가는 것 | 상태(`dff62ce`) |
|---|---|---|---|
| 구성 데이터 재생 | 웹 9:16 쇼츠 화면, 주차 중 차. `GET /api/trips/{code}/shortform`과 클립 | 없음(기존 주소의 API가 클립과 JSON을 내줌) | 있음(ADR-0021 2·3절) |
| 기기에서 만드는 영상 | 웹 `short-film.js`: 540×960 캔버스와 클립 소리를 `MediaRecorder`로 녹화해 현재 장면 하나를 파일로 만든다. 브라우저가 고르는 대로 MP4 또는 WebM이다. '영상 저장'은 내려받기, '공유'는 Web Share. 차 `ShortVideoExport.kt`: MediaCodec·MediaMuxer로 앞 45초까지 MP4를 만들어 갤러리 `Movies/Gachita`에 저장하고, '공유'는 Android 공유 창 | 없음. 기기는 구성 데이터와 클립만 받고, 만든 파일을 서버로 올리지 않음 | 코드와 단위 시험 있음(#239·#244·#245) |
| 서버의 힉스필드 생성 | API(T85): `GET /api/short-templates`, `POST /api/trips/{code}/short-plans`, `POST`·`GET`·`DELETE /api/trips/{code}/short-generations[/{id}]`, `GET …/{id}/file`. Seedance 2.5, 9:16, 720p. 자막과 원음은 서버가 FFmpeg로 합치고 결과는 S3에 둔다 | 캐릭터 PNG 둘(앱에 든 그림, 사진 아님), 발화 시각, 반응 지시. `audioReference:true`이면 장면 원음 조각도 | 배포했으나 꺼짐. 아래 2절 |

### 2. 서버 생성은 꺼서 배포한다

- 운영 배포는 `SHORTS_ENABLED=false`다(`backend/infra/gitops/apps/api/base/deployment.yaml`). 그래서 생성 요청은 503이고, 라이브 `/api/short-templates`는 `"enabled":false`를 준다(11/14 15시대에 확인).
- 키는 SSM에서 ExternalSecret `higgsfield`로 들어온다. 키가 있어도 `SHORTS_ENABLED`가 `true`가 아니면 생성하지 않는다.
- 차·웹 앱에는 이 API를 부르는 화면이 없다. 실제 생성 품질과 비용은 확인하지 않았다(시험의 공급자 영상은 대역).
- 켜는 것은 비용과 외부 발송이므로 지환님 승인으로 따로 정한다(AGENTS.md 8).

코드가 지금 거는 조건:

- 부르는 참가자와 동승자 전원이 녹음에 동의해야 한다(아니면 403).
- 제작 요청에 `externalGenerationConsent: true`가 있어야 한다. 주행 중이면 409다.
- `audioReference`의 기본값은 `false`다. 프롬프트에 대화 원문과 참가자 실명을 넣지 않는다.
- 만든 사람만 취소·삭제한다. 하루 생성 초 합계는 기본 120초다.
- 결과와 참조 자료는 여행 생성 뒤 48시간까지만 내준다. 삭제·철회·만료 뒤 S3 자료를 지우고 공급자 요청도 취소하거나 지운다.

### 3. 결과 파일이 나가는 길 — ADR-0020은 다시 살리지 않는다

- 서버가 만든 MP4는 `GET /api/trips/{code}/short-generations/{id}/file`로 나간다. 기존 주소(`gachita.mangowhois.ai`)의 API가 참가자 토큰 머리말을 확인하고, S3에서 읽어 통째로 준다(`video/mp4`, `Cache-Control: private, no-store`). 범위 요청은 받지 않는다.
- API는 결과의 S3 주소를 앱에 주지 않는다. 서명한 S3 주소(최대 1시간)는 힉스필드가 입력을 받아 가는 데만 쓴다.
- 기기에서 만드는 영상은 서버를 지나지 않는다.
- 그래서 `media` 하위 도메인, 영상 전용 ALB, 쿠키 인증은 만들지 않는다. ADR-0020은 대체된 채로 둔다.

### 4. ADR-0021이 힉스필드를 거절한 이유와 지금 코드

법적 판단은 적지 않는다. 코드가 하는 것과 하지 않는 것만 적는다.

| ADR-0021의 이유(#117) | 지금 코드가 하는 것 | 남은 위험 |
|---|---|---|
| 기본 약관상 입력을 학습에 씀 | 기본으로 원음을 보내지 않음(`audioReference:false`). 대화 원문·실명·위치를 프롬프트에 넣지 않음. 참조 이미지는 앱에 든 캐릭터 그림 | 학습 제외 설정이나 별도 계약은 코드와 문서에 없음. `audioReference:true`이면 아이 목소리가 든 원음 조각이 나감 |
| 국외로 옮김 | 기본으로 나가는 것을 캐릭터 그림·발화 시각·반응 지시로 줄임. 결과 뒤 공급자 요청을 취소하거나 지움 | 그래도 요청은 서버 밖 공급자로 나감. 외부 생성과 국외 이전을 밝히는 동의 문구가 없음(부르는 화면이 아직 없음). 공급자 쪽 삭제는 비동기이고, 접수 여부를 모르는 작업(`submission_unknown`)은 원격 삭제를 확인할 수 없음 |
| 18세 이상만 씀 | 나이를 확인하는 코드 없음. 동승자 전원 녹음 동의와 `externalGenerationConsent` 하나로 시작 | 요청한 참가자의 나이나 역할(보호자인지)을 보지 않음 |

ADR-0021에 없던 위험도 둘 생긴다.

- **기기에 남는 파일.** 기기에서 만든 영상과 내려받은 서버 영상은 동의 철회와 48시간 만료 뒤에도 기기에 남는다. 앱은 "저장한 영상은 동의를 꺼도 기기에 남아요."라고 알린다.
- **Cloudflare를 지나는 영상.** ADR-0021 3절은 '나가는 것이 작은 오디오와 JSON이라 Cloudflare 약관의 영상·큰 파일에 해당하지 않는다고 본다'고 했다. 서버 생성을 켜면 MP4가 같은 주소로 나가므로 이 판단을 다시 봐야 한다.

## 결과

- **비용:** 기기 영상은 서버 비용이 없다. 서버 생성은 켜면 공급자 요금이 들고, 하루 120초 한도가 상한이다. API 이미지에 ffmpeg·libass·한국어 글꼴이 들어가고, 생성 중에는 `/tmp`와 더 큰 메모리가 필요하다([생성 API](../api/short-generation.md)).
- **되찾은 것:** ADR-0021이 잃는다고 적은 '파일로 내려받기·SNS에 올리기'를 기기 영상으로 한다. 서버 생성은 캐릭터가 움직이는 장면을 더한다(꺼짐).
- **확인하지 못한 것:**
  - 실제 힉스필드 생성 품질과 비용
  - 기기 영상을 실제 휴대폰과 실차에서 만들고 저장하는 것
  - 웹이 브라우저마다 MP4를 만드는지 WebM을 만드는지
  - Cloudflare 약관 해석(문의하지 않음)
