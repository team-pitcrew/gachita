# ADR-0027: API는 미디어의 CloudFront 서명을 내주고 프로필 사진을 S3에 둔다

* **상태:** 채택됨, 2026-11-16 — [ADR-0026](0026-media-cdn-cloudfront-s3.md)(길·버킷 정책·키, 인프라)의 API 쪽이다(T178). 값이 들어오기 전까지 응답과 동작은 지금과 같다
* **바꾸는 것:** [ADR-0009](0009-family-group-and-qr-invite.md)의 프로필 사진 저장 위치(DB → S3), [ADR-0020](0020-media-delivery-subdomain.md) 4절의 '토큰을 URL에 넣지 않는다'(폰 웹 주소에 10~15분짜리 서명을 싣는다 — ADR-0026이 길을 바꿨고 여기서 응답 계약을 정한다)
* **관련:** T178(#613), T179(#614), [쇼츠 생성 API](../api/short-generation.md), [음성 문서](../api/voice.md), [계정](../api/accounts.md)

## 배경

오너 지시(11/16): 웹이 느리다. 쇼츠·프로필 사진 같은 파일은 CDN-S3로 내주고, 프로필 사진도 S3에 두고, 접근은 키로 한다. 웹 화면 파일도 옮긴다. 통상적인 방법을 쓴다.

ADR-0026이 CloudFront 배포(원본 = 클립 버킷, OAC, trusted key group)와 값이 오는 길을 정했다. 남은 것은 API다: 누구에게 서명을 주는지, 응답의 어느 자리에 싣는지, DB에 있는 프로필 사진을 어떻게 옮기는지.

## 결정

1. **API는 권한을 확인하고 서명만 내준다.** 서명은 canned policy(객체 하나 + 만료 시각)이고 SDK 없이 Node `crypto`로 만든다(`providers/media-cdn.js`): 정책 글을 RSA-SHA1로 서명 → base64 → CloudFront 치환(`+`→`-`, `=`→`_`, `/`→`~`).
2. **값 셋이 다 있을 때만 켜진다:** `MEDIA_CDN_BASE`, `MEDIA_KEY_PAIR_ID`, `MEDIA_PRIVATE_KEY`(RSA PEM). 하나라도 없으면 응답에 아무것도 더하지 않고 지금처럼 API가 본문을 준다. 개인 키가 잘못 들어온 환경도 서명 없이 돈다(경고 기록).
3. **CDN이 읽을 수 있는 접두사만 서명한다:** `shorts/`와 `profiles/`(ADR-0026 1절의 버킷 정책). 원음 클립(여행 코드 아래)과 기기 영상(`short-assets/`)은 서명해도 CDN에서 403이라 지금처럼 API로 받는다. 인프라가 접두사를 더 열면 그때 더한다.
4. **기존 필드와 경로는 그대로 두고 필드를 더한다**(v1.0.0 APK와 지금 웹이 쓰는 것을 바꾸지 않는다).

   | 자리 | 더하는 필드 | 객체 |
   |---|---|---|
   | 쇼츠 작업 한 건(`GET …/short-generations/{id}`)의 `result` | `mediaUrl`, `mediaAuth` | `shorts/{id}/final.mp4` |
   | 같은 응답의 표지 | `thumbnailMediaUrl`, `thumbnailMediaAuth` | `shorts/{id}/thumbnail.png` |
   | 콘텐츠 기록(`GET /profiles/me/trips`, `GET …/contents`)의 생성 영상 항목 | `mediaUrl`, `mediaAuth`, 표지가 있으면 `thumbnailMediaUrl`, `thumbnailMediaAuth` | 위와 같음 |
   | 내 프로필, 그룹 구성원 | `photoUrl`, `photoAuth` | `profiles/{id}/photo/…` |
   | `GET /api/config` | `mediaBase`, `assetBase`(8번) | — |

   `…Url`은 서명이 붙은 주소(폰 웹이 `<video src>`·`<img src>`에 그대로), `…Auth`는 `{url, expires, signature, keyPairId}`다. 차량 앱은 `url`을 부르며 `Cookie: CloudFront-Expires=…; CloudFront-Signature=…; CloudFront-Key-Pair-Id=…` 머리말을 붙인다(Pleos 앱은 토큰을 URL에 넣지 않는다).
5. **서명은 그 파일을 받을 수 있는 요청에만 낸다.** 지금 파일 경로가 보는 것과 같다: 여행 참가자, 보는 사람의 녹음 동의, 참가자 전원의 동의, 완성됐고 지금 동의 세대의 것, 원본(원음·줄 구성·화자·캐릭터)과 같음. 그래서 한 건 조회와 콘텐츠 기록에만 붙이고, 줄마다 원본을 다시 보지 않는 작업 목록(`GET …/short-generations`)과 만들기 응답에는 붙이지 않는다. 프로필 사진은 본인과 같은 그룹 구성원에게.
6. **만료는 10~15분, 5분 구간으로 올린다.** 같은 구간 안에서는 같은 주소가 나와 브라우저 캐시가 산다. 서명 하나는 객체 하나만 연다.
7. **프로필 사진은 버킷이 있으면 S3에 둔다:** `profiles/{프로필 id}/photo/{내용 sha256 앞 16자}.{png|jpg}`(ADR-0026 3절의 키 모양). DB에는 키(`photo_key`)와 형식만 남긴다. 버킷이 없는 환경(로컬)은 지금처럼 DB에 둔다. `GET /profiles/…/photo`는 어디에 있든 읽어 준다. 사진을 바꾸거나 지우거나 프로필을 지우면 옛 객체를 지운다(클립과 같은 지울 목록 `clip_trash` — 실패하면 다음 치우기에서 다시).
   - 옛 사진 옮기기: `node backend/api/profile-photos.js`(운영 파드 안에서 한 번). 이미 옮긴 줄은 건너뛰고 키가 내용 해시라 다시 돌려도 안전하다. 옮기는 사이 본인이 사진을 바꾼 줄은 건드리지 않는다. 실행은 지환님 승인 뒤.
8. **웹 화면 파일(오너 11/16 "웹 파일도 옮겨").** `WEB_ASSET_BASE`(예: `https://media…/public/web/{sha}`)가 있으면 서버가 화면 HTML(웹앱 첫 화면, `/demo` 같은 폴더의 `index.html`)을 줄 때 정적 파일을 가리키는 루트 절대 주소(`src="/app.js"`, `href="/style.css"`, 아이콘)를 그 값 아래로 바꾼다. 바꾸지 않는 것: `/api/…`, `/sw.js`, `/manifest.webmanifest`(같은 출처여야 함), 화면 주소(확장자 없음: `/`, `/demo/`), 다른 출처의 주소. 값이 없으면 HTML은 한 글자도 달라지지 않는다. HTML의 `cache-control: no-cache`와 ETag(바꾼 뒤의 본문으로 셈)는 그대로다. `GET /api/config`에 `assetBase`를 싣는다. 이 파일들은 `/public/` 아래라 서명하지 않는다. CSP 머리말은 지금도 없고 새로 넣지 않는다.

## 대안

| 방법 | 좋은 점 | 고르지 않은 이유 |
|---|---|---|
| 서명 쿠키(`Set-Cookie`)만 | 주소에 서명이 없음 | 미디어 호스트가 달라 쿠키 도메인·제3자 쿠키 제약을 따로 풀어야 하고 폰 웹 화면을 같이 바꿔야 한다. 차량 앱은 쿠키 머리말을 직접 붙이므로 `…Auth`로 같은 값을 준다 |
| custom policy(경로 묶음) | 서명 하나로 여러 파일 | 권한이 파일마다 다르다(동의·세대·원본). 한 서명이 여행 전체를 열면 5번을 지킬 수 없다 |
| 서명 SDK(`@aws-sdk/cloudfront-signer`) | 검증된 구현 | 서명은 스무 줄이고 의존성을 늘리지 않는다. 형식은 공개 키 검증 시험으로 지킨다 |
| 목록에도 서명 | 웹이 한 번에 받음 | 목록은 줄마다 원본을 다시 보지 않는다. 받을 수 없는 파일의 서명이 나갈 수 있다 |

## 결과와 위험

- **폰 웹의 주소에 서명이 실린다.** 주소를 아는 사람은 만료(10~15분)까지 그 파일 하나를 받을 수 있다. `Referer`로 새지 않게 웹이 `referrerpolicy="no-referrer"`를 붙여야 한다(프론트 파트).
- **동의 철회·삭제 뒤에도 잠깐 남는다.** S3 객체는 바로(실패하면 다음 치우기에서) 지우지만, 이미 내준 서명은 만료까지(최대 15분), 가장자리 캐시는 10분까지(ADR-0026 3절) 파일을 줄 수 있다. 무효화는 API가 부르지 않는다(ADR-0026).
- **되돌리기와 사진.** 이 이미지가 나간 뒤 새로 올린 사진은 S3에만 있다. 이전 이미지로 되돌리면 그 사진은 옛 코드가 읽지 못한다(사진 없음으로 보임).
- 원본 버킷은 하나(`CLIPS_BUCKET`)라고 본다. 쇼츠 버킷(`SHORTS_BUCKET`)을 따로 두면 그 버킷도 배포의 원본이어야 한다.
- 개인 키는 비밀 값이다(ADR-0026 2절의 길). 저장소·기록에 남기지 않는다.

## 확인한 것과 못 한 것

- 시험(Postgres·가짜 S3): 값이 없을 때 응답이 그대로, 서명이 공개 키로 검증됨, 같은 구간에서 같은 주소, 내주지 않는 접두사는 서명 없음, 서명이 붙는 자리와 붙지 않는 자리, 동의 철회 뒤 서명 없음, 사진의 저장·바꾸기·지우기·프로필 삭제, 옮기기의 반복 실행, 화면 HTML의 바뀌는 주소와 그대로인 주소·ETag·304.
- `make e2e`: 이미지로 여행 하나의 흐름 14단계.
- 확인하지 못한 것: 실제 CloudFront가 이 서명을 받는지(자원이 아직 없음), 차량 플레이어의 쿠키 머리말, 운영 데이터 옮기기, CDN에서 받은 모듈 스크립트가 도는지(모듈·CSS 안의 루트 절대 주소는 웹 파트가 상대 주소로 바꿔야 한다).
