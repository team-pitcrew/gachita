# ADR-0002: 앞단을 웹앱과 차량 앱으로, 뒷단을 직접 운영하는 K3s로

* **상태:** 채택됨, 2026-11-12 (지환님 요청)
* **관련:** T2, T4, T5, T6, T7

## 배경

기획서 v4는 자체 모바일 앱, 여행 세션·처리 서버, Pleos 차량 앱 세 묶음을 적었습니다. 지환님은 앞단을 웹앱 스택과 에뮬레이터 구동 스택으로 나누고, 뒷단은 AWS에 IaC와 GitOps, 직접 운영하는 K3s, Postgres, API 서버로 두라고 했습니다. 사용자 프로필은 만들되 OAuth는 걸지 않습니다.

Pleos는 주행 중 일반 앱의 CPU를 5% 미만, RAM을 400 MB 이하로 두라고 적었습니다. 에뮬레이터에서 잰 메모리는 웹 화면을 띄우는 방식이 약 253 MB, 네이티브가 약 96 MB였습니다.

## 결정

| 묶음 | 결정 | 다시 볼 때 |
|---|---|---|
| 웹앱 | 빌드 없는 HTML·CSS·ES 모듈, 설치형 웹앱 | 화면이 열 개를 넘거나 화면 사이 상태가 얽히면 Vite + React |
| 차량 앱 | Kotlin · Compose 네이티브. 웹뷰로 감싸지 않음 | 없음. Pleos SDK와 메모리 기준 때문 |
| API 서버 | Node 22 표준 `http`, 의존성은 `pg` 하나 | 경로가 서른 개를 넘거나 입력 검증이 반복되면 프레임워크와 TypeScript |
| 저장 | 여행 하나를 JSONB 문서 한 줄로. 프로필은 표 | 여행을 가로질러 조회할 일이 생기면 표로 나눔 |
| 프로필 | 서버가 발급한 무작위 토큰을 기기에 저장. 서버는 해시만 | 기기를 옮기는 요구가 생기면 1회용 코드 |
| 클라우드 | AWS EC2 한 대 + K3s, Terraform, Argo CD, CloudNativePG | 한 대로 못 버티면 노드를 늘림 |

## 결과

웹앱은 의존성이 없어 공급망 위험과 빌드 시간이 없지만 타입 검사가 없습니다. 클라우드는 관리형 서비스보다 손이 많이 갑니다. 자원을 실제로 만드는 일은 비용이 생기므로 따로 승인받습니다.
