# ADR-0004: 여행 원음은 대표 폰에서 녹음한다

* **상태:** 제안, 2026-11-13 (T10 결과. PR 병합으로 정함)
* **관련:** T10, T12, #12

## 배경

기획안 v4는 차량에서 여행 내내 원음을 길게 녹음한 뒤 받아쓰기, 화자 구분, 장면 고르기를 한다고 가정했고 대안을 두지 않았습니다. T10에서 이 가정을 Pleos Connect Emulator 2.1.0으로 확인했습니다([결과](../emulator/mic-recording.md)). 실차가 아니라 에뮬레이터에서 본 것입니다.

- 일반 앱도 `AudioRecord`로 차량 마이크의 원음을 녹음할 수 있었습니다. 앞 화면, 기어 D, 음악·TTS 재생 중, 마이크 포그라운드 서비스를 둔 화면 뒤에서 넣은 소리가 그대로 들어갔고, 내비를 앞에 둔 채 30분 동안 끊기지 않았습니다. CPU는 한 코어의 1% 안팎, 메모리는 약 51 MB였습니다.
- 서비스 없이 화면 뒤로 가면 약 5초 뒤 무음으로 막혔고, 포그라운드 서비스는 앱이 앞에 있을 때(또는 뒤로 간 직후 몇 초 안)만 시작할 수 있었습니다.
- **우리가 녹음하는 동안 Gleo는 PTT를 무시했고, Gleo가 먼저 듣고 있었으면 Gleo가 무음을 받았습니다. 우리 앱의 Pleos STT도 무음만 받아 받아 적지 못했습니다.**
- Pleos 문서에 적힌 차량 마이크 경로는 SpeechToText뿐이고, 이 경로는 앱에 원음을 주지 않습니다. 문서는 하드웨어를 SDK의 표준 API로만 쓰라고 적었습니다. `AudioRecord`가 심사에서 받아들여지는지는 모릅니다.

## 검토한 선택

| 선택 | 좋은 점 | 걸리는 점 |
|---|---|---|
| 차량에서 여행 내내 녹음 | 기획안 그대로. 차 안 모든 자리의 소리를 한 마이크로 받음 | 녹음하는 내내 Gleo와 우리 음성 대화가 막힘. 심사 정책이 불분명함. 1시간에 115 MB(16 kHz 모노)인 원음을 차에서 올려야 함 |
| 차량에서 짧게만 녹음(사용자가 누른 때) | Gleo가 막히는 시간이 짧음 | '여행 내내'라는 기획 의도를 채우지 못함. 장면 고르기에 쓸 소리가 적음 |
| **대표 폰에서 녹음** | 차의 음성 비서와 우리 차량 앱의 음성 대화를 막지 않음. 차량 앱은 화면과 SDK 호출만 맡아 자원 기준을 지키기 쉬움 | 폰 하나의 위치에 따라 뒷자리 소리가 작을 수 있음. 폰에서 화면 뒤·화면 꺼짐 녹음이 되는지 확인하지 않음. 폰 앱(또는 웹앱)과 서버로 올리는 길이 필요 |

## 결정

**여행 원음은 대표 폰에서 녹음합니다.** 차량 앱은 원음을 오래 녹음하지 않고, 차 안의 음성 입력은 Pleos STT의 짧은 질문·답과 Gleo 넘겨받기만 씁니다. 차에서 녹음이 꼭 필요한 기능이 생기면 사용자가 누른 짧은 녹음으로 두고, 그동안 Gleo가 듣지 못한다고 화면에 보입니다.

## 결과

- T12(음성 처리 흐름)는 녹음 기기를 대표 폰으로 두고 올리기, 받아쓰기, 화자 구분, 장면 고르기를 설계합니다. 폰에서도 화면 뒤, 화면 꺼짐, 통화·내비 음성과의 충돌, 길이를 먼저 확인해야 합니다.
- 기획안의 '차량에서 녹음' 문장을 '대표 폰에서 녹음'으로 맞춰야 합니다. 기획서는 이 저장소 밖에 있습니다.
- 실차에서 Gleo와 마이크를 나눠 쓰는 방식이 다르거나, Pleos가 원음 녹음 API를 내놓으면 이 결정을 다시 봅니다.
