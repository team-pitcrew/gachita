# ADR-0010: 주소는 gachita.mangowhois.ai, 가장자리는 Cloudflare

* **상태:** 일부 채택, 2026-11-13
  * 채택(지환, 11/13): 서비스 주소는 `gachita.mangowhois.ai` 하나, 가장자리는 Cloudflare. 클라우드 계정은 다른 프로젝트와 같이 쓰는 지금 계정.
  * 제안(승인 전): 서버로 가는 길을 Tunnel로(설계는 [ADR-0013](0013-network-edge-and-isolation.md)), Cloudflare에 터널·레코드를 만드는 것, API 토큰의 범위.
* **관련:** T44, #68, T27, T24, T25, T46, ADR-0002, ADR-0009

## 배경

지금 선언은 도메인 없이 `api.<고정 IP>.sslip.io` 주소를 쓰고, 클러스터 안의 Traefik 인그레스와 cert-manager(Let's Encrypt)가 가장자리를 맡습니다. 그다음 계획은 CloudFront와 ALB로 옮기고 도메인은 두지 않는 것이었습니다(T27의 이전 판). 아직 아무 자원도 만들지 않았습니다.

11/13에 두 가지가 정해졌습니다(지환). 서비스 주소를 `gachita.mangowhois.ai`로 잡고, 인프라 쪽은 Cloudflare를 씁니다. 계기는 QR 초대입니다(ADR-0009). 초대받은 사람의 폰이 밖에서 이 주소를 열어야 하고, QR에 담기는 주소는 바뀌지 않는 이름이어야 합니다.

`mangowhois.ai` 영역은 이미 Cloudflare에 있고 메일 전달에 쓰이고 있습니다.

## 검토한 선택

| 선택 | 좋은 점 | 걸리는 점 |
|---|---|---|
| CloudFront와 ALB(이전 계획) | AWS 안에서 끝남 | 켜 둔 시간만큼 비용. 도메인이 없어 주소가 길고 바뀜. 클러스터를 만들기 전에는 밖에서 닿을 길이 없음 |
| Cloudflare 프록시 + 원본 인증서 | 지금의 Traefik 선언을 거의 그대로 씀 | 서버의 443을 Cloudflare 대역에 열어 두어야 하고, 대역 목록을 관리해야 함 |
| **Cloudflare Tunnel** | 서버에 들어오는 포트를 열지 않음. 클러스터가 없어도 개발 기기의 서버를 같은 이름으로 내보낼 수 있어 시연과 QR 확인을 바로 함 | 클러스터 안에 터널 프로그램을 하나 더 돌림. Cloudflare에 장애가 나면 닿지 않음 |

## 결정

**주소는 `gachita.mangowhois.ai` 하나로 두고, 가장자리는 Cloudflare로 합니다.** 웹앱과 API는 지금처럼 한 서버가 같은 이름에서 내보냅니다(API는 `/api/`).

- 서버로 가는 길은 Cloudflare Tunnel을 제안합니다. 프록시 방식과 어느 쪽으로 갈지는 T27에서 정합니다.
- 먼저 개발 기기의 서버를 터널로 내보내 제출용 시연과 QR 초대 확인에 씁니다. 클러스터를 만들면(T24) 같은 이름을 클러스터로 돌립니다.
- DNS 레코드와 터널은 Terraform으로 만들고, 다루는 범위는 `gachita` 이름 하나입니다. 영역의 다른 레코드는 건드리지 않습니다.
- Traefik 인그레스의 Let's Encrypt 발급과 `sslip.io` 주소는 옮긴 뒤 걷어냅니다. CloudFront와 ALB는 만들지 않습니다.

## 결과

- T27의 내용이 'AWS 스택으로'에서 'Cloudflare로'로 바뀝니다. T24의 확인 주소도 이 이름이 됩니다.
- Cloudflare API 토큰이 새 비밀 값으로 생깁니다. 범위를 좁히고 저장소에 넣지 않으며, OIDC로 바꿀 수 없어 T25의 예외로 둡니다.
- 구글 OAuth의 리다이렉트 주소를 이 이름으로 등록해야 합니다(ADR-0006).
- 요청이 Cloudflare를 지나가므로, 원음이나 사진을 올리게 되면 동의 문구의 제3자 고지에 넣을지 T12에서 맞춥니다.
- 확인하지 못한 것: 이 영역의 Cloudflare 요금제와 Tunnel 사용 가능 여부, 올릴 수 있는 요청 크기 한도, 차량(에뮬레이터)에서 이 주소로 닿는지. 아직 아무것도 만들거나 바꾸지 않았습니다.
