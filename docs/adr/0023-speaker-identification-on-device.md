# ADR-0023: 화자 식별은 기기에서 하고, 대조 값의 저장과 조회는 서버가 맡는다

* **상태:** 채택됨, 2026-11-14. 구현은 서버 계약 → 차량 순서로 따로 올린다(아래 '결과'). 이 문서가 병합된 시점의 코드는 아직 ADR-0019의 서버 대조다
* **고침:** [ADR-0019](0019-speaker-matching.md)의 '서버가 발화 음성을 받아 대조한다'와 '화자는 서버의 대조만 붙인다', [ADR-0007](0007-voice-processing-flow.md)의 '화자 대조를 위해 발화 음성이 서버로 잠시 오간다'. ADR-0019의 나머지(좌석 구역으로 후보를 줄임, 기준값, 여행 참가자 단위 등록, 대조 값의 삭제 규칙, 1차 임베더, 사람이 고친 화자 우선)는 그대로 유효하다
* **관련:** T124, #353, T37(좌석·차량 대조), T38(서버 대조), T63·T69(차 안 암호화 보관), [ADR-0008](0008-in-car-capture-and-sdk-stt.md), [ADR-0014](0014-transcript-storage.md), [`docs/api/voice.md`](../api/voice.md)

## 배경

ADR-0019의 화자 대조는 서버에서 돈다. 차량 앱은 발화마다 차 안 원음에서 그 구간(최대 10초)을 잘라 `POST /voice-match`로 보내고, 출발 전 목소리 등록 때는 10초 음성을 `POST /participants/{id}/voice`로 보낸다. 서버는 계산한 뒤 소리를 버리고 대조 값(벡터)만 남긴다. 그래서 기록이 켜진 동안에는 **모든 발화의 소리가 한 번씩 서버를 거친다.** 동의 문구에도 '말소리가 잠시 서버로 갔다가 저장되지 않고 지워집니다'라고 적어 두었다.

그런데 1차 임베더(`backend/api/providers/voice.js`, 191줄)는 학습된 모델이 아니다. 16 kHz PCM에서 로그멜 평균·분산과 음높이 히스토그램을 내는 순수 계산이고 의존성이 없다. 같은 수식을 차량 앱(Kotlin)에서 돌리면 같은 값이 나온다. 좌석 구역 판정과 원음 보관은 이미 차 안에 있다(T37, T63).

11/14 오너 결정: **누가 말했는지 가르는 계산은 기기(차 안)에서 하고, 대조 값의 저장과 읽기는 서버가 맡는다.** 폰은 서버 기록본에서 차가 붙인 화자를 그대로 읽는다.

## 검토한 선택

| 선택 | 좋은 점 | 걸리는 점 |
|---|---|---|
| 그대로(서버 대조) | 바꿀 것이 없음. 임베더가 한 곳 | 발화마다 소리가 서버를 거침. 통신이 끊기면 화자가 밀림 |
| **계산은 기기, 대조 값 저장·조회는 서버**(채택) | 발화 소리와 등록 음성이 기기를 떠나지 않음. 끊겨도 화자가 붙음. 폰에서 등록한 프로필 값도 차가 씀 | 임베더가 두 곳(JS, Kotlin) — 공유 시험 벡터로 묶음. 대조 값이 차로 내려가 사본이 생김. 차가 붙인 화자를 서버가 믿어야 함 |
| 대조 값도 차에만 둠 | 서버에 생체 정보가 없음 | 폰에서 등록한 프로필 값을 쓸 수 없음. 차를 바꾸거나 앱을 다시 깔면 다시 등록. 오너 결정과 다름 |
| 대조 값을 차로 내리지 않고 서버가 벡터만 받아 대조 | 차에 사본이 없음 | 발화마다 통신. 벡터도 민감정보라 오가는 양만 줄 뿐. 끊기면 밀림 |

## 결정

### 1. 무엇이 기기를 떠나지 않게 되는가

- **발화 구간의 소리.** 차는 발화의 원음 구간을 차 안에서 벡터로 바꿔 대조하고, 화자(참가자 id)만 발화와 함께 올린다. 이 경로가 켜진 차량 앱은 `/voice-match`를 부르지 않는다.
- **등록 음성.** 출발 전 10초 등록도 차 안에서 벡터로 바꿔 **값만** 올린다. 서버의 등록 경로는 음성(`audio/wav`)과 값(`application/json`)을 둘 다 받는다.
- 발화의 벡터는 차 안에서 대조에 쓰고 버린다. 저장하지도 올리지도 않는다.

여전히 차 밖으로 나가는 소리는 사람이 고른 장면의 클립(T76)과 그 재전사(T75), 웹 입력의 첫 전사(T96)다. 이 결정은 그것들을 바꾸지 않는다.

### 2. 무엇이 서버에 남는가

- **대조 값(등록 벡터).** `trip_voice_prints`(여행 참가자 단위)와 `voice_prints`(프로필)에 지금처럼 둔다. 목소리에서 뽑은 값이라 **민감정보**다. 원본 음성으로 되돌릴 수는 없지만(112개 통계값) 사람을 가리는 데 쓰이므로 소리와 같은 수준으로 지운다. 삭제 규칙은 ADR-0019 그대로다(동의가 꺼지거나 다시 켜지면 바로, 여행을 치울 때 함께, 프로필은 `DELETE /profiles/me/voice`).
- **조회 경로.** 차가 그 여행의 대조 값을 받아 가는 읽기 경로를 연다. 참가자 토큰이 필요하고, **녹음에 동의한 참가자의 값만** 준다(동의가 꺼진 참가자는 프로필 등록값이 있어도 주지 않는다). 부르는 사람도 녹음에 동의한 참가자여야 한다. 응답은 `Cache-Control: private, no-store`이고, 기준값(`VOICE_MATCH_THRESHOLD`)과 임베더 이름을 함께 준다 — 차가 기준을 따로 적어 두지 않고 서버 값을 쓴다.
- 이 경로로 벡터가 참가자 기기에 내려간다. 지금의 `/voice-match`는 동의한 참가자가 소리를 보내 '누구인지'만 알 수 있었는데, 이제는 값 자체를 읽는다. 받는 범위를 '그 여행에서 모두 동의한 참가자' 안으로 묶고, 여행이 닫히면(48시간) 읽을 수 없다.

### 3. 차 안 사본의 암호화와 삭제 시점

차는 받은 대조 값을 다른 차 안 민감정보와 같은 방식으로 둔다(`Vault.kt`: Android Keystore로 감싼 데이터 키, AES-256-GCM, T69). 평문으로 두지 않는다. 지우는 때:

| 때 | 하는 일 |
|---|---|
| 그 참가자의 동의가 꺼짐 | 그 사람의 값을 사본에서 뺀다(서버도 그 값을 지움) |
| 동의 세대가 오름(누구든 철회) | 사본 전체를 지우고 다시 받는다. 발화별 화자 기록도 지금처럼 지운다 |
| 여행이 지워짐·만료됨(서버 404) | 여행의 다른 차 안 파일과 함께 지운다(`dropTrip`) |
| 다시 받을 때마다 | 서버 응답으로 통째로 바꾼다. 서버에서 사라진 값이 차에 남지 않게 |

차가 끊겨 있는 동안에는 마지막으로 받은 사본으로 대조한다. 그 사이 서버에서 지워진 값이 최대 다음 연결까지 차에 남는데, 수음 자체가 '마지막 동의 확인 뒤 5분'에 멈추므로(ADR-0007) 그 값으로 새 발화를 대조하는 시간도 5분을 넘지 않는다.

### 4. 차와 서버가 같은 값을 내는지: 공유 시험 벡터

임베더가 JS와 Kotlin 두 곳에 생긴다. 한쪽만 고치면 등록(서버 계산)과 대조(차 계산)의 값이 어긋나 조용히 '모름'이 늘어난다. 그래서:

- **시험 벡터 파일 하나**를 저장소에 둔다(`backend/api/voice-vectors.json`). 정수 연산만으로 만드는 입력 신호 몇 개(음높이가 다른 톱니파에 잡음을 더한 것, 무음에 가까운 것 — 언어가 달라도 표본이 똑같게)와 `voice.js`가 낸 출력 벡터를 담는다.
- 서버 시험은 `voice.js`가 이 파일과 같은 값을 내는지 본다(임베더를 고치면 파일을 다시 만들어야 통과). 차량 단위 시험은 **같은 파일**을 읽어 Kotlin 구현의 값이 허용 오차(성분마다 1e-6) 안인지 본다. 허용 오차는 두 언어의 `cos`·`log10` 마지막 자리 차이를 덮는 값이다.
- 임베더에 이름(`logmel-pitch-1`)을 붙인다. 값을 올릴 때 이름을 함께 보내고 서버가 자기 이름과 다르면 거절한다. 수식을 바꾸면 이름을 올린다 — 옛 APK가 옛 수식의 값을 올려 섞이지 않게.
- 값 등록은 모양도 본다: 112차원, 유한한 수, 세 묶음(로그멜 평균 26, 분산 26, 음높이 60)이 각각 평균 0·길이 1(음높이를 못 잡은 경우 길이 0).

### 5. 차가 붙인 화자를 서버가 어떻게 믿는가

`POST /utterances`의 항목에 선택 칸으로 화자(참가자 id), 화자 확신도, 판정 방법을 받는다. ADR-0019는 '올리는 쪽이 남의 이름을 붙이지 못하게' 이 칸을 받지 않았다. 여는 대신 이렇게 묶는다.

- **그 기기가 올린 발화에만.** 발화 올리기는 이미 '그 기기 이름을 처음 올린 참가자'만 할 수 있다. 화자 칸도 그 묶음의 발화에만 붙는다. 남의 기기가 올린 줄에는 닿지 못한다.
- **녹음에 동의한 이 여행의 참가자만.** 이 여행에 없는 id나 동의하지 않은 참가자의 id는 화자 없이 저장한다. 묶음 전체를 거절하지는 않는다 — 거절하면 확인 순번이 멈춰 차가 같은 묶음을 끝없이 다시 보낸다(ADR-0007의 옛 세대 발화와 같은 이유).
- **사람이 고친 화자는 덮지 않는다.** `speaker_by_hand`인 줄('모름'으로 고친 것 포함)은 그대로 둔다. 이미 화자가 있는 줄도 바꾸지 않는다. 화자가 비어 있는 줄을 같은 순번으로 다시 보내면 채운다(차가 대조 값을 늦게 받았을 때).
- **기존 클라이언트는 그대로.** 칸이 없으면 지금과 똑같이 저장한다.

새로 생기는 권한은 없다. 발화를 올린 참가자는 지금도 `PATCH /utterances/{device}/{seq}`로 자기 기기 발화의 화자를 동의한 참가자 누구로든 고칠 수 있다. 화자 칸은 같은 사람이 같은 범위에서 하는 일을 올리는 때에 함께 하게 할 뿐이다. 다만 판정 방법(`device-voice`)을 줄에 남겨, 사람이 고친 것·서버가 대조한 것·기기가 대조한 것을 나중에 가릴 수 있게 한다. 서버는 차의 계산을 다시 하지 않는다(소리가 없으니 할 수 없다). 차량 앱이 아닌 클라이언트가 참가자 토큰으로 거짓 화자를 올리는 것은 막지 못하며, 그 범위는 위의 '자기 기기 발화, 동의한 참가자'다.

### 6. 정확도는 합성 음성으로만 쟀다

수식을 옮길 뿐이라 정확도는 ADR-0019와 [등록 길이별 정확도 표](../research/voice-enroll-length.md) 그대로다: 합성 음성에서 후보 둘·3초 발화 85~95% 맞힘, 틀림 0%, 말한 사람이 후보에 없으면 5~10% 잘못 붙음. **사람 목소리(가족, 아이), 실차의 마이크와 소음으로는 재지 않았다.** 같은 성인끼리 가까운 목소리를 못 가리는 1차 임베더의 한계도 그대로다. 차로 옮겨서 달라지는 것은 두 가지다. 등록과 대조가 같은 마이크 경로의 소리로 계산된다(지금도 같음). 차의 계산 시간이 든다 — 3초 발화의 계산량은 프레임 300개의 512점 FFT와 자기상관이라 작지만, 실차 헤드유닛에서의 시간은 재지 않았다.

학습된 모델(ECAPA-TDNN)로 바꾸는 길은 이 결정으로 달라진다. ADR-0019는 서버 옆 별도 프로세스를 생각했지만, 이제 모델은 차 안에서 돌아야 한다(ONNX Runtime Mobile 등). 이번 범위 밖이고, 들일 때 이 문서를 고친다.

### 7. 기존 서버 대조 경로를 언제까지 남기는가

`POST /voice-match`와 음성으로 하는 등록은 **지우지 않는다.** 쓰는 곳이 둘 남아 있다: 이미 깔린 구버전 차량 APK, 그리고 웹 입력(T96)의 구간 대조. 새 차량 앱이 나간 뒤에는 그 차의 발화 소리가 이 경로로 오지 않는다.

닫는 조건(별도 티켓): 구버전 APK를 쓰는 기기가 없고, 웹 입력이 브라우저에서 벡터를 계산해 값만 올리도록 바뀐 뒤. 공모전 제출(11/15) 전에는 닫지 않는다.

### 8. 동의 문구

차량 구현이 병합될 때 기록 동의 문구의 한 문장을 바꾼다(voice.md, ADR-0007, 차·웹 화면이 같은 문장을 쓴다).

- 지금: '누가 말했는지 가리려고 말소리가 잠시 서버로 갔다가 저장되지 않고 지워집니다.'
- 바꿀 글: '누가 말했는지는 차 안에서 가립니다. 등록한 목소리는 화자를 가리는 값으로만 바뀌어 서버에 저장되고, 동의를 끄면 지워집니다.'

구현 전에는 문구를 바꾸지 않는다. 실제 경로와 문구가 어긋나지 않게 차량 PR과 함께 바꾼다. 웹 입력(T96)은 그 뒤에도 구간 소리를 서버로 보내므로, 웹 입력 화면의 고지는 그대로 둔다.

## 결과

- 서버(backend-api, 별도 티켓): 대조 값 조회 경로, `POST /utterances`의 화자 칸, 등록 경로의 값 받기, 시험 벡터 파일. `openapi.yaml`·서버·시험을 한 PR에서. `utterances`에 화자 확신도·판정 방법 칸이 늘어난다(비어 있어도 되는 칸).
- 차량(frontend-car, 별도 티켓, 서버 뒤): 임베더의 Kotlin 구현과 시험 벡터 단위 시험, 대조 값 사본의 암호화 보관과 삭제, 차 안 대조와 화자 올리기, 값으로 하는 등록, 동의 문구.
- 폰: 기록본은 발화의 `participantId`를 그대로 읽으므로 계약이 바뀌지 않는다. 프로필 목소리 등록을 폰에 만들 때는 브라우저에서 같은 수식으로 벡터를 계산해 값만 올린다(같은 시험 벡터로 맞춤).
- 병합 순서: 이 문서 → 서버 → 차량. 서버가 먼저 나가도 구버전 차량은 그대로 돈다(새 칸과 경로는 모두 선택). 새 차량 앱이 옛 서버를 만나면(조회 경로 404) 화자를 붙이지 않고 '모름'으로 둔다(사람이 고칠 수 있음). 소리를 보내는 옛 경로로 돌아가지 않는다.
