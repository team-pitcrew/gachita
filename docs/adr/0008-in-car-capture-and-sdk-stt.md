# ADR-0008: 여행 대화는 차량에서 수음하고 Pleos STT로 받아 적는다

* **상태:** 제안, 2026-11-13 (T35. PR 병합으로 정함)
* **관련:** T35, #58, T10(PR #52), T12(ADR-0007, PR #55), T36, T37, T39, T41

## 배경

T10의 PR에 처음 들어 있던 결정 기록 초안(ADR-0005, 병합 전에 뺌)은 여행 원음을 대표 폰에서 녹음하자고 했고, ADR-0007은 그 전제로 음성 처리 흐름을 정했습니다. 근거는 T10의 에뮬레이터 관찰이었습니다. 우리가 녹음하는 동안 Gleo가 듣지 못하고, 우리 앱의 Pleos STT도 무음만 받는다는 것입니다.

그 뒤 두 가지가 바뀌었습니다.

- **기준 문서.** 민준님의 참가신청서 문구정리본(11/13)은 차량 직접 수음을 기본으로 두고 폰 수음을 후순위 차선안으로 적습니다. 핵심 흐름은 휴대폰 없이 차량에서 끝납니다. 차량에서 수음하지 않으면 차량 특화성이 약해진다는 의견도 있었습니다(지민, 11/13).
- **실측.** 11/13에 Pleos Connect Emulator 2.1.0에서 다시 쟀습니다([E2E 실측](../emulator/e2e-flow.md)). 실차가 아닙니다.
  - Pleos STT가 무음을 받은 것은 STT가 마이크를 직접 여는 `request()` 경로에서만이었습니다. 우리 앱이 받은 원음을 `sendAudio()`로 넣으면 우리 녹음과 함께 11분 150문장을 받아 적었고, 말이 끝난 뒤 0.6초에 결과가 왔습니다.
  - 스테레오 두 채널은 완전히 분리돼 녹음됐고, 발화를 좌석 두 구역으로 가르는 것은 8번 모두 맞았습니다.
  - Gleo와는 여전히 마이크를 나눠 쓰지 못합니다. 다만 우리 전사에서 호출어를 알아채 `AudioRecord`를 멈추면 운전대 버튼이 받아들여졌고, Gleo가 끝나면 오디오 포커스 복귀로 알아채 다시 수음했습니다. 앱이 Gleo를 대신 깨우는 길은 없었습니다.

## 검토한 선택

| 선택 | 좋은 점 | 걸리는 점 |
|---|---|---|
| 대표 폰에서 녹음(처음의 초안) | Gleo를 막지 않음. 차량 앱이 가벼움 | 기준 문서와 다름. 차량 특화성이 약함. 폰 녹음은 확인한 적이 없음 |
| 차량에서 수음하고 서버 ASR로 받아쓰기 | 기준 문서의 구조 그대로. 모델을 고를 수 있음 | 원음 전체를 차 밖으로 보냄(1시간 115 MB, 동의와 보관 부담). Pleos SDK를 쓰지 않음 |
| **차량에서 수음하고 Pleos STT로 받아쓰기** | 받아쓰기에 원음을 보내지 않아도 됨. SDK 활용이 는다. 통신이 끊겨도 받아 적음 | Gleo와 마이크를 주고받아야 함. 화자·좌석은 SDK가 주지 않음. 사람 목소리와 소음 정확도는 재지 않음 |

## 결정

**여행 대화는 차량 앱이 직접 수음하고, 받아쓰기는 될 수 있으면 Pleos STT(ON_DEVICE)로 합니다.** 말로 하는 안내는 Pleos TTS를 씁니다.

- 차량 앱: 마이크 포그라운드 서비스의 `AudioRecord`(16 kHz, 2채널) → 모노로 합쳐 `sendAudio()` → 발화 단위(시각, 글자, 좌석 구역)를 기록본으로 서버에 보냄(T36, T37, T39).
- 서버: 같은 좌석 구역 안의 사람 구분(등록한 목소리와 대조), 도착 할 일과 장면 뽑기, 영상 생성. 원음을 어디까지 보낼지는 T12에서 정함.
- 기록본은 사람별 프로필에 묶어 저장합니다. 48시간 뒤 무엇을 남길지는 T39에서 정합니다.
- Gleo: 호출어를 알아채거나 사용자가 누르면 수음을 멈추고, 사용자가 운전대 버튼으로 Gleo를 부릅니다. Gleo가 끝나면 다시 수음합니다(T41). Gleo를 대신 깨우는 우회로는 만들지 않습니다.
- 폰 수음은 기준 문서대로 후순위 차선안으로 둡니다.

## 결과

- '대표 폰에서 녹음' 초안은 이 결정으로 대신합니다. 번호 0005는 쓰지 않고 비워 둡니다. PR #52의 관찰 결과(녹음 조건, 권한, 자원)는 그대로 근거로 씁니다.
- ADR-0007은 녹음 기기와 받아쓰기 위치를 이 결정에 맞춰야 합니다. 동의 세대, 보관 시계, 참가자 토큰 같은 나머지 결정은 그대로 쓸 수 있습니다.
- 서버 ASR 후보의 실측(상현, 11/13)은 Pleos STT와 비교하는 자료로 씁니다. 사람 목소리와 차 안 소음에서 Pleos STT가 모자라면 이 결정을 다시 봅니다.
- 확인하지 못한 것: 실차에서도 Gleo와 마이크를 나눠 쓰지 못하는지, `AudioRecord`로 원음을 받는 것이 Pleos 심사에서 받아들여지는지, 4자리를 따로 가릴 수 있는지, 넘겨받은 Gleo가 말을 알아듣는지(에뮬레이터가 멈춤).
- 에뮬레이터에서 재야 하는 후속 작업(T36, T37, T40, T41)은 지환이 맡습니다.
