# ADR-0015: 노드를 셋으로 나누고, 사설 서브넷과 ALB로 들어온다

* **상태:** 제안, 2026-11-13 (T27. PR 병합으로 정함. 병합되면 ADR-0010의 '서버로 가는 길'과 ADR-0013의 1절·3절, 10절의 한 대 전제를 대신함)
* **관련:** T27(#33), T24(#30), T28(#34), T25(#31), [ADR-0010](0010-domain-and-cloudflare-edge.md), [ADR-0013](0013-network-edge-and-isolation.md), ADR-0011(PR #74), ADR-0012(PR #77)

## 배경

- ADR-0013은 노드 하나를 전제로 Cloudflare Tunnel로 들어오고 로드 밸런서를 두지 않기로 했습니다. 서버 한 대가 죽으면 전체가 멈춥니다(ADR-0013의 10절).
- 11/13에 지환님이 방향을 바꿨습니다. EC2를 나누고, 들어오는 길은 ALB로 잡고, VPC의 서브넷도 나눕니다. T27의 할 일 '서버로 가는 길을 Tunnel로 둘지, 프록시한 레코드와 원본 인증서로 둘지 정함'의 답이기도 합니다.
- AWS와 Cloudflare에 아직 아무것도 만들지 않았습니다. 바뀌는 것은 선언(Terraform, 구축 단계, GitOps)뿐이라 옮기는 비용이 없습니다.
- 11/13 로컬 검증(Docker 위 K3s v1.36.6 + Cilium 1.20.4, 한 노드. 실제 EC2가 아님)에서 본 것:
  - K3s 서버 프로세스가 RSS 1.6 GiB를 썼습니다(CPU가 18개인 환경). 컨트롤 플레인을 앱·DB와 같은 노드에 두면 그만큼을 나눠 써야 합니다.
  - Traefik 2개가 요청 수를 따로 세어, 같은 사용자 주소로 동시에 80번 보냈을 때 429가 두 번뿐이었습니다(선언은 평균 20·순간 40).
  - 네트워크 정책은 선언대로 막고 열었습니다. 다만 본 것은 터널로 들어오는 길의 정책이라, 이 결정으로 바뀌는 들어오는 쪽은 다시 봐야 합니다.

## 검토한 선택

**들어오는 길**

| 선택 | 좋은 점 | 걸리는 점 |
|---|---|---|
| Cloudflare Tunnel(ADR-0013) | 들어오는 포트 0개. 인증서 관리 없음. 비용 없음 | 노드마다 터널 파드와 토큰. 노드가 죽은 것을 쿠버네티스가 알 때까지 죽은 Traefik으로 갈 수 있음(추정, 재지 않음). 터널에 장애가 나면 다른 길이 없음 |
| **Cloudflare 프록시 → ALB → Traefik** | AWS가 가용 영역 둘에 걸쳐 노드의 건강을 직접 확인하고 뺌. 교체할 때 연결을 비움. 터널 파드와 토큰이 없어짐 | 월 약 $30(ALB와 공인 IPv4 둘). 들어오는 포트가 생김(Cloudflare 대역만). 인증서와 대역 목록을 관리 |
| NLB | ALB보다 단순(L4) | HTTP 건강 확인과 원본 TLS를 Traefik이 맡아야 함 |
| CloudFront + ALB | AWS 안에서 끝남 | ADR-0010에서 뺌(주소와 가장자리는 Cloudflare) |

**서브넷**

| 선택 | 좋은 점 | 걸리는 점 |
|---|---|---|
| 공개 서브넷 하나(지금 선언) | 단순. NAT 없음 | 노드가 공인 IP를 가짐. ALB는 가용 영역 둘이 있어야 해서 그대로는 못 씀 |
| **공개 둘 + 사설 둘** | 노드에 공인 IP가 없음. 밖에서 닿는 것은 ALB뿐 | 나가는 길에 NAT가 필요(비용) |
| 공개 + 앱 + 데이터 3층 | DB를 서브넷과 보안 그룹으로도 가름 | DB 전용 노드가 가용 영역마다 있어야 함(노드 5대). 지금은 DB가 워커의 파드라 Cilium 정책(ADR-0013의 5절)이 같은 일을 함 |

**사설 서브넷에서 나가는 길**

| 선택 | 좋은 점 | 걸리는 점 |
|---|---|---|
| **NAT 게이트웨이 1개** | 운영할 것이 없음. Terraform 자원 하나 | 월 $43 + GB당 $0.059. 그 가용 영역이 죽으면 다른 영역의 노드도 밖으로 못 나감(이미지 받기, 구글 로그인, STS). 들어오는 요청은 계속 받음 |
| 가용 영역마다 1개 | 영역 장애에도 나감 | 월 $86 |
| NAT 인스턴스(t4g.nano) | 월 $7 안팎 | 직접 운영(패치, 장애 때 교체). 접었다 펴는 자동화에 손이 더 감 |
| VPC 엔드포인트만 | NAT 없음 | 구글, GHCR, GitHub에는 엔드포인트가 없어 닿지 못함 |

**ALB에서 클러스터로**

| 선택 | 좋은 점 | 걸리는 점 |
|---|---|---|
| **인스턴스 대상 + Traefik NodePort(대상 등록은 Terraform)** | 컨트롤러가 늘지 않음. Cilium 오버레이 그대로 | NodePort 하나를 엶(포트 규칙 예외 1건). 워커가 늘면 Terraform에 등록 |
| AWS Load Balancer Controller + 파드 IP 대상 | 파드로 바로 감 | 파드 IP가 VPC에서 보여야 해서 Cilium을 ENI 방식으로 바꿔야 함. 컨트롤러와 IAM 역할이 하나 더 |
| Traefik을 hostNetwork로 | NodePort 없음 | 포트 규칙이 막는 것(ADR-0013의 6절)을 가장 넓게 품 |

## 결정

**EC2를 서버 노드 하나와 워커 둘로 나누고, 노드는 사설 서브넷에 두고, 밖에서는 Cloudflare → ALB → Traefik으로 들어옵니다.** Cloudflare Tunnel은 클러스터의 들어오는 길로 쓰지 않습니다.

### 1. 노드

| 노드 | 사양 | 서브넷 | 올라가는 것 |
|---|---|---|---|
| 서버 1 | t4g.large | 사설, 첫째 가용 영역 | K3s 컨트롤 플레인, Argo CD, 컨트롤러(cert-manager, CloudNativePG, External Secrets, 파드 신원 웹훅). `control-plane` 테인트를 걸어 앱과 DB가 오지 않게 함 |
| 워커 2 | t4g.medium | 사설, 가용 영역마다 하나 | Traefik(워커마다 하나), API, Postgres 인스턴스 |

- 컨트롤러는 이미 컨트롤 플레인 노드 선택자와 테인트 허용이 걸려 있어(ADR-0013의 8절) 선언을 고치지 않아도 서버 노드로 갑니다.
- Postgres는 DB마다 인스턴스 둘(주와 복제, 워커마다 하나)로 올립니다. 복제는 비동기로 두고 WAL은 지금처럼 S3에 보관합니다. 워커 하나가 죽으면 CloudNativePG가 복제본을 주로 올립니다.
- API는 2개를 워커에 나눠 두고(지금의 `topologySpreadConstraints`), Traefik은 워커마다 하나씩(DaemonSet) 둡니다.
- 워커 하나의 메모리 요청은 약 1.7 GiB로 어림합니다(Cilium 320, Traefik 64, API 96, Postgres 둘과 백업 사이드카 1,152 MiB. ADR-0012의 요청값). t4g.medium에 들어간다고 보지만 재지 않았습니다.
- 컨트롤 플레인을 셋으로 늘리는 것은 다음 단계입니다. 서버 노드가 죽어도 요청은 계속 받지만(추정), 그동안 배포와 Postgres 승격이 멈춥니다. 이 시간이 문제가 되면 늘립니다.

### 2. VPC와 서브넷

| 서브넷 | 대역 | 두는 것 | 기본 경로 |
|---|---|---|---|
| 공개, 가용 영역 둘 | `10.10.0.0/24`, `10.10.1.0/24` | ALB, NAT 게이트웨이 | 인터넷 게이트웨이 |
| 사설(앱), 가용 영역 둘 | `10.10.10.0/24`, `10.10.11.0/24` | 서버 노드, 워커 | NAT 게이트웨이. S3는 게이트웨이 엔드포인트 |
| 사설(데이터), 예약 | `10.10.20.0/24`, `10.10.21.0/24` | 지금은 비워 둠 | - |

- VPC는 `10.10.0.0/16` 그대로입니다. K3s의 파드(`10.42.0.0/16`)·서비스(`10.43.0.0/16`) 대역과 겹치지 않습니다.
- 가용 영역은 이름을 박지 않고 쓸 수 있는 영역의 앞 둘을 씁니다(지금 선언의 방식).
- 데이터 서브넷은 대역만 잡아 둡니다. DB를 전용 노드나 관리형 DB로 옮길 때 씁니다. 그 전까지 DB의 격리는 네임스페이스와 Cilium 정책이 맡습니다(ADR-0013의 5절).
- 노드에는 공인 IP를 주지 않습니다. 관리 접속은 지금처럼 SSM 세션입니다(NAT를 거쳐 나감).

| 보안 그룹 | 들어오는 것 | 나가는 것 |
|---|---|---|
| ALB | 443, Cloudflare가 공개한 대역에서만 | 노드 보안 그룹의 Traefik NodePort |
| 노드 | ALB 보안 그룹에서 Traefik NodePort, 같은 보안 그룹끼리 전부(K3s API, kubelet, Cilium VXLAN) | 전부(파드가 나갈 곳은 Cilium 정책이 이름으로 막음) |

### 3. 들어오는 길과 TLS

```
폰·차량 ─HTTPS─▶ Cloudflare 엣지: TLS, WAF, 정적 파일 캐시, 요청 수 제한
   ─HTTPS(Cloudflare 대역만)─▶ ALB(공개 서브넷 둘): ACM 인증서, 노드 건강 확인
   ─HTTP(VPC 안)─▶ 워커의 Traefik(NodePort) ─HTTPRoute─▶ API ─▶ Postgres
```

- **TLS는 두 구간입니다.** 사용자와 Cloudflare 사이는 Cloudflare의 인증서, Cloudflare와 ALB 사이는 ACM 공개 인증서(DNS 검증)입니다. Cloudflare의 원본 검증은 Full (strict)로 두되, 영역 전체 설정을 바꾸지 않고 `gachita.mangowhois.ai` 이름에만 겁니다. ALB에서 Traefik까지는 VPC 안의 HTTP입니다.
- **영역에 생기는 레코드는 둘입니다.** `gachita`(ALB를 가리키는 프록시 레코드)와 ACM 검증용 레코드 하나(`gachita` 아래)입니다. 영역의 다른 레코드는 지금처럼 가져오지도 고치지도 않습니다.
- **원본 보호.** ALB는 Cloudflare가 공개한 대역에서 오는 443만 받습니다(대역 목록은 Terraform이 읽어 채움). 다른 Cloudflare 고객이 우리 ALB를 자기 원본으로 삼는 것까지 막으려면 Authenticated Origin Pulls(mTLS)를 더합니다. 2차로 두고, 넣기 전에 ALB와의 조합을 확인합니다.
- **ALB.** 대상은 워커 인스턴스의 Traefik NodePort입니다. 건강 확인은 Traefik의 `/ping`, 10초 간격으로 두 번 실패하면 뺍니다. 등록을 풀 때 30초 동안 연결을 비웁니다. Traefik 서비스는 `externalTrafficPolicy: Local`로 두어 ALB가 본 건강이 그 노드의 Traefik과 같게 합니다.
- **없어지는 것.** 클러스터의 cloudflared, 터널과 터널 경로, SSM의 터널 토큰. Cloudflare 토큰의 권한에서 Tunnel 편집이 빠지고 DNS 편집이 남습니다.
- 개발 기기의 서버를 터널로 내보내 시연과 QR 확인에 쓰는 것(ADR-0010)은 그대로 둡니다. 클러스터와 무관합니다.

### 4. 리버스 프록시

층마다 한 가지 일만 맡깁니다.

| 층 | 맡는 일 | 맡지 않는 일 |
|---|---|---|
| Cloudflare 엣지 | TLS, WAF, 정적 파일 캐시, 사용자 주소 기준 요청 수 제한 | 경로 나누기 |
| ALB | 노드 건강 확인, 가용 영역 사이 분산, 원본 TLS | 경로, 재시도, 요청 수 제한 |
| Traefik(Gateway API) | 호스트와 경로, 재시도, 본문 크기와 시간 제한 | TLS, 요청 수 제한 |

- **클러스터 안의 프록시는 Traefik 하나로 둡니다.** 경로는 지금처럼 Gateway API(HTTPRoute)로 적습니다. 프록시를 바꿀 일이 생기면 GatewayClass만 바꿉니다. ingress-nginx는 2026년 3월에 은퇴해 후보가 아닙니다([쿠버네티스 공지](https://kubernetes.io/blog/2025/11/11/ingress-nginx-retirement/)).
- **요청 수 제한은 Traefik 미들웨어에서 Cloudflare 엣지 규칙으로 옮깁니다.** Traefik은 복제본마다 따로 셉니다. 값을 복제본 수로 나눠 맞출 수는 있지만(PR #77의 방식) 워커 수가 바뀔 때마다 어긋납니다. 엣지에서 세면 원본에 닿기 전에 막고, HTTPRoute에 Traefik 전용 확장(`ExtensionRef`)이 남지 않습니다. 무료 요금제는 영역에 규칙이 하나라 이 이름에 씁니다.
- `CF-Connecting-IP`는 계속 믿을 수 있습니다. Traefik에는 ALB만, ALB에는 Cloudflare 대역만 닿습니다.

### 5. 포트 규칙과 네트워크 정책에서 바뀌는 것

- 포트 규칙(ADR-0013의 6절): `edge` 네임스페이스의 `traefik` 서비스 하나만 NodePort를 허용합니다. 나머지는 그대로 ClusterIP만입니다.
- `edge`의 정책: Traefik으로 들어오는 것을 cloudflared 파드 대신 공개 서브넷 대역(ALB)으로 바꿉니다. cloudflared의 정책은 지웁니다. Traefik에서 API로, API에서 두 DB로 가는 정책은 그대로입니다.

## 결과

**무엇이 죽으면 어떻게 되나(예상. 만들고 나서 잽니다)**

| 죽은 것 | 영향 | 되살아나는 길 |
|---|---|---|
| 워커 하나 | ALB가 건강 확인으로 뺌(20초 안팎으로 봄). API는 남은 워커가 받음. 주 Postgres가 그 워커에 있었다면 승격되는 동안 쓰기 실패 | 워커를 새로 띄우면 다시 합류. Postgres는 복제본을 다시 만듦 |
| 서버 노드 | 요청은 계속 받음(추정). 배포, Postgres 승격, 비밀 값 갱신이 멈춤 | EC2 자동 복구. 안 되면 구축 단계로 다시 세움 |
| 가용 영역 하나 | 남은 영역의 워커가 받음. NAT가 그 영역에 있었다면 밖으로 나가는 것(구글 로그인, 이미지 받기, 백업의 STS)이 실패 | NAT를 다른 영역에 다시 만듦. 이 일이 문제가 되면 NAT를 영역마다 둠 |
| Cloudflare | 밖에서 닿지 않음 | 기다림 |

**바뀌는 선언(이 결정이 병합된 뒤 구현 티켓으로 나눕니다)**

- Terraform: 서브넷 넷과 경로, NAT 게이트웨이, 보안 그룹 둘, ALB·리스너·대상 그룹, ACM 인증서와 검증 레코드, 인스턴스 셋, `gachita` 레코드를 ALB로. 터널 자원과 터널 토큰은 뺌.
- 구축 단계(Ansible): 워커가 클러스터에 붙는 단계, 서버 노드의 테인트.
- GitOps: cloudflared와 그 정책·비밀 값을 뺌. Traefik을 워커마다 하나와 NodePort로. 포트 규칙 예외. Postgres 인스턴스 둘. 요청 수 제한 미들웨어를 빼고 Cloudflare 규칙으로.
- IAM: 적용 역할에 ALB(Elastic Load Balancing)와 ACM 권한이 필요합니다. ADR-0011(PR #74)은 ALB를 만들지 않는다는 전제로 이 권한을 뺐습니다.
