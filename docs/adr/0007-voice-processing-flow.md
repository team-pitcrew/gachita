# ADR-0007: 원음은 대표 폰에서 녹음해 클라우드에서 받아쓰고, 장면은 사람이 고른다

* **상태:** 채택됨, 2026-11-13
* **관련:** T12, #13, T10(ADR-0005), ADR-0006

## 배경

기획 v4는 차 안 대화를 짧은 콘텐츠로 남긴다. T10이 에뮬레이터에서 확인한 결론: 일반 앱의 차량 마이크 녹음 자체는 되지만(기어 D·음악·TTS 중·30분 연속), 녹음 중에는 Gleo가 푸시투토크를 무시하고 우리 Pleos STT도 무음만 받는다. 여행 내내 차에서 녹음하면 차의 음성 기능이 마비되므로 원음은 대표 폰에서 녹음한다(ADR-0005).

T12가 정할 일: 올리기·받아쓰기·화자 구분·장면 고르기를 어디서(차량·폰·서버) 할지, 원음을 차 밖으로 보내는지와 동의·보관, 여행당 비용, 통신이 끊겼을 때의 동작.

## 검토한 선택

1. **차량에서 녹음하고 차량에서 받아쓴다.** T10 충돌(음성 비서 마비)과 차량 자원 원칙에 어긋난다. 기각.
2. **폰에서 녹음하고 폰에서 받아쓴다(온디바이스).** 원음이 차 밖으로 안 나가 강점이지만, 화자 구분 품질과 배터리 부담이 크고 기기 편차가 있다. 폰 성능이 좋아지면 다시 볼 가치가 있어 '남은 범위'로 남긴다.
3. **폰에서 녹음하고 실시간으로 클라우드에 스트리밍해 받아쓴다.** 여행 내내 스트리밍은 비용과 동의 범위가 커진다. 기각 — 조각을 쌓아 배치로.
4. **채택: 폰이 조각(1분 단위)으로 쌓아 올리고, 서버가 클라우드 STT(화자 구분 포함)로 받아쓰고, LLM은 장면 '후보'만 추천하며 사람이 고른다.**

## 결정

역할 분배:

| 곳 | 하는 일 |
|---|---|
| 대표 폰 | 원음 녹음(화면 뒤·꺼짐 확인 필요 — T10 남은 범위), 1분 조각으로 잘라 올리기(재시도 큐) |
| 차량 앱 | 화면(기록 중·일행·부탁), 장면의 시각·위치 남기기(moments). 마이크 안 씀 |
| 서버 | 조각 저장(S3), 받아쓰기·화자 구분(외부 STT 한 건), 장면 후보(LLM) |

- **원음은 차 밖으로 나간다**(폰 → 서버 저장소 → STT 제공자). 받아쓰기와 화자 구분은 외부 STT 한 건으로 묶어 처리한다(화자 라벨을 주는 서비스). 구체적 서비스는 external.md 후보표대로 계약 시점에 고른다. 이 결정으로 계약·결제를 하지는 않는다(티켓 범위 밖).
- **장면 고르기는 사람이 마지막을 결정한다.** LLM(Claude API 후보)은 받아쓰기와 moments를 보고 후보만 추천하고, 참가자가 남기는 moments 구조는 그대로다.
- **동의와 보관.** 기록 동의 절차(이미 있음)에 고지를 더한다: "대화가 녹음되어 받아쓰기 위해 클라우드(제3자)로 전송되고, 원음은 여행 기록과 함께 여행을 만든 뒤 48시간이 지나면 지워집니다. 남는 것은 받아쓴 텍스트와 장면입니다." 원음 보관은 여행 읽기 제한과 **한 시계**(여행을 만든 시각부터 48시간)를 쓴다 — T18 화면 문서 검토에서 '여행을 마친 뒤 48시간'과 기준 시각이 갈라지는 것을 바로잡았다. 지우는 길은 둘: 48시간 자동, 참가자 요청 즉시(명세 초안의 `DELETE /recordings`, 폰의 미전송 조각 큐도 함께 비운다).
- **동의 세대.** 여행에 동의 세대(consent generation)를 둔다. 참가자가 동의를 끄거나 원음 삭제가 일어나면 세대가 오른다. 폰은 조각을 만들 때의 세대를 조각에 적고, 서버는 지금 세대와 다른 조각을 받지 않고(409) 이미 받은 것은 폐기한다. 받아쓰기·장면 후보 작업은 시작 전과 결과를 저장하기 전에 세대를 다시 본다. 삭제·철회 이력을 서버에 남겨 늦은 결과가 폐기된 원음을 되살리지 않게 한다(리뷰: 오프라인 녹음과 철회의 충돌).
- **통신이 끊겼을 때.** 계속 되는 것: 차량 화면과 moments(저대역 JSON). **폰 녹음은 마지막 동의 확인 뒤 정해진 창(초안 5분) 안에서만 이어간다** — T17 차량 화면의 기준("최신 동의를 확인할 수 없으면 기록을 멈춘다")과 같다. 창이 지나면 녹음을 멈추고 자동으로 다시 시작하지 않는다(사람이 다시 켠다). 밀리는 것: 조각 올리기·받아쓰기·장면 후보 — 재연결한 폰은 올리기보다 먼저 여행의 동의 세대·삭제 상태를 동기화하고, 폐기 대상 큐를 지운 뒤 확인을 보내고, 남은 조각을 시각 순서로 올린다.
- **원음 삭제와 동의 철회는 다르다.** 원음 삭제는 이미 녹음된 것을 지우는 요청(받아쓴 텍스트·장면은 남을 수 있다), 동의 철회는 앞으로의 녹음을 멈추는 것. 화면과 응답은 서버 삭제 완료와 각 기기의 로컬 삭제 확인을 나눠 보이고, 전체 기기에서 즉시 지워졌다고 확인 없이 약속하지 않는다.
- **참가자 토큰.** 음성 경로의 인증은 프로필 토큰과 별개다. 참가(프로필·손님 모두) 응답에 여행·참가에 묶인 참가자 토큰을 발급하고, 서버에는 해시만 둔다. 권한 기준과 경로별 허용은 명세 초안(voice.md) 표를 따른다. 구현할 때 openapi·서버에 함께 넣는다.
- **위치 없는 장면도 저장한다.** 후보 가운데 좌표가 없는 것은 목록에서 볼 수만 있고 확정 저장이 안 되면 흐름이 끊긴다. moments 계약을 확장해 `lat`·`lng`는 '둘 다 있거나 둘 다 없음'만 허용하고, 위치 없는 장면은 목록에는 있고 지도에는 없는 것으로 저장·재조회한다(구현 PR에서 openapi·서버·T18에 반영). 좌표가 없다고 0,0을 채우거나 다른 장면의 좌표를 옮겨 적지 않는다.
- **여행당 비용 어림(30분 원음, 공개 요금 기준, 계약 때 다시 잼).** 받아쓰기+화자 구분: 분당 $0.02 안팎의 서비스 기준 약 $0.5~1. 장면 후보(LLM): 받아쓰기 텍스트 약 1만 토큰 들여 소형 모델 기준 $0.05 안팎. 합쳐 여행당 $1 안팎, 100여 줄 원격 비용보다 크지 않다.

## 결과

- `docs/api/voice.md`에 API 명세 초안을 둔다(구현 전이라 openapi.yaml에는 아직 안 넣는다).
- `docs/api/external.md`의 받아쓰기·장면 고르기 향을 이 결정으로 고친다.
- 구현·계약 전이다. 폰에서 화면 뒤·화면 꺼짐·길이 확인(T10 남은 범위)이 끝나야 올리기 흐름을 만든다. 기획 문서(v4)의 녹음 위치 문구도 이 결정에 맞춰야 한다(기획 쪽 과제).
